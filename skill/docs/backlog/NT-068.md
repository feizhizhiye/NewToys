## 一、背景与目标

PcTools 现有四份互不相干的 JSON 清单（`pc-scripts.json` / `pc-quick.json` / `package.json` / `sysinfo.manifest.json`），
每条记录是扁平字段，列定义与数据绑死；"一页 = 全部脚本"，**无法按需组合**。

目标：改成「**采集器 → 集合 → 视图 → 页面**」四层，数据入库，用户自己扫描、自己组集合、自己定义列；
信息面板成为**可承载多个集合的展示框架**，按采集器分节呈现。

同时模块整体改名**脚本管理器**（用户已拍板 —— 这是「菜单 Key 一经发布 ⛔ 不改」铁律的**授权例外**）。

### 三.2 数据落位（S2）

```
<配置根>/
  config/
    script-manager.json    ← 模块设置（IOptionsStore 分区 script-manager；进备份）
    script/
      script.json          ← 集合 / 条目 / 标签 / 视图 / 上次选中集合（手工数据，进备份）
  data/
    script/
      script.db            ← 观测快照 / 运行日志（可重建，不进备份）
```

- 🔴 **设置文件 ⛔ 不能是 `config\script\settings.json`**：`JsonOptionsStore.FilePath(module) = ConfigDir + Validate(module) + ".json"`，而 `Validate` **禁路径分隔符 / `.` / `..`**（`Core/Services/JsonOptionsStore.cs:169-184`）⇒ 传 `script\settings` 直接抛异常。要那么放必须改 `Core`（框架层冻结 + 改需求 §3.5），本期不做 ⇒ **落 `config\script-manager.json`**（沿用旧 `pc-tools.json` "分区名 ≠ 模块键"的惯例）。
- 🔴 **不改 `ConfigStoreService`**（框架层冻结）：模块内 `Path.Combine(cfg.ConfigDir, "script")` / `Path.Combine(cfg.DataDir, "script")`，目录不存在自建。将来若给它加 `GetModuleDataDir()`，另立卡。
- 🔴 **不改 `SqliteDatabase`**（`DatabasePath` 硬编码 `newtoys.db`）：模块内自建 `ScriptDatabase`，用 `Microsoft.Data.Sqlite` 直连（`Core` 的包引用可传递编译）。
- 手工数据用 **json 而非 db**：可手改、可备份、可 diff —— 只有观测/日志这类"会长大要查询"的才进 db（对齐 §3.5 `IOptionsStore` 口径）。

### 三.3 表结构（`data\script\script.db`，全部 `pc_` 前缀）

| 表 | 关键字段 |
|---|---|
| `pc_observations` | `item_id, run_id, row_key, attr, value, captured_at` + 索引 `(item_id, row_key)` / `(item_id, captured_at)` |
| `pc_runs` | `id, item_id, started_at, duration_ms, exit_code, stdout_digest, status, row_count` |

⚠️ 观测与条目**必须分表**：每次刷新写新行，并进条目表会炸。
⚠️ `attr` = **属性名字符串**（与 §三.13 的列 key 同一个键空间），⛔ 不用 NT-067 的 1-based 列位。
⚠️ 集合 / 条目 / 视图**不进 db**（它们在 `script.json`）—— 需求 §6.2 ④ 提到的 `pc_collections` 指"前缀隔离"的命名约定，本期没有这张表。

- `role` ∈ `script` / `command` / `collector` / `package`（脚本也能当采集器，用同一张表 + 标记）；`collections[].kind` 是**另一套枚举**，见 §三.0。

### 三.5 `collectable` 判定（S3）

| 条件 | 结果 | 文案 |
|---|---|---|
| `.py/.ps1/.bat/.cmd` 且文件存在 | ✅ | — |
| 命令 / 脚本 `capture=true` 且不在黑名单 | ✅ | — |
| 含 `start` / `explorer` / `control` / `ms-settings:` / `shutdown` / `pause` | ❌ | 有副作用或需交互 |
| 文件不存在 | ❌ | 文件缺失 |
| 用户手动排除 | ❌ | 手动排除 |

- 库页新增列「可采集」：`✔` / `✖`（悬浮原因）
- 工具条筛选「仅可采集」← **按需生成集合的入口**
- 集合成员选择器：默认只列可采集项，勾「显示不可采集」后灰显不可勾

### 三.7 集合管理（S4）

- **独立菜单项** `script-collections`，主从两栏（左 280px 集合列表 + 右成员表 / 详情卡）
- 左栏：搜索框 + 筛选（kind / 标签）+ 分段（置顶 / 最近使用 / 全部）+ 每行（名称 · kind 图标 · 成员数 · ★）
- 右栏上：成员表（勾选即增删，即时生效无保存按钮）
- 右栏下：详情卡 = 名称 / 图标 / kind / 描述 / 默认视图 / 刷新策略 / 标签
- 工具条：新建 / 复制 / 删除（二次确认，`builtin` 不可删）/ 归档 / 🔍 扫描目录 / 📤 发送到信息面板 / 导出
- **几十个集合的规模**：靠「搜索 + 置顶 + 最近使用 + 标签筛选」解决，⛔ 本期不做层级分组（超过 ~80 个再评估）
- **内置集合（需求 §6.2.5）**：`脚本库`（`kind=script`）/ `命令库`（`kind=command`），`builtin=true` —— 首次启动随 `script.json` 播种；**可改名、⛔ 不可删**；成员由 S3 切库时的全量清单填充（只读，用户要自定义就新建集合）

### 三.8 信息面板 = 集合选择框 + 分节（S5）

```
[工具条]  集合 ▾ │ 视图 ▾ │ 🔄 全部刷新 │ ⚙ 节设置
[主体]   ScrollViewer
   ▸ 磁盘使用.ps1    ● ok   12:03  18 行   [⟳] [⌄]
        └ 表（该采集器自己的列）
   ▸ 卷信息.ps1      ● warn 12:03   4 行   [⟳] [⌄]
[底栏]   本次 412ms · 3 节 · 22 行（分页关闭）
```

🔴 **用户 2026-10-17 否决横向 Chip 条**：「除了标签页栏和工具条，不要有横向排列的按钮了，整体体验如浏览器，做成选择框吧」。
⇒ 顶部**只有一个集合选择框**，一次显示**一个集合**的节（浏览器：一次一个页面，切页靠标签/下拉）。

- **选择框 = 工具条 `ToolbarItemKind.Combo`**（`ItemsPath` / `SelectedPath` / `DisplayPath`，`Shared` 既有能力，零新增 UI 机制）
- 下拉项排序 = **★置顶 → 最近使用 → 名称**（几十个集合靠这个把常用的顶到前几行）
- 下拉文案 = `名称 · 成员数`（如 `磁盘体检 · 3`）
- 切换集合 = 卸载旧节 + 加载新节；**记住 `lastCollectionId`**，重启恢复上次的集合
- 🔴 **⛔ 不做工作区 / 多集合并存 / Chip 条**；需要"同时看两类数据"⇒ 把它们放进同一个集合（集合本就是为此设计）
- **`📤 发送到信息面板`** = 选中该集合 + 跳转到信息面板（⛔ 不再"追加"）
- 集合内**两级折叠不做**（只剩节级折叠）；节级折叠状态入视图定义
- 节头：采集器标题 + 状态点（`ok/warn/error` **着色**）+ 上次采集时间 + 行数 + 折叠 + 局部刷新
- 节头吸顶：Avalonia 无原生 sticky → 手动浮层（参考设置页 `StuckHeader` 先例）
- 节数上限 40；每节**预览 20 行 + 展开全部**
- **分节模式关闭分页**（底栏改摘要：本次耗时 · 节数 · 总行数）；`layout=merged` 才启用合并表 + 分页（需各采集器有共同 `row_key`）
- **空态**：无集合 ⇒ 「还没有集合」+「去创建集合」；集合为空 ⇒ 「这个集合还没有采集器」+「去添加」

### 三.9 执行频率三层（S6）

| 层级 | 字段 | 语义 |
|---|---|---|
| 采集器 | `intervalSeconds` + `auto` | 单条节奏；0 = 只手动 |
| 集合 | `refreshMode` = `manual` / `on-enter` / `timer` + `refreshSeconds` | 进页面刷 / 停留时定时刷 |
| 视图 | 同名字段可覆盖 | 同一集合不同视图可不同频率 |

**硬约束**：
1. 只有 `readonly=true`（采集器全部满足）允许 `auto=true`；有副作用的一律灰掉并提示原因
2. 最小间隔 2s、上限 3600s（沿 NT-067）
3. 前一次未完成 → 跳过本次（不排队、不叠加）
4. 离开页面停表；后台不停表本期不做
5. 只刷新**未折叠**的节
6. `retentionMode=latest` 禁用趋势展示（UI 明示）

### 三.10 保留策略（S2/S6）

| `retentionMode` | 行为 | 适用 |
|---|---|---|
| `latest` | 写入后删同 `item_id` 的旧观测，只留最新一批 | 只读类型 / 包列表（默认） |
| `count` | 保留最近 `retentionN` 次 run | 需要看趋势的采集器 |
| `days` | 按 `captured_at` 删超过 `retentionN` 天的 | 同上，按时间 |

- `readonly=true` 的条目**强制** `latest`，UI 锁定不可改
- 清理时机：写入同事务清理 + 启动时全库兜底一次（`days` 模式）

### 三.11 命令当脚本用（S5 附带）

命令库里的命令 = **无脚本文件的采集器**，满足以下条件即可在信息面板参与分节：

1. `role=command` 且 `capture=true` 且不在副作用黑名单
2. 输出走**解析器**：`line`（每行一个值）/ `csv` / `regex` / `json`（默认 json，与脚本一致）
3. 强制超时（默认 15s、上限 120s、超时杀进程树）
4. ⛔ **不复用** `QuickActionService.BuildRunPlan`（那是可见窗口给用户看的），改复用 `ScriptRunner` 的捕获逻辑
5. 副作用黑名单命中 → 强制 `collectable=false`、`capture=false`

### 三.12 内置数据播种

- **内置采集器**：默认 6 个采集脚本（os/cpu/mem/disk/net/runtime）随包播种到脚本目录 `sysinfo\`（保留 NT-067 的 `SysInfoSeeder`：**只加不覆盖** + `.seeded`）
- 首次启动自动登记为 `role=collector` 的 items（这是程序内置数据，非用户数据迁移）
- **内置集合**：`脚本库`（`kind=script`）/ `命令库`（`kind=command`），`builtin=true`（播种规则见 §三.7）
- `sysinfo.manifest.json` **废弃**，不读、不写、不删（留文件不管）

### 三.13 列 schema：归属与生成（S5 关键落点，替代废弃的 manifest `columns[]`）

需求 §6.2.6 只写"节体 = 该采集器自己的列，由输出 `attrs` 并集决定"，落点在本节定死：

| 场景 | 列 schema 落点 | 说明 |
|---|---|---|
| `layout=sectioned`（默认） | **`items[].columns`** | 每采集器一份，节与节列宽 / 列序独立 |
| `layout=merged` | `views[].columns` | 合并表共用一份列（要求各采集器有共同 `row_key`） |

- **列 key = `attrs` 的属性名字符串**（与 `pc_observations.attr` 同一键空间）。⛔ 不用 NT-067 的 1-based 列位 —— 该模型随 `sysinfo.manifest.json` 一起废弃。
- **生成时机**：某采集器**首次成功采集** → 按该次输出 attrs 的顺序并集生成 `{ key, title=key, visible=true, order=出现序, width:"" }` → **原子写回 `script.json`**；后续新出现的 attr **追加到末尾**，⛔ 不改已有列（用户调过的顺序 / 宽度不丢）。
- **用户改列**：`⚙ 节设置` / 列设置 → 写回同一份 `columns`（唯一写入点 = 仓储）。
- **列宽**：本期不做拖拽（沿 NT-067）；`width` 留空 = 自适应，填数值 = 固定 px。
- 尚无 schema 的采集器 ⇒ 节体显示「还没有列，先刷新一次」。
- 输出解析失败 ⇒ 该次不进 attrs 并集（不污染列），节体保留旧数据 + 节头标 `error`。
