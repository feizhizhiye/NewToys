## 背景 / 问题（三处根因，缺一都不会「按节点展开」）

| # | 位置 | 现状 | 后果 |
|---|---|---|---|
| 1 | `Services/BookmarkService.cs` `ImportHtml`（70~94 行） | `Walk(node, folder)` 里 `if (h3) folder = 名字` —— **覆盖**而非拼接，子 `<DL>` 递归只带本级名字 | 只保留**最后一级**文件夹名，父路径全丢；同名末级跨路径合并 |
| 2 | `Models/BookmarkItem.cs` `Folder` | 单值 `string`，语义 = 末级名 | 没有「路径」概念，无法还原层级 |
| 3 | `Views/BookmarkView.axaml`（48 行） | 单层 `ListBox.list-page` 平铺，Folder 只是第 3 列文本 | 没有容器/树概念 |

⇒ 浏览器里 `工作/项目A/文档` 三层嵌套，导入后是 3 条平铺，分组列显示 `文档`。

## 目标形态

**整页就是一棵树**：文件夹行（可展开 / 折叠、带条数）与书签行（叶子）同列表混排，缩进表示层级 —— 与浏览器书签管理器 / 书签下拉菜单一致。

示意：`工作 ▾ → 项目A ▾ → [Jira 看板 · jira.company.com · 200]`。

## 设计决策

**D1 · `Folder` 升级为「路径」，⛔ 不做持久化树结构**
- 约定分隔符 `/`，例 `工作/项目A/文档`。
- 老数据（单层名）天然等价单层路径 ⇒ **零迁移**，`web_docs` 存储格式不变。
- 树由扁平列表**派生**，不新增持久化结构。
- ⛔ 否决「持久化 `FolderNode` 嵌套」：要迁移、要改 6 处 `Folder` 用法、拖拽移动复杂化。
- 已知限制（接受）：文件夹名自身含 `/` 会被拆级（罕见）。

**D2 · 整页单树（用户 2026-10-24 定调）**
- `ListBox` 换 `TreeView`，同一 `TreeDataTemplate` 内按 `IsFolder` 切换两种行样式。
- ⛔ 已否决「左侧文件夹树 + 右列表」：用户要的是「列表本身按节点展开」，左树只是导航、不是展开。
- 代价（如实记录）：比左树方案多约 60 行 —— 树形态要接管**筛选 / 排序 / 分页**三个语义（见步骤 3、5）。

**D3 · 空文件夹不保留** —— 派生树只能从「有书签的路径」长出中间节点；纯空目录导入后消失（接受）。

## 实现步骤

### 1. 新增 `Models/BookmarkNode.cs`（视图节点，⛔ 不持久化）
```
Kind        // Folder | Bookmark
Name        // 显示名（文件夹名 / 书签标题）
Path        // 文件夹 = 全路径；书签 = 所属文件夹全路径
Url / CheckStatus / CheckOk / IsBatchOpen
Children    // ObservableCollection<BookmarkNode>（书签为空）
Count       // 文件夹 = 含子孙的书签数
IsExpanded
Item        // 书签时指向源 BookmarkItem（命令层取它）
```
- `BookmarkItem` **不动**（存储 / 详情卡 / 命令都依赖它）。

### 2. `BookmarkService.ImportHtml` 修路径
```csharp
void Walk(INode node, string parentPath)
{
    var cur = parentPath;                       // H3 只改 cur，⛔ 不改 parentPath
    foreach (var child in node.ChildNodes)
    {
        if (child is not IElement el) continue;
        if (el.LocalName == "h3")
        { cur = Join(parentPath, (el.TextContent ?? "").Trim()); continue; }
        if (el.LocalName == "a")
        { /* 原逻辑不变；BookmarkItem.Folder = cur */ continue; }
        Walk(el, cur);                          // DT / DL / DD 一律传 cur
    }
}
static string Join(string p, string n)
    => n.Length == 0 ? p : p.Length == 0 ? n : p + "/" + n;
```
- 🔴 与原实现的唯一差别：`cur` 基于 `parentPath` 拼，**不是**把参数 `folder` 直接改写 ⇒ 同层多个 `<H3>` 互不污染。
- `folderSet` 收集**全路径 + 全部祖先前缀**（`工作`、`工作/项目A`）；`BookmarkImportResult.Folders` 语义 = 路径数。
- 保留原行为：按 URL 去重、跳过 `javascript:` / `place:`、空标题回落 URL。

### 3. `BookmarkViewModel` —— 树派生 + 三个语义接管
**3.1 `RebuildTree()`**：`_all` 变更后重建。按 `Folder` 拆 `/` 逐级建文件夹节点；`Count` = 子孙书签数；同级按 `Name` `OrdinalIgnoreCase` 排序；**一期默认全展开**（不记忆折叠状态）。

**3.2 筛选重建（🔴 必须做，否则搜到看不见）**：搜索 / 快速筛选生效时，**重建只含命中书签及其全部祖先节点**的子树，并强制 `IsExpanded=true`；无命中 → 空态。

**3.3 排序语义收窄**：表头排序只在**同一父节点内**对书签排序（⛔ 不跨层重排，否则树结构被打散）。「按分组」排序即树本身的层级序，该列排序失效并置灰。

**3.4 选中映射**：`SelectedNode`（`BookmarkNode`）；既有 6 个命令（检测 / 批量 / 打开 / 送抓取 / 编辑 / 删除）内部改取 `SelectedNode?.Item`，选中文件夹行时全部不可用（`CanExecute=false`）。

### 4. `Views/BookmarkView.axaml(+cs)`
- `ListBox` → `TreeView`，`TreeDataTemplate ItemsSource="{Binding Children}"`；行内仍是 `v:ColumnGrid ColumnSpecs="{Binding $parent[TreeView].DataContext.VisibleColumnSpecs}"`：
  - 第一列 = 缩进占位（`Margin` 由节点的 `Depth × 16` 换算）+ 文件夹箭头/名称+条数 或 书签标题
  - 网址列 / 状态列位置不变 ⇒ **表头与列天然对齐**（缩进只作用在第一列内容）
- 行高 28（对齐 `ui.md` 列表行高）；文件夹行文字 `PrimaryTextBrush` + 500，书签行 400。
- 页面内 `UserControl.Styles` 覆盖 `TreeViewItem`：`MinHeight=28` / `Padding="0"` / selected `CardSelectedBrush` / hover `ContentBrush`（`ui.md` §105~108）；🔴 只用 `DynamicResource` 主题键。
- 🔴 显式写 `public BookmarkView(){ InitializeComponent(); }`（漏了整块 XAML 静默不加载）。
- 一期文件夹行**不加图标**（`App.axaml` 无 `IconFolder`，补资源 = 动 Shell）。

### 5. 分页 / 详情卡取舍
- **分页关闭**：树形态必须全量（否则折叠树被切成页无意义）→ `ListFooterBar` 只留「共 N 条 · M 个文件夹」计数，分页槽隐藏。
- **详情卡**：选中书签行照旧；选中文件夹行 → 详情卡显示「文件夹路径 / 书签数」只读摘要（复用现有详情卡 `DetailCardDescriptor`，不加新 Kind）。若成本超预期，降级为「选中文件夹时详情区留空」。

### 6. 浏览器配置（⛔ 不新建概念，复用已有 `LaunchConfig.Browser1/2`）
- 「指定浏览器配置」= **设置 → 启动与行为**（`LaunchConfigView`）里已有的 **浏览器1 / 浏览器2**（名称 + 程序路径 + 参数模板 + 网址列表），首页一键按钮已用它批量开网址。
- 书签页工具条右侧加下拉 `打开方式 ▾`：`系统默认浏览器` / `浏览器1 · {Name}` / `浏览器2 · {Name}`；未设 `ProgramPath` 的项标「未配置」并禁用。
- 注入 `ILaunchConfigService`（`Shared`，Shell 已注册 singleton）；执行走现成 `LaunchRunner.OpenBrowser(exe, argsTemplate, urls)`（`Shared/Services/LaunchRunner.cs:11` —— 已支持 `{url}` 占位、未配程序自动回退默认浏览器）。
- 🔴 **写入口径变更（用户 2026-10-24 授权）**：`app.json` 的 `Launch` 原「唯一写入点 = 设置页」，现追加第二写入点 = 书签页「写入浏览器配置」，且必须经 `ILaunchConfigService.Save()`（⛔ 不直接写 `IAppConfigService.Launch`）。写入 = **追加 + URL 去重**，幂等。

### 7. 两种选中态的详情卡
**7.1 选中文件夹行（`Kind=Folder`）** → 详情卡换文件夹摘要：字段 = 文件夹路径 / 书签数（含子孙）；动作：
- `🌐 全部打开`：子树全部 URL → `OpenBrowser(当前选中配置)`，**⛔ 不写 `LaunchConfig.Urls`，纯临时调用**
- `🔗 全部检测`：子树逐条 `CheckOneAsync`（复用现有并发与状态回写）
- 保存 / 删除 / 送抓取 / 加入批量 → 隐藏

**7.2 选中书签行（`Kind=Bookmark`）** → 现有详情卡不变，另加两处：
- `🌐 打开` 改为按下拉配置打开（下拉 = 系统默认时行为与现在完全一致）
- 新增 `📌 写入浏览器配置`（仅当选了具体配置时可用，`CanExecute` 跟随）：把该 URL 追加进该配置 `Urls` 并 `Save`，状态栏「已写入 浏览器1（共 N 条）」

### 8. 一期 ⛔ 不做
树节点右键（新建子文件夹 / 重命名 / 删除文件夹）、拖拽移动书签、折叠状态持久化、空文件夹保留。
