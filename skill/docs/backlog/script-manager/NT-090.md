# NT-090 · 脚本中心：运行台搬家 + `web-crawl` 泛化为「运行结果」

> 状态：✅ **就绪**（2026-10-22 细化；同日实施）｜优先级：P1
> 关联模块：`script-manager`（单模块内；⛔ 不动 Shared/Core/Shell/UI）
> 关联需求：需求规格 §2.3.2（`web-crawl` 泛化为运行结果查看台 / 集合新增类别 `crawl`）、§2.3.5（数据与文件归属）、§6.2（脚本中心）
> 依赖：**NT-089 S1**（抓取能力整体平移）已实施；被 NT-092 / NT-093 依赖
> 创建：2026-10-22

## 一、背景与目标

089 已完成「抓取能力整体平移」，但两处目录常量仍写死 `web-tools`（089 §四明确留给 090）：`FlowService.flows`、`RunRecordService.runs`。
同时需求 §2.3.2 定案：`web-crawl` 从「爬虫面板」泛化为**运行结果查看台**（脚本 / 命令链的执行结果与日志）。

用户可见变化：

1. 左树「爬虫面板」→「运行结果」（⛔ Key `web-crawl` 不变）。
2. 运行结果页新增 ④「运行记录」节：历史 run 列表 + 打开目录 / 打开日志 / 复制诊断。
3. 集合类别新增「抓取集合」（`crawl`）：可建、可筛选、可「发送到对应页面」（跳 `web-crawl`）。
4. `flows\*.json` / `runs\` 落到 `<DataDir>\script\` 下，旧目录内容一次性搬过来。

## 二、范围

### A · 目录归位（含老目录搬迁）

| 项 | 动作 |
|---|---|
| `FlowService.FlowsDir` | `<DataDir>\web-tools\flows` → `<DataDir>\script\flows`；首次访问时搬旧目录 `*.json`（⛔ 不覆盖同名新文件、整段 try/catch、只搬一次） |
| `RunRecordService.RunsRoot` | `<DataDir>\web-tools\runs` → `<DataDir>\script\runs`；同样搬旧目录（按脚本子目录整体搬） |
| 校验 | `grep -rn "\"web-tools\"" src/Module.ScriptManager` 只剩 `RuleRunService.ScrapeModule`（读 `config\web-tools.json` 的 UA/超时，NT-094 设置拆分后归位） |

### B · 集合类别 `crawl`

1. `ScriptCollectionKind`：`Crawl = "crawl"`；`Normalize` 认它；`Label` = 「抓取集合」；`PageKey` = `web-crawl`。
2. `CollectionRow.InUseHint` 补 `crawl` 档文案。
3. `CollectionViewModel`：`KindFilterOptions`、`KindOptions` 各加一项「抓取集合」。
4. `RoleMatchesKind`：`crawl` ⇒ 成员角色 `script` / `collector`（抓取集合成员 = 脚本条目，`Target` = 起始网址）。
5. ⛔ 不做集合消费（运行台读集合当任务清单归 NT-092 命令链），本卡只让类别「可建 / 可筛 / 可跳转」。

### C · `web-crawl` 泛化为运行结果查看台

1. 菜单标题「爬虫面板」→「运行结果」（`ScriptManagerModule.cs` 注册行；Key / View / Order 不变）。
2. 新增 ④「运行记录」节（`CrawlSection` key=`history`）：
   - 数据源 = 当前「脚本 ▾」选中脚本的最近 N 条 run（`RunRecordService.History(script, 10)`，新增方法，读 `runs\<脚本>\*\result.json`）。
   - 行 = 时间 / 起始网址 / 条目数 / 错误数 / 列数；行右键：📂 打开目录、📄 打开日志（`diag.txt`）、📋 复制诊断；双击 = 打开目录。
   - 空态：该脚本还没跑过。节头 ⟳ = 重新读取。
3. 每次跑完（`FetchLinksAsync` / 下载批结束）刷新该节。
4. ⛔ 不改执行语义（仍走 `RuleRunService`），⛔ 不做脚本来源泛化到脚本库条目（属 NT-092 命令链），⛔ 不改命令链 / 五段槽位。

### ⛔ 不做

- ⛔ 不改菜单 Key、不动 Shared/Core/Shell/UI。
- ⛔ 不做命令链（NT-092）、出口代理（NT-093）、设置拆分（NT-094）。
- ⛔ 不删旧目录（搬完留空壳，与 089 同口径）。

## 四、技术要点

- **迁移写法照抄 `RuleFileService.MigrateLegacyRules`**（089 已验证）：目录常量改后首次访问搬旧目录，只搬一次、不覆盖、try/catch。
- **新增 UI 控件 / 命令**：`RunRecordService.History(script, n)` 返回 `List<RunRecord>`（按目录名字典序倒序 = 时间倒序）。
- **XAML 新节**：沿用 `Border.section` + `Border.section-head` 样式；行右键命令挂行对象（ContextMenu 在弹出树，取不到页面 VM）⇒ 行模型自带 `ICommand?`。
- 🔴 行尾 CRLF（`core.autocrlf=true`）：批改用 `splitlines(keepends=True)` 原样写回。
- 改动全在 `Module.ScriptManager` 一个程序集 ⇒ 与 NT-088（Core）分批；与 089 同程序集但已分 commit。

## 六、风险 / 假设

1. **假设**：`crawl` 集合成员角色 = 脚本条目（`Target` = 起始网址），本卡不消费；若后续 092 要另种成员语义，只改 `RoleMatchesKind` 一处。
