# NT-147 · 表头右键 / 行右键职责分离（资源管理器口径）
- 状态：✔ 已完成（2026-11-05 静态检查 PASS / FAIL 0，⏳ 待用户本地 build）
- 优先级：P1
- 关联需求：需求 **§4.8** ｜ 规范 **`ui.md` §6.3c §10.1 §12**
- 依赖：NT-123（原生表格迁移；本卡取代其「列显隐改到行右键」的取舍）
- 创建 / 完成：2026-11-05

## 背景
NT-123 迁 `TableView` 时为省一套表头菜单，把「▤ 列」「🔎 筛选」「仅看已安装」塞进行右键；而唯一的 `ContextMenu` 挂在控件级，表头右键冒泡到宿主 ⇒ 表头也弹行菜单（安装 / 卸载 / 复制 Id），语义错位。项目自身 `ui.md` §10.1 与需求 §4.8 写的却是「查看态 → 表头右键」。

## 方案（用户 2026-11-05 拍板「参考 windows 的资源管理器的逻辑改吧」）
- 表头右键三段：① 列宽（本列按表头文字适配 / 恢复本页默认列宽）② 列显隐勾选（首列标识列置灰 + 提示）③「🔎 筛选」快捷项（读 VM `QuickFilters`）。
- 行右键：只留作用于选中行的功能动作。
- ⛔ 不复活「自动调整全部列宽」（v3.20 实测按全文测宽把其他列挤到 0，规格判不可救药）；⛔ 不做列重排 / 列像素设定对话框。
- 资源管理器「更多…」段在项目列数少（≤13）时等价为全量顶层勾选清单，不另开对话框。

## 技术要点
- `TableViewHost` 新增 `_headerMenu` / `_rowMenu`：右键 `PointerPressed` Tunnel 阶段按坐标命中 `TableViewColumnHeader`（表头背景透明，⛔ 靠 `e.Source` 找祖先会漏掉文字以外的空白区）→ 切换 `ContextMenu`；`ContextRequested` Tunnel 把键盘触发（无 `PointerPressed`）切回行菜单。**在按下阶段切换**而非 `ContextRequested`，避开框架读取菜单的时序。
- 列菜单每次 `Opening` 重建（列标题随排序箭头变、显隐可能在别处改过、`QuickFilters` 会重建）；两个菜单都手工同步 `DataContext`（规范 §3.8）。
- 「本列适配」复用已有 `MinWidthOf`（表头文字宽）写 `GridLength(Pixel)`；默认宽度在 `SyncColumns` 时按列缓存，恢复时写回。**全程不碰 Shared / Core / Shell**，只动 `NewToys.UI`（方案已展示并经用户确认）。
- 软件包页「仅看已安装」并入 `QuickFilters.Insert(0, new FilterQuickItem { Command = ToggleInstalledOnlyCommand })`，功能入口不丢；该项 v3.19 原本就设计为表头右键菜单项。
