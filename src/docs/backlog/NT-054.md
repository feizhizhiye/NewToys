## 背景 / 目标

- 现状：详情卡共 **16 张**，两种形态 —— ① `Views/Detail/<Xxx>DetailView.axaml`（4 张，已抽 UserControl，走 `IDetailPanelProvider`）；② 页内自绘 `<Border Classes="detail-card">`（**12 页**，见《工程规范》§3.8 技术债 **B13「详情面板上提」**，契约与 Shell 容器已实装、迁移暂缓）。
- 痛点：90% 的字段行是「`field-label` + `field-value`」的纯重复手写 XAML；同一张卡的外壳（340px / 滚动条 8px 偏移 / 空态 / 示例态 / 分区）在每页各抄一遍。
- 目标：**卡片结构由「描述符」声明、Shell 统一渲染** —— 页面只声明「展示什么、怎么改、有哪些动作」，不再手写卡片 XAML。
- 定位（用户定调）：**详情卡的功能一律是对主显示区列表数据的补充与修改**；命令编辑等复杂交互也**在卡内实现，不走弹窗卡**。

## 技术要点 / 约束（规范章节、坑点、关键文件）

### 分层归属（🔴 牵涉框架层，阻塞上报第 1 种，用户已拍板接受）

| 件 | 归属 | 理由 |
|---|---|---|
| 描述符 POCO（`DetailCardDescriptor` / `DetailField` / `DetailAction` / 枚举） | `Shared/Details/` | 纯 POCO，**零 Avalonia 依赖** → 合规（Shared/Core 不引 Avalonia） |
| 渲染器控件 `DetailCardHost`（含 7 个 `DataTemplate`） | `Shell/Controls/` | 必须引 Avalonia；模块禁引 Shell → 只此一处可放 |
| 模块侧来源接口 `IDetailCardSource { DetailCardDescriptor? Card { get; } }` | `Shared/Services/` | 与既有 `IDetailPanelProvider` 并列，模块 VM 实现 |
| 各页卡片声明 | 模块内 VM | 每页一个 `DetailCardDescriptor` 实例 |

### 契约草案

```
DetailCardDescriptor
├─ Sections: DetailSection[]             // 分区：Header / TogglePath(标题勾选框) / IsExpanded / Fields[]
├─ Actions:  DetailAction[]              // 动作区：Text / Command / IsEnabledPath / IsVisiblePath / ConfirmText
└─ Custom:   object?                     // 逃生舱：非空则整卡自定义，忽略上面两项

DetailField
├─ Label: string                         // field-label 文案
├─ ValuePath: string                     // 绑定路径（相对卡 DataContext，如 "DetailRow.TypeText"）
├─ Kind: FieldKind                       // 7 种
├─ Commit: EditCommitMode                // Instant / OnBlur / Explicit
├─ VisibleWhen / EnabledWhen: string?    // 布尔路径，支持 "!" 前缀（替代 IsVisible/IsEnabled 绑定）
├─ OptionsPath / OptionValuePath / OptionDisplayPath: string?   // Select 用
├─ Placeholder / Hint / Rows: ...
└─ 修饰位：Mono / MultiLine / Selectable / Password
```

### 关键坑点

- 🔴 **绑定路径是字符串 → 静默失败**：属性改名后不报错、不崩溃，只是白板。**必须**同步给 `skill/scripts/` 加一条检查（描述符 `ValuePath` vs VM 属性名），否则失去现有 `check-axaml-props.ps1` 的编译期兜底。（同类先例：首页 `AppMenuItem.Icon` 字符串驱动已被记为技术债。）
- **`SelectComplex`（预设下拉）**：`ComboBox` 需要 `ItemsSource` + `SelectedValue` + `SelectedValueBinding` + `ItemTemplate` 四件套（见 `VideoBatchView.axaml:574-591`），模板要一次性写对，⛔ 别让每页再抄。
- **条件可见的联动**：如批量队列 `EditIsCut`（分区标题勾选框）→ `IsCutReEncode`（同分区内一行的可见性）。描述符必须支持分区级勾选框 + 字段级 `VisibleWhen`，这是覆盖 VideoBatch 的**硬需求**。
- **示例态**：`IsDetailSample` ⇒ 整卡 `IsEnabled=false`（v3.32 §4.8.3）。由 Shell 渲染器统一处理，⛔ 不能靠每页各写一遍。
- **滚动条覆盖式**：卡片 `Padding` 右 4 + 滚动内容 `Margin` 右 8（规范 §3.6 / 需求 §4.8 第 7 条），Shell 一处写死。
- ⛔ **不引第三方控件**：`bodong.Avalonia.PropertyGrid` 只作**参考实现**读，引包违反「禁第三方 UI 库」铁律。
- ⛔ **不做运行时 JSON / XAML 加载**（v1 不做）：字符串驱动 UI 在本项目已有技术债先例；描述符用 **C# 对象字面量**，享受编译期检查 + IDE 补全。
