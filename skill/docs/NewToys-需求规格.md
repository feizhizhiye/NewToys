## 一、定位

**NewToys 是作者个人自制的工具集——「带 GUI 的脚本管理器」。** 非商业、非通用产品，「自用顺手」第一。

每个页面 ≈ 一条或几条命令行 + 一份 `config/` 配置的封装。

- 🧭 **干净启动（v3.60 定位）**：软件 = **空壳 + 按需加载**。启动后只有**必要配置**（主题 / 列宽偏好 / 模块注册）与**首页、设置页**有内容，其余列表**一律初始为空** —— 没有任何页面"必须有数据显示"，内容由用户自己导入 / 收集（工作项 NT-060）。
- 🧭 **用户画像（v3.60 定位）**：使用者是**具有一定电脑知识的人** ⇒ ⛔ 不做保姆式引导 / 内置示例内容；**配置可读、可手改、可备份**是加分项（选型时优先可读性，见 §3.5）。

## 二、边界

**判据**：「如果我只写个脚本会怎么写？现在少让用户做哪一步？」—— 这就是功能边界。

- **做**：把作者日常高频的终端 / 系统能力，包成可点、可配、可备份的界面。
- **不做**：脚本里不会有的东西——社交、推荐、引导、埋点、账号、云同步、**在线插件市场 / 商店**。
- **本地模块热加载**（丢 DLL 进 `Modules\`、点刷新即时装配）**要做** —— 它不联网、不下载、不建生态，等于「加一个本地脚本」。

### 2.1 远期规划（暂不实现；**勿立项、勿重复评估** —— 省 token）

以下均为**长期方向**，近期**不实现**；除用户明确启动外，⛔ 不在会话里重复讨论 / 提 todo / 写代码：

1. **上架应用商店**：商店版配置与打包 —— release 档条件播种、打包排除 dev 文件、商店版仅含 `default`。近期无上架计划。
2. **跨平台 Debian 13**（承接 §3.7）：主平台仍为 Windows 10 LTSC；Linux 迁移属远期。
3. **脚本管理器模块的备份 + 多平台预留**：整个 `Module.ScriptManager`（收藏夹 / 命令库 / 脚本库 / 软件包 / 信息面板）远期要支持
   - **备份**：各子工具的清单 / 配置可导出导入（现仅部分列表页有）。
   - **多平台**：包管理器（winget → Linux 包管理器）、脚本运行 shell、系统设置入口等**平台相关能力集中封装**，便于整体替换（承接 §3.7）。
4. **脚本中枢「编排」态 + 工作流引擎（新模块，远期）**：脚本中枢四态 = 收集（脚本库 / 命令库）→ 展示（信息面板，§6.2.6）→ 编排（管道页）→ 工作流。复杂逻辑引擎**独立成新模块**（如 `Module.Workflow`）：多脚本**数据驱动串联**（管道 → DAG 工作流 → 可视编排），信息展示 / 管道只做消费者；当前**不立项、不评估**（YAGNI）。信息展示期沉淀的「输出契约（列号数组 + RowKey + status + 下游可消费）」即未来管道 / 工作流的地基。

### 2.2 编排能力上限（2026-10-19 用户定调 · **L3/L4 封顶**）

- **能力分级**：L1 单条命令 → L2 集合 / 分类 / 收藏 → **L3 命令链（有序执行 + 变量传递 + 失败策略：遇错停止 / 跳过继续）** → L4 条件分支 → L5 图编排（fan-out / 循环 / 子流程）→ L6 触发与调度（定时 / 文件监听）。
- 🔴 **本项目封顶 L3**；**L4 仅在真撞上时做，且优先写进脚本**；**⛔ L5 / L6 永不做**。
- **命名口径**（决定需求预期，⛔ 别混）：叫「**命令链 / 抓取管道 / 多步抓取**」，⛔ 不叫「工作流 / 节点 / 执行实例」。
- **L3 唯一落点 = 复用「集合」加执行语义**（集合已有 `order` 字段）：`▶ 依次运行` + 每条约定 `capture` 输出 + 变量占位符传参；⛔ 不新造工作流模型、⛔ 不做可视化连线。
- **触发门槛**（未满足前 ⛔ 不设计、⛔ 不预留架构）：① 同样几条命令第 3 次手动挨个点；② 某条命令的输出开始被手工复制给另一条；③ 集合里出现 `01_` `02_` 这类顺序命名。
- 🔴 **现在唯一要守住的伏笔**：命令必须有 `capture` + 明确输出格式（`line / csv / regex / json`）—— 这是将来串联的技术前提，已有机制不要破坏。
- **两条正交轴别混**：Python 扩「**单节点能力上限**」，规则流水线扩「**节点之间的连接**」；⛔ 不要因为加了 Python 就认为该上工作流引擎（脚本本身就是万能节点，会抑制节点间编排的需求）。

### 3.4 模块化与热加载

- 模块编译为独立 DLL（`Module.<模块名>.dll`），实现 `IModule { RegisterServices, Initialize }`。
- **菜单只能在 `Initialize` 注册**；`RegisterServices` 禁注册菜单。
- **启动双轨**：Debug 用 `#if DEBUG` 显式类型清单；Release 扫 `<程序目录>\Modules\`，跳过已加载同名。
- **运行期热加载**：丢 DLL 进 `Modules\` → 点刷新 → 即时装配，不重启。
  - 只读本地 `Modules\`，**不联网不下载**；`Path.GetFullPath` 校验路径落在 `Modules\` 内。
  - 每个 DLL 用独立 `AssemblyLoadContext`（`isCollectible:true`）；`NewToys.Shared/Core` 由默认 ALC 共享。
  - 逐个 `try-catch` 隔离：单 DLL 失败不影响宿主与其他模块。
  - 只做「新增」，同名不替换不卸载。

- **模块自包含（硬约束）**：模块所需的一切（View / VM / 服务 / 设置页）都在**自己的 DLL** 里；加载时只往界面注册（菜单、设置页），⛔ 不把模块代码搬进 Shell 或其他模块，⛔ 不靠其他模块代持页面。
- **模块设置页归本模块**（🔴 **v3.66 改口径**，分类 = **模块设置**）：每个模块把自己的设置页（View/VM）放在本模块 `Views/` + `ViewModels/`，在 `Initialize` 里注册进**本模块自己的分组**（`RegisterFunction("<模块键>", "settings-<模块键>", "<模块名>设置", …, 99/100)` —— 例：`RegisterFunction("script", "settings-script", "脚本管理器设置", …, 100)`；**标题保持长名**，`Order` 只作组内排序，见 §4.9）。🔴 ⛔ **不再跨组注册到 `settings`**（该分组已随「设置」一级菜单项一并删除）；`MenuService` 的**延迟补登**机制保留（规范 §3.2），现仅作"分组 key 打错"的兜底。
- **框架设置归 Shell（应用级设置页）**：主题外观 / 更新 / **运行环境**（配置档 + 外部程序路径）/ 一键按钮 / 加密 DNS / 数据备份 / 关于等**应用级设置**由 **Shell 承载**（View/VM 放 `src/Shell/Views` + `ViewModels`，与首页同构，⛔ 不再单设 `Module.Settings`）；⛔ 模块自己的东西不许塞进来。判据：**描述"本软件自身运行环境 / 应用行为" ⇒ 应用级；描述"某个功能扩展怎么工作" ⇒ 模块级**。
- **宿主分组由 Shell 创建（v3.66 改口径）**：启动时 `RegisterModule("system", "系统", "IconSettings", 999, isHome:true)` —— 一个 **`IsHome` 的不渲染分组**，承载"五个应用级设置的**节锚点 Key** + 功能清单（`settings-all`）"的**寻址**（左树 / 首页模块计数 / 功能清单页三处都按 `!IsHome` 过滤 ⇒ 它不出现在任何菜单里，但 `OpenTab` / 收藏卡仍能 `FindItem` 到）。🔴 **⛔ 不再有 `settings` 分组**（「设置」一级菜单项已删除）；模块设置页**注册进各自模块的分组**（不再跨组 ⇒ 不依赖延迟补登；补登机制仍保留在 `MenuService` 以防分组 key 打错）。
- **`Module.*` 不再含框架组件（v3.62）**：原 `Module.Settings` 撤销并入 Shell ⇒ `Modules\` **只含功能模块**，Shell **不再无条件引用任何 `Module.*`**（`Shell.csproj` 的无条件 `ProjectReference` 与 `Directory.Build.props` 的 OutDir 例外一并删除）；`scripts/build.ps1` 产物计数校验 = 只数功能模块。加载后健全性检查：**宿主分组 `system`** 不存在（Shell 自身注册失败）→ 日志 + 状态栏各一行，⛔ 不静默（常量 `ModuleLoader.HostGroupKey`）。
- **框架自给（硬约束）**：一个功能模块都不加载时，框架本身必须完整可用——**首页 / 一键启动 / 收藏夹 / 主题 / 多配置 / 设置全套**均不依赖任何功能模块（Settings 是框架组件，不随功能模块增减；现状已满足：首页与一键启动的全部依赖在 Shared/Core；新增框架功能时保持此性质）。

  - 用户要做"同一批文件、多套标签"用库内 `tags` / `collections` 表达；要彻底隔离就新建配置档（= 一套新库）。
- **应用根** = `%LocalAppData%\NewToys`，环境变量 **`NEWTOYS_HOME`** 整根切换（test vs prod）。
- **数据迁移**：① 首次运行新版时，若 `<应用根>\config` 存在而 `profiles\` 不存在 → 现有 `config/data/logs` **整体移动**到 `profiles\default\` 并写 `active-profile.txt = default`；失败则**保持旧结构运行**并在「设置 → 配置」提示。② NT-113 存储分层：`data\` 存在时整目录改名为 `store\`，再把旧总库按表拆进 4 个模块库（旧库改名 `store\legacy\newtoys-v1.db`，⛔ 不删），可重建内容搬进 `cache\`，完成写 `store\.layout-v2.done`；每步幂等、可重入。
- **切换配置 = 重启应用**（本窗重启到目标配置，显式传 `--profile`；⛔ **不写** `active-profile.txt`——那是全局默认指针，多实例下会互偷；热切换改动面大、极易残留半新半旧状态）。**设为默认配置**（设置 → 配置页）才写 `active-profile.txt`，影响以后**无参启动**的实例。
- **多实例（一个配置一个窗口）**：可同时启动多个实例各跑不同配置——数据隔离靠**目录天然达成**（每配置独立 `config/data/logs`，SQLite / 配置 / 缩略图 / 任务 / 日志全隔离）；`NEWTOYS_HOME` 可整根切换（两个不同根 = 完全隔离）。
  - 启动参数 `NewToys.exe [--profile <配置名>]`：无参 = 读 `active-profile.txt`（全局默认）；参数非法 / 配置不存在 → 回退默认 + 状态栏一行提示。
  - **每配置单例**：同一配置同时只允许一个实例（命名互斥）；第二例提示「该配置已在运行」后退出，⛔ 不静默抢占、⛔ 不抢前台焦点。
  - `active-profile.txt` 只写两处：**首次迁移**（= default）与**设为默认配置**。
  - 窗口标题 = `NewToys · <配置名>`（任务栏区分多实例；**左树底部也与版本号同显**，见 §4.3）；「设置 → 配置」页每配置行提供「🚀 新开」（带 `--profile` 起新进程）。
  - 首启迁移竞态（两实例同时首次启动）容忍：失败保持旧结构 + 下次自愈（既有兜底），⛔ 不加迁移锁。
- **内置配置档 `debug` / `default` / `release`（v3.37）**：三档**永久驻留开发机**（`profiles\<名>\`，⛔ 无任何自动清理；用**「重置为初始态」**替代「删除」）。
  - `default`：本地日常使用（真实设置与数据）。
  - `debug`：开发 / 测试；**首启播种 = 复制当前 `default` 内容**为初始态（测试资源后续接入）。
  - `release`：干净初始态（上架前审计；**上架为远期，见 §2.1**）。
  - 三档在**开发构建（Debug）**首启自动播种；商店版（远期）仅含 `default`、无切换入口。
- **模块只读设置**，唯一写入点在该设置的设置页；功能入口页**只读**（⛔ 不许回写 → 双真相源）。
- 🧩 **选项存储 `IOptionsStore`（v3.60 新增，工作项 NT-061）**：Core 提供一个**按模块分区的 KV 接口**（`Get / Set / Remove`，模块只调接口，⛔ 不碰文件、不知道底下是 json 还是 SQLite）；
  **默认实现 = `config\<module>.json`**（可读 / 可手改 / 随 profile 目录隔离），将来可整体换成 SQLite 的 `options` 表而**调用方零改动**。
  - **启动必需项**（路径 / 主题 / profile 相关）**保持 json**：启动前必须读到、且用户要能手改 ⇒ ⛔ 不进 SQLite。
  - **"记忆类"数据**（搜索历史 / 最近目录 / 上次筛选 / 上次导入路径）才值得进 SQLite —— 会增长、多行、要查询。
  - ⛔ **所有配置按 profile 目录隔离**（多配置天然目录隔离，SQLite 若要加则一个 profile 一个库文件，⛔ 不加 profile 列）。
- 🧩 **每模块一个设置页（v3.60，工作项 NT-061；🔴 v3.66 菜单归属改）**：配置写入点**下沉到模块** —— View/VM 归模块，菜单项**注册进本模块的一级菜单**（NT-021 先例推广到 ScriptManager / WebTools / VideoTools / MediaAssets 四模块；⛔ 不再进 `settings` 组 —— 该组已删），
  见 §4.9。**功能入口页的数据源输入框可编辑**（回车 + 失焦都提交）⇒ 提交给**模块设置服务**走 `IOptionsStore` 落盘，页面 ⛔ 不直接写文件（唯一写入点仍是一处）。
  路径无效 / 无权限 ⇒ **状态栏红色警示 + ⛔ 不写盘**（保持上一个有效值），⛔ 不是"不能编辑"。
- **改系统级配置的页面必须二次确认**（如网络工具的 Hosts 写入 → 改系统 hosts 文件；winget 源增删已改由命令库执行，命令条目的 UAC 即确认）。

### 3.6 默认数据（不许硬编码；v3.60 收窄为「只给默认路径」）

- **内容清单不写死在 C# 里**；默认内容随程序发布在 `<程序目录>\defaults\*`。
- 🔴 **v3.60 收窄**：⛔ **不提供默认内容清单**（取消 `defaults\pc-quick.default.json` / `pc-scripts.default.json` 的播种；软件不再替用户准备条目）——
  软件只提供**默认路径**（`defaults\` 保留"默认目录 / 默认文件名"这类**常量**，可作为配置项的默认值），内容**全部由用户自己导入 / 收集**（工作项 NT-060）。
- 此后一切以用户那份为准（用户删掉的条目不会被"复活"）。
- 🔵 **v3.66 补充（配置整改第 ④ 条）**：允许**随包示例**，但只限"第一次运行的一次性礼物" —— 示例脚本 / 示例命令由 `ExampleSeeder` 播种一次（标记 `<脚本目录>\examples\.seeded`），**删了不复活**；⛔ 仍不提供"每次启动都补齐"的默认清单（内置采集器除外，属程序功能的一部分）。

### 3.7 跨平台预留

- 主平台 **Windows 10 LTSC**；迁移方向 **Debian 13**。
- 平台相关能力（winget / `ms-settings:` / ffmpeg）**集中封装**，便于整体替换。
- 路径一律 `Path.Combine`；外部相对路径 `Path.GetFullPath` 后校验落在目标目录内。
- 🔴 **跨平台判定一律用运行时信号，⛔ 不做 OS 嗅探**（`OperatingSystem.IsWindows()` / `#if` / `x:OnPlatform` 都在加载期一次性求值，无法响应运行期切换）。
  窗口装饰的唯一判据 = **`WindowDecorationMargin.Top > 0`**（等价于「框架正在替本窗口绘制装饰」）：

  | 平台 | `WindowDecorationMargin.Top` | 含义 |
  |---|---|---|
  | Win32（开了客户区扩展） | = 标题栏高（> 0） | 框架在画标题栏；**边框 / 阴影仍归 DWM** |
  | Linux X11（CSD 双门激活） | = 标题栏高 + 阴影厚（> 0） | 框架画全部四件套 |
  | macOS | 恒 `0` | 框架从不启用绘制装饰，走原生 |
  | 任意平台（关掉客户区扩展） | `0` | 系统原生装饰，⛔ 自绘标题栏不得出现 |

  ⚠️ Linux/X11 需 `X11PlatformOptions.EnableDrawnDecorations = true` 才启用绘制装饰；Wayland 的 CSD/SSD 是**运行期协商**，必须订阅变化、不能只在构造期读一次。

#### 4.1.1 窗口装饰与窗框（**走 Avalonia 12 官方 CSD 路线**）

> v3.38 立「官方 CSD」。🔴 **2026-10-15 同日两次反转后定案**：先按 NT-034 基线（Win32 补丁）回退，随后据**跨平台评估**（Wayland / Debian 13 只有官方 CSD 接得上 —— Linux 无 DWM / `WS_*` 样式位 / GDI region 概念）**重新采纳官方 CSD**。
> ⇒ 口径：**框架能做的交给框架**；Win32 侧仅保留「方角」两处（② 与技术债 §7 **B16 / B17**）。

**① 官方路线（唯一实现方式）**

| 机制 | 用途 |
|---|---|
| `ExtendClientAreaToDecorationsHint="True"` | 激活客户区扩展（也是 `ElementRole` 生效的前提） |
| `ExtendClientAreaTitleBarHeightHint="40"` | 声明自绘标题栏高度 |
| `WindowDecorations="Full"` | 只为拿**完整标准窗口样式**（贴靠资格 / 系统菜单 / 最小化动画）；⛔ 不等于让 Avalonia 画默认窗框 |
| `WindowDecorationsTheme` | 顶掉默认装饰的正门：`App.axaml` 里以**隐式键** `{x:Type chrome:WindowDrawnDecorations}` 注册空 `ControlTheme`（**不设 Template** → 框架不生成装饰视觉），引用用 `DynamicResource` |
| `WindowDecorationProperties.ElementRole` | 给自绘元素标角色：`TitleBar`（系统拖动 + 双击最大化 + 贴靠）/ `User`（放行点击）/ `ResizeN…SW`（八向缩放） |

- 客户区扩展记账**交 Avalonia 12 官方接管**（⛔ 不自接管 `WM_NCCALCSIZE`）。
- `WindowDecorationProperties` / `ElementRole` 由系统负责拖动 / 缩放 / 命中测试（`BeginMoveDrag` / `BeginResizeDrag` 仅作兜底）。

**② Win32 仅保留「方角」，其余一律禁止**

| 补丁 | 现状 |
|---|---|
| `Win32Properties.SetWindowCornerPreference` + `DwmSetWindowAttribute(33,1)` + `SetWindowRgn` 矩形区域 | ✅ **保留**（NT-034 三保险 / NT-042 裁决；技术债 §7 **B16**） |
| 手工补 `WS_CAPTION` / `WS_THICKFRAME` 样式位 | ⛔ **已删**（NT-041）：官方 `Full` 自带这些位 |
| 接管 `WndProc` 改 `WM_NCCALCSIZE`「零内缩」 | ✅ **保留（Windows 独有的例外）**：消灭 ≈8px **非客户区**边框（Avalonia CSD 按 `WS_CAPTION|WS_THICKFRAME` 扣出，贴靠态系统不画那圈 → 露缝）；钩子只在 Windows 装得上，Linux 不走此路径 |
| 贴靠几何纠偏（只认 tile 矩形） | ✅ **保留**（2026-10-21 定案，`FixTiledGeometry`）：系统按「外框 = 客户区 + 边框」算贴靠矩形，零内缩下多算的 16px 全变可见内容 ⇒ 按「矩形正好是某 tile」改写回精确半屏 / 四分屏 |

- ℹ️ **贴靠几何结论（2026-10-21 实测，取代 2026-10-15 的「接受 1~2px」）**：
  - **≈8px**（左右下，贴靠态）= 非客户区那圈边框 → 由 **零内缩** 消除（Windows-only 例外）✅ 已验收；
  - **16px**（半屏偏宽，初次与后续一致）= 系统贴靠矩形做「外框 = 客户区 + 8px/边」换算的**必然多算**（普通窗口被自己那圈边框吃掉，本窗口没有）⇒ 由 `FixTiledGeometry` 纠回，实测左右贴靠均精确 960×1040；
  - ⛔ 别再试「去掉零内缩」或「DwmExtendFrameIntoClientArea 清零」—— 2026-10-21 两条都实测无效（详见 `ShellView.Win32.cs` 注释）。

**③ 窗口外框（自绘 1px）+ 激活 / 失焦两态**（P0，见 NT-039）

- 根因：开了客户区扩展后 **DWM 把边框交给应用画**，Avalonia 在 Win32 上又只接管标题栏（`:has-border` / `:has-shadow` 恒 `false`）→ 应用不画就没有边界。窗口叠在同色窗口上时视觉上完全混淆。
- **外框**：窗口根容器外包 1px 描边，颜色用语义键 **`WindowBorderBrush`**（激活）／**`WindowBorderInactiveBrush`**（失焦，更淡）。
- **最大化时收掉外框**（否则贴屏幕边很脏，且 Win11 最大化本就无边框）。
- **失焦态**由 `Window.IsActive` 驱动：切换上面两个键（必要时标题栏文字同步降级 —— 参照 WinUI `TitleBar` 的 `Deactivated` 视觉状态）。
- 🔴 **跨平台门控**：`WindowDecorationMargin` / 框架已在画边框时（X11 CSD）⛔ 不重复画 → 判据见 §3.7，⛔ 不用 OS 嗅探。

**④ 标题栏配色**

- 底色 **`ContentBrush`**（与窗口背景一致），底部 1px `DividerBrush` 分割线；文字 / 图标 `PrimaryTextBrush`。
  - ✅ `TitleBarBrush` / `TitleBarTextBrush` / `TitleBarButtonHoverBrush` 三键经 **NT-043 拍板「不启用」**，已由 **NT-049** 从 `App.axaml.cs` 删除；标题栏底色 / 文字 / 按钮 hover 统一走现有键（`ContentBrush` / `PrimaryTextBrush` / `CardHoverBrush`），关闭按钮 hover 仍用 `TitleBarCloseHover*`。

### 4.2 标签栏（并入标题栏中段）

- **位置**：不再是独立一行；在标题栏中段横向排列。每个标签页 = 一个打开的功能页面，一对一绑定菜单 Key（首页同样显示在标签栏，仅不可关闭）。
- 组件：`ItemsControl` + 横向 `ScrollViewer`（滚动条隐藏）；标签项**只有标题 13px**（**不带图标**，样式与左菜单二级项一致）。
- 🔴 **首页常驻标签栏（v3.69，取代 v3.67/v3.68 的「不显示 / 仅激活时显示」）**：首页是**默认页**，但与其他标签一样显示在标签栏、可参与横向滚动，仅 `CanClose=false`；零标签兜底照旧回首页。**全部标签一律参与横向滚动**；**`＋` 按钮 ⛔ 不进 `ScrollViewer`**（常驻最末，滚不丢）。⛔ **不做「固定其他标签页」功能**（「固定」需求走首页收藏夹 / 常用功能）。
- 🔴 **标签栏宽度类浏览器（v3.68）**：标签栏随标签数量变长；`＋` **紧跟最后一个标签**（不是钉在整条最右），且在标签溢出时**常驻最右、始终可见**（实现 = 滚动区 `MaxWidth` 收到「栏宽 − `＋` 宽」）。
- **`✕` 关闭按钮**：**不占位**（标签宽度只按文字算）、**叠在标题文字上层**贴右端；平时 `Opacity=0` 且不吃鼠标，**悬停该标签才出现**（允许与文字重叠 —— 换更窄标签）。
- **激活态只看颜色（v3.22 简化）**：激活标签 = **文字用强调色**，其它跟普通标签一样；⛔ **不垫背景色**（那块底色会盖住关闭按钮、也让"激活"和"悬停"分不清）；⛔ **不画下方指示条**（那条线会被误认成阴影）。
- **关闭按钮的悬停观感（v3.22）**：鼠标落在关闭按钮上时——① **按钮放大**（20→24px 见方，图标字号同步放大）；② **背景恒透明**（⛔ 不画灰底方块）；③ **图标变红**（`DangerBrush`），形成"红 ✕"提示这是一个**删除类**动作。未悬停时回归次要文字色。
  - ⚠️ 实现前提：关闭按钮必须套**裸按钮主题**（`Theme="{StaticResource BareButtonTheme}"`，`App.axaml` 里定义）—— Fluent 的 `Button` 模板会在 `:pointerover` 自己画底并把前景改白，**样式 setter 压不过模板状态**。
- **行为**：
  - **点左菜单二级项** → 打开 / 激活对应标签页（**同 Key 已存在则激活，不新建**）。
  - **点标签** → 切换；**中键 / `×`** → 关闭（首页除外）。
  - **在标签区滚轮** → 切换标签（上滚上一个、下滚下一个，**到头即止、不循环**，v3.69）。
  - **跟随滚动**：切换后用**最小滚动**让当前标签**始终可见**（类 Chrome），不做"强推边缘"。
  - **`＋`** → **导航到首页**（v3.67；仍按 key 单例，已开则激活）。⛔ 不再直达「功能清单」页 —— 它的入口在**首页收藏卡尾部的「显示更多」**（内嵌）与「关于」节按钮。
  - **右键** → 关闭 / 关闭其他 / 关闭右侧 / 全部关闭（首页除外）。
  - **快捷键**：`Ctrl+W` 关闭当前 ｜ `Ctrl+Tab` 下一个 ｜ `Ctrl+1..9` 跳第 N 个。
- **单例语义**：同一 Key 只允许一个标签页存在（工具类应用，非文档编辑器）。

### 4.3 左侧菜单栏（180px / 折叠 48px，窗口级）

- 结构 = **首页（叶子）** + **一级分组（可展开）** + **二级功能（叶子）**。一级分组与首页**点击不打开页**，只展开 / 折叠。
- **图标**：一级分组 + 首页 = **矢量图标**（`Shell/App.axaml` 的 `Icon*` `Geometry`，模块注册时 `icon` 传几何键）；**二级功能不显示图标**（只留文字）。
- **样式区分**：一级 = 图标 + **加粗**（SemiBold）；二级 = **缩进 16px** + 常规字重 + `SecondaryTextBrush`。
- **交互**：
  - 一级**默认折叠**；点叶子 → 打开 / 激活标签页 + **确保其父级分组展开**并高亮该二级节点（父级一级同时高亮）。
  - ⛔ **不自动收起其它一级** —— 手动展开的分组保留。
  - **折叠态（48px）**：只保留一级菜单图标（自动隐藏展开箭头、标题与全部二级项）。
  - **折叠态高亮**：折叠时不展开任何一级，但当前页所属一级的**图标显示强调色**（知道"现在在哪个模块"）。
  - **折叠左菜单栏时**自动把全部一级分组收起。
  - 切到**首页**（不属于任何一级分组）→ 不动各级展开态，只清高亮。
- **「设置」组已删除（v3.66）**：左树**不再有**「设置」一级节点 —— 应用级设置是**一个整页**（§4.9.2，入口 = 版本行齿轮 / `Ctrl+,` / 标题栏搜索），**模块设置各自挂在本模块一级菜单下**（如「脚本管理器」下的「脚本管理器设置」，见 §6.5）。`isHome:true` 的**宿主分组**（键 `system`）只承载"节锚点 + 功能清单"的寻址，⛔ 不进左树。
- **持久化**：`config/columnlayout.json`，壳级页 Key `"shell"`：`treeCollapsed` + `treeGroup:<groupKey>`（各一级展开态，**默认 false**、**恢复落盘**）。
- **底部「配置 · 版本」区（v3.28 改）**：左菜单栏**最底部**固定一行显示 **`<当前配置名> · <版本号>`**——版本号取 `UpdateService.CurrentVersion`（编译时自动生成，与「设置 → 关于」**同一个**），配置名取 `IProfileService.ActiveProfile`（多实例时一眼看出本窗口在用哪套数据）；**折叠态隐藏**。
- **设置入口（v3.62）**：该行右侧放**设置齿轮**（⛔ 不新增行、⛔ 不改动左树其余结构）→ 打开应用级设置页（§4.9.2 / §6.5）；**折叠态**该行整体隐藏 ⇒ 齿轮必须有折叠态落点（折叠时保留图标，或走 `Ctrl+,`）。

### 4.4 主内容区（中间）

- 单个 `ContentControl`，绑定当前激活标签页的 `Content`。
- **每个标签页持有自己的 View 实例**，切标签**不重建**；**关闭标签时才销毁**（实现 `IDisposable` 则调用）。
- 无激活标签 → 显示空态引导（居中提示），不崩。

### 4.5 详情卡（右侧 340px，可开合）

- **承载内容**：**选中项的具体信息**（参数、前后对比等）**以及该部分的命令**（如剪辑区间 + 将要执行的 ffmpeg 命令行）。
- **契约** `IDetailPanelProvider`（`Shared/Services/`，页面 VM 可选实现）：
  `HasDetailPanel`（该页是否有详情）｜`IsDetailOpen`（当前是否展开）｜`DetailContent`（详情内容）｜`DetailChanged`（通知 Shell 刷新）｜`ToggleDetail()`（页面右上角按钮调）｜`OpenDetail()`（右键首项调）。
- **Shell 职责**：标签切换时检查 `ActiveTab.ViewModel is IDetailPanelProvider` → 是则显示右列 + 订阅 `DetailChanged`（**先解绑旧 Tab 的订阅**，防泄漏）；否则隐藏该列。
- **入口**：**工具条容器的右上角浮层**（v3.53 收口）—— 单个开关按钮（`❯` 收起 / `❮` 展开，常驻不隐藏）→ `ToggleDetail()`；右键首项「▤ 显示详情栏」→ `OpenDetail()`。
  🔴 **浮层三条硬规则（v3.53）**：① ⛔ **不占独立列**（废原 `Grid Columns="*,Auto"` 口径）、⛔ 不参与工具条容器宽度计算；② 是**覆盖层**（`Panel` 同格叠放，`HorizontalAlignment=Right` + `VerticalAlignment=Top`），样式与容器内按钮**同源**（`ghost`）、宽度更窄且**固定**（防开合抖动）；③ **容量计算时必须预留其安全区** —— ⛔ 不许遮住工具条里任何按钮（"不占布局"与"算法避让"两者并存）。
  🔴 **开关由 Shell 统一渲染**（随工具条一起，见 §4.8.5）；页面⛔ 不再各写一份 `detail-toggle` 块。
  ⛔ **表头不再放详情开关**（旧的"贴右缘热区 + 窄边按钮"已废除）：它占掉一整列表头宽度、鼠标不靠近还点不到，且与表头"排序 / 列显隐"两种交互混在一处。
- **宽度与记忆**：宽 **340px**；是否展开落 `config/columnlayout.json`（`FlagDetailPanel`，**按页面 Key 分别记忆**）；隐藏时该列宽度为 0，内容区铺满。
- ⏸ **页面迁移暂缓**：契约与 Shell 消费逻辑**已就位**，各页目前仍用**页内右列**（见 §4.8）；迁移方式见规范 §3.6 / §3.8。

#### 4.5.1 详情卡声明式规范（v3.45；工作项 NT-054）

**定位**：详情卡 = **对主显示区列表数据的补充与修改**。卡片结构由**描述符声明**、**Shell 统一渲染**，⛔ 不再逐页手写卡片 XAML。命令编辑等复杂交互**在卡内实现**，⛔ 不做弹窗卡。

**三区模型（每张卡 = Fields + Actions + Custom）**

| 区 | 承载 | 对应「改什么」 | 机制 |
|---|---|---|---|
| **Fields** | 声明式字段行（分区 / 标题 / 字段 / 分隔线 / 提示） | **属性级增删改**（改显示名、评分、描述、状态回显） | 描述符 → Shell 渲染 |
| **Actions** | 声明式命令按钮（文案 / 命令 / 可用条件 / 可见条件 / 确认框） | **动作级**（应用到磁盘、批量打开、连通性、保存修改） | `ICommand` 绑定 |
| **Custom** | 逃生舱（整卡替换为自定义 View） | 声明式覆盖不了的整卡交互 | 页面自绘，粒度 = **每页一个** |

**字段 Kind（11 种 + 修饰位）**

| Kind | 用途 | 修饰位 |
|---|---|---|
| `Text` | 单行输入 | `Mono`（等宽）/ `Selectable`（只读可复制）/ `Password` |
| `Pair` | **成对输入**（v3.92 / 2026-10-24）：一行两个输入框 + 中间固定符号（默认 `×`），给「宽 × 高」这类天然成对的数值用 | `Placeholder` / `SecondValuePath` / `SecondPlaceholder` / `PairSeparator` / `Mono` |
| `Check` | 勾选框（含分区标题处） | — |
| `Select` | 下拉（简单值 / 对象 + 显示路径 / **索引通道**） | — |
| `Number` | 数值 / 评分（可带取值集合，如 0~5） | — |
| `Chips` | **集合编辑器**（标签：chips + 增 / 删） | — |
| `Hint` | 纯提示文字（含空态；也用于「前缀 + 动态值」的一行说明） | — |
| `Divider` | 分隔线 | — |
| `List` | **只读列表**（键值行 / 对比行：左标签 + 主文本 + 固定符号 + 右侧强调值 + 第二行说明） | — |
| `IconBar` | **图标动作组**（NT-058 / v3.59）：一行 32×32 方形小图标按钮，溢出换行 | `IsActivePath` / `ConfirmText` / `IsDanger` / `IsSeparator` |
| `EditableList` | **可编辑列表**（2026-10-19）：每行 = 只读左标签 + 可编辑文本框，**失焦提交** | `OptionsPath` / `ItemLabelPath` / `ItemTextPath`（读写）/ `ItemCommandPath`（提交命令，参数 = 候选项） |

- 只读文本一律 `Text` + `Selectable`；多行一律 `Text` + `MultiLine`（数量与宽度不限）。
- 🧩 `IconBar` 的**成员是 `DetailField.IconActions`**（`List<DetailIconAction>`，顺序即渲染顺序、数量不限、同一卡可多组；⛔ 与本行其它取数属性互斥）。
  纯图标没有文字 ⇒ **`ToolTip` 必填**（悬停讲语义；置灰时也要讲原因）；`IsSeparator` 渲染成组内的竖线。
  ⚠️ 它**只固定视觉样式、⛔ 不固定排列**，⛔ 不是「Actions 区的替代品」—— Actions 区仍按下面「卡内零操作按钮」的口径用。
- `Select` 有两种落值通道：**值**（默认，`ValuePath` + 可选 `OptionValuePath`）与**索引**（`IndexPath` + `LiteralOptions`，
  用于页面 VM 上本来就是「第几个选项」的字段，如编码器 / 码率模式）。
- ⛔ **加新 Kind 是「加法」**：新需求优先用现有 Kind + 修饰位；确实需要新交互时才加一个 Kind（配一个 `DataTemplate`），不影响既有卡。
  ⚠️ **v3.47 补记**：`List` 是**用户拍板新增的第 8 种** —— 详情卡里的「只读列表」用原 7 种表达不了
  （VideoBatch「处理前 → 处理后」、资产卡「关联 / 文件位置」），故补一个 Kind，**而不是**让整卡走 `Custom` 逃生舱。
  ⚠️ **v3.92 补记**：`Pair` 是**第 11 种** —— 视频两页的「宽 / 高」原来拆成上下两行，用户看不出这两个数是一件事；
  合到一行（`宽 [ ] × [ ] 高`）只加一个 Kind，⛔ 不改 `Text` 的既有行为。

**提交语义（统一为 3 种）**

| 语义 | 行为 | 典型 |
|---|---|---|
| `Instant` | 双向绑定即落盘 | 勾选框、下拉选完即改 |
| `OnBlur` | 失焦提交 | 改名框、参数框 |
| `Explicit` | 需工具条「💾 保存修改」显式提交 | 批量队列参数 / 命令 |

- ⛔ 现状的 4 种随意实现（失焦即存 / 显式提交 / 即时落盘 / 按钮提交）**统一到本表 3 种**。
- ⛔ **卡内零操作按钮**（既有原则，§6.6）：保存 / 重置这类动作归**工具条**，⛔ 不进 Fields 区；Actions 区只放**与该卡内容强绑定**的卡内动作。
  ⚠️ **v3.59 例外**：`IconBar`（Fields 区末尾的一排**图标**动作）不受这条约束 —— 它表达的是「同一张卡、高频、语义靠图标就够」的动作（收藏 / 保存 / 刷新 / 删除），
  ⛔ 低频重操作（移动 / 复制到其它存储源）仍不进卡，归任务中心或后续入口。

**刷新契约**

1. **属性级**改动 → 靠 `INotifyPropertyChanged` 自动同步主显示区列表（如改评分 → 列表列自动变）。
2. **动作级**改动（应用到磁盘 / 加标签 / 删除）→ **由页面 VM 负责回刷**列表与卡片；描述符**不参与**刷新。

**覆盖基线（当前 16 张卡）**

| 卡 | 关键形态 | 声明式覆盖 |
|---|---|---|
| 媒体资产 · 资产（`AssetDetailView`） | 可编辑显示名（OnBlur）+ 5 只读 + 可复制路径 + 评分 + 多行描述 + **标签 chips** | ✅ |
| 媒体资产 · 存储 / 标签 / 回收站（3 张） | 只读 + 单行编辑 + 命令 | ✅ |
| 视频工具 · 批量队列（`VideoBatchView`，**最复杂**） | **3 个可折叠分区**（分区标题带勾选框）+ 预设下拉（对象）+ CRF 条件可见 + 多行自定义参数 + **命令区**（自动生成 / 可手改 / 重置） | ✅ |
| 视频工具 · 预览 / 列表 | 同上结构子集 + 数值字段 | ✅ |
| 脚本管理器 · 信息面板 / 软件包 / 命令库 / 脚本库（4 张） | 只读 + 可复制 + 命令 | ✅ |
| 设置 · 路径配置 | 单行编辑 + 命令 | ✅ |
| Web 工具 · 书签 / Ping / Hosts / 爬虫（4 张） | 单行编辑 + 下拉（DNS 切换）+ **多行 hosts 内容** + 命令 | ✅ |

→ **16/16 声明式可覆盖**；`Custom` 逃生舱在本基线内**无需启用**（保留给未来新交互）。

**关键约束**

- 描述符用 **C# 对象字面量**声明，⛔ 不做运行时 JSON / XAML 加载（字符串驱动 UI 在本项目已有技术债先例）。

#### 4.8.1 列宽（v3.21 收口为通用规则；视频两页首发，能力对所有列表页可用）

1. **三态 + 单列自适应**：星号比例（`ListColumn.Width` 默认，如 `3.2*`）→ 手动像素（拖表头边界 / **双击边界**）→ 隐藏（`0`，列索引不动）。⛔ **没有「自动调整全部列宽」开关**（v3.20 删除）；**双击某一列边界 = 该列自适应**（宽 = max(表头文字宽, 示例值宽) + 4px，右侧列吸收差额）。
2. **手调列宽只存会话**（⛔ 不落 `columnlayout.json`）：切标签页不丢、重启还原；列显隐切换不影响已手调宽度。
3. **示例数据行（Sample）+ 固定表头宽列（v3.22 重做）**
   - **每列给一条示例值**（`ListColumn.Sample`，如 `★` / `29.97` / `.mp4` / `1:02:03`）—— 它是一条**"设计时数据 / 水印行"**：
     - 列表**没有真实数据时**显示这条示例行（半透明、明显是占位，⛔ 不可选、不可勾选、**不参与**统计 / 排序 / 筛选 / 导入导出）；
     - 列表**有真实数据后示例行整条消失**。
   - **判据**：把**示例文本宽**与**表头文字宽**比一比 —— 示例 ≤ 表头 → 该列宽**锁成表头宽**（只是初始宽；用户一拖就解除锁定）；示例 > 表头 → 不锁（照旧星号、可拖）。⛔ 绝不按真实行逐行测宽（虚拟化只 measure 可见行 → 滚动会让列宽抖动）。
   - 锁定宽度 **不小于最小列宽 34px**（表头文字很短的列也留得下把手）；锁定列**照样有把手、可拖、可双击自适应**（见 §6.4.15）。
   - **适用范围（v3.32 扩为全列表页）**：**每个列表页的每一列都要填 `Sample`**，详情卡无选中时也显示示例值 —— 汇总规则见 **§4.8.3**。

#### 4.8.4 主显示区（工具条 / 筛选条）基本范例（v3.41 收口 · 所有列表页照此）

> **定位**：列表列的「主显示区」= **工具条 → 筛选条 → 列表** 三行。本节是这三行的**基准形态** —— 新列表页**直接照做**，⛔ 不各页自创；样板实现 = 媒体资产「全部资产」页（含 5 个类型薄壳页）。
> **为什么收口**：工具条按钮一多就换行、筛选条一换行列表区就被挤压跳动 —— 主显示区的**高度必须可预期**，这是"成熟感"的底座。

1. **工具条默认最多两行，并按容器宽度自动"能放多少就显示多少"**（v3.42 收口）：
   - 工具条按钮 = 一串**按优先级排序**的序列（越靠前越不会被折），**末尾固定一个「⋯」按钮**；
   - 🔴 **两行内放得下就全部显示**（宽窗口 / 收起详情卡时会自动一路展开，⛔ 不需要手动点）；放不下才把序列**尾部**几项收进「⋯」；
   - 点「⋯」= **全部显示**（不受宽度限制）、再点收起；全部放得下时「⋯」自己消失；
   - 「⋯」按钮**只放图标、⛔ 不带文字**（展开态换成 `▲` 提示"可收起"）；按钮宽度固定 ⇒ 开合不会让工具条重新换行；
   - 🔴 **底线：⛔ 不许出现"窗口一窄就破两行"** —— 容量按**最窄工况**（960 窗口 + 详情卡展开，可用宽推导见 `ui.md` §2）算，
     宁可少显示一个按钮，⛔ 也不许挤到第三行；
   - ⚠️ XAML 里的**排列顺序 = 优先级顺序**（即折叠顺序的反序）：要改"哪个按钮先被折"，把它在工具条里的位置前后挪即可。
2. **按钮文字取"最短可比达义"**（v3.41 用户定调）：
   - ⛔ **不重述本页上下文**：本页就是资产库 ⇒「🔄 重读」而非「🔄 重读资产库」；本页已有勾选框 ⇒「🗑 移入回收站」而非「🗑 移入回收站（选中）」。
   - 同类动作用**动词区分**，⛔ 不并列两个同名词：`🗄 并入…`（并入外部库）vs `💿 另存为…`（另存本库）。
   - 省略掉的名词 / 前置条件**写进 `ToolTip`**（⛔ 不许省到有歧义）。
3. **「需先勾选」的按钮用提示词表达，⛔ 工具条不放指示文字**（v3.41 用户定调）：
   - 按钮 `ToolTip` 写全「动作 + 前置条件」（如「先在列表里勾选行，再点这里打标签」）；
   - 🔴 这类按钮**禁用时提示词也必须弹得出来** —— 实现要点见 `ui.md` §9（`ToolTip.ShowOnDisabled`）；不加就是"灰按钮 + 提示词弹不出来"，用户无从知道要先勾选；
   - ⛔ 工具条里**不再放**「未勾选 / 已勾选 N 个」这类指示文字（勾选状态在列表勾选框上一眼可见）。
4. **筛选条恒为一行，⛔ 不许出现滚动条**（v3.41 用户定调）：
   - 筛选项横向排死在**一行**：窗口变窄时**筛选项自己变窄** —— ⛔ 不换行、⛔ 不横向滚动、⛔ 不折叠进二级；
   - **前提是筛选项数量固定**（当前列表页固定 = 类型 / 存储源 / 状态 / 标签 4 项）。将来若要"按表头扩展更多筛选类型"，属**新需求**（须一并定值域来源），需先立项，⛔ 不得用滚动 / 换行方案硬塞；
   - 筛选条**高度恒定** ⇒ 列表区不被挤压跳动。

5. 🔴 **工具条前三项固定（v3.60，用户定调）**：① 本页的**数据入口动作**（📁 扫描 / 📂 导入 / 📥 导入书签…）→ ② **路径 / 来源输入框** → ③ **搜索框**；

#### 4.8.5 工具条由 Shell 统一承载（v3.53 用户立项；工作项 NT-055）

> **定位**：列表页工具条（§4.8.4）的**实现只存在一份** —— 由 Shell 的 `ToolbarHost` 统一渲染，页面⛔ 不再自写 `Border.toolbar` XAML。
> **同套路三连**：§4.6 状态栏（`IStatusProvider`）→ §4.5.1 详情卡（`IDetailCardSource` + `DetailCardHost`）→ 本节工具条。**页面给数据，Shell 给实现。**
> **为什么**：20 个页面各写一份工具条 XAML（≈600~700 行）、16 个页面各手写 12 行详情开关块、折叠逻辑只在「全部资产」页有一份。改一处要动 20 处，且新页面靠"照抄旧页面"必然漂移。

1. **契约** `IToolbarSource`（`Shared/Services/`，页面 VM **可选**实现）：
   `Toolbar`（`IReadOnlyList<ToolbarItemDescriptor>`；**空 / null = 本页无工具条** ⇒ Shell ⛔ 不渲染、⛔ 不留空行）｜`ToolbarChanged`（工具条构成变化时通知 Shell 重建）。
2. **描述符** `ToolbarItemDescriptor`（`Shared/`，**纯数据、⛔ 不引 Avalonia**，命令用 BCL `ICommand`）：
   - 支持 **8 类项**：`Button` / `SplitButton`（主按钮语义 + 菜单项集合）/ `Toggle`（勾选框）/ `TextField`（输入框，可配"回车即执行"的命令）/ `Combo`（下拉：预设 / DNS 预设）/ `Label`（次要色文字 —— 🔴 v3.77 起**新页面⛔ 不用**，改 `ToolTip`；仅作历史兼容保留）/ `Separator`（分组竖线）/ `ChipGroup`（单选 / 多选按钮组：按数据源动态生成一排可高亮按钮，如「源」）/ **`MultiCombo`（v3.77 多选下拉：按钮显示汇总文案 `TextPath`，浮层里每项一个勾选项，勾选态双向绑数据项的 `SelectedPath`，选中项右侧打 ✓；点击后执行 `CommandPath`，参数 = 数据项）**；
   - 每项含 `Text` / `Command` / `IsEnabled` / `ToolTip` / `ShowToolTipOnDisabled` / `Priority`（**= XAML 顺序 = 折叠顺序的反序**，越靠前越不易被折）；
   - 🔴 **v3.77：工具条里⛔ 不放只读文字说明**（「这是啥」一律写进 `ToolTip`）—— 按钮 / 输入框 / 下拉**各自带提示词**，相互之间⛔ 不再夹 `Label`；
   - ⛔ **加新项类型是"加法"**：优先用现有项 + 修饰位表达；确实表达不了、且属**通用交互**（多页可复用，如按钮组）时才加一个 Kind（配一条渲染分支）；**只为某一页的特殊布局**（表单式撑满）不加 Kind —— 该页保持页内自绘，⛔ 不为了统一而强行改造页面。
3. **Shell 职责**：渲染工具条行 + **自动折叠算法**（口径 = §4.8.4 第 1 条：两行放得下就全显示、放不下才折尾部，末尾固定「⋯」）+ **浮动详情开关**（§4.5）；切标签时探测当前页 VM 是否实现契约并重建（复用 `IStatusProvider` / `IDetailCardSource` 的同一探测点）。
4. **迁移是逐页 opt-in**：未实现契约的页面继续用页内自绘工具条；🔴 **同一页⛔ 不得 Shell 与页面各渲染一份**（探测到契约就不渲染页内、未探测到才由页面自绘）。
5. **验收判据**：任取一个已迁移页 —— ① 页内已无 `Border.toolbar`、无 `detail-toggle` 块；② 工具条行为与迁移前**逐项一致**（文案 / 顺序 / 启停条件 / 悬停提示 / 禁用时提示 / 回车命令 / SplitButton 主按钮语义）；③ 把窗口从 1280 拉到最窄 960（详情卡展开）工具条仍 ≤ 2 行，被折按钮随宽度自动变化，拉宽后自动展开回位；④ ↕ 工具条行在**未迁移页**上高度为 0（无空白）。

#### 4.9.1 设置总表（v3.53 用户立项；工作项 NT-056）

**定位**：把「路径配置」与「配置」两张表**合成一张** —— 不是把两种数据揉在一列，而是**同一张表承载不同分类的行**，用**分类列**区分行类型、并据此决定"哪些工具可用"。

1. **列的基准形态**（统一表头）：**分类 ｜ 名称 ｜ 当前值 ｜ 类型 ｜ 说明 ｜ 操作**。
   - `分类`：**行类型判别列**，取值 `路径` / `配置`；🔴 **可排序、可筛选**（走 §4.8.2 的列基建）—— 这是把两表合并后"还看得清"的关键。
   - `名称`：路径项键名 / 配置名（⚠️ 两义，故**必须有分类列**兜住）。
   - `当前值`：路径 = 可编辑值（`OnBlur`）；配置 = 数据目录（只读展示）。
   - `操作`：**按分类分派** —— 路径 = 📂 浏览 / ↗ 打开位置；配置 = ⇄ 切换 / 🚀 新开 / ⭐ 设为默认 / ✏ 重命名 / 🗑 删除 / ♻ 重置。
2. **工具可用性由选中行的分类决定**：与分类强绑定的工具（`⇄ 切换` / `🚀 新开` / `⭐ 设为默认` / `♻ 重置` / `📂 浏览` …）在选中另一分类的行时**不可用**（置灰 + 提示词说明"该操作只对 <分类> 行可用"）；与分类无关的（📂 打开配置目录 / 💾 保存 / ＋ 新建）始终可用。
3. **详情卡按分类切换字段集**：选中行的分类变化时，Shell 侧详情卡**整体重建**（`DetailCardHost` 已支持 `Card` 变化即 `Rebuild()`）—— 页面 VM 须在分类变化时**通知 `Card` 属性变化**（⛔ 不得沿用"缓存一次"的静态卡写法）。
4. **可扩展性（本节的根本理由）**：分类是**开放集合** —— 后续若要"**指定某个功能默认使用哪个 json / 配置**"，只加一个分类值（如 `功能绑定`）+ 该分类的行与工具，⛔ **不再新开页面**。
5. **页面归属**：合并后只保留 **`settings-path`**（标题改「**路径与配置**」，Key ⛔ 不改——首页跳转 / 收藏白名单按 Key 寻址），删除 **`settings-profile`** 菜单项（§5.1 菜单 Key 一经发布⛔不改，此处是**移除整项**，不涉及改 Key）。
6. **验收判据**：① 左树「设置」组少一项、只剩「路径与配置」；② 该页一张表里同时能列出路径行与配置行，按分类排序 / 筛选可用；③ 选中配置行时，路径专属工具置灰且提示词说明原因；④ 选中不同分类的行，工具条（保存 / 浏览 / 新建配置…）按分类启停（🔴 v3.66：本页**已无右详情卡** —— 它现在是应用级设置页的「运行环境」节，设置页不分左右栏）；⑤ 配置侧原有 7 个动作全部可用且语义不变（切换仍二次确认 + 本窗重启）。

## 五、导航模型（硬约束）

### 5.1 核心概念

- 一个**标签页** = 一个打开的功能页面 = **缓存的 View 实例** + 一份 VM + 一个历史栈。
- 打开页面的**唯一入口** = 标签页；菜单点击、`+` 等都是「打开 / 激活某个 Key 的标签页」。

### 5.2 标签页模型

`TabItemViewModel`：`Key`（菜单 key）｜`Title`｜`IconKey`｜`Content`（缓存的 View）｜`ViewModel`（供 Shell 检测契约）｜`CanClose`（首页 = false）｜`BackStack` / `ForwardStack` / `CanGoBack` / `CanGoForward`。

`ShellViewModel`：`Tabs` / `ActiveTab` + `OpenTab(key)` / `CloseTab(t)` / `GoBack()` / `GoForward()` / `Refresh()` / `ToggleTree()` / `ToggleDetail()`。

### 5.3 历史栈

- **每个标签页独立维护**，栈元素是「页面内的导航状态快照」。
- **可进**：目录切换、执行搜索、从列表进入子详情。**不进**：列表内选中不同条目（选中态）、筛选 / 排序变化（视图状态）。
- **契约** `IHistoryProvider`：`CaptureState()`（返回 null = 不记录）｜`RestoreState(state)`｜`StatePushed`（通知 Shell push）。
- 页面通过 `StatePushed` 通知 Shell push `CaptureState()`；前进 / 后退时 Shell 调 `RestoreState`；**未实现该契约的页面** → 前进 / 后退灰显。

### 5.4 启动时序

`ShellViewModel` 构造函数末尾调 `OpenTab("home")`（首页 = **默认页**，初始化内容区；首页与其他标签一样显示在标签栏，仅不可关闭）；其余启动时序（DI → 模块加载 → 主题 → Show）不变。

### 5.5 防闪退铁律

1. `OpenTab` 找不到 key **不得抛异常** → 忽略并记日志。
2. `ActiveTab.Content` 为 null → 内容区显示空态，不崩。
3. 关闭最后一个标签页 → **自动打开首页**（保证始终有激活标签）。
4. 关闭首页标签 → **拒绝**（`CanClose=false`）。
5. View + VM 缓存，关闭标签时销毁（`IDisposable` 若实现则调用）。

#### 6.2.4 信息展示（脚本输出呈现器，原系统信息 `pc-info`）

> **脚本中枢四态（脚本管理器）**：收集（脚本库 `script-library` / 命令库 `script-commands`）→ **展示（信息面板 `script-info`，本小节）** → 编排（管道页，远期）→ 工作流（新模块，见 §2.1-4）。本页 = 通用「脚本输出呈现器」，切"组合脚本"= 切 manifest。

- **改名与 Key**：原「系统信息」页升级为通用脚本输出呈现器；标题为「信息面板」、Key `script-info`（NT-068 全局改名，`pc-*`→`script-*`）。
- **执行底座（PcTools 内，⛔ 不进 Core）**：新增 `ScriptRunner` 统一「解释器选择（复用 `QuickActionService` 的 pwsh / python / ps5.1 → PATH 回退）+ 进程启动 + 捕获 stdout/stderr + 超时/取消 + 工作目录/环境变量」。信息展示、`QuickActionService`、未来 `PackageManagerService` 迁回 PcTools 后均建于其上，解释器选择只留一处。
- **manifest 契约**：`scripts/sysinfo/sysinfo.manifest.json` 集中定义
  - `columns[]`：`{key(数字), title, width, visible}` —— 表头可自定义（显隐 / 顺序 / 宽度走 manifest + `ColumnLayoutService`）。
  - `scripts[]`：`{file, group, interval}` —— 本页由哪些脚本组成；`interval`=秒，0=仅手动。
  - 随包在 `defaults\` 播种基础采集脚本 + manifest；用户可在脚本目录覆盖 / 增删（承接 §3.5 / §3.6「只给默认路径」）。
- **脚本输出契约（另类抽象）**：脚本只输出**按列号对齐的值数组**（如 `["操作系统","系统版本","Windows 11 24H2"]`），完全不感知显示；换表头 = 改 manifest，脚本零改动。解析失败 = 丢该样本，整页不炸（单脚本独立 try/catch + 状态栏报「哪个脚本失败」）。
- **多脚本合并**：共用同一列 schema，行打 `ScriptId`（= scripts 下标或 file）；复用 `ListPageViewModelBase` 筛选 / 排序 / 列显隐；`group` 用于归类 / 筛选。
- **行模型**：`SysInfoRow { ScriptId, RowKey, Status, Values[] }`（`Status` ∈ `ok`/`warn`/`error`，本期只落模型不着色，供 §2.1-4 管道 / 工作流消费）；`RowKey` 用于定时刷新**就地匹配**（保留选中 / 详情卡，不重建 Items）。输出外壳（`{rows:[{key,status,values}]}` / 顶层数组 / 裸二维数组）、`RowKey` 取值链、编码与解析宽松规则见 `modules/script-manager.md` §3 / §5。
- **定时刷新（per-script）**：全局 `DispatcherTimer` 扫描 `interval>0` 脚本单独重跑，只更新该 `ScriptId` 下行的「同 RowKey 原地改值 / 新增追加 / 消失删除」；手动「🔄 重新检测」= 全跑。最小 interval 限 ≥2s 防卡 UI。
- **应用路径段**：保留为**内置采集器**（读 `_cfg/_store/_pc` 配置值，仍是合并来源），或留 `app-paths.ps1` 占位供替换（二选一，实施时定）。
- **功能按钮**：🔄 重新检测（全跑）/ 重跑该脚本（行·分组右键）/ ✏ 编辑脚本（manifest 或某脚本在编辑器打开）/ 📂 打开脚本目录 / ⚙ 列设置（自定义表头入口）/ ⏱ 刷新间隔（改 manifest 各 `script.interval`）/ 📋 复制行·复制全部（沿用）/ 导入导出脚本集合（打包 manifest+脚本分享）。
- **边界**：软件包页保持独立（winget 定宽表解析 + 写动作），⛔ 不塞进通用 presenter；未来管道页另立（见 §2.1-4）。**状态着色 / Sparkline 本期不做**（留作增强）。

#### 6.2.5 脚本集合（`script-collections`，v3.71 / NT-068 新增）

- **定义**：**集合 = 若干采集器（脚本 / 命令）的组合**，是信息面板一屏展示的整套数据单位；与媒体资产的「集合」同义（都是手工分组），⛔ 不另造术语。
- **集合带 `kind`**，决定它在哪个页出现：`script` → 脚本库 / `command` → 命令库 / `info` → 信息面板 / `package` → 软件包。**页面归属由 kind 决定，⛔ 不为每个集合新增菜单项**。
  - 🔴 **v3.81 加回 `package` 一档**（NT-082，用户定调）—— 它不是「用集合冒充 winget 查询结果」，而是**包清单容器**：成员 = `role=package` 条目（`Target` = 包 Id），发送到软件包页后按清单显示安装状态。定位是**跨包管理器的架构预设**（将来 apt / flatpak / snap 各有后端，集合按后端归类，页面再把成员命令绑成按钮）。（v3.79 曾整体删除，理由「软件包是实时查询结果」；现按「实时查询走搜索、手工清单走集合」并存。）`role=package` 条目只在「软件包」类集合的候选池里出现。
  - 🔴 **kind 必须真正生效**（v3.76 / NT-073，取代 v3.71 的「kind=script/command 只在集合页当分组容器」口径）：**信息面板的 `集合 ▾` 只列 `kind=info`**；脚本库页只认 `kind=script`，命令库页只认 `kind=command`；不属于该页 kind 的集合 ⛔ 不出现。
  - **非 info 集合**没有刷新 / 视图语义 ⇒ 集合详情卡里的「刷新策略 / 刷新间隔 / 默认视图 / 视图数」按 kind **禁用**（灰显不可编辑，值保留，改回 info 即恢复）。
- **多库索引**（v3.76 / NT-073）：**库 = `kind ∈ {script, command}` 的集合**，一个页面可以有多个库，每库可有自己的根目录（`rootPath`，空 = 用设置页的全局脚本目录）。
  - **库页 = 展示 + 收录**：脚本库页 / 命令库页通过 `库 ▾` 选当前库（默认上次用的库，另有「全部库」看并集）；列表只显示 `collectable=true` 的成员，带「所属库」列。
  - **收录必须归属一个库**：导入文件 / 导入文件夹 / 🔍 扫描目录 → 自动加入当前库（「全部库」视图下先选目标库）；⛔ 「不属于任何库」不是合法常态。
  - **库级导入导出**：`📤 导出库` 支持索引包（定义 + 成员相对路径 + `rootPath`）与全量包（zip = 索引包 + 脚本文件本体）；`📥 导入库` 可新建库或按名称覆盖，文件冲突默认跳过并逐条列出；命令库只支持索引包。
  - **库页删除条目 = 从当前库移出**：多库时只解除当前库的成员关系，⛔ 不删条目本体 / 不删文件；条目因此无归属时收回默认库；要彻底删条目走集合页。
  - 同一物理文件只对应一条 item（按绝对路径去重），可同时属于多个库；`rootPath` 只对 `kind=script` 有意义（命令是命令行字符串）。
  - **删库**：只删库定义 + 成员关系，⛔ 不删条目 / 不删文件；只属于该库的条目**收回同 kind 的默认库**。
  - **复制库**：连视图与成员关系一起复制（`rootPath` 同样带过去）。
  - 扫描 / 导入 / 相对路径解析 / `missing` 判定 / 整库导出都以**所属库的 `rootPath`** 为上下文。
  - 🔴 **内置库不做全量同步**：默认库只接纳「不属于任何库」的新条目，⛔ 不再把全部脚本 / 命令硬塞进去（否则多库无意义）。
- **独立菜单项**（用户 2026-10-17 拍板）：主从两栏 = 左 `280px` 集合列表 + 右成员表 / 详情卡。
  - 左栏：搜索框 + 筛选（kind / 标签）+ **分段（置顶 / 最近使用 / 全部）** + 每行（**第一行 = 图标 · 名称 · 类别徽标**；第二行 = 成员数 · 在用；行尾 ★）。🔴 类别文案在「左栏徽标 / 筛选下拉 / 详情卡类别」三处必须完全一致（信息面板 / 脚本库 / 命令库 / 软件包，v3.81 起四档）；左栏宽 **240px**；🔴 **集合名全局唯一**，改名撞名 ⇒ 不落盘 + 提示，新建 / 复制自动改名避重；★ = 置顶，详情卡「置顶」勾选框切换
  - 右栏上：成员表（**勾选即增删，即时生效、无保存按钮**，沿 §3.7）；**候选池按当前集合的 kind 过滤**（脚本库集合只列脚本、命令库集合只列命令、信息面板集合列全部可采集条目），另有「显示全部类型」开关可跨类勾选；默认只列 `collectable=true` 项，勾「显示不可采集」后灰显不可勾
  - 右栏下：详情卡 = 名称 / 图标 / kind / 描述 / 默认视图 / 刷新策略 / 标签
  - 工具条：新建 / 复制 / 删除（二次确认；**只有「在用」的集合不可删**）/ 归档 / 🔍 扫描目录 / **📤 发送到对应页面**（按 kind 跳信息面板 / 脚本库 / 命令库 / 软件包并选中该集合；左栏集合行右键同样一项）/ 导出
- **其他页面正在使用的集合**（v3.75 / NT-072，v3.76 扩展；**v3.78 修订**）：**按 kind 分键记录** —— 信息面板、脚本库页、命令库页各记一个「当前库」（`lastCollectionIdByKind`）。左栏该行显示强调色短标「在用」（悬停给删除前怎么切走的说明）。🔴 **「在用」= 唯一删除门槛**：在用的删除按钮直接拒绝（提示改名 / 归档），不再只是警示；**两个默认库恒「在用」**（兜底接收无归属条目）⇒ 自然受保护，`builtin` 不再是独立规则。
  - **沉底规则**：只有 `kind=info` 的「在用」集合沉底（它关系到信息面板的可恢复性）；`script` / `command` 库与**默认库**不沉底（用户高频切库 / 默认库本就置顶，沉底会挤掉置顶）。
- **几十个集合的规模**靠「搜索 + 置顶 + 最近使用 + 标签筛选」解决；⛔ 本期不做层级分组（超过 ~80 个再评估）。
- **内置集合**：**`默认脚本库` / `默认命令库`**（`builtin=true`，可改名、可改类别；恒「在用」⇒ 不可删，可归档）；改类别走后下次启动自动补回该 kind 的默认库。用户自建的库可删。
- **`collectable`（可采集）**：脚本 = 扩展名合法且文件存在；命令 = 不在副作用黑名单（`start` / `explorer` / `control` / `ms-settings:` / `shutdown` / `pause`）且 `capture=true`。自动判定 + **用户可手动覆盖**（`collectableSource` = `auto` / `user`）。脚本库 / 命令库新增「可采集」列 + 工具条筛选「仅可采集」—— 这是**按需生成集合**的入口。
- **扫描由用户手动触发**（⛔ 不自动登记）：`🔍 扫描目录` → 候选面板三态（已入库灰 / 新文件默认勾选 / 不可采集灰显不可勾）→ `➕ 加入库`，可同时选「加入集合 → 某集合」。
- **删除条目不删文件**；文件不存在 ⇒ `missing=true`（列表标红 / 灰）。

#### 6.2.6 信息面板（`script-info`：集合选择框 + 分节）

- **定位**：从「一页 = 一份 manifest 的全部脚本」改为**可承载多个集合的展示框架**（用户 2026-10-17：「信息展示页作为一个展示框架，可以承载很多集合」）—— **一次显示一个集合，通过顶部选择框在几十个集合间切换**（浏览器体验：一次一个页面，切页靠标签 / 下拉）。
- 🔴 **⛔ 不要横向排列的按钮组**（用户 2026-10-17 否决 Chip 条：「除了标签页栏和工具条，不要有横向排列的按钮了，整体体验如浏览器，做成选择框吧」）：
  - 顶部**只有工具条**：`集合 ▾` + `视图 ▾` + `🔄 全部刷新` + `📂 脚本目录`（2026-10-19：删「⚙ 节设置」）
  - `集合 ▾` = 工具条既有 **`ToolbarItemKind.Combo`**（`ItemsPath` / `SelectedPath` / `DisplayPath`），零新增 UI 机制
  - 下拉项排序 = **★置顶 → 最近使用 → 名称**；文案 = `名称 · 成员数`
  - 切换集合即整屏换（卸载旧节 + 加载新节）；**记住 `lastCollectionId`**，重启恢复上次的集合
  - ⛔ **不做工作区 / 多集合并存 / Chip 条**。需要"同时看两类数据"⇒ 把它们放进**同一个集合**（集合本就是为此设计）
- **分节呈现（用户 2026-10-17：「一个脚本展示的信息一节」）**：
  - 主体 = `ScrollViewer` 内按**采集器分节**（一个集合内的多个采集器各占一节）；节可折叠（折叠状态入视图定义）
  - 节头：采集器标题 + `status` 状态点（`ok`/`warn`/`error` **着色**）+ 上次采集时间 + 行数 + 折叠 + **局部刷新**（2026-10-19：删节头 `⚙`）
  - 选中节 = **点节任意处**（节头 / 节点），只把右侧详情卡切到这一节，**不主动展开面板**；打开面板 = 右键节 →「⚙ 显示这一节的详情 / 设置」
  - 详情卡「本视图的显示」= 列 chips（显隐）+ **表头名称**（逐列改名，失焦提交，写 `views[].sectionColumns.titles`）
  - 节体：**该采集器自己的列**（由输出 `attrs` 并集决定），节与节之间列宽独立；复用 NT-067 的 `SysInfoGrid`
  - 节头吸顶：手动浮层实现（Avalonia 无原生 sticky；参考 §4.9 设置页 `StuckHeader` 先例）
  - 节数上限 40（超出提示）；每节**预览 20 行 + 展开全部**
  - **分节模式关闭分页**（底栏改摘要：本次耗时 · 节数 · 总行数）；`layout=merged` 才启用合并表 + 分页（需各采集器有共同 `row_key`）
  - **空态**：无集合 ⇒ 「还没有集合」+「去创建集合」；集合为空 ⇒ 「这个集合还没有采集器」+「去添加」
- **`📤 发送到信息面板`**（集合页）：= **选中该集合 + 跳转到本页**（⛔ 不是"追加"）；已选中时状态栏提示「已在信息面板中」。

- **执行频率三层**：采集器级 `intervalSeconds` + `auto` ／ 集合级 `refreshMode`（`manual` / `on-enter` / `timer`）+ `refreshSeconds` ／ 视图级可覆盖。硬约束：仅 `readonly` 项允许 `auto`；最小 2s、上限 3600s；前一次未完成跳过本次；离开页面停表；**只刷新未折叠的节**。

- **边界**：⛔ 不做后台刷新 / 托盘常驻采集；⛔ 不做列宽拖拽（改宽走列设置）；⛔ 不改 `ListPageViewModelBase` / `ListPageSkeleton` 既有机制。

#### 6.4.1 两页详情卡（同一套规格）

> **原则：这两个页面的详情卡是同一个东西** —— 都是"把一条任务翻译成一条 ffmpeg 命令"。「视频预览」页只是**额外**能在左边看画面、拖着时间条定区间。因此两页详情卡的**分区顺序、折叠方式、命令区形态必须一致**，改一处就要同步另一处。

**统一规格**

1. **分区顺序 = ffmpeg 命令的书写顺序**：`输入 / 区间` → `编码与画质` → `输出` → `命令`。
   ⛔ **「任务类型」勾选不单独占一块放最上面** —— 它由下面两个分区自己表达（勾了哪个就执行哪段），单独列出来既重复又占地方。
2. **两个分区各自可折叠**，标题行左侧是一个**勾选框**（该段是否参与命令）+ 右侧折叠箭头；**取消勾选即自动折叠**，折叠只影响界面、**是否执行由勾选决定**。
   ⛔ **两页的勾选框都可交互**（不是只读装饰）：批量页的勾选框 = 该任务是否含这一段，**勾 / 取消即切换任务类型**（见第 5 条）。
3. **详情卡里只有"参数 + 命令"，不放任何操作按钮**（跑 / 保存 / 删除 / 打开目录 / 复制…）—— 它们属于**命令之外的动作**，一律排到列表上方的工具条里。⛔ 详情卡顶部不放按钮条。
4. **命令区**固定在最后：`SelectableTextBlock` 显示完整命令行 + 可编辑的参数框 + `↺ 重置为自动` + `📋 复制命令`；手改后参数变化**不再覆盖**手改值，执行以手改为准。
5. **两页的差异只有两处**：
   - 「视频预览」页的区间由左边的时间条驱动；「批量处理」页的区间在详情卡里填（该页没有预览画面）。
   - **勾选框的初值来源不同**：预览页由用户现勾（剪辑 / 转码可同时勾 = 一条命令干两件事）；批量页由**选中任务的类型**给出初值（`CutTask` = 只勾剪辑、`TranscodeTask` = 只勾转码、混合任务 = 两段都勾）。
     **批量页勾选框可交互**：勾上一段 / 取消一段 → 任务在「剪辑 / 转码 / 剪辑+转码」之间转换（两段都取消 = 回到「仅转码」并提示，⛔ 不允许出现"两段都不参与"的空任务）。
6. **详情卡布局一致性（本次收紧）**：宽度恒定 340（共享样式 `Border.detail-card` 锁定，⛔ 不动）；**折叠任意分区只影响该分区高、不影响整卡宽度**；所有「标签 + 输入 / 下拉」控件的**左对齐、宽度一致**（输入与 `ComboBox` 同宽、同 `HorizontalAlignment=Stretch`）；`ComboBox` 展开**不挤出 / 不遮挡**其它控件（本页 XAML 约束宽度，⛔ 依赖覆盖层自行处理）。两页 XAML 同一段结构照抄，改一处同步另一处。

> ⚠️ **用户再次强调**：预览页与批量页详情卡必须**完全一致**（同为 ffmpeg 命令可视化编辑器）。改动任一边前须比对另一页 XAML 确认无漂移，禁止两边各写一套。

**"完全一致"验收清单**（改任一边后逐条比对）

#### 6.4.2 「视频预览」页（单任务编辑器）

- **定位**：只负责**边看边制定一个**任务（剪辑 / 转码 / 剪辑+转码）；真正运行在「批量处理」页。⛔ **本页一次只编一个任务**（从列表 / 批量送来的多条只取首条，其余在状态栏提示）。
- **主内容区 = 预览**：
  - **预览画面（类播放器窗口）始终显示**：载入后大画面常驻；未载入时显示空态提示（⛔ 不再整块隐藏，避免布局跳动）。
  - **预览区占主区主体、面积尽量大**：抬高低限 `MinHeight`、压缩上下留白，给画面更多空间。
  - **三条时间条（预览位置 / 开始 / 结束）始终显示**（⛔ 不再只在有 `Duration` 或勾选剪辑时才出现）：拖动即时抽帧；`开始 / 结束` 仅在勾选「剪辑」时可操作，未勾选时灰显但仍占位（布局稳定）。
  - **三条时间条纵向间距压缩**（v3.13 收过一次，v3.16.1 **再收紧**：行间 `Spacing=10`、每条 `Slider` 高度压到 26、组上方外边距 6→4），整体更紧凑，把纵向空间还给预览画面。
  - **「结束」滑块默认停最右**（v3.16.1）：整段 = 结束在片尾，探测到时长后自动把结束值填成总时长（滑块停最右、右侧显示片长）；
    ⛔ 不再和上面两条一起挤在最左（三条都停 0 时读不出"结束=片尾"这层意思，看着还像没对齐）。「↺ 区间重置」同样把结束置为整段末尾。

- **状态栏常驻「当前视频信息」**：载入后状态栏每一行都带当前文件前缀 —— `🎬 {文件名} · {分辨率} · {时长} · {完整路径}`，后面再跟动作反馈（`已复制命令` / `已发送到批量处理` …）。
  ⛔ 不允许动作反馈把"当前预览的是哪个文件"冲掉：VM 内部统一走一个 `SetStatus(msg)` 拼前缀，⛔ 不各处直接赋值 `StatusText`。未载入文件时显示"未载入视频"。

  - 同一按钮兼「自动播放预览」开关：开 = 按时间轴自动逐帧推进（抽帧模拟播放），关 = 仅手动拖动。

- **顶部工具条**（动作全归这里）：`📂 选择视频` · `▶ 拖拽快览`（类播放器图标）· `➡ 发送到批处理` · `↺ 区间重置` · `📋 复制命令` · `↺ 重置为自动` · `❮/❯ 详情`。
- **从「视频列表」送来的文件 → 默认进入预览**（自动探测时长 + 抽当前帧）。
- 🔴 **取件时机**：见 §4.8 硬规则 8（取件点必须在 `OnAttachedToVisualTree`，`protected override`）。

#### 6.4.4 批量处理·任务的导出 / 导入

- **导出**：工具条「📤 导出任务」→ 把当前队列（剪辑 + 转码两类）序列化成 JSON 文件（复用 `VideoTaskStore` 的 `TaskFile` 结构）。

- **拖动表头列边界 = 手动调列宽**（能力已对所有列表页开启；页面只需给表头 `ColumnGrid` 写 `IsResizable="True"`）：

  - 被锁成表头宽的列**同样可拖**：动手即解除锁定，`LockColumnsBySample` 之后不再覆盖它。
  - 手调宽度**只存本次会话**（⛔ 不落 `columnlayout.json`）：切标签页不丢、重启还原；列显隐切换不影响已手调宽度。

#### 6.4.17 字幕：软字幕封装 / 硬字幕烧入（v3.92；工作项 NT-100）

**定位**：一条**转码任务**可以选择「挂一份字幕」——软字幕 = 只封装、不重编码；硬字幕 = 烧进画面（必须重编码）。⛔ 不做字幕编辑（打轴 / 调时间），只做 ffmpeg 能做的两件事。

| 项 | 规格 |
|---|---|
| 字幕文件 | `.srt` / `.ass` / `.ssa` / `.vtt`；空 = 不加字幕。详情卡 Actions 区「📝 选择字幕文件…」 |
| 字幕方式 | `不加字幕` / `软字幕` / `硬字幕`（三选一，落 `TranscodeTask.SubtitleMode`） |
| 软字幕命令 | `-i 源 -i 字幕 -map 0 -map 1 -c copy -c:s srt -metadata:s:s:0 language=chi -disposition:s:0 default` |
| 软字幕容器 | **固定 `.mkv`**（mp4 / mov 装不了文本字幕轨）；切到软字幕时输出名后缀自动改成 `.mkv` |
| 软字幕代价 | **不重编码** ⇒ 编码 / 分辨率 / 码率 / 旋转设置**不生效**（详情卡有明示提示行） |
| 硬字幕命令 | 追加滤镜 `subtitles='路径':force_style='FontSize=N,MarginV=N'`（**排在旋转 / 缩放之后**，字随最终画幅） |
| 硬字幕样式 | 字号（像素，0 = 用字幕自带样式，默认 22）/ 底部边距（像素，0 = 不设，默认 24） |
| 硬字幕强制重编码 | 预设是「只换容器（copy）」时**自动升级成 libx264**（否则滤镜无处落脚） |
| 预检（`CommandLint`） | 选了方式没挑文件 / 字幕文件不存在 / 软字幕输出非 `.mkv` / 硬字幕 + `-c copy` → 红字报错 |
| 摘要 / 存储 | 列表「参数」列显示 `… · 软字幕 · xxx.srt`；三个字幕字段随任务一起 JSON 持久化 |

#### 6.4.18 多段剪切 + 拼接（v3.92；工作项 NT-101）

**定位**：一条剪切任务可以**切多段再拼成一条**（去广告 / 只要几个片段）。⛔ 不做可视化分段列表编辑器，用**一行一段的文本**表达。

| 项 | 规格 |
|---|---|
| 输入 | 详情卡「多段剪切」多行框：每行 `开始-结束`（`00:00:05-00:00:12` 或 `5-12.5`；分隔符支持 `-` `~` `→` 逗号 空白） |
| 生效条件 | 解析出 **≥2 段** ⇒ 多段模式，**忽略**「开始 / 结束」；<2 段 = 按原单段剪切走（不报错） |
| 即时反馈 | 框下提示「已识别 N 段 · 合计 时长 · 多段会强制重新编码」；一行都解析不出来 = 不显示提示 |
| 命令 | `-i 源 -filter_complex "[0:v]trim=…,setpts=…[v0];[0:a]atrim=…,asetpts=…[a0];…[v0][a0]…concat=n=N:v=1:a=1[v][a]" -map [v] -map [a] -c:v libx264 -crf N -preset veryfast -c:a aac -b:a 192k` |
| 编码 | **强制重新编码**（copy 无法拼时间轴）；CRF 取详情卡「重编码 CRF」，预设下拉在多段模式下不参与 |
| 已知限制 | 命令假设源**有音轨**（无音轨文件会因 `[0:a]` 不存在报错，页面如实显示 ffmpeg 报错） |
| 预检 | 段区间非法（结束 ≤ 开始）的行被丢弃，只在提示行体现；命令本身走 `-filter_complex`，预检不拦 |

#### 6.4.19 画面裁剪 + 黑边探测（v3.93；工作项 NT-102）

**定位**：去掉画面黑边 / 只留一块画面。⛔ 不做可视化拖框取景，用**四个数（宽 / 高 / X / Y）+ 一个探测按钮**。

| 项 | 规格 |
|---|---|
| 输入 | 详情卡「裁剪（宽 × 高）」「裁剪起点（X × Y，左上角）」两组成对输入 |
| 生效条件 | 宽、高**同时 > 0** 才裁剪；只填一个 ⇒ 命令里不出现 crop（预检红字） |
| 黑边探测 | 详情卡动作 `🖼 探测黑边`：跑 2 秒 `cropdetect=24:2:0`，把最后一条 `crop=W:H:X:Y` 填进四个框；预览页从「预览位置」取，批量页从区间起点取 |
| 命令 | `-vf crop=w:h:x:y`，位置 = **旋转之后、缩放之前**（坐标是源画面像素） |
| 编码 | 裁剪是滤镜 ⇒ `-c copy` 预设自动升级 `libx264` |
| 精度 | 宽高向下取偶（yuv420p 2×2 采样要求偶数），预检提示「会自动取偶」 |
| 失败 | 探测不到 ⇒ 状态栏照实说、**不改**已有裁剪值（⛔ 不填 0×0 覆盖） |
| 批量页 | 探测结果只进编辑缓冲，`💾 保存修改` 才写回任务（与其它字段一致） |

#### 6.4.20 音轨：静音 / 音量增益 / 替换（v3.93；工作项 NT-103）

**定位**：一个**音频方式下拉**（保持 / 静音 / 音量增益 / 替换音轨），互斥由下拉保证 —— ⛔ 不用三个独立勾选框。

| 方式 | 命令 | 约束 |
|---|---|---|
| 保持原音频（默认） | 走预设的音频设置 | — |
| 静音 | `-an`，不再输出任何 `-c:a` | 与 GIF 预设一致（GIF 本来就无声） |
| 音量增益 | `-af volume=NdB`（正 = 变响） | 预设音频是 `copy` 时自动改 `aac`（`-af` 对 copy 无效） |
| 替换音轨 | 源输入后追加 `-i 音频` + `-map 0:v:0 -map 1:a:0` + `-c:a aac` | ⛔ 与软字幕**不能同时用**（两处都要 `-map`，预检红字） |

- 「🎵 选择音频文件…」挑完文件若方式还是「保持原音频」⇒ 自动切到「替换音轨」。
- 参数列 / 命令摘要显示音频摘要（非默认值才追加）。
- 多音轨选择 / 音频延迟：**本期不做**。

#### 6.4.21 按目标体积压缩（v3.93；工作项 NT-104）

**定位**：上传限制下「压到 N MB 以内」—— 用户只填 MB，码率由程序反算。

| 项 | 规格 |
|---|---|
| 输入 | 详情卡「目标体积（MB；0 = 不用）」 |
| 反算 | `视频 kbps = MB × 8192 ÷ 源时长秒数 − 音频 kbps − 8`，下限 50 kbps |
| 优先级 | **目标体积 > 目标码率 > CRF**（三者同时填，体积赢） |
| 命令 | `-b:v Nk -maxrate 1.5Nk -bufsize 2Nk`（单遍 ABR；⛔ 不做两遍） |
| 提示行 | 「按 50 MB ÷ 时长 ≈ 视频 xxx kbps（已扣音频与容器开销）」 |
| 失败 | 读不到源时长 ⇒ 算不出来（预检红字）；`-c copy` 预设遇目标体积自动升级 `libx264` |
| 生命周期 | 换源文件时清零（依赖具体文件时长） |

#### 6.4.22 时间轴区间标记（v3.94；工作项 NT-105）

**定位**：「预览位置」那条滑条换成一条**看得见剪辑区间**的时间轴轨道 —— 原先区间只在两条滑条上各有一个 thumb，多段剪切（§6.4.18）更是完全看不出剪的是哪几段。

| 项 | 规格 |
|---|---|
| 形态 | 预览画面下方第一行 = 时间轴轨道（`Module.VideoTools/Controls/TimelineTrack`，自绘 `Control`，高 44）；「开始 / 结束」两条滑条**保留**在下方做微调 |

- **扫描**（异步任务，**直接入库**）：忽略规则 → 遍历（**默认含子目录**，可关）→ 依次按 `storage+relative_path` / `size+mtime` / `quick_hash+size` 匹配（前两级**零 IO**；第三级只在"库里同 size 的位置已带 quick_hash"时才读前 N MB）→ 建 / 更新 `assets`+`file_locations`（批量事务）→ 提取元数据 + 生成缩略图 → 本次未出现的旧 location 标 `missing`（⛔ 不删 Asset）。🔴 新文件 ⛔ **不立即算完整内容哈希**（那会把每个文件整读一遍，实测几分钟扫不完一个目录 + 硬盘狂响）；完整哈希归 NT-021 的「补全哈希」任务。
- **预览扫描**（v3.29，**用户操作主路径**；🔴 ⛔ **一个字节都不写库**）：选一个文件夹（或几个文件）→ 只遍历 + 建**内存行**（⛔ 不建 assets / file_locations、⛔ 不算任何哈希）→ 列表进入**草稿态** → 用户二选一：
  - 入口 = 工具条首条 **SplitButton「📁 扫描」**（v3.30 用户定调）：主按钮直接点 = 选文件夹；右侧箭头下拉 = 「📁 文件夹…」/「📄 文件…」—— 样式对齐视频列表的「📂 导入」（`SplitButton.ghost`）。⛔ 不再摆两个独立按钮。手输路径另有工具条输入框，框内**回车**即预览扫描。
  - **💾 加入库**（`AssetService.CommitRows`）：按所在目录分组、各自登记 / 复用存储源（`root_path` 去重），**一个事务**批量落库；⛔ 只建索引、绝不动磁盘文件。
  - **🧹 清除列表**：丢弃内存结果、回到库视图，换文件夹重新扫描。
  - ⛔ 草稿态之外「加入库 / 清除列表」**一律置灰**（不做"能点却没反应"的按钮）。
- **批量登记 + 扫描全部**：「➕ 登记文件夹」把目录加进**待扫列表**（⛔ 登记时不扫描），可连续登记多个；「🔄 扫描全部」= `ScanAsync(null)`，一次把所有在线存储源扫完并**直接入库**。
- **工具条组成（页面级，§4.8 硬规则 9；v3.29 / v3.30 定型）**：`📁 扫描`（SplitButton：主钮 = 选文件夹 / 下拉 = 「📁 文件夹…」·「📄 文件…」）→ 路径输入框（回车即预览扫描）→ 搜索框 → `➕ 登记文件夹` → `🔄 扫描全部` → `🗄 打开库文件` → `💾 加入库` → `🧹 清除列表` → `☑ 含子目录` → `🏷 加标签` → `🗂 加集合` → `💾 存为智能集合` → `🔄 重读资产库`（**只重读数据库**，⛔ 不扫盘；命名见 §4.8 硬规则 10）→ 末位详情开关。⛔ 单条动作（📂 打开 / 📁 打开所在文件夹）一律归列表右键菜单。
- **多库融合**（NT-026）：`🗄 并入库文件…` = 选一个外部 `newtoys.db` **合并进主库**（主库即工作副本；`ATTACH` 只读挂载源库、⛔ 不改源文件；storages 按 root_path 去重、assets 一律新建、file_locations 按 storage+relative_path / hash+size 去重、标签分类集合按名字去重；一个事务，重复并入第二次基本全跳过）；`💾 保存` = 把当前库**另存为**新 .db（VACUUM INTO 一致快照；目标已存在 → 确认后覆盖）；"**减**" = 勾选行后「🗑 移入回收站（选中）」（软删除可恢复，⛔ 不做"按来源库拆出去"）。细节见 `modules/media-assets.md` §3。
- **逻辑操作**（直接改库 + 写 `operation_logs`，reversible=1）：显示名 / 标签 / 分类 / 集合 / 关联 / 软删除 / 恢复 / 评分描述。
- **物理操作**（⛔ 先写 `operation_logs`(pending) 再动磁盘；成功改 success、失败改 failed 并留 `before_json`）：重命名 / 移动 / 复制 / 删除；默认送**系统回收站**（`SHFileOperationW`，视频工具先例）且**二次确认**；防穿越 + 冲突检查；⛔ 失败不自动回滚磁盘，下次扫描按 hash/inode 校准。
- **外部变更**：文件不见 → `missing`；新路径 → hash 匹配视为移动；⛔ 移动硬盘离线（Storage `online=0`）时**不动**其下 file_locations，重新上线再扫描校准。
- **跨页投递**：模块内单例 Store（仿 `VideoTaskStore`）；🔴 取件点在 `OnAttachedToVisualTree`（§4.8 硬规则 8）。

**复用硬约束**（不在此复述，指向权威）：列表页一律继承 `ListPageViewModelBase`（`Shared/Models`）+ 三列布局 + 工具条 / 筛选条收进列表列 + 详情开关在工具条末位；`Views/ColumnGrid.cs` 本模块自建**第五份**副本（规范 §3.6，改动同步五处）；详情卡内容由 VM 实现 `IDetailPanelProvider.DetailContent` 提供（目标形态，规范 §3.8 / B13），详情卡内允许**编辑 + 「💾 保存」+「↗ 应用到文件」**（v3.29 用户定调，覆盖旧"零操作按钮"规则；⛔ 别放无关的全局动作）；状态栏由基类统一实现、每页 ≥1 行 `StatusText`；单元格内边距 8 / 表头 32 / 行 28（§4.10.2）。

#### 6.6.1 资产浏览页（`assets-browse` · v3.99 新增 · NT-115）

> 定位：**按磁盘位置翻资产**。与 `assets-all`（按元数据找）互补，两页**不得**互相抢职责（本页 ⛔ 不提供扫描 / 导入 / 并入 / 导出）。

  - `▦ 图标卡`：缩略图 + 名称 + （大小 · 修改时间）；卡片宽 300。
  - `☰ 详细信息`：列定义与 `assets-all` 同一套，列偏好按**独立页键** `assets-browse` 落 `columnlayout.json`（⛔ 不共用 `assets-all` 偏好）。

- **缩略图**：🔴 只为**已入库**的视频 / 图片生成与解码；未入库项显示类型占位（⛔ 不读盘）。浏览时只读缓存，按**可视区懒解码**（首屏 36 张 + 滚动补），LRU 上限 300；缺缓存的由后台任务队列补生成。图片缩略图用**本机原生解码**，视频仍用 ffmpeg 抽帧。
- **加入资产库**（`➕`）：文件 ⇒ 只索引自身（无归属源时把**所在目录**登记为源，⛔ 不登记盘符根）；文件夹 ⇒ 递归扫描（已在某存储源之内 ⇒ 归该源；目录里含**已登记的其它源** ⇒ 那部分文件跳过，⛔ 不重复索引）。批量入库走任务队列（可取消 / 有进度）。

- **性能红线**：切目录 200ms 内出首屏（缩略图可后到）；容器数受分页约束（默认 120 项/页）。
- ⛔ 不做：拖放移动复制 / 新建文件夹 / 目录级体积时长统计 / 视频内联播放 / 文件夹的重命名与删除（交资源管理器）。

## 七、设计原则（六条）

1. **模块化** — 按模块拆分，可独立开发 / 启停。
2. **插件化** — 模块编译为独立 DLL，运行时装配，加模块不改宿主。
3. **轻量务实** — 工具类应用，重效率稳定，UI 不炫技。
4. **自控** — 不引入任何第三方 UI 库 / 图标包，全局控件自己写。
5. **命令行封装** — 功能以「包既有命令行 / 系统能力」为主，不超命令行上限；配置一律落文件、可备份。
6. **可热加载** — DLL 放入 `<程序目录>\Modules\`，运行中点「刷新」即时装配，不必重启；加载源仅限本地文件夹。
