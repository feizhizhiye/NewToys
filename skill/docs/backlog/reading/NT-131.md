## 一、背景 / 目标

用户原话：「增加书源类型分组管理，方便删除，增加书源校验功能」。
现状痛点：

1. **只能一条一条删**：《全部资产》等页早就是多选批量，书源页还是 `SelectionMode="Single"`、`ScopeRows()` 只返回当前行 —— 导进几百条源后根本清不动。
2. **没有分类视角**：列表只有「名称 / 分组 / 类型 / 状态」四列文本，无法「只看这个分组」「只看文本源」。
3. **没有真·可用性判定**：「状态」列是导入时的静态判定（规则字段齐不齐），站点挂了 / 改版了照样标「可用」，用户没法知道哪些源已经死了。

## 二、范围

| 项 | 内容 |
|---|---|
| 筛选条 | 页内 TopArea 三个下拉：类型（全部 / 文本 / 图片 / 音频 / 视频）、分组（全部 + 库里实际出现过的分组）、校验（全部 / 未校验 / 通过 / 无结果 / 失败）；与工具条搜索框 AND 叠加；右侧显示「筛出 N / 共 M 条」 |
| 多选批量 | `SelectionMode="Multiple"` + `SelectedItems="{Binding BatchSelection}"`；右键「☑ 全选当前结果 / ☐ 取消选择 / ⇄ 反选」；启用 / 停用 / 导出 / 删除的作用域改为多选集合 |
| 改分组 | 右键「📁 改分组…」→ `DialogHooks.InputAsync` 输组名（留空 = 未分组）；写 `group_name` 并回写 `rules_json.bookSourceGroup` |
| 校验 | 工具条「🔬 校验」浮层：关键词 + 范围（当前筛选 / 选中 / 全部已启用）→ 每源跑一次搜索 → 逐条上屏「通过 / 无结果 / 失败」+ 原因，结论随跑随落库 |
| 校验列 | 列表新增「校验」列（可排序、可隐藏），详情卡加「校验 / 上次校验」 |
| 清失效 | 「只看失效」快捷筛选 + 「🗑 删除全部失效」（校验失败 + 无结果，确认框报两类条数） |
| 数据 | `book_sources` 增 `check_state` / `check_note` / `checked_at`（schema v3 → v4，`EnsureColumn` 补列，老库无损升级） |

## 三、验收标准

- [ ] 顶部三个下拉各自生效、可叠加；右侧计数随筛选变化；分组下拉只列库里存在的分组
- [ ] Ctrl / Shift 多选后「启用 / 停用 / 删除 / 导出」都作用于**全部选中**；右键「全选当前结果」只选当前筛选出来的行
- [ ] 「📁 改分组」把选中源改到新分组；导出 JSON 里 `bookSourceGroup` 同步变化；留空 = 未分组
- [ ] 「🔬 校验」输关键词跑完：逐条出结论、列表「校验」列与「上次校验」同步更新；中途关浮层 = 取消，已跑完的结论保留
- [ ] 「只看失效」只留失败 / 无结果的源；「🗑 删除全部失效」删前报条数，删后列表与计数同步
- [ ] 重新导入同一批 JSON **不清空**已校验结论
- [ ] `pwsh skill/scripts/accept.ps1` 一次通过

## 四、技术要点 / 约束

1. 🔴 **只改 `Module.Reading`**：⛔ 未动 Shared / Core / Shell / NewToys.UI。
2. 校验复用 `CrawlService.SearchManyAsync`（并发门 / 取消 / 逐源回调现成），只跑搜索段；`SourceCheckService` 负责分类 + 落库。
3. `Progress<T>` 包 onSource 回调，结论回到 UI 线程逐条上屏；落库在回调里逐条做（取消也留得住）。
4. `ON CONFLICT(url) DO UPDATE` 故意不覆盖三列校验字段。
5. 新列走 `ReadingDatabase.EnsureColumn`，`Version` 3 → 4。
