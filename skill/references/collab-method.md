# 通用协作方法论（跨项目母本）

> 本文件与具体项目无关。复制到任何新项目时，只需改同目录的 `<project>-spec.md`，本文件原样保留。
> v1.1 · 2026-10-12

---

## 一、铁律（通用，跨项目适用）

1. **变更顺序**：新需求 → 先写需求/规格文档 → 再改代码 → 最后更新台账。⛔ 先改代码后补文档。
2. **框架层冻结**：架构/框架层改动先问用户；新功能只在模块/业务层。
3. **版本记录走 git commit**（`<type>: <简述>`），⛔ 不写 md 日志；指导性文档仅过时/冲突才改；**代码 > 文档**。
4. **评估/讨论类内容不进文档**，只在会话里谈。
5. **停手仅 5 种**：改框架层 / 删用户已确认实现 / 需求自相矛盾 / 文档与代码冲突且影响本次 / 缺关键标识符。其余按最合理假设推进并在交付里标注假设。
6. **不代跑构建/编译**：构建由用户本地执行；AI 只做静态自检，⛔ 不谎称「已编译通过」。

## 二、规划 / 执行双模式工作流

> 🔴 **NewToys 权威流程以 `src/docs/NewToys-AI协作提示词.md`【规划 / 执行双模式工作流】为准**；本文件 §二 是**跨项目通用母本**，与 `src/docs` 冲突时以 `src/docs` 与 `src/` 源码为准。
> 核心：把「想清楚」和「写代码」彻底拆开。规划可多轮累积、只写文档；执行作为一个独立会话批量跑。
> 待办明细统一放 `src/docs/backlog/NT-xxx.md`（格式见该目录 `README.md`）；台账三、只放紧凑索引。

- **规划模式（默认，只写文档）**：
  - 跟用户讨论、澄清歧义（评估只在会话里谈，不落文档）；
  - 确认后的需求写进《开发需求》（框架 / 边界级才动需求；单页细节不进需求）；
  - 生成 / 补充待办 → 在 `src/docs/backlog/NT-xxx.md` 写明细（验收标准 / 技术要点 / 依赖 / 范围），并在台账三、索引登记；
  - ⛔ 规划模式**绝不改 `src/` 代码**，无论讨论几轮。新待办默认 `📝 草稿`。
- **执行模式（显式触发，才碰代码）**：
  - 仅当用户发「**执行全部就绪待办**」或「执行 NT-xxx」时进入；
  - 读台账三、，筛 `✅ 就绪` 且依赖已 `✔ 已完成` 的条目，按 **依赖 → 优先级（P0>P1>P2）** 排序；
  - 逐条实现 → 静态自检（`scripts/check.ps1`）→ 标 `🔄 执行中` → 成功标 `✔ 已完成` + git commit + 回写台账；
  - 🔴 **遇阻塞（5 种停手情形之一）立即停并报**，不偷偷跳过、不擅自扩范围。
- **草稿闸门**：`📝 草稿` 永不执行；讨论中随时追加草稿，攒够验收细节再升 `✅ 就绪`。
- **细节生命周期**：`NT-xxx.md` 是执行模式工作稿，随 `src/` 改动追加「执行记录」；验收后细节文件**全量保留**（⛔ 不删，按需读取；2026-10-14 用户定调）（详见 `backlog/README.md` 清理策略）。台账三、只翻状态、不随细节删。
- ⚠️ **「睡觉让 AI 跑」= 睡前开一个会话发「执行全部就绪待办」**，agent 在循环里把就绪项跑完；⛔ 不用 automation 定时触发（无迭代编译-修复循环，跑不动代码）。

## 四、静态自检（交付前必跑）

- `.axaml` ↔ `.axaml.cs` 同步；using / 类型 / 命名空间对得上；主题键在白名单；引用的资源键都存在。
- 改列表页：表头与行同套列定义；隐藏列用宽度 0；`Grid.Column` 索引逐字核对。
- 改跨页投递：取件点在视图挂载回调（非数据上下文变更回调）。
- 改标签/树/导航：单例判定、关首页被拒、关最后自动回首页。
- 项目特定检查见 `<project>-spec.md`；部分项可用 `scripts/check.ps1` 自动化。

---

## 五、交付要求

- 变更清单（增/改/删逐条）+ 前置基线 + 用户本地验证命令。
- 直接写工作区，用 read/ls 确认落盘；⛔ 不打 zip、不列下载链接、不做 sources md 快照。
- 功能级交付 git commit（`<type>: <简述>`）；纯修报错不回写台账。
- 摸底用 grep/read 定向检索，⛔ 不整读、⛔ 不读 `artifacts/ bin/ obj/`。

---

## 六、分级读档原则

- 只加载用得上的：先读入口（`AGENTS.md` 类）+ 台账基线，再按任务读规格相关章节。
- 冲突以源码为准并回写文档；框架约束是硬规则，不可擅改。
- 同一条规则只在权威文档定义一次，其余引用不复制（避免双源漂移）。
