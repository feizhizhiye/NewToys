## 背景 / 目标
`Views/ColumnGrid.cs` 在 **5 个模块里各存一份**（MediaAssets / PcTools / VideoTools / WebTools / Shell，各 417~418 行 = **2086 行重复**，且 MediaAssets 那份已多 1 行 = 已开始漂移）。
根因是三条铁律的必然产物：**模块禁互引** + **模块禁引 Shell** + **Shared/Core 不引 Avalonia** ⇒ View 层件**无处可放**。

**目标**：新增 `NewToys.UI`，把跨模块复用的 View 层件收进去，并顺势把「列表页」收敛成一个标准骨架。

## 依赖图
```
Shared ← Core ← Shell ← Module.*
Shared ← UI（引 Avalonia；⛔ 不引 Core / Shell）← Module.*  + Shell
```
- `NewToys.UI` 引 `Shared` + Avalonia，**⛔ 不引 Core / Shell**（保持单向，任何模块都能引）。
- `ModuleLoader` 的**默认 ALC 共享清单**要加 `NewToys.UI`，否则宿主与模块加载的不是同一份类型 ⇒ 类型不匹配（`Core/Services/ModuleLoader.cs`）。

## 🔴 UI 库纪律（新增程序集最容易踩的坑）
UI 被所有模块引用 ⇒ 与 Shared/Core **同级** ⇒ **改一次 = 全模块重编**。因此：
1. **UI 只放"写完即冻结"的稳定控件**；任何还在高频微调的东西（尤其视觉表层的"再调两轮"）⛔ 不许进 UI。
2. **31 个 `*Brush` 主题刷子必须留在 Shell 的 `App.axaml`**（⛔ 不搬）；UI 控件里的样式**只能用 `DynamicResource` 引用这些键**，⛔ 不许自带色值 —— 否则改一次配色就触发全模块重编。
3. UI 不承载业务：不放 VM 基类（`ListPageViewModelBase` 继续留 `Shared`）、不放服务、不放具体的行模板（各页行模板差异大，硬抽象会变"参数爆炸的万能控件"）。

## 技术要点 / 约束
- 🔴 `ColumnGrid` 注释里的**列数防线**（`ColumnDefinitions.Count` 必须 ≥ 子元素最大 `Grid.Column` + 1，否则 `VirtualizingStackPanel.RealizeElements` 下 `Grid.MeasureCell` 越界崩）必须原样保留 —— 合一时最容易丢的就是这段。
- 🔴 UI 里任何 XAML ⛔ 不许写死色值，一律 `DynamicResource` 引主题键（`skill/scripts/check.ps1` 的主题键检查需覆盖 UI 目录）。
- 类型页合并前先确认 **`AssetAllViewModel` 的继承链只有三处虚成员被覆盖**（`SetPresetType` / `PageKey` / `StatusPrefix`）；类型页删除后，这三个 `protected virtual` 可收窄为普通成员 —— 顺手减面。
- 分批之间不要混批改动（用户偏好：逐处改 → 逐处验）。
