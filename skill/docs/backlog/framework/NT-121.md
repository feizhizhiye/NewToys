## 背景 / 目标

用户提问（2026-10-29）：「我在资产库里挑选的 h264 视频，如何发送到视频工具里编辑转码命令」，并定调：
**在 `Shared/Services/` 做一个通用的跨模块信息传递服务，后续所有的跨模块信息传递都走这个渠道**。

现状缺口：

| 现状 | 说明 |
|---|---|
| 模块间零通道 | 需求规格 §3.6 只写了「走 Shared 契约」，但 Shared 里没有任何投递型契约 |
| 已有三套私货 | `WebTransferService`（`NewToys.UI`，网络工具 ↔ 抓取）、`VideoTaskStore`（视频工具模块内跨页）、`AssetNavigationStore`（媒体资产模块内跨页）—— 各自为政，新增跨模块需求就要再造一个 |
| 直接跳页没法带东西 | `INavigationService.NavigateTo(key, parameter)` 的 `parameter` 全工程无人消费 |

目标：一个**通用**投递通道 + 第一个真实使用者（资产库 → 视频列表），并保证「目标页没开 / 已开」两种时序都不丢消息。

## 技术要点 / 约束

- 🔴 **为什么是「信箱 + 订阅」而不是纯事件总线**：`NavigationService.NavigateTo` 每次都 `ActivatorUtilities.CreateInstance` 新建 View，但 `ShellViewModel.OpenTab` 发现标签已存在时只切 `ActiveTab`（VM 不重建）⇒ 订阅者「可能不存在」也「可能常驻」。只在构造里拉 = 页已开时丢消息；只订阅 = 页未开时丢消息。
- 🔴 **订阅按弱引用持有 owner**：VM 是 `AddTransient`，标签关闭后无人回收订阅表里的强引用。`Subscribe(topic, owner, handler)` 存 `WeakReference(owner)` + `handler.Method`，派发时 `MethodInfo.Invoke(owner, payload)`。
- 🔴 **handler 必须是 owner 的实例方法**（⛔ 别传捕获变量的 lambda）—— 弱引用绑的是 owner，闭包委托绑不回去。
- 🔴 派发全挂了的兜底：若快照里的订阅者全部已被回收，消息**退回信箱**，等页面重建时取。
- ⛔ 不做跨进程（Redis / MQ 对本单进程桌面应用过重）；⛔ 不做消息持久化（进程内语义，重启即清）。
- ⛔ 存量不动：`WebTransferService` / `VideoTaskStore` / `AssetNavigationStore` 保留原样，迁移另开卡。
