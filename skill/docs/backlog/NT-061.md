## 背景 / 目标
用户拍板：不用只读框（软件只提供**默认路径**，不提供默认加载项）；**每一次输入由页面自己记忆到该配置目录下**，选项可用 SQLite 管理；
**每个功能模块一个设置页**注册到 `settings`。评估后的落地口径：
- 存储**不直接上 SQLite** ⇒ 抽象 `IOptionsStore`（KV + 按模块分区），**先 json 实现**，将来可整体换 SQLite 而调用方零改动；
- **启动必需项保持 json**（可手改 / 可备份，用户画像 = 有电脑知识的人）；只有"记忆类"（搜索历史 / 最近目录 / 上次筛选）才值得进 SQLite；
- **写入点下沉到模块设置服务**，页面 VM ⛔ 不直接写文件（"唯一写入点"原则保住，只是从全局设置页下沉到模块设置页）。

## 技术要点 / 约束
- 🔴 **框架层（Core / Shell）改动 = 本卡首审项**；契约放 `Core`（⛔ Core 不引 Avalonia），实现放 `Core/Services`。
- 现有写入路径要收敛：现在模块各自读写 `config\<module>.json` 的代码 ⇒ 改走 `IOptionsStore`（⛔ 不要并存两套）。
- `IOptionsStore` 的键建议 `模块键.选项名`，值用 `string`（调用方自己序列化简单类型）⇒ 换 SQLite 时表结构就是 `module / key / value / updated_at`。
- 工具条 `TextField` 的提交：现有「回车即执行」走反射取 `EnterCommandPath` ⇒ 新增"失焦提交"要复用同一通道，⛔ 不再加第二处反射。
- 只读框现由 `ToolbarHost.BuildTextField` 掌管 `Text`（`IsReadOnly` 分支 + `Tag` 暂存）⇒ 改成可编辑后**整段删除**，改走 `TwoWay` + 提交命令。
- 状态栏红字：走既有 `IStatusProvider` / 状态栏通道，⛔ 不自绘新控件。
- SQLite（若后续要）：一个 profile 一个库文件；**"记忆类"数据单独表**，⛔ 不把启动必需项搬进去。
