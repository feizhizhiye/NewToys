## 背景 / 目标
原计划照抄 5 遍 `AssetAllViewModel` 落地 5 个类型页 —— **v3.34 用户拍板改为「薄壳 + 预设类型」**：实现只一份（`AssetAllView` / `AssetAllViewModel`），5 个类型页**共用**它，布局 / 工具条 / 筛选条 / 详情卡与「全部资产」页**完全一致**。

同时排除两件旧范围：**卡片 / 网格视图不做**（v3.34）；**类型专属列延后**（数据源 `assets.metadata_json` 现在恒为 `{}` —— 元数据提取尚未实装，做了也是空列，见「不做」节）。

## 技术要点 / 约束（规范章节、坑点、关键文件）
- 🔴 **零框架改动（已核代码，勿动）**：`ShellViewModel.ResolveViewModel`（行 500）按 `AssetVideoView → AssetVideoViewModel` **命名约定**解析 → 派生 VM 天然命中；`ResolveView`（行 459）只按类名找 View 类型 → 薄壳类名唯一即可。`AssetAllView.axaml.cs` 全部接线都是 `DataContext is AssetAllViewModel`（`is` 对派生类成立）→ 基类实现一行不用动。
- 🔴 **理想形态 = 连 `AssetAllViewModel` 都不用改**：
  - `PageKey` 是 `protected override string`（非 sealed）→ 子类可继续 `override`；
  - 预设类型：基类构造末尾 `BuildStaticOptions()` 把 `FilterType` 设为「全部」→ 子类构造里**直接再赋一次** `FilterType = TypeOptions[n]`（`FilterType` 生成的 setter 是 public）→ 自动触发 `OnFilterTypeChanged → ApplyView()`，**无需重查库**；
  - 状态栏前缀：基类构造写过一次 `StatusText` → 子类构造里再赋一次即可（`StatusText` 为 public setter）。
  - ⇒ 只有发现确实开不了缝（例如将来要按类型给**不同列集合**）才加 `protected virtual`，**改基类属框架层，需用户同意**。
- **薄壳写法**（`Views/AssetVideoView.axaml`）：
  ```xml
  <UserControl xmlns="https://github.com/avaloniaui" xmlns:x="..." xmlns:views="using:NewToys.MediaAssets.Views" x:Class="NewToys.MediaAssets.Views.AssetVideoView">
    <views:AssetAllView/>
  </UserControl>
  ```
  `.axaml.cs` 只 `InitializeComponent()` —— ⛔ **不搬** `AssetAllView.axaml.cs` 的任何接线（`ScanSplit.Click` / `ImportPathBox.KeyDown` / `HeaderGrid.ColumnResize|HeaderMeasured` 全在基类实例内，天然生效）。
- **VM 子类**（各 ~20 行）：`public partial class AssetVideoViewModel : AssetAllViewModel`，只写 `PageKey => "assets-video"` + 构造里设 `FilterType` / `StatusText` 前缀。
- ⚠️ **详情卡实例**：每份 VM 各自 `new AssetDetailView()`（基类懒建逻辑照旧）；⛔ 别让 5 页共用同一实例 → DataContext 冲突。
- ⚠️ **`QueryRows(limit: 2000)` 静默截断（现存缺陷，本轮顺手修）**：`AssetAllViewModel.Reload()` 全量读 + 客户端过滤 → 资产超 2000 条时「全部资产」少显示且**不报错**。方案：改为 `QueryRows(FilterType?.Value, limit: …)`（`QueryRows` 已有 `type` 参数）或提高上限 + 状态栏提示「显示前 N 条」。
- ⚠️ **列索引本轮不动**：列集合与「全部资产」页**完全相同**（8 通用列），XAML 里 `Grid.Column="0..7"`（表头 / 示例行 / 行模板三处）**不需要改**；将来加专属列时三处索引统一扩，⛔ 别漏一处。
- ⚠️ **需本地验证点**（AI 不代跑编译）：
  1. `UserControl` 内嵌 `UserControl` 的 `DataContext` 继承是否正常（常规做法，低风险）；
  2. 薄壳页里表头拖宽 / 表头右键 ContextMenu 是否仍生效（ContextMenu 的 DataContext 同步在 `AssetAllView.OnDataContextChanged` 里做，弹出树不继承）；
  3. 5 个标签页并行打开时各自列显隐 / 详情开合独立。

## 不做（本轮，已由需求 §6.6 承接）
- **类型专属列**（视频 时长 / 分辨率 / 编码；音乐 艺术家 / 专辑；书籍 作者 / ISBN；图片 尺寸 / 相机；文档 页数）→ 依赖**元数据提取**（`assets.metadata_json`，目前恒为 `{}`；归 NT-021 或其后），届时统一扩列（表头 / 示例行 / 行模板 + `AssetRow` 字段 + `QueryRows` 解析 + `FieldText` / 排序映射）
- **卡片 / 网格视图**（v3.34 明确不做，⛔ 不再引用 `video-fav` 卡片先例）
- 图片页特判（与其他四页同构）
