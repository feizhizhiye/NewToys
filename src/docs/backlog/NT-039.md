## 背景 / 目标

**根因**：开了 `ExtendClientAreaToDecorationsHint=True` 后，**DWM 把窗口边框交给应用画**；而 Avalonia 12 在 Win32 上只接管标题栏（`RequestedDrawnDecorations = TitleBar`，`:has-border` / `:has-shadow` 恒 `false`）。结果：**应用不画就没有边界** —— 窗口叠在同色窗口上时视觉上完全混淆（用户实测反馈）。

**目标**：① 窗口四周始终有可见的 1px 边界；② 一眼能看出哪个窗口是激活窗口。

> 范式来源：VS Code / Chrome / WinUI `TitleBar`（失焦时切 `Deactivated` 视觉状态）的通行做法。

## 验收标准（可验证清单）
- [ ] 窗口四边有 **1px 描边**，颜色 = `WindowBorderBrush`（激活）/ `WindowBorderInactiveBrush`（失焦）。
- [ ] **失焦时外框变色**（更淡），切回来恢复 —— 用两个窗口叠放实测。
- [ ] **最大化时外框收掉**（`BorderThickness=0`），还原后恢复。
- [ ] 浅色 / 深色两套主题下边框都可见（不能跟 `ContentBrush` 同色）。
- [ ] 100% / 125% / 150% 缩放下边框不发虚、不断续。
- [ ] 外框**不吃掉**窗口缩放热区（八向拖拽仍可用，见 NT-041 验证项）。
- [ ] 静态自检通过：`pwsh skill/scripts/check.ps1` + `check-axaml-props.ps1`。

## 技术要点 / 约束
- **主题键 32 → 34**：新增 `WindowBorderBrush` / `WindowBorderInactiveBrush`，在 `App.axaml.cs` 的 `ApplyTheme()` 里**明暗两套同时补齐**（深色 / 浅色各 2 个值）。改动后同步规范 §2.2 与 `skill/scripts/check.ps1` 的白名单。
- **外框位置**：包在 `ShellView.axaml` 根 `Grid` 外层（新加一层 `Border`），⛔ 不塞进现有行/列布局里。注意 `ResizeGrips` 那层在最外、占 `RowSpan=2`，需确认它相对外框的层级（热区不能被 1px 外框盖掉）。
- **最大化门控**：复用现成的 `OnPropertyChanged(WindowStateProperty)` 钩子（已有 `UpdateMaxIcon` / `UpdateResizeGrips`）。
- **激活态信号**：`Window.IsActive`（`OnPropertyChanged` 判 `IsActiveProperty`）。⚠️ 若实测该属性在 Win32 不触发 `PropertyChanged`，降级方案 = 窗口过程里处理 `WM_ACTIVATE`（此时须按 §4.1.1 ② 登记技术债）。
- 🔴 **跨平台门控**：判断「是否已有边框」用 **§3.7 的运行时信号**（`WindowDecorationMargin`），⛔ **不用 `OperatingSystem.IsWindows()`** —— 否则 X11 CSD 下会画两遍边框。
