## 背景 / 目标
落地存储源管理页（local / removable / nas），并把「外部变更处理」规则做实：移动硬盘离线不误标 missing、重新上线扫描校准、外部改名/移动靠 hash 识别为移动。

## 验收标准（可验证清单）
- [ ] 存储源列表：名称 / 根路径 / 类型 / 状态（online/offline）/ 最近扫描 / 文件数
- [ ] 工具条：添加 / 扫描选中 / 扫描全部；行操作：编辑 / 移除（**仅移索引、⛔ 不删磁盘文件**）/ 重新扫描
- [ ] 详情卡：存储源详情 + 统计（按类型分布、已用大小）+ 最近错误
- [ ] 移动硬盘离线（`online=0`）→ 其下 file_locations **不被标 missing**；重新上线 + 扫描 → 状态恢复
- [ ] 外部改名 / 移动文件后重新扫描 → 识别为「移动」（hash 匹配），⛔ 不是「新建 + 丢失」
- [ ] 外部删除 → 标 missing，⛔ 不删 Asset

## 技术要点 / 约束（规范章节、坑点、关键文件）
- 离线判定：扫描前探测 Storage 根可访问性（⛔ 不抛异常，记 online=0）
- 匹配优先级照 NT-015：path → hash+size → inode+device
- 移除存储源 = 删索引（其下 file_locations 一并清或标 deleted），⛔ 不动磁盘
- 扫描走 NT-015 的 `ScanService`/`TaskQueue`；从存储源页点「扫描」→ 跳任务中心看进度（`AssetNavigationStore` 跨页投递，取件点 `OnAttachedToVisualTree`）

- **离线语义**：每次重读逐个体 `Directory.Exists` 探测并写回 `online`；扫描选中时离线但根可达 → 自动改回在线再扫；离线且不可达 → 明确拒绝（⛔ 不入队必然被跳过的任务）；`ScanService` 原有"跳过离线存储源"行为不变（其下位置不标 missing）。
- **扫描走任务队列**：入队 → `INavigationService.NavigateTo("assets-tasks")` 跳任务中心看进度/取消；队列变空闲自动回读统计（`TaskQueue.Changed` → Dispatcher.Post）。
- ⚠️ **偏差记录**：① 跳任务中心用 `INavigationService`（NT 提的 `AssetNavigationStore` 是按资产投递，扫描无资产载体）；② 跨存储源的"移动"识别仍按 NT-015 既有匹配级（同存储源内改名 = size+mtime 命中；换根 = 新资产 + 旧位置 missing，完整哈希校准归 NT-021）；③ 类型编辑用"循环切换"（DialogHooks 只有输入/确认两种钩子，⛔ 未新造选择对话框）。
