## 背景 / 目标

用户需求（2026-10-28，编译通过后追加）：

1. 把 7z 路径也放进软件设置页（= 应用级「设置 → 运行环境」）；
2. 备份中心加一个「类似日历 todo」的页面，用 SQLite 管理备份记录和密码；
3. 备份文件的加密主要是**防止在云端泄露被查看**（设计判据，不是新功能）；
4. 备份中心设置页增加「默认备份目录」—— 原默认路径 `…\profiles\<配置>\store\backup\archives` 太深，想手动往里放文件得点很多层。

拍板（2026-10-28 用户答复）：

| 问题 | 结论 |
|---|---|
| 「默认备份目录」指哪个 | 可设置的浅层目录（不是新增第二个目录概念）；默认值改为 `%USERPROFILE%\NewToys\Backup` |
| 日历页形态 | **两者合一**：月视图同时显示「已发生的备份」与「计划中的待办」 |
| SQLite 迁移范围 | **记录 + 密码全迁**：任务 / 包清单 / 运行记录 / 待办 / 密码库全部进 `backup.db` |

## 技术要点 / 约束

- 🔴 **公开 API 不变**是本次降风险的关键：四个存储类的方法签名原样保留，页面 VM 不需要跟着改。
- 🔴 密码库条目仍是**密文进库**（`vault_items.blob` = base64(nonce|cipher|tag)）：库文件单独拷走也解不出密码。
- 🔴 `todos` 只是备忘，⛔ 不触发自动备份（定时任务属 v2）；`due_date` 存 `yyyy-MM-dd` 本地日期。
- 🔴 全表重写（`DELETE` + `INSERT`）而非逐条 diff：任务 / 包数量级小，整表写在事务里更不容易漏。
- ⛔ 不动 `Core/BackupService`（配置档备份），命名继续避开。
