## 背景 / 目标
用户 2026-10-16：「分页直接做，默认不显示，**只有当列表超出页面底部才显示**」。

现状：**全仓零分页** —— 列表一次性全量加载进内存（`AssetAllViewModel.StatusSummary()` 直接读 `Items.Count`，打印「共 N 个资产」），表头排序与筛选都在 `ObservableCollection` 里做。
「隐藏/显示」的 UI 部分很容易，**真分页的成本全在数据层**，因此与 NT-063（控件库）分离，单独立卡。

## 目标
1. 列表数据**按需取页**（SQLite `LIMIT/OFFSET`），不再是整表入内存
2. **排序下推到 SQL**（⛔ 否则分页后排序只对当前页生效 = 排错序 —— 这是分页最大的隐性坑）
3. 总数走**独立 `COUNT(*)`**（⛔ 不再用 `Items.Count`，否则总数 = 当前页条数）
4. 底栏由 NT-063 的 `ListFooterBar` 承载，**列表未超出页面底部时不显示**

## 验收标准
1. 任意列表页在数据量 < 一屏时，**底栏不可见**；滚到底部/数据量超屏时出现
2. 翻页后：**排序保持正确**（按 SQL 侧排序，⛔ 不是页内排序）、**筛选条件保持**、**选中项落到页内第一条**
3. 总数（`共 N 条`）与实际库内符合条件的条数一致（⛔ 不是当前页条数）
4. 切换页大小 / 跳末页不会越界（末页不足 ▸ 不出现空行）
5. **批量操作语义明确**：批量删除 / 批量勾选在跨页时的行为要写清楚并在 UI 上给出口径（推荐：**只作用于当前页选中项**，并在底栏写明「已选 M（当前页）」）
6. 编译通过 = 验收通过（沿用 2026-10-14 定调）

## 技术要点 / 约束
- 🔴 **排序必须下推 SQL**：现 `ListPageViewModelBase` 的排序在内存 `ObservableCollection` 上做（若分页后仍这样 ⇒ 每页各自排），改 `ORDER BY` + 稳定的次级排序键（加主键兜底，防同值行翻页时串位）
- 🔴 **计数与列表两条查询必须用同一套筛选条件**（建议抽一个 `BuildWhere(filters, search)` 同时产出 WHERE 子句与参数，**⛔ 别写两份** —— 两份漂移 = 总数与列表对不上）
- SQLite 唯一入口：`Core/Services/SqliteDatabase.cs`（🔴 不另开连接）
- 页大小预设值：`50 / 100 / 200 / 500` 可选 + 记住上次选择（落 `IOptionsStore` 的 `shell` 分区）
- 分批：先做一个**样板页**（推荐「全部资产」页）跑通，再推广到其余列表页（16 页逐个）
- ⛔ **不要为了分页引入懒加载/虚拟化替代方案**：`ListFooterBar` 的分页与 UI 虚拟化是两件事，本卡不做虚拟化

## 实施记录（2026-10-16）
**落地范围 = 样板页「全部资产」（`assets-all`）+ 基类分页状态 + 底栏插槽接线**；其余 15 页未迁（见「推广方式」）。

1. **`Shared/Models/ListPageViewModelBase.cs`**（框架层，卡内授权）：
   - 新增分页状态：`PageIndex`（1 起）/ `PageSize` / `TotalCount` / `PageCount` / `PageText` / `HasPaging` / `HasFooterContent` + `SetContentOverflow(bool)`（宿主页量布局回填）；
   - 命令 `FirstPage / PrevPage / NextPage / LastPage`；`PageSize` 变化即落 `IOptionsStore` 的 `shell` 分区（键 `list-page-size`）+ 收敛页码 + 重取；
   - `PagingEnabled` / `IsPagingSuspended` 两个虚属性（默认 false = **旧行为零变化**，派生页 opt-in）；
   - 排序 / 筛选变化统一走 `ResetToFirstPage()`（⛔ 不停在旧结果集第 N 页）；`ClampPageIndex()` 供派生类读完数据后收敛。
2. **`Module.MediaAssets/Services/AssetService.cs`**：`AssetQuery`（record）+ `CountAssets` + `QueryPage`；
   `BuildWhere` / `BuildOrderBy` / `ClauseToSql` 三个私有构造器 —— **列表与计数传同一个 query，WHERE 只写一份**；
   排序下推（文本列 `COLLATE NOCASE`，恒定 `a.id` 次级键）；LIKE 通配符转义；`json_extract` 一律 `json_valid` 守卫（⛔ 损坏 JSON 不炸整条查询）；组织信息映射改**按页 id 查**（⛔ 不拉全表）。
3. **`AssetAllViewModel`**：override `PagingEnabled => true`（`IsPagingSuspended => IsDraft`）；
   `Reload → LoadPageFromDb`（COUNT + LIMIT/OFFSET）；`ApplyView` 二分（库态 = 渲染当前页；草稿态 = 原内存路径 `ApplyViewMemory`）；
   状态栏总数改 `TotalCount`；批量勾选 / 全选口径 = **当前页**（`_all` 即当前页）；编辑保存后 `RefreshView` 重取 + 选中项**按 Id 认领**（⛔ 不跳走）；
   ctor 卫哨 `_booted`（筛选默认值不触发 3 次重取）。
4. **UI 插槽接线**：`ListFooterBar` 加 `PageSizes / PageSize / ShowPaging`（页大小下拉 + 「已选 M（当前页）」），
   🔴 内部绑定从 `$parent[UserControl]` 整体改为 **code-behind 按属性直配**（NT-063 遗留项：该壳此前的
   `ShowFooter` 恒 false ⇒ 内部绑定从未真正渲染验证过；本卡首次让它显示 ⇒ 按 ListPageSkeleton 口径重写，`FooterState` 类随之删除）；
   `ListPageSkeleton` 整组转发（含底栏→骨架的页大小回填，⛔ 不断链）；`AssetAllView` 绑全套分页属性 +
   code-behind 量 `ScrollViewer` 溢出回填 `SetContentOverflow`（底栏显隐的另一半口径）。

**编译错四连修（2026-10-16 用户本地 build 报错，修复类 ⇒ 当场闭环）**：① `FindDescendantOfType` 在
`Avalonia.VisualTree` 命名空间（补 using；先例 SettingsView）；② Avalonia ScrollViewer 是 `Extent`/`Viewport`（Size），
⛔ 非 WPF 的 `ExtentHeight`/`ViewportHeight`；③ CS0165：`numeric && TryParse(out var num)` 短路 ⇒ num 未赋值，改 `var num = 0.0;`。
教训：Avalonia 成员名以 ref 目录 XML 为准，⛔ 别按 WPF 记忆写；check-axaml-props 只核 axaml 属性名，不管 C# 成员名。

**已知边界（本轮不做，标注假设）**：
- 推广未做：其余 15 个列表页仍全量内存（`PagingEnabled` 默认 false ⇒ 行为不变）。
- `ConsumePendingAsset`（跨页定位）只搜当前页；目标在别页时提示「不在当前列表」。
- 筛选 / 排序口径自本卡起以 **SQL 侧为准**（文本大小写、极端空值边界与原内存实现可能有差异）。
- 页大小 = 全局一个（shell 分区），⛔ 不按页各记。

非 SQLite 数据源在各自 Repository 里同构实现）+ View 把 `AssetAllView.axaml` 的分页绑定照搬过去。
