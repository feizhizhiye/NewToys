# NT-034 · 窗口圆角修复（最大化 / 分屏方角）
- 状态：✔ 已完成（已验收 · 2026-10-14）
- 优先级：P1
- 关联：ShellView.axaml.cs（Win32 贴靠 / 边框逻辑，v3.28 / v3.29）
- 创建：2026-10-14 ｜ 更新：2026-10-14

## 背景 / 目标
窗口用 `WindowDecorations="BorderOnly"` + `ExtendClientAreaToDecorationsHint="True"`（系统贴靠路线）。Win11 下 DWM 默认给窗口**顶部两个圆角**。现有 `WM_NCCALCSIZE` 接管（`SnapFrameWndProc`）只对**最大化**保留了 8px 边框、未关闭 DWM 圆角偏好，导致：
- 最大化：标题栏顶边与屏幕顶边之间有圆角缺口 / 不贴合。
- 分屏（snap 半屏）：窗口与屏幕边 / 邻窗之间有圆角露缝、观感错位。

## 验收标准
- [ ] 最大化后标题栏顶边与屏幕顶边完全贴合，无圆角缺口。
- [ ] 左 / 右半屏分屏：窗口与屏幕边、邻窗严丝合缝，无圆角露缝。
- [ ] 拖到顶边最大化、Win+↑↓ 贴靠后同样无圆角问题。
- [ ] 普通窗口形态符合所选方案（已确认：始终方角）。

## 技术要点 / 约束
- **主方案**：Avalonia 官方开关 `Win32Properties.SetWindowCornerPreference(window, WindowCornerPreference.DoNotRound)`（只在 `OnOpened` 调一次）。
- 兜底：P/Invoke `DwmSetWindowAttribute` + `DWMWA_WINDOW_CORNER_PREFERENCE`(33) = `DWMWCP_DONOTROUND`(**1**)。⚠️ 枚举：DEFAULT=0 / DONOTROUND=**1** / ROUND=2 / ROUNDSMALL=3 —— 写成 2 是"强制圆角"（实测踩过）。
- 兜底调用点：`OnOpened` 与 `OnPropertyChanged(WindowState)`（状态变化时 Avalonia 会重算窗口属性，需补回）。
- 🔴 只靠兜底**不够**：Avalonia 每次 `ShowWindow`（最大化 / 分屏 / 全屏）都会把圆角重算成 ROUND，见下方执行记录第三次。
- Win10 该属性被忽略（本就无圆角），无害；失败路径 try-catch 保守处理，装不上不影响现有窗口。
- ⛔ 不动框架层；仅改 `src/Shell/Views/ShellView.axaml.cs`（新增 P/Invoke + 两处调用）。

## 决策（2026-10-14 评估讨论确认）
- ✅ **采用始终方角（DonotRound）**：最大化 / 分屏 / 普通窗一律方角，彻底消除圆角缺口与露缝。用户已确认放弃"普通窗保留圆角"的备选（其 snap 检测更复杂且有边缘态）。

## 范围 / 预估文件清单
- 改：`src/Shell/Views/ShellView.axaml.cs`（新增 `DwmSetWindowAttribute` / `DWMWA_WINDOW_CORNER_PREFERENCE` / `DWMWCP_DONOTROUND` 常量与调用；`InstallSnapFrameFix` 末尾 + `OnPropertyChanged` 的 `WindowState` 分支各加一处）。

- 🔴 **2026-10-14 用户二次反馈：仍圆角** —— 改常量后仍无效。**真根因** = **Avalonia 自己会设圆角**：`src/Windows/Avalonia.Win32/WindowImpl.cs` 在窗口属性更新时主动调用 `DwmSetWindowAttribute(..., DWMWCP_ROUND)`（见 [Avalonia#17294](https://github.com/AvaloniaUI/Avalonia/issues/17294)）→ 覆盖我们的 DONOTROUND。**修法**：`ShellView` 在 `OnLoaded` 订阅 `LayoutUpdated`，启动头 8 帧反复重设 DONOTROUND 压过它，之后自动摘订阅；`OnOpened` 与 `WindowState` 分支照旧重设（状态变化也会被 Avalonia 重算）。⏳ 待重新编译复验。
- 🔴 **2026-10-14 用户三次反馈：还是圆角（并提示"看下 Watt Toolkit 怎么做的"）** —— 已定位到**源码级确凿根因**（比 Watt Toolkit 更直接）：

  `WindowImpl.cs`（12.x）里的原话：
  ```csharp
  private void UpdateWindowCornerPreference()
  {
      int cornerPreference = (int)HintsToCornerPreference(_cornerHints,
          _isClientAreaExtended && WindowState != WindowState.FullScreen
              ? DwmWindowCornerPreference.DWMWCP_ROUND          // ← 强制圆角
              : DwmWindowCornerPreference.DWMWCP_DEFAULT);
      DwmSetWindowAttribute(_hwnd, DWMWA_WINDOW_CORNER_PREFERENCE, &cornerPreference, sizeof(int));
  }
  ```
  调用链：`_cornerHints` 默认 = `NoHint(0)` → 取 `noHintDefault` = **ROUND**（本窗口 `ExtendClientAreaToDecorationsHint="True"` → `_isClientAreaExtended` 恒 true）。
  而 `UpdateWindowCornerPreference()` 的调用点是 **`ExtendClientArea()`**，后者又被 **`ShowWindow()`** 调用 —— **最大化 / 还原 / 分屏（snap）/ 全屏切换全都走 `ShowWindow`**。
  ⇒ 我们手动写的 `DwmSetWindowAttribute(DONOTROUND)` **每次窗口状态变化都会被覆盖成 ROUND**；"启动时压几次 / 压头 8 帧"这类打法**必然失效**（这就是前两轮都失败的原因）。

  **第 3 次修法（根治，放弃硬碰硬）**：改用 Avalonia **官方开关**
  `Win32Properties.SetWindowCornerPreference(this, Win32Properties.WindowCornerPreference.DoNotRound)`
  （`Avalonia.Controls.Win32Properties`，12.1.3 本地程序集已核实存在；源码 `src/Avalonia.Controls/Platform/Win32Properties.cs`）。
  它把偏好写进 `WindowImpl._cornerHints` → 之后**每次重算都按它来** → 最大化 / 分屏 / 全屏自动保持方角，不需要再压帧。
  - ⛔ **两个调用纪律**（静态构造里是 `Changed.AddClassHandler`，只在**属性变化**时下发，且要求 `window.PlatformImpl` 已就绪）：
    ① 只能在 `OnOpened` 调**一次**；⛔ 别在构造函数里先调（若那时 PlatformImpl 未就绪则不下发，而 `OnOpened` 再设**同值**不触发 Changed → 永久失效）。
    ② 不用 `LayoutUpdated` 压帧了（已删除 `_cornerReasserts` / `OnLayoutUpdatedForCorners`）。
  - 兜底保留：手写的 `ApplyNoRoundCorners()`（P/Invoke，常量已改为 1）仍在 `OnOpened` 与 `WindowState` 分支调用，官方开关万一不生效还能顶一下。
  - 关于 Watt Toolkit（SteamTools，同为 Avalonia）：未找到其处理圆角的直接源码证据；但既然 Avalonia 已提供官方开关，就不需要照抄第三方 workaround。
  ⏳ 待用户本地 `build.ps1` 编译 + 实机复验（普通窗 / 最大化 / 分屏三种形态）。
