## 一、定位

**NewToys 是作者个人自制的工具集——「带 GUI 的脚本管理器」。** 非商业、非通用产品，「自用顺手」第一。

每个页面 ≈ 一条或几条命令行 + 一份 `config/` 配置的封装。

## 二、边界

**判据**：「如果我只写个脚本会怎么写？现在少让用户做哪一步？」—— 这就是功能边界。

- **做**：把作者日常高频的终端 / 系统能力，包成可点、可配、可备份的界面。
- **不做**：脚本里不会有的东西——社交、推荐、引导、埋点、账号、云同步、**在线插件市场 / 商店**。
- **本地模块热加载**（丢 DLL 进 `Modules\`、点刷新即时装配）**要做** —— 它不联网、不下载、不建生态，等于「加一个本地脚本」。

## 三、技术框架（硬约束）

> 本节锁「软件框架长成什么样」。具体类名 / API 签名 / 踩坑见规范。

### 3.1 分层与依赖

```
Shared（契约 / 模型，不引 Avalonia）
  ▲
Core（服务实现，不引 Avalonia）
  ▲
Shell（宿主，引 Avalonia，AssemblyName=NewToys → NewToys.exe）
  ▲
Module.*（功能模块，只引 Shared + Core）
```

- **单向依赖**，禁止反向。
- **禁止模块引用 Shell**（循环依赖）；**禁止模块之间互相引用**；跨模块协作走 `Shared` 契约。
- **Shared / Core 禁止引用 Avalonia**（系统明暗、平台能力由 Shell 探测后注入）。
- 公共基类 / 契约放 `Shared`；被 ≥2 模块用或属应用级能力才上提，判断不清默认放模块内部。
- **UI 契约**（定义在 `Shared/Services/`，页面 VM 可选实现、Shell 统一消费）：
  `IDetailPanelProvider`（详情卡）、`IHistoryProvider`（历史栈）、`IStatusProvider`（状态栏）。

### 3.2 技术栈（锁定，禁止擅升擅降）

| 组件 | 版本 |
|---|---|
| .NET | net10.0 |
| Avalonia | 12.1.4 |
| CommunityToolkit.Mvvm | 8.4.2 |
| Microsoft.Extensions.DependencyInjection | 9.0.0 |
| Microsoft.Data.Sqlite | 9.0.0 |

- **禁止引入任何第三方 UI 组件库**（Material / Suki / FluentAvalonia / Semi 等）。
- **禁止引入第三方图标字体 / 图标包**；图标以 Avalonia 内置 `Geometry` 路径数据为**最终方案**（只可手工摘取公开图标集如 Lucide / Feather 的路径数据）。
- 包版本集中在 `src/Directory.Packages.props`（中央包管理）；csproj **不写** `<PackageVersion>`。
- `LangVersion=latest`、`Nullable=enable`、`ImplicitUsings=enable`。

### 3.3 框架层冻结

- `Shared / Core / Shell` 稳定后默认不再改，**新功能只在 `Module.*` 内**。
- 确需改框架层（新增全局服务 / 契约、调全局布局）**必须先获用户明确同意**，交付里独立说明。

### 3.4 模块化与热加载

- 模块编译为独立 DLL（`Module.<模块名>.dll`），实现 `IModule { RegisterServices, Initialize }`。
- **菜单只能在 `Initialize` 注册**；`RegisterServices` 禁注册菜单。
- **启动双轨**：Debug 用 `#if DEBUG` 显式类型清单；Release 扫 `<程序目录>\Modules\`，跳过已加载同名。
- **运行期热加载**：丢 DLL 进 `Modules\` → 点刷新 → 即时装配，不重启。
  - 只读本地 `Modules\`，**不联网不下载**；`Path.GetFullPath` 校验路径落在 `Modules\` 内。
  - 每个 DLL 用独立 `AssemblyLoadContext`（`isCollectible:true`）；`NewToys.Shared/Core` 由默认 ALC 共享。
  - 逐个 `try-catch` 隔离：单 DLL 失败不影响宿主与其他模块。
  - 只做「新增」，同名不替换不卸载。

- **模块自包含（硬约束）**：模块所需的一切（View / VM / 服务 / 设置页）都在**自己的 DLL** 里；加载时只往界面注册（菜单、设置页），⛔ 不把模块代码搬进 Shell 或其他模块，⛔ 不靠其他模块代持页面。
- **模块设置页归本模块**：每个模块把自己的设置页（View/VM）放在本模块 `Views/` + `ViewModels/`，在 `Initialize` 里注册进 **`settings` 分组**（`RegisterFunction("settings", "settings-<模块键>", …)`，Order 从 **100** 起、每模块独占一段 +10；**0~99 保留给框架设置**）。跨组注册由框架**延迟补登**保障（规范 §3.2）：分组尚未注册时暂存，待其建立时补登，⛔ 不抛异常。
- **框架设置归 `Module.Settings`**：主题 / 路径 / 一键按钮 / 加密 DNS / 软件源 / 配置 / 数据管理 / 关于 / 功能清单等**框架级设置**留在 `Module.Settings`。
- **必备模块（物理必备）**：`Module.Settings` 与 Shared/Core/Shell 同属**框架组件**——Shell **无条件 `ProjectReference`**、`Directory.Build.props` 的模块 Release `OutDir` 规则对它**开例外**（⛔ 不进 `Modules\`）、DLL **只随 `NewToys.exe` 直出程序根目录**、**启动时第一个加载**（必载清单置顶，先于一切功能模块）；缺失 = **启动失败**（同 Shared/Core 的硬依赖，⛔ 不做降级）。`Modules\` 自此**只含功能模块**；`scripts/build.ps1` 的产物计数校验同步改为只数功能模块（2026-10-13 用户授权改构建脚本）。加载后健全性检查：`settings` 分组仍不存在（如 `SettingsModule.Initialize` 自身抛异常被吞）→ 日志 + 状态栏各一行，⛔ 不静默。
- **框架自给（硬约束）**：一个功能模块都不加载时，框架本身必须完整可用——**首页 / 一键启动 / 收藏夹 / 主题 / 多配置 / 设置全套**均不依赖任何功能模块（Settings 是框架组件，不随功能模块增减；现状已满足：首页与一键启动的全部依赖在 Shared/Core；新增框架功能时保持此性质）。

### 3.5 配置与数据

- **多配置**：`<应用根>\profiles\<配置名>\{config,data,logs}`；**当前配置**记在 `<应用根>\active-profile.txt`（必须在 `profiles\` **之外**，否则切换时把自己也换掉）。
- **所有设置落 `<配置根>\config\*.json`**（才能被数据管理页备份 / 导入）。
- **用户功能数据**同样落 `config\`、一样进备份。
- **本地数据库**落 `<配置根>\data\newtoys.db`（可随时重建的缓存，**不进备份**）；日志落 `<配置根>\logs\`。
- **应用根** = `%LocalAppData%\NewToys`，环境变量 **`NEWTOYS_HOME`** 整根切换（test vs prod）。
- **数据迁移**：首次运行新版时，若 `<应用根>\config` 存在而 `profiles\` 不存在 → 现有 `config/data/logs` **整体移动**到 `profiles\default\` 并写 `active-profile.txt = default`；失败则**保持旧结构运行**并在「设置 → 配置」提示。
- **切换配置 = 重启应用**（本窗重启到目标配置，显式传 `--profile`；⛔ **不写** `active-profile.txt`——那是全局默认指针，多实例下会互偷；热切换改动面大、极易残留半新半旧状态）。**设为默认配置**（设置 → 配置页）才写 `active-profile.txt`，影响以后**无参启动**的实例。
- **多实例（一个配置一个窗口）**：可同时启动多个实例各跑不同配置——数据隔离靠**目录天然达成**（每配置独立 `config/data/logs`，SQLite / 配置 / 缩略图 / 任务 / 日志全隔离）；`NEWTOYS_HOME` 可整根切换（两个不同根 = 完全隔离）。
  - 启动参数 `NewToys.exe [--profile <配置名>]`：无参 = 读 `active-profile.txt`（全局默认）；参数非法 / 配置不存在 → 回退默认 + 状态栏一行提示。
  - **每配置单例**：同一配置同时只允许一个实例（命名互斥）；第二例提示「该配置已在运行」后退出，⛔ 不静默抢占、⛔ 不抢前台焦点。
  - `active-profile.txt` 只写两处：**首次迁移**（= default）与**设为默认配置**。
  - 窗口标题 = `NewToys · <配置名>`（任务栏区分多实例；**左树底部也与版本号同显**，见 §4.3）；「设置 → 配置」页每配置行提供「🚀 新开」（带 `--profile` 起新进程）。
  - 首启迁移竞态（两实例同时首次启动）容忍：失败保持旧结构 + 下次自愈（既有兜底），⛔ 不加迁移锁。
- **内置配置档 `debug` / `default` / `release`（v3.37）**：三档**永久驻留开发机**（`profiles\<名>\`，⛔ 无任何自动清理；用**「重置为初始态」**替代「删除」）。
  - `default`：本地日常使用（真实设置与数据）。
  - `debug`：开发 / 测试；**首启播种 = 复制当前 `default` 内容**为初始态（测试资源后续接入）。
  - `release`：干净初始态（上架前审计；**上架为远期，见 §2.1**）。
  - 三档在**开发构建（Debug）**首启自动播种；商店版（远期）仅含 `default`、无切换入口。
- **模块只读设置**，唯一写入点在该设置的设置页；功能入口页**只读**（⛔ 不许回写 → 双真相源）。
- **改系统级配置的页面必须二次确认**（如软件源增删 → 改系统 winget）。

### 3.6 默认数据（不许硬编码）

- **内容清单不写死在 C# 里**；默认内容随程序发布在 `<程序目录>\defaults\*`，**首次运行**播种成 `config\` 或用户目录下的用户文件。
- 此后一切以用户那份为准（用户删掉的条目不会被"复活"）。

### 3.7 跨平台预留

- 主平台 **Windows 10 LTSC**；迁移方向 **Debian 13**。
- 平台相关能力（winget / `ms-settings:` / ffmpeg）**集中封装**，便于整体替换。
- 路径一律 `Path.Combine`；外部相对路径 `Path.GetFullPath` 后校验落在目标目录内。
- 🔴 **跨平台判定一律用运行时信号，⛔ 不做 OS 嗅探**（`OperatingSystem.IsWindows()` / `#if` / `x:OnPlatform` 都在加载期一次性求值，无法响应运行期切换）。
  窗口装饰的唯一判据 = **`WindowDecorationMargin.Top > 0`**（等价于「框架正在替本窗口绘制装饰」）：

  | 平台 | `WindowDecorationMargin.Top` | 含义 |
  |---|---|---|
  | Win32（开了客户区扩展） | = 标题栏高（> 0） | 框架在画标题栏；**边框 / 阴影仍归 DWM** |
  | Linux X11（CSD 双门激活） | = 标题栏高 + 阴影厚（> 0） | 框架画全部四件套 |
  | macOS | 恒 `0` | 框架从不启用绘制装饰，走原生 |
  | 任意平台（关掉客户区扩展） | `0` | 系统原生装饰，⛔ 自绘标题栏不得出现 |

  ⚠️ Linux/X11 需 `X11PlatformOptions.EnableDrawnDecorations = true` 才启用绘制装饰；Wayland 的 CSD/SSD 是**运行期协商**，必须订阅变化、不能只在构造期读一次。

#### 4.1.1 窗口装饰与窗框（**走 Avalonia 12 官方 CSD 路线**）

> v3.38 立「官方 CSD」。🔴 **2026-10-15 同日两次反转后定案**：先按 NT-034 基线（Win32 补丁）回退，随后据**跨平台评估**（Wayland / Debian 13 只有官方 CSD 接得上 —— Linux 无 DWM / `WS_*` 样式位 / GDI region 概念）**重新采纳官方 CSD**。
> ⇒ 口径：**框架能做的交给框架**；Win32 侧仅保留「方角」两处（② 与技术债 §7 **B16 / B17**）。

**① 官方路线（唯一实现方式）**

| 机制 | 用途 |
|---|---|
| `ExtendClientAreaToDecorationsHint="True"` | 激活客户区扩展（也是 `ElementRole` 生效的前提） |
| `ExtendClientAreaTitleBarHeightHint="40"` | 声明自绘标题栏高度 |
| `WindowDecorations="Full"` | 只为拿**完整标准窗口样式**（贴靠资格 / 系统菜单 / 最小化动画）；⛔ 不等于让 Avalonia 画默认窗框 |
| `WindowDecorationsTheme` | 顶掉默认装饰的正门：`App.axaml` 里以**隐式键** `{x:Type chrome:WindowDrawnDecorations}` 注册空 `ControlTheme`（**不设 Template** → 框架不生成装饰视觉），引用用 `DynamicResource` |
| `WindowDecorationProperties.ElementRole` | 给自绘元素标角色：`TitleBar`（系统拖动 + 双击最大化 + 贴靠）/ `User`（放行点击）/ `ResizeN…SW`（八向缩放） |

- 客户区扩展记账**交 Avalonia 12 官方接管**（⛔ 不自接管 `WM_NCCALCSIZE`）。
- `WindowDecorationProperties` / `ElementRole` 由系统负责拖动 / 缩放 / 命中测试（`BeginMoveDrag` / `BeginResizeDrag` 仅作兜底）。

**② Win32 仅保留「方角」，其余一律禁止**

| 补丁 | 现状 |
|---|---|
| `Win32Properties.SetWindowCornerPreference` + `DwmSetWindowAttribute(33,1)` + `SetWindowRgn` 矩形区域 | ✅ **保留**（NT-034 三保险 / NT-042 裁决；技术债 §7 **B16**） |
| 手工补 `WS_CAPTION` / `WS_THICKFRAME` 样式位 | ⛔ **已删**（NT-041）：官方 `Full` 自带这些位 |
| 接管 `WndProc` 改 `WM_NCCALCSIZE`「零内缩」 | ✅ **保留（Windows 独有的例外）**：消灭 ≈8px **非客户区**边框（Avalonia CSD 按 `WS_CAPTION|WS_THICKFRAME` 扣出，贴靠态系统不画那圈 → 露缝）；钩子只在 Windows 装得上，Linux 不走此路径 |
| 贴靠几何外部纠偏（比对 / 屏幕几何自检） | ⛔ **已删**（NT-048）：首次偏宽是**系统行为**（第三方 Firefox 同复现）⇒ 方向错误 |

- ℹ️ **残留分两种，别混**（2026-10-15 实测：贴靠第 1 次缝小 ~1px、第 2 次变大 ~8px）：
  - **≈8px**（左右下）= 非客户区那圈边框 → 由 **零内缩** 消除（Windows-only 例外）✅ 已验收（2026-10-15 实机：连续贴靠 8px 消失）；
  - **≈1~2px**（**仅第一次分屏、左右下偏大**；常规态为左右不对称：左半屏重叠 / 右半屏缝隙）= **系统取整 / 动画帧落位**，Firefox 同复现 ⇒ **接受**，⛔ 不做外部几何纠偏。

**③ 窗口外框（自绘 1px）+ 激活 / 失焦两态**（P0，见 NT-039）

- 根因：开了客户区扩展后 **DWM 把边框交给应用画**，Avalonia 在 Win32 上又只接管标题栏（`:has-border` / `:has-shadow` 恒 `false`）→ 应用不画就没有边界。窗口叠在同色窗口上时视觉上完全混淆。
- **外框**：窗口根容器外包 1px 描边，颜色用语义键 **`WindowBorderBrush`**（激活）／**`WindowBorderInactiveBrush`**（失焦，更淡）。
- **最大化时收掉外框**（否则贴屏幕边很脏，且 Win11 最大化本就无边框）。
- **失焦态**由 `Window.IsActive` 驱动：切换上面两个键（必要时标题栏文字同步降级 —— 参照 WinUI `TitleBar` 的 `Deactivated` 视觉状态）。
- 🔴 **跨平台门控**：`WindowDecorationMargin` / 框架已在画边框时（X11 CSD）⛔ 不重复画 → 判据见 §3.7，⛔ 不用 OS 嗅探。

**④ 标题栏配色**

- 底色 **`ContentBrush`**（与窗口背景一致），底部 1px `DividerBrush` 分割线；文字 / 图标 `PrimaryTextBrush`。
  - ✅ `TitleBarBrush` / `TitleBarTextBrush` / `TitleBarButtonHoverBrush` 三键经 **NT-043 拍板「不启用」**，已由 **NT-049** 从 `App.axaml.cs` 删除；标题栏底色 / 文字 / 按钮 hover 统一走现有键（`ContentBrush` / `PrimaryTextBrush` / `CardHoverBrush`），关闭按钮 hover 仍用 `TitleBarCloseHover*`。

### 4.2 标签栏（并入标题栏中段）

- **位置**：不再是独立一行；在标题栏中段横向排列。每个标签页 = 一个打开的功能页面，一对一绑定菜单 Key。
- 组件：`ItemsControl` + 横向 `ScrollViewer`（滚动条隐藏）；标签项**只有标题 13px**（**不带图标**，样式与左菜单二级项一致）。
- 🔴 **首页标签固定不滚动（v3.45）**：标签再多，**首页标签也始终可见** —— 它单独占位列、⛔ 不进横向 `ScrollViewer`。**首页是唯一固定元素**；⛔ **不做「固定其他标签页」功能**（「固定」需求走首页收藏夹 / 常用功能）。其余标签与 `＋` 按钮一律参与横向滚动。
- **`✕` 关闭按钮**：**不占位**（标签宽度只按文字算）、**叠在标题文字上层**贴右端；平时 `Opacity=0` 且不吃鼠标，**悬停该标签才出现**（允许与文字重叠 —— 换更窄标签）。
- **激活态只看颜色（v3.22 简化）**：激活标签 = **文字用强调色**，其它跟普通标签一样；⛔ **不垫背景色**（那块底色会盖住关闭按钮、也让"激活"和"悬停"分不清）；⛔ **不画下方指示条**（那条线会被误认成阴影）。
- **关闭按钮的悬停观感（v3.22）**：鼠标落在关闭按钮上时——① **按钮放大**（20→24px 见方，图标字号同步放大）；② **背景恒透明**（⛔ 不画灰底方块）；③ **图标变红**（`DangerBrush`），形成"红 ✕"提示这是一个**删除类**动作。未悬停时回归次要文字色。
  - ⚠️ 实现前提：关闭按钮必须套**裸按钮主题**（`Theme="{StaticResource BareButtonTheme}"`，`App.axaml` 里定义）—— Fluent 的 `Button` 模板会在 `:pointerover` 自己画底并把前景改白，**样式 setter 压不过模板状态**。
- **行为**：
  - **点左菜单二级项** → 打开 / 激活对应标签页（**同 Key 已存在则激活，不新建**）。
  - **点标签** → 切换；**中键 / `×`** → 关闭（首页除外）。
  - **在标签区滚轮** → 切换标签（上滚上一个、下滚下一个，循环）。
  - **跟随滚动**：切换后用**最小滚动**让当前标签**始终可见**（类 Chrome），不做"强推边缘"。
  - **`+`** → 打开「功能清单」页（当选择器用）。
  - **右键** → 关闭 / 关闭其他 / 关闭右侧 / 全部关闭（首页除外）。
  - **快捷键**：`Ctrl+W` 关闭当前 ｜ `Ctrl+Tab` 下一个 ｜ `Ctrl+1..9` 跳第 N 个。
- **单例语义**：同一 Key 只允许一个标签页存在（工具类应用，非文档编辑器）。

### 4.3 左侧菜单栏（180px / 折叠 48px，窗口级）

- 结构 = **首页（叶子）** + **一级分组（可展开）** + **二级功能（叶子）**。一级分组与首页**点击不打开页**，只展开 / 折叠。
- **图标**：一级分组 + 首页 = **矢量图标**（`Shell/App.axaml` 的 `Icon*` `Geometry`，模块注册时 `icon` 传几何键）；**二级功能不显示图标**（只留文字）。
- **样式区分**：一级 = 图标 + **加粗**（SemiBold）；二级 = **缩进 16px** + 常规字重 + `SecondaryTextBrush`。
- **交互**：
  - 一级**默认折叠**；点叶子 → 打开 / 激活标签页 + **确保其父级分组展开**并高亮该二级节点（父级一级同时高亮）。
  - ⛔ **不自动收起其它一级** —— 手动展开的分组保留。
  - **折叠态（48px）**：只保留一级菜单图标（自动隐藏展开箭头、标题与全部二级项）。
  - **折叠态高亮**：折叠时不展开任何一级，但当前页所属一级的**图标显示强调色**（知道"现在在哪个模块"）。
  - **折叠左菜单栏时**自动把全部一级分组收起。
  - 切到**首页**（不属于任何一级分组）→ 不动各级展开态，只清高亮。
- **「设置」组**作为一级节点，展开显示其设置子页；`RegisterModule(..., isBottom:true)` 保留（标记「设置组」语义），由左菜单渲染。
- **持久化**：`config/columnlayout.json`，壳级页 Key `"shell"`：`treeCollapsed` + `treeGroup:<groupKey>`（各一级展开态，**默认 false**、**恢复落盘**）。
- **底部「配置 · 版本」区（v3.28 改）**：左菜单栏**最底部**固定一行显示 **`<当前配置名> · <版本号>`**——版本号取 `UpdateService.CurrentVersion`（编译时自动生成，与「设置 → 关于」**同一个**），配置名取 `IProfileService.ActiveProfile`（多实例时一眼看出本窗口在用哪套数据）；**折叠态隐藏**。

### 4.4 主内容区（中间）

- 单个 `ContentControl`，绑定当前激活标签页的 `Content`。
- **每个标签页持有自己的 View 实例**，切标签**不重建**；**关闭标签时才销毁**（实现 `IDisposable` 则调用）。
- 无激活标签 → 显示空态引导（居中提示），不崩。

### 4.5 详情卡（右侧 340px，可开合）

- **承载内容**：**选中项的具体信息**（参数、前后对比等）**以及该部分的命令**（如剪辑区间 + 将要执行的 ffmpeg 命令行）。
- **契约** `IDetailPanelProvider`（`Shared/Services/`，页面 VM 可选实现）：
  `HasDetailPanel`（该页是否有详情）｜`IsDetailOpen`（当前是否展开）｜`DetailContent`（详情内容）｜`DetailChanged`（通知 Shell 刷新）｜`ToggleDetail()`（页面右上角按钮调）｜`OpenDetail()`（右键首项调）。
- **Shell 职责**：标签切换时检查 `ActiveTab.ViewModel is IDetailPanelProvider` → 是则显示右列 + 订阅 `DetailChanged`（**先解绑旧 Tab 的订阅**，防泄漏）；否则隐藏该列。
- **入口**：**工具条容器的右上角浮层**（v3.53 收口）—— 单个开关按钮（`❯` 收起 / `❮` 展开，常驻不隐藏）→ `ToggleDetail()`；右键首项「▤ 显示详情栏」→ `OpenDetail()`。
  🔴 **浮层三条硬规则（v3.53）**：① ⛔ **不占独立列**（废原 `Grid Columns="*,Auto"` 口径）、⛔ 不参与工具条容器宽度计算；② 是**覆盖层**（`Panel` 同格叠放，`HorizontalAlignment=Right` + `VerticalAlignment=Top`），样式与容器内按钮**同源**（`ghost`）、宽度更窄且**固定**（防开合抖动）；③ **容量计算时必须预留其安全区** —— ⛔ 不许遮住工具条里任何按钮（"不占布局"与"算法避让"两者并存）。
  🔴 **开关由 Shell 统一渲染**（随工具条一起，见 §4.8.5）；页面⛔ 不再各写一份 `detail-toggle` 块。
  ⛔ **表头不再放详情开关**（旧的"贴右缘热区 + 窄边按钮"已废除）：它占掉一整列表头宽度、鼠标不靠近还点不到，且与表头"排序 / 列显隐"两种交互混在一处。
- **宽度与记忆**：宽 **340px**；是否展开落 `config/columnlayout.json`（`FlagDetailPanel`，**按页面 Key 分别记忆**）；隐藏时该列宽度为 0，内容区铺满。
- ⏸ **页面迁移暂缓**：契约与 Shell 消费逻辑**已就位**，各页目前仍用**页内右列**（见 §4.8）；迁移方式见规范 §3.6 / §3.8。

#### 4.5.1 详情卡声明式规范（v3.45；工作项 NT-054）

**定位**：详情卡 = **对主显示区列表数据的补充与修改**。卡片结构由**描述符声明**、**Shell 统一渲染**，⛔ 不再逐页手写卡片 XAML。命令编辑等复杂交互**在卡内实现**，⛔ 不做弹窗卡。

**三区模型（每张卡 = Fields + Actions + Custom）**

| 区 | 承载 | 对应「改什么」 | 机制 |
|---|---|---|---|
| **Fields** | 声明式字段行（分区 / 标题 / 字段 / 分隔线 / 提示） | **属性级增删改**（改显示名、评分、描述、状态回显） | 描述符 → Shell 渲染 |
| **Actions** | 声明式命令按钮（文案 / 命令 / 可用条件 / 可见条件 / 确认框） | **动作级**（应用到磁盘、批量打开、连通性、保存修改） | `ICommand` 绑定 |
| **Custom** | 逃生舱（整卡替换为自定义 View） | 声明式覆盖不了的整卡交互 | 页面自绘，粒度 = **每页一个** |

**字段 Kind（8 种 + 修饰位）**

| Kind | 用途 | 修饰位 |
|---|---|---|
| `Text` | 单行输入 | `Mono`（等宽）/ `Selectable`（只读可复制）/ `Password` |
| `Check` | 勾选框（含分区标题处） | — |
| `Select` | 下拉（简单值 / 对象 + 显示路径 / **索引通道**） | — |
| `Number` | 数值 / 评分（可带取值集合，如 0~5） | — |
| `Chips` | **集合编辑器**（标签：chips + 增 / 删） | — |
| `Hint` | 纯提示文字（含空态；也用于「前缀 + 动态值」的一行说明） | — |
| `Divider` | 分隔线 | — |
| `List` | **只读列表**（键值行 / 对比行：左标签 + 主文本 + 固定符号 + 右侧强调值 + 第二行说明） | — |

- 只读文本一律 `Text` + `Selectable`；多行一律 `Text` + `MultiLine`（数量与宽度不限）。
- `Select` 有两种落值通道：**值**（默认，`ValuePath` + 可选 `OptionValuePath`）与**索引**（`IndexPath` + `LiteralOptions`，
  用于页面 VM 上本来就是「第几个选项」的字段，如编码器 / 码率模式）。
- ⛔ **加新 Kind 是「加法」**：新需求优先用现有 Kind + 修饰位；确实需要新交互时才加一个 Kind（配一个 `DataTemplate`），不影响既有卡。
  ⚠️ **v3.47 补记**：`List` 是**用户拍板新增的第 8 种** —— 详情卡里的「只读列表」用原 7 种表达不了
  （VideoBatch「处理前 → 处理后」、资产卡「关联 / 文件位置」），故补一个 Kind，**而不是**让整卡走 `Custom` 逃生舱。

**提交语义（统一为 3 种）**

| 语义 | 行为 | 典型 |
|---|---|---|
| `Instant` | 双向绑定即落盘 | 勾选框、下拉选完即改 |
| `OnBlur` | 失焦提交 | 改名框、参数框 |
| `Explicit` | 需工具条「💾 保存修改」显式提交 | 批量队列参数 / 命令 |

- ⛔ 现状的 4 种随意实现（失焦即存 / 显式提交 / 即时落盘 / 按钮提交）**统一到本表 3 种**。
- ⛔ **卡内零操作按钮**（既有原则，§6.6）：保存 / 重置这类动作归**工具条**，⛔ 不进 Fields 区；Actions 区只放**与该卡内容强绑定**的卡内动作。

**刷新契约**

1. **属性级**改动 → 靠 `INotifyPropertyChanged` 自动同步主显示区列表（如改评分 → 列表列自动变）。
2. **动作级**改动（应用到磁盘 / 加标签 / 删除）→ **由页面 VM 负责回刷**列表与卡片；描述符**不参与**刷新。

**覆盖基线（当前 16 张卡）**

| 卡 | 关键形态 | 声明式覆盖 |
|---|---|---|
| 媒体资产 · 资产（`AssetDetailView`） | 可编辑显示名（OnBlur）+ 5 只读 + 可复制路径 + 评分 + 多行描述 + **标签 chips** | ✅ |
| 媒体资产 · 存储 / 标签 / 回收站（3 张） | 只读 + 单行编辑 + 命令 | ✅ |

  2. 表头与行模板**完全相同的星号列定义**（逐字一致）；动态列用 `<v:ColumnGrid ColumnSpecs="{Binding VisibleColumnSpecs}">`；左右内边距一致（8px）。
  3. `ContextMenu` 挂在独立弹出树，**不保证继承宿主 DataContext** → 必须在 code-behind `OnDataContextChanged` 里**手工同步**（行菜单 + 表头菜单都要）。
  4. 列显隐元数据 `ListColumn` + 服务 `IColumnLayoutService`（落 `config/columnlayout.json`）。⛔ 列元数据里**不再追加 `Detail` 占位列**——详情开关已移到工具条（§4.5）。

  8. **详情开关 = 工具条容器右上角的浮层**（v3.53 收口，替代原 `Grid ColumnDefinitions="*,Auto"` 独立列口径）：⛔ 不占列、⛔ 不参与宽度计算；浮层样式与容器内按钮同源（`ghost`）、宽度更窄且固定；折叠算法容量预算内**预留其安全区**（⛔ 不遮按钮）。开关本身由 **Shell 统一渲染**，页面⛔ 不自写。
  9. **工具条 vs 右键菜单的职责划分**（v3.29 用户定调）：**工具条只放页面级功能**（扫描 / 导入 / 筛选 / 入库 / 清除列表 / 重载数据 …，作用于整个列表或页面）；
     **针对某一条的动作一律放行右键菜单**（打开 = 播放 / 阅读 / 看图、打开所在文件夹、打开库文件 ……）。
     ⛔ 不要把"打开 / 播放 / 阅读"这类单条动作做成顶部按钮 —— 那是页面级区域，放进去既不对应也不好找。
  10. 🔴 **页面内「重载数据」按钮的命名**（v3.31 用户定调；原「🔄 刷新」全面更名）：凡是"丢掉内存这份、回到来源重新取一遍"的按钮，
      一律写成 **`🔄 <动词><来源>`** —— ⛔ 不再只写「刷新」（光看"刷新"既分不出**从哪取**、也分不出**要等多久**）。动词按数据源三选一：
      - **重扫** = 枚举**磁盘目录**（如「🔄 重扫目录」）；
      - **重读** = 读**数据库 / 配置文件 / 注册表**（如「🔄 重读资产库」「🔄 重读书签」「🔄 重读注册表」）；
      - **重查** = **联网查询**（如「🔄 重新查询」，秒级到十几秒 → 字面上必须与毫秒级的"重读"分开）。
      ⛔ **同一页内若有两个这样的按钮，名称必须不同** —— 如视频列表工具条「🔄 重扫目录」（重扫磁盘目录）、
      媒体资产「🔄 重读资产库」（只重读数据库，⛔ 不扫盘）。
      ⚠️ **标题栏 `⟳` 不属本条** —— 它做的是"销毁并重建标签页"（§4.1），不是重载数据。
- **跨页投递的数据（本页一次只处理一条 / 一批）**：文件、任务等经 `VideoTaskStore` 之类的单例在页面间传递。⛔ **只在 `OnDataContextChanged` 里取是不够的** —— 标签页已存在时切回来只换可视树、`DataContext` 不变，该回调**不再触发**，表现为"送过去的文件要刷新页面才出现"。取件点必须挂在**每次进入页面都会跑**的回调上（`OnAttachedToVisualTree`）。

#### 4.8.1 列宽（v3.21 收口为通用规则；视频两页首发，能力对所有列表页可用）

1. **三态**：星号比例（`ListColumn.Width` 默认，如 `3.2*`）→ 手动像素（拖表头边界）→ 隐藏（`0`，列索引不动）。⛔ **没有「自动调整列宽」开关**（v3.20 删除）。
2. **手调列宽只存会话**（⛔ 不落 `columnlayout.json`）：切标签页不丢、重启还原；列显隐切换不影响已手调宽度。
3. **示例数据行（Sample）+ 固定表头宽列（v3.22 重做）**
   - **每列给一条示例值**（`ListColumn.Sample`，如 `★` / `29.97` / `.mp4` / `1:02:03`）—— 它是一条**"设计时数据 / 水印行"**：
     - 列表**没有真实数据时**显示这条示例行（半透明、明显是占位，⛔ 不可选、不可勾选、**不参与**统计 / 排序 / 筛选 / 导入导出）；
     - 列表**有真实数据后示例行整条消失**。
   - **判据**：把**示例文本宽**与**表头文字宽**比一比 —— 示例 ≤ 表头 → 该列宽**锁成表头宽**（不可拖拽、不参与自动调整）；示例 > 表头 → 不锁（照旧星号、可拖）。⛔ 绝不按真实行逐行测宽（虚拟化只 measure 可见行 → 滚动会让列宽抖动）。
   - 锁定宽度 **不小于最小列宽 34px**（表头文字很短的列也留出空间，让**边界把手始终可显示、可拖**）。
   - **适用范围（v3.32 扩为全列表页）**：**每个列表页的每一列都要填 `Sample`**，详情卡无选中时也显示示例值 —— 汇总规则见 **§4.8.3**。

#### 4.8.2 表头右键「🔎 筛选」的分类项（v3.21）

- **叫法统一**：列表里表示"这一类 / 这一组"的列，列标题与筛选文案**统一叫「类型」**（旧的「分类」「类别」一律改称「类型」，列键 `Category` / `Kind` / `Type` 不变 —— 改键会丢用户列显隐偏好）。
- **有「类型」列的页**，右键「🔎 筛选」子菜单**必须列出该列出现过的值**（点一下即筛该值），位于「＋ 添加筛选列… / 🧹 清空筛选」之后。
- **视频列表**把**类型（扩展名）**列进筛选（每个类型值一项，按"等于"匹配）。
  （v3.32：原「标签」项随标签功能一并移除，见 §6.4.6。）

#### 4.8.3 示例数据（列表行 + 详情卡；v3.32 扩为全列表页）

> **动机**：列表页常在"还没数据 / 还没选中"时显示空白，看不出这一页长什么样、有哪些列 / 哪些字段。示例数据 = **设计时数据（水印）**，让页面在空态下也能看出结构。

1. **每个列表页的每一列都要填示例值**（`ListColumn.Sample`）—— ⛔ 不留空列（留空 = 该列不参与锁宽判定，空态下也看不出来这一列是什么）。
   - 列表**没有真实数据时**显示一条**示例行**（半透明、明显是占位，⛔ 不可选 / 不可勾选 / **不参与**统计 / 排序 / 筛选 / 导入导出）；有真实数据后整条消失（规则同 §4.8.1 第 3 条）。
2. **详情卡在"没有选中项"时默认显示示例数据**（而不是空白或一句空态提示）：
   - 详情卡各字段以**示例值**填充（与列表示例行**同一批数据**，语义一致），让用户一眼看到这一卡的字段构成；
   - 示例态**必须可辨识**：整卡呈**半透明**（或字段值统一灰显）+ 一行「**（示例数据）**」标识；⛔ 不能让示例态看起来像真实可操作的数据；
   - 🔴 **示例态下所有交互 / 编辑控件一律禁用**（文件名字段 / 标签 / 💾 保存 / ↔ 应用到文件 / 打开 …）—— 否则用户会去改、去保存一份假数据（报错或写坏状态）。列表里的单条动作（右键菜单）在示例态同样不适用。
   - 一旦**有选中项**，立刻切回该条的真实数据（示例态消失）；取消选中（清空选择）后可回到示例态（或空态，由页面自定，但**默认回到示例态**）。
3. **实现位置**：示例行 / 示例值能力已在 `ListPageViewModelBase`（`ListColumn.Sample` / `SampleRowTexts` / `HasSampleRow` / `SampleSpecs`）；详情卡示例态的公共部分（"无选中 → 用示例项" 的开关与半透明容器）**收到基类**（`Shared/Models`，⛔ 各页别再各写一套），**逐页**只需给出该页的"示例项"字段值与"哪些控件在示例态禁用"。
   > ⚠️ 本节涉及**框架层**（`Shared/ListPageViewModelBase`）—— 已由用户于 v3.32 明确授权改动（仅限本能力）。
4. **验收判据**：任取一个列表页 —— ① 未扫描 / 未载入时，列表有一条半透明示例行、**每一列都有值**；② 详情卡未选中时显示的是同一批示例值（半透明 + 「（示例数据）」标识），且所有按钮 / 输入框点不动；③ 选中一条真实数据后，列表示例行消失、详情卡切到该条真实值且控件可用；④ 清空选中后回到示例态。
5. **落地分批（v3.32 用户确认）**：本节**目标态 = 全部列表页**，但**分批推进** —— 首批只做 **视频两页（视频列表 / 批量处理）+ 媒体资产「全部资产」** 作样板，其余页按模块排期（明细见 `backlog/NT-028.md`）。

#### 4.8.4 主显示区（工具条 / 筛选条）基本范例（v3.41 收口 · 所有列表页照此）

> **定位**：列表列的「主显示区」= **工具条 → 筛选条 → 列表** 三行。本节是这三行的**基准形态** —— 新列表页**直接照做**，⛔ 不各页自创；样板实现 = 媒体资产「全部资产」页（含 5 个类型薄壳页）。
> **为什么收口**：工具条按钮一多就换行、筛选条一换行列表区就被挤压跳动 —— 主显示区的**高度必须可预期**，这是"成熟感"的底座。

1. **工具条默认最多两行，并按容器宽度自动"能放多少就显示多少"**（v3.42 收口）：
   - 工具条按钮 = 一串**按优先级排序**的序列（越靠前越不会被折），**末尾固定一个「⋯」按钮**；
   - 🔴 **两行内放得下就全部显示**（宽窗口 / 收起详情卡时会自动一路展开，⛔ 不需要手动点）；放不下才把序列**尾部**几项收进「⋯」；
   - 点「⋯」= **全部显示**（不受宽度限制）、再点收起；全部放得下时「⋯」自己消失；
   - 「⋯」按钮**只放图标、⛔ 不带文字**（展开态换成 `▲` 提示"可收起"）；按钮宽度固定 ⇒ 开合不会让工具条重新换行；
   - 🔴 **底线：⛔ 不许出现"窗口一窄就破两行"** —— 容量按**最窄工况**（960 窗口 + 详情卡展开，可用宽推导见《工程规范》§2.1）算，
     宁可少显示一个按钮，⛔ 也不许挤到第三行；
   - ⚠️ XAML 里的**排列顺序 = 优先级顺序**（即折叠顺序的反序）：要改"哪个按钮先被折"，把它在工具条里的位置前后挪即可。
2. **按钮文字取"最短可比达义"**（v3.41 用户定调）：
   - ⛔ **不重述本页上下文**：本页就是资产库 ⇒「🔄 重读」而非「🔄 重读资产库」；本页已有勾选框 ⇒「🗑 移入回收站」而非「🗑 移入回收站（选中）」。
   - 同类动作用**动词区分**，⛔ 不并列两个同名词：`🗄 并入…`（并入外部库）vs `💿 另存为…`（另存本库）。
   - 省略掉的名词 / 前置条件**写进 `ToolTip`**（⛔ 不许省到有歧义）。
3. **「需先勾选」的按钮用提示词表达，⛔ 工具条不放指示文字**（v3.41 用户定调）：
   - 按钮 `ToolTip` 写全「动作 + 前置条件」（如「先在列表里勾选行，再点这里打标签」）；
   - 🔴 这类按钮**禁用时提示词也必须弹得出来** —— 实现要点见《工程规范》§3.6（`ToolTip.ShowOnDisabled`）；不加就是"灰按钮 + 提示词弹不出来"，用户无从知道要先勾选；
   - ⛔ 工具条里**不再放**「未勾选 / 已勾选 N 个」这类指示文字（勾选状态在列表勾选框上一眼可见）。
4. **筛选条恒为一行，⛔ 不许出现滚动条**（v3.41 用户定调）：
   - 筛选项横向排死在**一行**：窗口变窄时**筛选项自己变窄** —— ⛔ 不换行、⛔ 不横向滚动、⛔ 不折叠进二级；
   - **前提是筛选项数量固定**（当前列表页固定 = 类型 / 存储源 / 状态 / 标签 4 项）。将来若要"按表头扩展更多筛选类型"，属**新需求**（须一并定值域来源），需先立项，⛔ 不得用滚动 / 换行方案硬塞；
   - 筛选条**高度恒定** ⇒ 列表区不被挤压跳动。

5. **验收判据**：任取一个列表页 —— ① 默认态工具条 ≤ 2 行；② **把窗口从 1280 拉到最窄 960（详情卡展开），工具条仍 ≤ 2 行**、且被折的按钮数随宽度自动变化；③ **把窗口拉宽 / 收起详情卡，原被折的按钮要自动回到工具条上（一路展开到「⋯」自己消失）**；④ 点「⋯」能全部显示 / 收起；⑤ 窗口从 1280 拉到 960 时筛选条始终一行、无滚动条、无换行；⑥ 未勾选时悬停"需先勾选"的按钮能弹出提示词。

#### 4.8.5 工具条由 Shell 统一承载（v3.53 用户立项；工作项 NT-055）

> **定位**：列表页工具条（§4.8.4）的**实现只存在一份** —— 由 Shell 的 `ToolbarHost` 统一渲染，页面⛔ 不再自写 `Border.toolbar` XAML。
> **同套路三连**：§4.6 状态栏（`IStatusProvider`）→ §4.5.1 详情卡（`IDetailCardSource` + `DetailCardHost`）→ 本节工具条。**页面给数据，Shell 给实现。**
> **为什么**：20 个页面各写一份工具条 XAML（≈600~700 行）、16 个页面各手写 12 行详情开关块、折叠逻辑只在「全部资产」页有一份。改一处要动 20 处，且新页面靠"照抄旧页面"必然漂移。

1. **契约** `IToolbarSource`（`Shared/Services/`，页面 VM **可选**实现）：
   `Toolbar`（`IReadOnlyList<ToolbarItemDescriptor>`；**空 / null = 本页无工具条** ⇒ Shell ⛔ 不渲染、⛔ 不留空行）｜`ToolbarChanged`（工具条构成变化时通知 Shell 重建）。
2. **描述符** `ToolbarItemDescriptor`（`Shared/`，**纯数据、⛔ 不引 Avalonia**，命令用 BCL `ICommand`）：
   - 支持 **4 类项**：`Button` / `SplitButton`（主按钮语义 + 菜单项集合）/ `Toggle`（勾选框）/ `TextField`（输入框，可配"回车即执行"的命令）；
   - 每项含 `Text` / `Command` / `IsEnabled` / `ToolTip` / `ShowToolTipOnDisabled` / `Priority`（**= XAML 顺序 = 折叠顺序的反序**，越靠前越不易被折）；
   - ⛔ **加新项类型是"加法"**：优先用现有 4 类 + 修饰位表达；确实表达不了的页面**本页暂不迁移**（保持页内自绘），⛔ 不为了统一而强行改造页面。
3. **Shell 职责**：渲染工具条行 + **自动折叠算法**（口径 = §4.8.4 第 1 条：两行放得下就全显示、放不下才折尾部，末尾固定「⋯」）+ **浮动详情开关**（§4.5）；切标签时探测当前页 VM 是否实现契约并重建（复用 `IStatusProvider` / `IDetailCardSource` 的同一探测点）。
4. **迁移是逐页 opt-in**：未实现契约的页面继续用页内自绘工具条；🔴 **同一页⛔ 不得 Shell 与页面各渲染一份**（探测到契约就不渲染页内、未探测到才由页面自绘）。
5. **验收判据**：任取一个已迁移页 —— ① 页内已无 `Border.toolbar`、无 `detail-toggle` 块；② 工具条行为与迁移前**逐项一致**（文案 / 顺序 / 启停条件 / 悬停提示 / 禁用时提示 / 回车命令 / SplitButton 主按钮语义）；③ 把窗口从 1280 拉到最窄 960（详情卡展开）工具条仍 ≤ 2 行，被折按钮随宽度自动变化，拉宽后自动展开回位；④ ↕ 工具条行在**未迁移页**上高度为 0（无空白）。

### 4.9 设置页

- 即时生效（⛔ 禁保存按钮）vs 显式保存（多字段表单）的判据不变；每页 ≥1 行 `StatusText`。
- 设置页作为**标签页**打开（不再是「二级菜单 → 页面」路径）。
- 🔴 **模块专属设置归模块**（v3.40，NT-050；媒体资产 NT-021 先例）：只服务某个模块的设置页，**View/VM 代码放在该模块内**，由模块 `Initialize` 自注册进 `settings` 分组（`menu.RegisterFunction("settings", "settings-模块键", "<模块名>设置", …, 100+)`）；数据文件仍落模块自己的 config。设置模块只保留**应用级**设置。菜单 Key 一经发布⛔不改（首页跳转 / 收藏白名单按 Key 寻址）。
- **同主题可合并单页**（v3.40，NT-051）：设置项按主题密度可多节合并到一页（节标题 + 卡片），⛔ 不硬拆一页一项；合并后只保留**主 Key**（原 Key 从菜单移除）。
- 🔴 **窄界面适配基线**（v3.40，NT-053）：设置页必须在**最窄 960×640**（左树展开、设置页无详情卡 ⇒ 内容宽 **720**）与**默认 1280×800** 两种下可用——根容器 `ScrollViewer`（纵向自适应）、列布局用星号/比例、⛔ 不给内容层写超过 720 累计的固定宽容器；至少适配其中一种即达标，目标两种全适配。

#### 4.9.1 设置总表（v3.53 用户立项；工作项 NT-056）

**定位**：把「路径配置」与「配置」两张表**合成一张** —— 不是把两种数据揉在一列，而是**同一张表承载不同分类的行**，用**分类列**区分行类型、并据此决定"哪些工具可用"。

1. **列的基准形态**（统一表头）：**分类 ｜ 名称 ｜ 当前值 ｜ 类型 ｜ 说明 ｜ 操作**。
   - `分类`：**行类型判别列**，取值 `路径` / `配置`；🔴 **可排序、可筛选**（走 §4.8.2 的列基建）—— 这是把两表合并后"还看得清"的关键。
   - `名称`：路径项键名 / 配置名（⚠️ 两义，故**必须有分类列**兜住）。
   - `当前值`：路径 = 可编辑值（`OnBlur`）；配置 = 数据目录（只读展示）。
   - `操作`：**按分类分派** —— 路径 = 📂 浏览 / ↗ 打开位置；配置 = ⇄ 切换 / 🚀 新开 / ⭐ 设为默认 / ✏ 重命名 / 🗑 删除 / ♻ 重置。
2. **工具可用性由选中行的分类决定**：与分类强绑定的工具（`⇄ 切换` / `🚀 新开` / `⭐ 设为默认` / `♻ 重置` / `📂 浏览` …）在选中另一分类的行时**不可用**（置灰 + 提示词说明"该操作只对 <分类> 行可用"）；与分类无关的（📂 打开配置目录 / 💾 保存 / ＋ 新建）始终可用。
3. **详情卡按分类切换字段集**：选中行的分类变化时，Shell 侧详情卡**整体重建**（`DetailCardHost` 已支持 `Card` 变化即 `Rebuild()`）—— 页面 VM 须在分类变化时**通知 `Card` 属性变化**（⛔ 不得沿用"缓存一次"的静态卡写法）。
4. **可扩展性（本节的根本理由）**：分类是**开放集合** —— 后续若要"**指定某个功能默认使用哪个 json / 配置**"，只加一个分类值（如 `功能绑定`）+ 该分类的行与工具，⛔ **不再新开页面**。
5. **页面归属**：合并后只保留 **`settings-path`**（标题改「**路径与配置**」，Key ⛔ 不改——首页跳转 / 收藏白名单按 Key 寻址），删除 **`settings-profile`** 菜单项（§5.1 菜单 Key 一经发布⛔不改，此处是**移除整项**，不涉及改 Key）。
6. **验收判据**：① 左树「设置」组少一项、只剩「路径与配置」；② 该页一张表里同时能列出路径行与配置行，按分类排序 / 筛选可用；③ 选中配置行时，路径专属工具置灰且提示词说明原因；④ 选中不同分类的行，右侧详情卡字段集随之切换（不需要手动刷新）；⑤ 配置侧原有 7 个动作全部可用且语义不变（切换仍二次确认 + 本窗重启）。

### 4.10 视觉规范（硬约束）

> 「成熟感」不是布局给的，是视觉密度 + 图标质量给的。

#### 4.10.1 图标

- **矢量图标**：Avalonia `Geometry`，统一定义在 `Shell/App.axaml` 的 `Resources`，键名 `Icon*`（已定义 `IconHome` / `IconPc` / `IconWeb` / `IconVideo` / `IconSettings`）。
- 这些是**描边型**路径（24×24 网格）→ 用 `<Path Data=… Stroke=… StrokeThickness="1.5" Stretch="Uniform"/>`，**不是**填充型 `PathIcon`。
- ⛔ **禁引入第三方图标字体 / 包**；⛔ 不写死图标颜色（随主题）。
- 尺寸基线：左菜单一级 / 首页 **16px**、标题栏工具按钮 **18px**、标签关闭按钮 **10px**。
- **框架层已全矢量化**（NT-045/046）：标题栏 / 标签 / 左树 / 窗口按钮一律 `<Path>` + 本文件 `Icon*` 键，⛔ 图标字体 / 字符 / emoji / `Rectangle`·`Border` 拼几何。
- **数据驱动图标**（二级功能菜单 `RegisterFunction(icon)` / 首页一键按钮 / 模块页内数据行）**目标同为矢量 `Geometry`**，当前仍为 emoji 字符串（技术债，见《工程规范》§7；收敛工作项 **NT-047**）。
  ⛔ **键名不存在就地没图标，不做 emoji 回退** —— 避免两套渲染长期并存。

#### 4.10.2 密度基线

| 区域 | 尺寸 |
|---|---|
| 标题栏高 | 40px（含标签页；底色 = 主题背景） |
| 标签页标题字号 | 13px |
| 标签项内边距 | 水平 8px / 垂直 3px（无图标） |
| 左菜单栏宽度 | 180px（折叠 48px） |
| 树行高（一级 / 叶子） | 30px |
| 树节点缩进 | 每级 16px |
| 内容区外边距 | `12` |
| 工具条 `Border.toolbar` 内边距 | `12,6` |
| 筛选条 `Border.filter-bar` 内边距 | `12,4` |
| 卡片 `Border.card` | 圆角 8px、内边距 12px |
| 按钮圆角 | 6px |
| 按钮 `primary` / `ghost` 内边距 | `12,6` / `10,5` |

| 状态栏高 | 26px |

- **原则：能紧则紧** —— 桌面工具的"密度感"来自"同样的信息用更少的空白"。

#### 4.10.3 字号层级

| 用途 | 字号 | 字重 |
|---|---|---|
| 页面标题（内容区顶部） | 15px | SemiBold |
| 正文 / 表单标签 | 13px | Regular |
| 表头 / 次要信息 / StatusText | 12px | Regular |
| 标签页标题 / 树节点文字 | 13px | Regular |

⛔ 不引入超过 3 档字号（避免层级混乱）；字体沿用 Avalonia 默认系统字体，⛔ 不引外部字体。

#### 4.10.4 视觉一致性

- **圆角**：卡片 8 / 按钮 6 / 输入框 4；⛔ **标题栏域一律**`CornerRadius=0`（标签项、窗口按钮、标题栏容器）—— v3.22：容器不要圆角，最大化利用空间。
- **间距**：用 4 的倍数（4/8/12/16），⛔ 不用奇数；**默认取小值**（相邻控件间距 4~8，容器内边距 12）。
- **横向流式容器的换行间距**（v3.29，用户定调"后续所有类似的容器都这样做"）：工具条 / 筛选条等用 `WrapPanel` 装按钮 / 输入框的容器，**必须**设 `ItemSpacing`（元素间水平距，8）+ `LineSpacing`（换行后行与行的上下距，4）—— ⛔ 别让换行后的第二行贴死第一行（按钮一多就换行，必踩）。有了 `ItemSpacing` 就**别再给每个元素写右 Margin**（两套间距会叠加）。
- **例外：列表页筛选条不再是 `WrapPanel`**（v3.41，见 §4.8.4 第 4 条）：筛选条改成**恒一行容器**（等分星号 `Grid` + `Grid.ColumnSpacing`）⇒ 上一条不适用，⛔ 不要给它套 `WrapPanel`（换行）或 `ScrollViewer`（滚动条）。
- **分割线**：`DividerBrush` 1px。**选中态**：统一用 `active` class，⛔ 不用本地值写 `Background`。
- **主题强调色（激活态）加深**：菜单栏 / 标签页**激活项**的强调色当前太淡 → 提高对比（仍用 `AccentPalette` 单一强调源，⛔ 写死色值）。
- **按钮样式 / 颜色全局统一**：所有按钮统一用共享样式（`Button.primary` / `Button.ghost` / `Button.row-btn` 等），⛔ 页面自造配色；颜色一律 DynamicResource 主题键。
- **工具条内元素顺序**（v3.29 用户定调）：**动作按钮在前、输入框紧随其后**（与扫描相关的路径框紧跟扫描按钮），两个输入框（路径 / 搜索）**挨在一起**，其余按钮依次排列 —— ⛔ 别把输入框散落在按钮中间。搜索框与"路径输入框"归为一类，永不分开。
- **列表页导入导出控件一致**：有导入导出需求的列表页（快捷设置 / 设置与脚本 / 视频列表 / 软件包已装导出）使用**同一套控件 + 同一布局 + 同一样式**。
- **输入框水印**：所有输入框用 `PlaceholderText` 显示提示（水印）；初次启动**不显示具体文件路径**等具体值，且删掉输入框前多余的静态提示文字（水印已覆盖）。
- **弹层样式统一**：文本框右键菜单（paste / copy / cut）与确认对话框，使用当前主题配色（`*Brush` 语义键），符合整体 UI。

## 五、导航模型（硬约束）

### 5.1 核心概念

- 一个**标签页** = 一个打开的功能页面 = **缓存的 View 实例** + 一份 VM + 一个历史栈。
- 打开页面的**唯一入口** = 标签页；菜单点击、`+` 等都是「打开 / 激活某个 Key 的标签页」。

### 5.2 标签页模型

`TabItemViewModel`：`Key`（菜单 key）｜`Title`｜`IconKey`｜`Content`（缓存的 View）｜`ViewModel`（供 Shell 检测契约）｜`CanClose`（首页 = false）｜`BackStack` / `ForwardStack` / `CanGoBack` / `CanGoForward`。

`ShellViewModel`：`Tabs` / `ActiveTab` + `OpenTab(key)` / `CloseTab(t)` / `GoBack()` / `GoForward()` / `Refresh()` / `ToggleTree()` / `ToggleDetail()`。

### 5.3 历史栈

- **每个标签页独立维护**，栈元素是「页面内的导航状态快照」。
- **可进**：目录切换、执行搜索、从列表进入子详情。**不进**：列表内选中不同条目（选中态）、筛选 / 排序变化（视图状态）。
- **契约** `IHistoryProvider`：`CaptureState()`（返回 null = 不记录）｜`RestoreState(state)`｜`StatePushed`（通知 Shell push）。
- 页面通过 `StatePushed` 通知 Shell push `CaptureState()`；前进 / 后退时 Shell 调 `RestoreState`；**未实现该契约的页面** → 前进 / 后退灰显。

### 5.4 启动时序

`ShellViewModel` 构造函数末尾调 `OpenTab("home")`（首页作为首个固定标签页）；其余启动时序（DI → 模块加载 → 主题 → Show）不变。

### 5.5 防闪退铁律

1. `OpenTab` 找不到 key **不得抛异常** → 忽略并记日志。
2. `ActiveTab.Content` 为 null → 内容区显示空态，不崩。
3. 关闭最后一个标签页 → **自动打开首页**（保证始终有激活标签）。
4. 关闭首页标签 → **拒绝**（`CanClose=false`）。
5. View + VM 缓存，关闭标签时销毁（`IDisposable` 若实现则调用）。

#### 6.4.1 两页详情卡（同一套规格）

> **原则：这两个页面的详情卡是同一个东西** —— 都是"把一条任务翻译成一条 ffmpeg 命令"。「视频预览」页只是**额外**能在左边看画面、拖着时间条定区间。因此两页详情卡的**分区顺序、折叠方式、命令区形态必须一致**，改一处就要同步另一处。

**统一规格**

1. **分区顺序 = ffmpeg 命令的书写顺序**：`输入 / 区间` → `编码与画质` → `输出` → `命令`。
   ⛔ **「任务类型」勾选不单独占一块放最上面** —— 它由下面两个分区自己表达（勾了哪个就执行哪段），单独列出来既重复又占地方。
2. **两个分区各自可折叠**，标题行左侧是一个**勾选框**（该段是否参与命令）+ 右侧折叠箭头；**取消勾选即自动折叠**，折叠只影响界面、**是否执行由勾选决定**。
   ⛔ **两页的勾选框都可交互**（不是只读装饰）：批量页的勾选框 = 该任务是否含这一段，**勾 / 取消即切换任务类型**（见第 5 条）。
3. **详情卡里只有"参数 + 命令"，不放任何操作按钮**（跑 / 保存 / 删除 / 打开目录 / 复制…）—— 它们属于**命令之外的动作**，一律排到列表上方的工具条里。⛔ 详情卡顶部不放按钮条。
4. **命令区**固定在最后：`SelectableTextBlock` 显示完整命令行 + 可编辑的参数框 + `↺ 重置为自动` + `📋 复制命令`；手改后参数变化**不再覆盖**手改值，执行以手改为准。
5. **两页的差异只有两处**：
   - 「视频预览」页的区间由左边的时间条驱动；「批量处理」页的区间在详情卡里填（该页没有预览画面）。
   - **勾选框的初值来源不同**：预览页由用户现勾（剪辑 / 转码可同时勾 = 一条命令干两件事）；批量页由**选中任务的类型**给出初值（`CutTask` = 只勾剪辑、`TranscodeTask` = 只勾转码、混合任务 = 两段都勾）。
     **批量页勾选框可交互**：勾上一段 / 取消一段 → 任务在「剪辑 / 转码 / 剪辑+转码」之间转换（两段都取消 = 回到「仅转码」并提示，⛔ 不允许出现"两段都不参与"的空任务）。
6. **详情卡布局一致性（本次收紧）**：宽度恒定 340（共享样式 `Border.detail-card` 锁定，⛔ 不动）；**折叠任意分区只影响该分区高、不影响整卡宽度**；所有「标签 + 输入 / 下拉」控件的**左对齐、宽度一致**（输入与 `ComboBox` 同宽、同 `HorizontalAlignment=Stretch`）；`ComboBox` 展开**不挤出 / 不遮挡**其它控件（本页 XAML 约束宽度，⛔ 依赖覆盖层自行处理）。两页 XAML 同一段结构照抄，改一处同步另一处。

> ⚠️ **用户再次强调**：预览页与批量页详情卡必须**完全一致**（同为 ffmpeg 命令可视化编辑器）。改动任一边前须比对另一页 XAML 确认无漂移，禁止两边各写一套。

**"完全一致"验收清单**（改任一边后逐条比对）

| # | 项 | 判据 |
|---|---|---|
| 1 | 分区顺序 | 剪辑 → 转码 → 输出 → 命令，两页一致 |
| 2 | 分区标题行 | 都是「勾选框 + `✂ 剪辑（截区间）` / `🔁 转码（换编码 / 格式）`」，勾选框都**可交互** |

  - 把手与拖动逻辑在 `ColumnGrid`（`IsResizable` 开启时自动生成，默认关闭）；拖动经 `ColumnResize` 事件 → VM `ResizeColumns` 写「手动列宽」→ `VisibleColumnSpecs` 输出像素宽 → 表头与所有行**同规格重建**（列索引永不错位，沿用规格串机制）。
  - 手调宽度**只存本次会话**（⛔ 不落 `columnlayout.json`）：切标签页不丢、重启还原；列显隐切换不影响已手调宽度。

### 6.6 媒体资产（`Module.MediaAssets`）

**定位**：把本地视频 / 音乐 / 文档 / 书籍 / 图片等文件索引进 SQLite，并在库里完成标签、分类、集合、关联、重命名 / 移动 / 复制 / 删除管理的**通用文件资产库**（视频只是其中一类）。

- 与**首页·收藏夹**不同：首页收藏 = 常用功能按钮；本模块的"常用文件"语义由**集合**承担。

**核心流程**（细节见 `backlog/NT-015~022.md`）：

- **扫描**（异步任务，**直接入库**）：忽略规则 → 遍历（**默认含子目录**，可关）→ 依次按 `storage+relative_path` / `size+mtime` / `quick_hash+size` 匹配（前两级**零 IO**；第三级只在"库里同 size 的位置已带 quick_hash"时才读前 N MB）→ 建 / 更新 `assets`+`file_locations`（批量事务）→ 提取元数据 + 生成缩略图 → 本次未出现的旧 location 标 `missing`（⛔ 不删 Asset）。🔴 新文件 ⛔ **不立即算完整内容哈希**（那会把每个文件整读一遍，实测几分钟扫不完一个目录 + 硬盘狂响）；完整哈希归 NT-021 的「补全哈希」任务。
- **预览扫描**（v3.29，**用户操作主路径**；🔴 ⛔ **一个字节都不写库**）：选一个文件夹（或几个文件）→ 只遍历 + 建**内存行**（⛔ 不建 assets / file_locations、⛔ 不算任何哈希）→ 列表进入**草稿态** → 用户二选一：
  - 入口 = 工具条首条 **SplitButton「📁 扫描」**（v3.30 用户定调）：主按钮直接点 = 选文件夹；右侧箭头下拉 = 「📁 文件夹…」/「📄 文件…」—— 样式对齐视频列表的「📂 导入」（`SplitButton.ghost`）。⛔ 不再摆两个独立按钮。手输路径另有工具条输入框，框内**回车**即预览扫描。
  - **💾 加入库**（`AssetService.CommitRows`）：按所在目录分组、各自登记 / 复用存储源（`root_path` 去重），**一个事务**批量落库；⛔ 只建索引、绝不动磁盘文件。
  - **🧹 清除列表**：丢弃内存结果、回到库视图，换文件夹重新扫描。
  - ⛔ 草稿态之外「加入库 / 清除列表」**一律置灰**（不做"能点却没反应"的按钮）。
- **批量登记 + 扫描全部**：「➕ 登记文件夹」把目录加进**待扫列表**（⛔ 登记时不扫描），可连续登记多个；「🔄 扫描全部」= `ScanAsync(null)`，一次把所有在线存储源扫完并**直接入库**。
- **工具条组成（页面级，§4.8 硬规则 9；v3.29 / v3.30 定型）**：`📁 扫描`（SplitButton：主钮 = 选文件夹 / 下拉 = 「📁 文件夹…」·「📄 文件…」）→ 路径输入框（回车即预览扫描）→ 搜索框 → `➕ 登记文件夹` → `🔄 扫描全部` → `🗄 打开库文件` → `💾 加入库` → `🧹 清除列表` → `☑ 含子目录` → `🏷 加标签` → `🗂 加集合` → `💾 存为智能集合` → `🔄 重读资产库`（**只重读数据库**，⛔ 不扫盘；命名见 §4.8 硬规则 10）→ 末位详情开关。⛔ 单条动作（📂 打开 / 📁 打开所在文件夹）一律归列表右键菜单。
- **多库融合**（NT-026）：`🗄 并入库文件…` = 选一个外部 `newtoys.db` **合并进主库**（主库即工作副本；`ATTACH` 只读挂载源库、⛔ 不改源文件；storages 按 root_path 去重、assets 一律新建、file_locations 按 storage+relative_path / hash+size 去重、标签分类集合按名字去重；一个事务，重复并入第二次基本全跳过）；`💾 保存` = 把当前库**另存为**新 .db（VACUUM INTO 一致快照；目标已存在 → 确认后覆盖）；"**减**" = 勾选行后「🗑 移入回收站（选中）」（软删除可恢复，⛔ 不做"按来源库拆出去"）。细节见 `backlog/NT-026.md`。
- **逻辑操作**（直接改库 + 写 `operation_logs`，reversible=1）：显示名 / 标签 / 分类 / 集合 / 关联 / 软删除 / 恢复 / 评分描述。
- **物理操作**（⛔ 先写 `operation_logs`(pending) 再动磁盘；成功改 success、失败改 failed 并留 `before_json`）：重命名 / 移动 / 复制 / 删除；默认送**系统回收站**（`SHFileOperationW`，视频工具先例）且**二次确认**；防穿越 + 冲突检查；⛔ 失败不自动回滚磁盘，下次扫描按 hash/inode 校准。
- **外部变更**：文件不见 → `missing`；新路径 → hash 匹配视为移动；⛔ 移动硬盘离线（Storage `online=0`）时**不动**其下 file_locations，重新上线再扫描校准。
- **跨页投递**：模块内单例 Store（仿 `VideoTaskStore`）；🔴 取件点在 `OnAttachedToVisualTree`（§4.8 硬规则 8）。

**复用硬约束**（不在此复述，指向权威）：列表页一律继承 `ListPageViewModelBase`（`Shared/Models`）+ 三列布局 + 工具条 / 筛选条收进列表列 + 详情开关在工具条末位；`Views/ColumnGrid.cs` 本模块自建**第五份**副本（规范 §3.6，改动同步五处）；详情卡内容由 VM 实现 `IDetailPanelProvider.DetailContent` 提供（目标形态，规范 §3.8 / B13），详情卡内允许**编辑 + 「💾 保存」+「↗ 应用到文件」**（v3.29 用户定调，覆盖旧"零操作按钮"规则；⛔ 别放无关的全局动作）；状态栏由基类统一实现、每页 ≥1 行 `StatusText`；单元格内边距 8 / 表头 32 / 行 28（§4.10.2）。

## 七、设计原则（六条）

1. **模块化** — 按模块拆分，可独立开发 / 启停。
2. **插件化** — 模块编译为独立 DLL，运行时装配，加模块不改宿主。
3. **轻量务实** — 工具类应用，重效率稳定，UI 不炫技。
4. **自控** — 不引入任何第三方 UI 库 / 图标包，全局控件自己写。
5. **命令行封装** — 功能以「包既有命令行 / 系统能力」为主，不超命令行上限；配置一律落文件、可备份。
6. **可热加载** — DLL 放入 `<程序目录>\Modules\`，运行中点「刷新」即时装配，不必重启；加载源仅限本地文件夹。
