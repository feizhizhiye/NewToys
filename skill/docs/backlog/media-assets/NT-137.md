## 一、背景 / 目标

用户 2026-11-03 提问（原话「分类管理和集合管理能否像标签管理一样，采用相同的布局，为视频、音乐等生成一些常用标签；另外考虑一下如何实现从媒体资产模块导出播放列表到查看器的音频播放里面，是否需要扩充音频播放器，或者改名为音乐播放器；如果要联网修改音乐文件的属性，应该放在音乐播放器还是资产模块里，如何提供歌词显示，如何实现歌词简单翻译等，不做桌面歌词」）。

用户拍板：全部按推荐方案执行，**合并成 1 张卡，一次 build**。

1. 分类 / 集合从「左树 / 左列表 + 右成员表」改成与标签页**同构的列表页**。
2. 预置一批常用标签（视频 / 音乐 / 图片 / 文档 / 通用）。
3. 资产库能把选中的音乐**直接送进播放器**，也能**导出 .m3u8**；播放器改名为「音乐播放」并补 m3u 导入 / 播放列表记忆。
4. 音乐文件属性（ID3 / FLAC / MP4）编辑 + 联网补全归**资产模块**（播放器只读）。
5. 歌词支持**双语**（文件内双行 + 外置译文文件），⛔ 不做桌面歌词。

## 四、技术要点

- 🔴 **框架层改动（已获用户批准）**：`Shared/Services/IModuleBus.cs` 加 `ModuleTopics.AudioPlay`；`NewToys.UI/Viewers/AudioPlayer` 加 `TranslationLoader` / `CurrentIndex` / 双语 `SetLyrics`。⛔ 未动 Core / Shell，⛔ 未改任何菜单 Key。
- 分类列表的 DFS 序号是**默认排序键**，用户点表头后让位给列排序；`Depth` 只影响缩进、不影响排序。
- `AudioPlay` 与 `ViewerTopics.OpenFiles` 是两条独立通道（载荷类型不同：路径数组 vs `ViewerOpenRequest`）。
- `TranslationLoader` 用委托而不是接口：UI 库不引模块服务，分层不倒挂。
- MusicBrainz 必须带 UA、单次 GET、超时 15s；联网结果只进编辑框，写盘是独立动作（用户可先改再存）。
