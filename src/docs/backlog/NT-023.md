## 背景 / 目标
用户新需求（2026-10-13，v3.25）：
① 每个模块的设置 View/VM 写进**本模块**，软件加载后**自注册进 `settings` 二级菜单**；
② 框架相关设置全归 `Module.Settings`，且 **Settings 升为必备模块**（如 Shared/Core 一样的"必须在"）；
③ **一个功能模块都不加载时，框架本身（首页 + 一键启动）照常可用**；
④ 模块所需一切在自身 DLL，只在加载时往界面注册。

前置诊断（2026-10-13 代码核对）：跨组 `RegisterFunction` 在分组未注册时抛 `InvalidOperationException`，且被 `ModuleLoader.InitializeAll` 的逐模块 try-catch **吞掉** → Release 目录扫描（`Directory.EnumerateFiles` 顺序不保证）下菜单项**静默丢失**。本项 = 框架层改造；**改框架层已获用户明确同意**（即本需求本身），交付里独立说明。

## 验收标准（可验证清单）
- [ ] `MenuService.RegisterFunction` 分组未注册 → **暂存不抛异常**；`RegisterModule` 建立该分组时**补登**（按 Order 重排，同 Order 保持暂存序）
- [ ] Debug / Release 两种加载轨下，模块自注册进 `settings` 组都生效（构造场景：某模块 `Initialize` 先于 `Module.Settings` 跑）
- [ ] `InitializeAll` 完成后健全性检查：`settings` 分组缺失 → 日志 + Shell 状态栏一行警告，**启动不中断**
- [ ] 删光 `Modules\` 里的功能模块 DLL（仅留 `Module.Settings`）→ 首页 / 一键启动 / 收藏 / 主题 / 设置全部可用
- [ ] 再删 `Module.Settings.dll` → **仍能启动**：首页 + 一键启动可用，仅设置不可用 + 有提示；其他模块的设置页不显示（暂存项无分组可补，⛔ 不崩）
- [ ] 现有 10 个框架设置页（`settings-general` ~ `settings-all`）注册行为不变（回归）
- [ ] 功能清单页 / 首页收藏卡能正确列出模块自注册的设置页

## 技术要点 / 约束（规范章节、坑点、关键文件）
- `MenuService`：加暂存表；`RegisterFunction` 分组缺失 → 入暂存；`RegisterModule` 建组后补登（去重 + 按 Order 重排；⛔ 不改变已有项的更新语义）
- 🔴 暂存项在分组**始终未建立**时不显示——已知降级行为，由健全性检查报一行兜底（⛔ 不静默、⛔ 不弹错误窗阻断启动）
- `ModuleLoader.InitializeAll` 完成后解析 `IMenuService` 查 `FindGroup("settings")`；提示落点执行时定（状态栏一行优先，⛔ 不阻断）
- **必备 = 构建保证 + 运行时降级**：随 slnx 必然构建、Debug 显式清单与 Release `Modules\` 必含；⛔ **不把 `Module.Settings` 改成 Shell 直接引用**（那会破坏 `Modules\` 布局铁律与模块可替换性）——若用户要"物理必备"再议
- 框架自给现状（已核对）：首页 + 一键启动依赖 = `IMenuService` / `LaunchRunner` / `ILaunchConfigService` / `IFavoritesService`，全在 Shared/Core；新增框架功能时保持此性质
- 顺序无关性：补登机制使加载顺序不再影响菜单正确性（Debug 显式清单 / Release 目录扫描 / 热加载三条路径都覆盖）
