## 一、背景（用户 2026-10-19 指令）

1. 「脚本集合列表里增加软件包分类」——**不是**回到 v3.79 之前「用集合冒充 winget 查询结果」；
   按用户口径：**这是预设**，为以后跨平台切换包管理器（apt / flatpak / snap）做架构性兼容，
   甚至进一步把集合成员命令绑成页面按钮。
2. 「集合右键增加发送到对应页面显示的功能」——按集合类别自动跳对应页并选中该集合。
3. 「命令库增加 winget 源操作相关命令，预设中科大源切换命令」——**已具备**（NT-080 R6：设置 → 软件源 →
   `＋ 加入命令库`，6 条命令含「切到中科大镜像」），本次不改。

## 二、设计口径

| 项 | 结论 |
|---|---|
| `kind=package` 的语义 | **包清单容器**：成员是 `role=package` 条目，`Target` = 包 Id。实时查询仍走 `winget search`；手工清单走集合 |
| 候选池 | `role=package` 条目 ↔ 「软件包」类集合是**一对一**关系：包条目只在软件包集合出现，⛔ 不混进其他集合（反之亦然） |
| 「发送到对应页面」 | `ScriptCollectionKind.PageKey(kind)` → `script-info` / `script-library` / `script-commands` / `script-packages`；写 `lastCollectionIdByKind.<kind>` 后 `NavigateTo` |
| 软件包页怎么"显示" | 工具条 `集合 ▾`：第一项「（不按集合）」，其余 = 未归档软件包集合；选中 ⇒ 列表 = 集合成员，状态按一次 `winget list` 缓存比对（⛔ 不逐包 `winget show`） |
| 清单怎么建立 | 软件包页行右键 `📥 加入集合`：写 `role=package` 条目（`Title`=显示名 / `Target`=Id / `Category`=源），按 Id 幂等；没选集合 ⇒ 第一个软件包集合，没有就建「我的软件包」 |
| 后端边界 | 未改：本期仍只有 winget 后端；集合只是"清单表达层"，不是"后端切换开关" |

## 四、验收标准

1. 集合页左栏类型筛选 + 详情卡「类别」下拉都有「软件包」；老数据 `kind=package` 的集合正常显示为「软件包」（不再被归成信息面板）。
2. 集合页选中一个「软件包」集合 → 右栏候选池只列 `role=package` 条目；选中其他类别集合时包条目完全不出现。
3. 工具条 / 左栏右键「📤 发送到对应页面」：
   - 信息面板集合 → `script-info` 并选中它；脚本库集合 → `script-library` 的 `库 ▾` 选中它；命令库同理；
   - 软件包集合 → `script-packages` 的 `集合 ▾` 选中它（第一次进入也生效）。
   - **追加微调**：左栏右键菜单项显示为「📤 发送到信息面板 / 脚本库 / 命令库 / 软件包」之一，随选中集合的类别实时变（未选中集合时落「信息面板」）。
4. 软件包页：`📋 已安装` → 右键任一行 `📥 加入集合` ⇒ 状态栏提示已加入；
   `集合 ▾` 自动出现「我的软件包」（或首个已有软件包集合）并切换过去，列表只剩这批包且「已安装 / 可升级」状态正确。
5. 重复「📥 加入集合」同一个包 ⇒ 提示已在集合里，不重复写条目。
6. 关掉软件包页再进（或重启）⇒ `集合 ▾` 停在上次的软件包集合；`config\script\script.json` 的 `lastCollectionIdByKind.package` 有值。
7. 静态检查 0 阻断（`accept.ps1 -SkipBuild` 已过）。

## 五、假设与遗留

- 「命令绑定对应按钮」（集合成员命令 ✕ 页面按钮）**未做**：本次只落"清单 + 显示"，属于用户所说"进一步"。
- 清单状态只来自 `winget list` 缓存：未安装的包显示不出"可安装版本"（需 `winget show`）；按成本取舍先不做。
- 一个包条目只归属一个软件包集合时最自然；当前数据结构允许多归属，未强制。
- 跨后端（apt / flatpak）仍未立项：届时「软件包」集合按后端再分（`Category` 已留出源/后端位）。
