## 背景 / 目标
视频列表选中文件夹即扫描，独立「扫描」按钮冗余；数千视频会卡 UI；同文件入库重复；「清空媒体缓存」语义与「清除列表」混淆且用途有限。需清理 + 优化。

## 验收标准（可验证清单）
- [ ] 删「🔍 扫描」按钮；选中文件夹（或目录框回车）即触发扫描
- [ ] 数千视频：列表虚拟化 + 扫描分批入列，不卡 UI；仍卡则分页 / 增量绑定（只绑可见窗）；DB 按 path 索引
- [ ] 入库去重：以**全路径（大小写不敏感）为主键 UPSERT**；可选内容哈希（前 N MB + size + 修改时间）软去重，命中更新路径；批量导入同逻辑；UI 反馈「跳过 N 个已存在」
- [ ] 删「🧹 清空媒体缓存」按钮（保留「清除列表」，语义见 §6.4.11）

## 技术要点 / 约束
- 删扫描按钮：`VideoListView` 工具条移除按钮；扫描触发改目录选择 / 目录框回车（保留 `FolderBox` 输入框，用户明确要留）。
- 数千视频：`ListBox` 虚拟化（默认 VirtualizingStackPanel，执行期确认未关）；`VideoScanner` 分批 yield 入 `_all`；若仍卡，VM 分页（只绑可见窗）；`video_catalog` 已有 path 索引（执行期确认，缺则 `CREATE INDEX`）。
- 去重：`VideoCatalogService.Upsert` 改按 `path.ToLowerInvariant()` 主键；`ImportVideoFiles` / `ReadFile` 同逻辑；内容哈希软去重可选，命中则 `MovePath` 更新而不新增；UI 计数跳过数。
- 删清空媒体缓存：`VideoListView` 工具条移除该按钮（= 删 SQLite ffprobe 缓存，用途有限、易混淆）。
