## 背景 / 目标
现状 `ConfigStoreService.ExportBackup()` = 把 `config\*.json` 全部读成字符串塞进**一个 JSON**，`ImportBackup` 按 `Files[]` 覆盖。
三个硬问题：
1. **备份不完整**：不含 `data\`（`newtoys.db` / 缩略图 / 脚本实体文件），也不含应用根 `app.json` —— 用户以为备份了全部内容，实际只有设置。
2. **容器不适配大文件**：JSON 内嵌文本无法承载 db；也无法选择性恢复。
3. **入口分散**：资产页另有「保存资产库为 newtoys.db / 选 db 并入」（`AssetAllViewModel:1821/1835`）、视频页有任务 JSON 导出、脚本页有库包导出 —— 多条路径写同一批文件。

目标（用户拍板方向）：**默认只备份 shell 级设置**；模块与数据按「路由（section）」可扩展，用户按需勾选。

- [ ] 10. `pwsh skill/scripts/accept.ps1` PASS；手工验收：导出 → 改设置 → 导入 → 设置回滚且库未被覆盖。

## 技术要点 / 约束
- 🔴 容器必须是 zip：db / 缩略图无法进 JSON；zip 同时支持「只恢复其中一节」。
- 🔴 `VACUUM INTO` 需要目标路径不存在（已存在会报错）⇒ 生成临时文件名再打包。
- 🔴 恢复前必须校验 `manifest.app` 与当前一致、`SchemaVersion` 不高于当前（高于 ⇒ 拒绝并提示升级软件）。
- ⚠️ `Data` 节可能几百 MB：显示大小 + 导出进度 + 取消；⛔ 默认勾选（用户明确要求默认只备设置）。
- ⚠️ 备份里**不包含** `env.json` 的绝对路径时更安全，但用户换机需要 —— 折中：`Env` 节里路径字段标记为「本机」并在恢复时提示可能失效。
- 建议补最小单测：section 打包/解包、路径穿越拒绝、旧格式导入。⛔ 不铺 UI 测试。

**与卡内写法的偏差**
1. `RestoreFrom` 返回 `(int Ok, int Skipped)` 而不是 `void` —— 界面要报告"几项被跳过"，避免服务再猜一遍。
2. 「两个入口」落成**同一份节清单的不同默认勾选**（`shell`+`module.*` 默认勾 / `data.*`、`env` 默认不勾），而不是两个独立页面 —— 卡验收 3 的语义（默认选中 / 默认不勾）保持不变，且用户可自由增减。
3. manifest 里的大小是 `EstimateBytes()` 的**估算值**（字段名 `estimatedBytes`），不是压缩后精确字节。
4. 恢复不做"只恢复勾选的节"：勾选控制导出，恢复按 manifest 全量（弹确认时列出全部节）。
