## 一、背景（用户 2026-10-19 实机反馈）

1. **「用脚本集合冒充软件包分类」不成立** —— 软件包是 winget 的实时查询结果，不是可手工归档的条目 ⇒ 集合页的「软件包」类别删除。
2. **后端范围**：暂时只支持 winget；将来跨平台（apt 等）**另开独立软件包页**，⛔ 不在现有页切后端。
3. 🔴 **bug**：工具条源多选框勾 `store` 源不生效（勾了等于没勾，列表 / 搜索都不用它）。
4. 🔴 **bug**：设置页源分类不对 —— 实机 `winget source list` = `winget` + `winget-font`；`winget-font` 被误判成**社区源**（地址含 `cdn.winget.microsoft.com`），于是「字体源」与「社区源」被算成同一档互相关停；`msstore` 不在系统里却给了可拨开关（拨了必失败）。
5. **切源需要管理员权限**（每条 `source add/remove/reset` 都要 UAC）—— 页面文案与实现都必须如实反映。

## 二、实测事实（验收依据）

- `winget --version` = **v1.29.380**；`winget source --help` 子命令只有：`add / list / update / remove / edit / reset / export`
  ⇒ **没有 `source enable` / `source disable`**（旧实现"先试 enable、失败再回退 remove"= 每次白弹一次 UAC 才失败）。
- `winget source list` 列 = 名称 / 参数 / **显式**（无类型列）；`winget source export` 才给 `Arg / Type / Explicit / TrustLevel`。
- 实机 `winget-font` 的 `Explicit=true` ⇒ 重新 `add` 时必须回放 `--explicit`，否则它会被卷进每次默认搜索。

**v3.80 验收标准**（取代 §四 2~4）：

1. 软件包页工具条**没有源选择框**；搜索任何关键字都只跑 `winget search <q>`（不传 `--source`），状态栏显示「已查 N 个源，含全部默认源」；有显式源（如 `winget-font`）时结果里能出现字体包。
2. 安装 / 详情能正确带上行自带的源（商店包 `msstore` 仍能读详情、能装）。
3. 设置 → 软件源：只看到 6 条命令 + 按钮；点 `＋ 加入命令库` ⇒ 命令库页多出集合「winget 源」和 6 条命令（其中 4 条带「需要管理员权限」），**再点一次不重复添加**（状态栏提示「已有，无新增」）。
4. 到命令库运行「列出全部源」⇒ 输出可见且不需要 UAC；运行「移除字体源」⇒ 弹 UAC，点「否」= 什么也没改。
5. `config\package.json` 不再出现 `defaultSource` / `sourceCategories` / `sourceDefinitions`；老文件里残留字段被忽略、不报错。
6. 静态检查 0 阻断（`accept.ps1 -SkipBuild` 已过）。

## 七、假设与遗留（v3.80）

- 命令库执行**不再有"确认框"**（源 remove / reset 这类破坏性命令靠命令条目自己的描述提醒；UAC 点「否」= 不生效）。这是用户接受的取舍：命令库本来就是"我让你跑什么就跑什么"。
- 命令模板里的镜像地址写死在设置页 VM（`SourceCommandInfo`），⛔ 与 `package.json` 无关；换镜像改那条命令文本即可。
