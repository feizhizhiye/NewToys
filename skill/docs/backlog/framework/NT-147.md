# NT-147 · 表头右键 / 行右键职责分离（资源管理器口径）
- 状态：✔ 已实施（2026-11-05 首次实现 + 同日返工修到闭环；⏳ 待用户本地 build 后实机确认）
- 优先级：P1
- 关联需求：需求 **§4.8** ｜ 规范 **`ui.md` §6.3c §10.1 §12**
- 依赖：NT-123（原生表格迁移；本卡取代其「列显隐改到行右键」的取舍）
- 创建 / 完成：2026-11-05

## 背景
NT-123 迁 `TableView` 时为省一套表头菜单，把「▤ 列」「🔎 筛选」「仅看已安装」塞进行右键；而唯一的 `ContextMenu` 挂在控件级，表头右键冒泡到宿主 ⇒ 表头也弹行菜单（安装 / 卸载 / 复制 Id），语义错位。项目自身 `ui.md` §10.1 与需求 §4.8 写的却是「查看态 → 表头右键」。

用户验收口径（2026-11-05 返工指令）：**表头右键只负责列的显隐与列宽自适应，行右键负责功能，两个菜单不要用一样的**。

## 方案
- 表头右键两段：① `↔ 本列宽度自适应` / `⟲ 恢复本页默认列宽` ② 全量列显隐勾选（首列标识列置灰 + 提示）。⛔ 不放筛选、排序、行功能。
- 行右键：页面原有的功能项，⛔ 不插「▤ 列」。（筛选项后续由 NT-148 统一移到顶区筛选条）
- ⛔ 不复活「自动调整全部列宽」（v3.20 实测按全文测宽把其他列挤到 0）；单列自适应 = 表头文字宽与 `ListColumn.Sample` 示例值宽取大，**封顶 320px**，只改右键命中那一列。
- ⛔ 不做列重排 / 列像素设定对话框；资源管理器「更多…」段在项目列数少（≤13）时等价为全量顶层勾选清单。

## 返工原因（首版为什么没生效）
首版在 `PointerPressed` Tunnel 阶段把 `ContextMenu` 属性切换成另一份菜单对象。**框架打开菜单的时机不可控**（`ContextRequested` 可能重复触发 / 顺序不同），切换被覆盖 ⇒ 用户实测「表头右键和行右键还是一样」。
二版改为：**只保留页面声明的那一份 `ContextMenu`，在 `Opening` 的最后一刻按落点重建 `Items`** —— 表头清空后填列项，行区还原首次捕获的原始项。菜单对象不变，内容完全不同，且不受框架时序影响。

## 技术要点
- `PointerPressed` Tunnel 只记录右键坐标与 `_headerMode`；`TryHitHeader` 取所有 `TableViewColumnHeader` 的包围盒 `Union`（列间空隙 / 最右空白也算表头），⛔ 靠 `e.Source` 找祖先会漏掉透明背景上的空白区。
- `ContextMenu.Opening` 里首次捕获原始行项到 `_rowMenuItems`，之后每次打开 `Clear()` → 按 `_headerMode` 填列项或还原行项；DataContext 手工同步（规范 §3.8）。键盘触发（`Shift+F10`，无 `PointerPressed`）在 `ContextRequested` Tunnel 里复位 `_headerMode`。
- 默认列宽在 `SyncColumns` 时按列缓存到 `_defaultWidths`，「恢复默认」逐列写回。
- **全程不碰 Shared / Core / Shell**，只动 `NewToys.UI`（方案已在上一轮展示并经用户确认）。
