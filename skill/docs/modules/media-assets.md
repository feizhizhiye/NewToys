## 1. 职责与边界

- **定位**：本地媒体资产的索引 + 整理（标签 / 分类 / 集合）+ 物理操作（移动 / 复制 / 软删 / 永久删）+ 任务队列。
- 🔴 **`FileOperationService` = 唯一动磁盘处**；其它服务只改索引。
- 物理删除唯一入口 = 列表右键「⛔ 从磁盘删除」（二次确认 + 任务队列 + 删索引）；详情卡 IconBar 的 🗑 只做**软删除**（移入回收站）。

## 2.5 操作逻辑（交互契约）

> 跨模块共用语义见 `../ui.md` §10。本模块**所有磁盘写入只经 `FileOperationService`**，其它操作只改索引。

### 全部资产 `assets-all`（唯一资产浏览页）

工具条顺序：`📁 扫描`(SplitButton: 文件夹 / 文件) + 路径框(回车=预览) → `➕ 登记` → `🔄 扫描全部` → `🏷 加标签` → `📚 加集合` → `🗑 移入回收站` → `⤫ 从库移除` → `📊 读媒体信息` → `🔍 查重合并` → `💾 加入库` → `🧹 清除列表` → `🔄 重读` → `🗄 并入…` → `💿 另存为…` → `📤 导出` → `📥 导入`。

> 批量类按钮（加标签 / 加集合 / 移入回收站 / 从库移除 / 读媒体信息）的启用条件是**有选中行**（`HasSelectedRows`）；选中口径 = 列表原生多选（见下表「多选」行）。底栏「已选 N」显示选中条数。

| 操作 | 触发 | 结果 / 状态变化 | 约束 |
|---|---|---|---|
| 扫描预览 | `📁 扫描` 主钮 / 菜单「📄 文件…」/ 路径框回车 | 结果进列表（**草稿态**） | **⛔ 只进内存、不入库**；入库要再点 `💾 加入库` |
| 加入库 | `💾 加入库` | 草稿写进 `store\assets\assets.db` | 仅草稿态可用（`IsDraft`）；无预览结果时给提示；**同存储源内同路径只入库一次**（重复点全部跳过，⛔ 不产生重复资产、不复活回收站行） |
| 清除列表 | `🧹 清除列表` | 只清显示（含勾选 / 筛选） | 库里的数据仍在，点 `🔄 重读` 找回；⛔ 不删文件 |
| 登记文件夹 | `➕ 登记` | 登记为长期维护目录 | 登记后才进「🗄 并入 / 扫描全部」范围；**与已有源互为父子的拒绝登记**（会重复入库） |
| 扫描全部 | `🔄 扫描全部` | 重扫已登记目录 | 忙碌禁用 |
| 加标签 / 加集合 | `🏷 加标签` / `📚 加集合` | 对**勾选行**批量叠加 | 无勾选 ⇒ 禁用 + ToolTip 说明 |
| 移入回收站 | `🗑 移入回收站` | **软删**（可恢复） | 同上；也走 `FileOperationService` |
| 从库移除 | `⤫ 从库移除` | 删 `assets` + 它的 `file_locations` 记录 | 对勾选行；**⛔ 不碰磁盘**（清理重复行的正解）；文件仍在已登记源目录里 ⇒ 下次扫描会重新入库 |
| 查重合并 | `🔍 查重合并` | 先报组数 → 确认 → 每组保留一条资产，其余标签 / 分类 / 集合 / 关联 / 位置并过去后删除 | 只认**完全相同的物理路径**（忽略大小写 / 分隔符）；⛔ 不动磁盘；不同路径的真副本要手工「从库移除」 |
| 读媒体信息（批量） | `📊 读媒体信息` | 勾选行逐个跑 ffprobe（视频）/ 读文件头（图片），写 `metadata_json` | 只跑**还没读过**的（时长 / 分辨率 / 编码全空）⇒ 重复点击幂等；走任务队列、可取消；单条失败不影响其余 |
| 读媒体信息（单条） | 详情卡 IconBar `⚡` | 对当前选中资产跑一次 | 同上；读完 `RefreshView` 按 Id 认领选中项，详情卡不跳走 |
| 多选 | 鼠标 / 键盘：无修饰键=只选该行、`Ctrl`=增选/取消、`Shift`=从基准行连选、`Ctrl+Shift`=追加连选、`Ctrl+A`=全选当前页 | 选中真相在 VM `SelectedRows`；View 只回填 `SelectedItems` | 🔴 Avalonia 的 `Multiple` 单击默认是「追加」⇒ code-behind 在**隧道**阶段接管，无修饰键也自己处理（替换语义）；⛔ 无勾选列、⛔ 两套状态；分页口径 = 只在当前页有效 |
| 全选 / 反选 / 清空 | 列表右键尾部三项 | 改当前页选中集 | 与 `Ctrl+A` 同一入口（`SelectAllCommand`）；详情卡跟随最后点击行 |
| ⛔ 从磁盘删除 | 行右键「⛔ 从磁盘删除…」 | 二次确认 → 任务队列 → 删索引 | **唯一物理删除入口**；详情卡 IconBar 的 🗑 只做软删 |
| 打开 / 定位 | 行右键「📂 打开」「📁 打开所在文件夹」 | 系统关联打开 / 资源管理器定位 | 状态栏先显示「正在打开/正在定位…」（慢盘唤醒期间有反馈、窗口不卡）；失败 ⇒ 状态栏 `⚠` |
| 类型切换 | 筛选栏**既有类型下拉** | 列集合 / 详情卡视频字段 / 状态栏前缀一起切 | **即时设定、⛔ 不落盘**；`CaptureUserColumnPrefs` 保住用户列偏好 |
| 搜索 | 工具条搜索框（88 宽） | 名称 / 路径 / 标签「包含」；**空格分词后每词都要命中**（AND） | 分词口径唯一源 = `AssetService.SplitSearchTokens`；SQL 与草稿态内存筛共用，⛔ 不许两边各写一套 |
| 并入其他库 | `🗄 并入…` | 打开库 A → 打开库 B → `💾 保存`（工作副本模型） | 合并后按主键去重 + 关系重挂（否则生孤儿资产） |
| 导入资产 | `📥 导入` | 选 json 列表 → **草稿态预览**（再点 `💾 加入库`）；选 `*.db` → **等同「并入」**（摘要确认 → 任务队列 → 完成后自动刷新） | ⛔ 不静默入库（两条路都要确认）；`.db` 走合并才保得住评分 / 描述 / 标签 |

| 导出 / 导入 | `📤 导出` / `📥 导入` | 列表 JSON | 默认目录 = `store\assets\`（未建出退回 `store\`） |
| 勾选 | 表头 `☑` 右键 → 全选 / 取消 / 反选 | 勾选状态变化 | — |
| 详情卡编辑 | 选中 → 卡内改字段 | 收藏 / 评分 / chips **即时落盘**；文件名改完需 `✏ 应用新文件名` 才动磁盘 | ⛔ 收藏/评分不走「保存」 |

### 资产浏览 `assets-browse`（资源管理器形态 · NT-115 → NT-116 改造）

**分工**：`assets-all` 按**元数据**找（搜索 / 标签 / 筛选），`assets-browse` 按**磁盘位置**翻（我知道它大概在哪个盘哪个文件夹）。
🔴 **数据来源 = 磁盘实时枚举为主 + 索引叠加**：左树 = 盘符 / 共享根 + 逐层子目录（**展开才枚举该层**，⛔ 不递归整盘）；右侧 = 当前目录的真实内容（子目录 + 全部文件）。索引命中 = 「已入库」（有缩略图、可做库操作），未命中 = **标灰但功能不减**（可打开 / 定位，库操作点了给提醒）。

**布局**：左「目录树」（宽 240，工具条 `◧ 目录树` 可整体收起）｜ 右「面包屑 + 双视图 + 底栏」；右侧详情卡由 Shell 统一承载（本页实现 `IDetailPanelProvider` / `IDetailCardSource`，工具条末位详情开关照旧）。

工具条顺序：`▦ 图标卡 / ☰ 详细信息`（按钮组）→ 排序（名称 / 大小 / 修改时间 / 类型，再点同一项 = 反向）→ 类型下拉 → 搜索框 → `➕ 加入资产库` → `🔄 重读` → `↥ 上一级` → `◧ 目录树`。

| 操作 | 触发 | 结果 / 状态变化 | 约束 |
|---|---|---|---|
| 选目录 | 点左树节点 / 面包屑任一段 | 右侧换成该目录的**内容**（子目录 + 文件，实时枚举）；上次选中目录落 `media-assets.json` 的 `LastBrowseFolder`（绝对路径），下次进页面自动回到 | 🔴 树 = 绝对目录（盘符 / 共享根 → 逐层懒加载），**存储源不占层级**；路径不在任何源内 ⇒ 节点标灰（仍可浏览） |
| 展开 / 折叠 | 点节点（**首次展开才枚举该层子目录**；再点一次已选中的目录 = 收起 / 展开，不重载内容）/ 树工具条**单键「↕ 展开全部 / ↕ 折叠全部」** | 左树扁平化重建 | 🔴 默认全折叠；`展开全部` **只展开已枚举过的层级**（⛔ 不递归扫盘）。单键文案由 `ExpandAllText` 算（还有已读取的层级折叠着 ⇒ 显示「展开全部」，否则显示「折叠全部」），⛔ 不再两个按钮 |
| 树筛选「已加入资产库」 | 树工具条 `已加入资产库`（开着时描边 / 文字变强调色，`Classes.active`） | 左树只留**已入库目录 + 它们的上级链**；开启时把每个存储源逐层展开到可见 | 🔴 保留判据 `IsLibraryBranch` = 自身 `InLibrary` **或**某存储源根在它下面（只留已入库节点的话连 `D:\` 都不出现，树会是空的）；⛔ 只筛**树**，右侧目录内容照常全显示；已入库节点的子孙必然也已入库，所以子树整体保留 |
| 树节点右键 | 右键左树任一目录 →「➕ 加入资产库」（已在库里的目录该菜单项禁用） | 递归把这**一个**目录加入资产库（走任务队列，可取消；完成后重读索引） | 🔴 右键**只瞄准**：⛔ 不改选中、⛔ 不导航；瞄准节点记在 VM `ContextNode`（`AssetBrowseView.axaml.cs` 在 `PointerPressed` 隧道阶段记，⛔ 不用 `ContextRequested`——常被菜单自己先吃掉） |
| 未入库（标灰） | — | 目录节点 / 卡片 `Opacity 0.55` | 用户明确要求「置灰但能操作」：打开 / 定位照常，库操作会提示先「➕ 加入资产库」（⛔ 不做成禁用不可点） |
| 视图切换 | 工具条 `▦ 图标卡` / `☰ 详细信息` | 即时生效，落 `media-assets.json` 的 `BrowseViewMode`（重启恢复） | 两套视图**共用一份数据**（切视图不清选中） |
| 图标卡尺寸 | —（固定，无 UI 入口） | 卡片宽 300，缩略图区高 = 宽 × 0.62；`BrowseIconSize` 只为承接历史配置，读取时一律收敛到 300 | 唯一合法值在 `IconSizeChoices`；改宽度 = 改这一处常量 |
| 图标卡内容 | — | 缩略图（无图 ⇒ 类型占位，「文件夹」同理）+ 名称（单行省略）+ 副行「大小 · 修改时间」 | 只有**已入库**的视频 / 图片才解码缩略图；未入库项 ⛔ 不读盘 |
| 详细视图 | 表头 + 行 | 与 `assets-all` **同一套列定义**（`Models/AssetColumns.cs` 共享）；列显隐 / 列宽按本页页键 `assets-browse` 落 `config\columnlayout.json` | 视频三列（时长 / 分辨率 / 编码）默认隐藏，用表头右键开 |

| 加入资产库 | 右键「➕ 加入资产库」/ 工具条 | 文件 ⇒ 只索引自身；文件夹 ⇒ 任务队列里递归扫描入库 | 🔴 嵌套规则：目标在已登记源之内 ⇒ **归该源**（⛔ 不新建重叠源）；目录里含**已登记的子源** ⇒ 那部分文件**跳过**；完全无归属 ⇒ 把该目录登记为新源（⛔ 不登记盘符根）。已在库里的项自动跳过 |

| 缩略图 | **随滚动自动补**（无按钮） | View 订阅 `ScrollViewer` 的 `Offset` / `Extent` / `Viewport` 变化 → `ReportViewport`：① 先解**已缓存**的可视区（上下各一屏，`_thumbRequested` 去重）；② 缺缓存的排进**生成泵**。泵在 `TaskQueue` 里跑，串行出队、每批 4 张并行跑 `ThumbnailService.GenerateAsync`，**一批落盘就回填界面**，队列空了才退 | 🔴 生成跟着滚动持续追加（⛔ 进目录一次性整页批处理）：`_thumbGenQueue` 上限 60 条、超出丢最早；查盘 180ms 去抖、扫描期间滚到的新窗口记在 `_thumbScanNext` 里接着扫；可取消、逐条报进度、单条失败不停批。图片走**本机原生解码**，视频仍走 ffmpeg（`-threads 1 -an -sn -q:v 4`） |
| 空态 | — | 目录打不开 → 「权限不足 / 磁盘掉线」；目录空 → 「这个目录是空的」；筛选没命中 → 另一种文案 | 本页 ⛔ 不做扫描 / 导入的完整流程（只做「加入资产库」这一件事） |
| 加载态 | 选目录 / 翻页 / `🔄 重读` | 目录枚举在**后台线程**（`AssetBrowseService.LoadDirectory`）；页面先出空态「正在读取目录…」，回来一次性填 | ⛔ 不在 UI 线程枚举（大目录 / 慢盘）；代数号作废过期结果 |
| 分批填卡 | 切目录 / 翻页 / 换尺寸 / 改搜索 | 首屏同步填一屏（≤24 张，立即可点可滚），其余按后台优先级逐批续上 | 一页 500 张一次性 Add 会让切目录僵住数秒；批次按代数作废；选中在全部到位后统一认领 |
| 缺失 / 离线 | — | 已入库但 `missing`（文件被外部删掉）的行 `Opacity 0.4`；打不开的目录节点标「（无法访问）」 | 回收站资产不进列表 |

## 5. 坑点（🔴 实测过）

1. 🔴 **扫描「大小 + 修改时间」当识别键会碰撞**（误判为复制 / 改名）⇒ 必须叠加路径，见 NT-032。
2. 🔴 **多库融合重复 / 重叠并入会产生孤儿资产**（NT-033 已修）⇒ 合并后按主键去重 + 关系重挂。
3. 集合排序当前用 **⬆⬇ 按钮**（⛔ 不是拖拽）；**智能集合规则未实装**（NT-018 偏差，仍开放）。
4. 回收站曾缺「删除时间」列（NT-029 已修）；移动 / 复制无 UI 入口（NT-030 已补）。
5. 收藏 / 评分 **即时落盘**（⛔ 不走「保存」）；「移动到 / 复制到（目标存储源）」整块已删（低频重操作不进卡）。
6. 资产详情卡 chips 的 `OptionsPath` 必须是常驻集合实例，否则 ComboBox 回写会抹掉页面值（见 `../ui.md` §7.2）。
7. `AssetTasksView` **不是标准列表页**（三块堆叠 + `ScrollViewer`）⇒ ⛔ 不套 `ListPageSkeleton`。
8. 空态引导只覆盖资产列表类页（`assets-all` 等）；`assets-categories` / `assets-collections` 数据源是左树 + 成员列表，**无空态也无 `HasItems`**（NT-060 遗留，未补）。
9. 🔴 **右键「📂 打开 / 📁 打开所在文件夹」⛔ 不许在 UI 线程直接 `File.Exists` + `Process.Start`**：两者都要碰目标文件所在卷，机械硬盘休眠唤醒要数秒、网络盘还要等超时 ⇒ 整窗卡死，用户会以为「比资源管理器慢」。资源管理器双击快是因为它不做前置存在性检查、且关联处理器已在 shell 进程内热加载。现在统一走 `AssetAllViewModel.FileOps.cs::RunOffUiThread`（线程池 + `Dispatcher.UIThread.Post` 回投文案）。
10. 🔴 **`TagsExpr` / `CategoriesExpr` / `CollectionsExpr` 内层必须 `SELECT n.name AS name`**：外层 `group_concat` 只能引用内层**输出列名**（`name`），写成 `group_concat(n.name, …)` 会让 SQLite 抛 `no such column: n.name`。这三个表达式只出现在 **WHERE（搜索）/ ORDER BY（按那三列排序）/ 表头筛选**，不在 `QueryPage` 的 SELECT 里 ⇒ 列表本身照常显示，但**任何关键字搜索恒返回 0 行、按标签/分类/集合排序恒空**，且异常被 `catch` 吞成空页（2026-10-27 修；`LastQueryError` 现在会上状态栏 `⚠`）。
11. 🔴 **登记父子目录 = 同一文件入库两次**：扫描匹配（`存储源+相对路径` → `大小+修改时间` → `快速哈希`）全部只在**当前存储源的索引**内做，⛔ 不跨源 ⇒ 父源与其子目录源各扫一遍，同一物理文件落成两条资产、列表里同一个文件出现多行。
    - 已封口的三处：登记入口拒绝互为父子的源（`AssetService.FindOverlappingStorage`）、子目录归到覆盖它的源（`FindCoveringStorage`，`💾 加入库` 与按目录导入都走它）、扫描时跳过被在线父源覆盖的子源 + 父源扫描按完整路径**认领**子源既有位置（`LoadOverlappingLocations`）。
    - 存量重复靠 `🧹 合并重复`（`MergeDuplicatePaths`）清：合并只认**物理路径完全一致**（`AssetService.PathKey`：小写 + 统一分隔符 + 去尾斜杠）；映射盘 `Z:\` 与 `\\nas\` 双写法路径不同，合并看不到，要手动移除其中一个源。
12. 🔴 **对话框 `await` 之后必须回到 UI 线程**：`await DialogHooks.ConfirmAsync(...).ConfigureAwait(false)` 会让后续代码跑在线程池上，紧接着的 `Reload()` → `Items.Clear()` / `Selected` setter → Shell `ToolbarHost` 改可视属性，直接抛 `InvalidOperationException: The calling thread cannot access this object…`（未捕获 ⇒ **整个窗口崩掉**，日志 `logs\crash-*.log`）。
    - 规则：模块内所有 `DialogHooks.*Async` 一律 `ConfigureAwait(true)`（本项目 `RuleCatalogViewModel` / `VideoFileService` 同口径）；`Reload()` 自身还有一道 `Dispatcher.UIThread.CheckAccess()` 兜底。
    - 别在 `DialogHooks` 的调用点上写 `ConfigureAwait(false)` 图"性能"——它换来的是跨线程崩溃。
13. 🔴 **批量改 `ListBox.SelectedItems` 必须先关 `AutoScrollToSelectedItem`**：`SelectingItemsControl` 默认每 `Add` 一项就把该项滚进视野（虚拟化下还要实例化容器 + 触发布局）⇒ 全选 / 大范围 `Shift` 连选上百行 = 上百次滚动，表现为「列表自己往下滚 + 界面卡死」。`AssetAllView.BulkUpdateSelection` 统一处理（临时关滚动 + `_syncingSelection` 抑制回抛 + `finally` 恢复，保证键盘方向键仍自动滚动）。
14. 🔴 **资产浏览页的「一行」= 一个磁盘条目**（文件或子文件夹）：同一资产在 A / B 两个目录各出现一次是正确语义 ⇒ 缩略图键 / 选中认领 / 去重一律按**绝对路径**，⛔ 用 `LocationId` 或 `Row.Id`（未入库项的合成行 `Id=0`，用 Id 会让它们全部互相匹配）。库操作的对象 = `SelectedRows`（**只装已入库项**），未入库项只走「打开 / 定位 / 加入资产库」。
15. 🔴 **缩略图缓存淘汰时⛔ 不许 `Dispose`**：被淘汰的 `Bitmap` 可能正被界面的 `Image` 持有，释放后下一帧渲染会崩在 Skia 里。`AssetThumbCache` 只丢引用、交给 GC；LRU 上限 300 远大于一页（≤500，默认 120），正常使用不会淘汰正在显示的图。
16. 🔴 **目录树计数按「已入库子孙文件数」累加，不是 `Children.Count`**：`AssetBrowseService.CountByAncestor` 对每条已入库位置行的目录一路加到根（父目录 = 自己 + 全部子孙），未入库目录显示 0（不显示徽标）。
17. 🔴 **树 = 磁盘真实目录 + 懒加载，⛔ 别再按索引建树**：顶级 = 所有可访问盘符 + 不在任何盘符下的存储源根（UNC）；**节点首次展开才枚举它这一层**（`AssetBrowseService.LoadChildDirectories`，⛔ 不递归），权限 / 掉线 ⇒ `IsAccessible=false` 显示「（无法访问）」。`展开全部` 只展开**已枚举过的层级**（递归全盘展开等于进页面就把所有盘扫一遍）。节点是否「已入库」= 路径落在某个 `storages.root_path` 之内（`AssetBrowseService.IsUnder`）。
18. 🔴 **切目录卡顿的三处真凶**：① 左树是 `ListBox#TreeList`（自带虚拟化；⛔ 换回 `ItemsControl` + `StackPanel` 就是给每个节点建 Button）且 `RebuildTree()` 一次性换 `TreeNodes` 引用；`SelectNode` 只在展开状态**真的**变了才重建，选高亮只动「旧 + 新」两个节点；② 目录内容枚举（`DirectoryInfo.EnumerateFileSystemInfos`）一律在**后台线程**，回 UI 按 `_viewVersion` 校验后填卡；③ 排序 / 筛选在 UI 线程也要 O(n) 文化比较 ⇒ 大目录先丢后台。
19. 🔴 **缩略图只解「可视区」，⛔ 别在填卡时全量解；且只解已入库项**：未入库项 ⛔ 不读盘（`AssetTile.WantsThumb` 里已经排除）。口径 = `FillChunk` 只解首屏 `InitialThumbQuota`（36）张；其余靠 **`ScrollViewer` 的 `Offset` / `Extent` / `Viewport` 属性通知**驱动 `ReportViewport(offset, viewport, extent)`，VM 按「平均每项占高」估算索引范围、上下各预取一屏，`_thumbRequested`（按**绝对路径**）去重。🔴 **⛔ 用 `LayoutUpdated` 当滚动驱动**：滚动只改 ScrollViewer 偏移，不保证每帧都触发本页布局回调 ⇒ 滚到底部时可视区一次都没上报过，缩略图停在首屏那 36 张（本轮 bug 根因）。缺缓存的图由**生成泵**随滚动持续追加生成（不是进目录一次性整页批处理）。换视图 / 换尺寸时 View 要解绑旧 ScrollViewer 的监听并把 `_lastReportedOffset` / `_lastReportedExtent` 重置成 `NaN`。
20. 🔴 **嵌套文件夹（用户明确点名）**：① 目标目录**在**某个已登记源之内 ⇒ 扫码归该源，⛔ 不新建重叠源；② 目标目录**包含**已登记的其它源 ⇒ 那部分文件**跳过**（`AssetLibraryAddService` 用 `FindCoveringStorage` 过滤），否则同一物理文件被两个源各索引一次（见坑点 11）；③ 单文件入库且没有任何源覆盖它时，登记的是**它所在的目录**，⛔ 不登记盘符根（否则一扫就是整个盘）。
