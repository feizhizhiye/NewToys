## 背景 / 目标
用户新需求（2026-10-13，v3.25；同日追加拍板「物理必备」）：
① 每个模块的设置 View/VM 写进**本模块**，软件加载后**自注册进 `settings` 二级菜单**（Order 从 100 起）；
② 框架相关设置全归 `Module.Settings`，且 Settings 做成**如 Shared/Core 的框架组件**——**物理必备：跟 `NewToys.exe` 同目录**；
③ **一个功能模块都不加载时，框架本身（首页 + 一键启动 + 设置全套）照常可用**；
④ 模块所需一切在自身 DLL，只在加载时往界面注册。

前置诊断（2026-10-13 代码核对）：跨组 `RegisterFunction` 在分组未注册时抛 `InvalidOperationException`，且被 `ModuleLoader.InitializeAll` 的逐模块 try-catch **吞掉** → Release 目录扫描（`Directory.EnumerateFiles` 顺序不保证）下菜单项**静默丢失**。
🔴 约束（根目录越界）：`scripts/build.ps1` 按 `src/Module.*` **目录数**校验 `Modules\` 里的 DLL 数，不匹配每次构建都报警告 → ⛔ **不能用 props 把 `Module.Settings` 排除出 `Modules\`**，采用「Shell 无条件引用 + Modules\ 冗余副本被跳过」方案。改框架层已获用户明确同意（即本需求本身），交付里独立说明。

## 验收标准（可验证清单）
- [ ] Release 产物：`Module.Settings.dll` 在**程序根目录**（与 `NewToys.exe` 并列，生效那份），`Modules\` 里另有一份冗余副本；`build.ps1` 的 DLL 计数校验**无警告**
- [ ] 启动顺序：`Module.Settings` **第一个**初始化（`settings` 分组先于一切功能模块存在）
- [ ] Debug / Release 两种轨下，功能模块自注册进 `settings` 组都生效（构造场景：某模块 `Initialize` 先于 `Module.Settings` 跑——延迟补登兜底）
- [ ] `Modules\` 清空（仅剩冗余副本也无妨）→ 首页 / 一键启动 / 收藏 / 主题 / 设置**全套可用**（需求 ③）
- [ ] 删 `Modules\` 里的 `Module.Settings.dll` → **无任何影响**（根目录那份生效）
- [ ] 删根目录的 `Module.Settings.dll` → **启动失败**（硬依赖，符合预期；⛔ 不设计成降级）
- [ ] `InitializeAll` 后健全性检查：`settings` 分组仍不存在（模拟 `SettingsModule.Initialize` 抛异常）→ 日志 + 状态栏一行，⛔ 不静默
- [ ] 现有 10 个框架设置页（`settings-general` ~ `settings-all`）注册行为不变（回归）；功能清单页 / 首页收藏卡能列出模块自注册的设置页

## 技术要点 / 约束（规范章节、坑点、关键文件）
- `Shell.csproj`：`Module.Settings` 的 `ProjectReference` **移出 Debug 条件组**，与 Shared/Core 并列（无条件）；Debug 条件组只留功能模块
- `App.axaml.cs`：`GetDebugModuleTypes()` → `GetMandatoryModuleTypes()`——**必载清单 = `Module.Settings` 置顶**（无条件）；`#if DEBUG` 再追加 PcTools/WebTools/VideoTools（+未来的 MediaAssets）；Release 只传 `[Settings]`
- `ModuleLoader.LoadAll` 语义改「**必载清单 + 扫 `Modules\` 补全**」：先加载必载清单，再扫描（`IsAlreadyLoaded` 跳过同名——`Modules\` 里的 `Module.Settings.dll` 冗余副本、Shared/Core 都由此跳过）；⛔ 不再「传 null 才扫描」
  - Debug 副作用：扫的是 `BaseDirectory\Modules`（不存在→兜底扫程序目录）→ 功能模块 DLL 都在显式清单里已加载 → 全部跳过，无行为变化
- `MenuService` **延迟补登**（纵深防御，非主保障——主保障是 Settings 物理置顶）：`RegisterFunction` 分组未注册 → 暂存不抛异常；`RegisterModule` 建组时补登（去重 + 按 Order 重排）。防的是「未来有人调了必载清单顺序 / 热加载模块先注册」等顺序意外
- `InitializeAll` 后健全性检查：解析 `IMenuService` 查 `FindGroup("settings")`，缺失写日志 + Shell 状态栏一行（提示落点执行时定，⛔ 不弹错误窗阻断）
- ⛔ 不改 `src/Directory.Build.props`（Settings 继续出 `Modules\`，保 build.ps1 计数校验通过 + 零拷贝铁律）
- 框架自给现状（已核对）：首页 + 一键启动依赖 = `IMenuService` / `LaunchRunner` / `ILaunchConfigService` / `IFavoritesService`，全在 Shared/Core；新增框架功能时保持此性质
