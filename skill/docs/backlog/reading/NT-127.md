## 一、为什么

批1 交付后实机反馈 **发现页点了没内容**。静态复核发现 4 处硬伤（见下），

## 三、技术要点

1. 🔴 **`exploreUrl` 有两种分隔符**：`&&` 与**换行**（真实书源换行占多数）。只按 `&&` 切 ⇒ 整张表并成一条、
   地址里混进「分类名::」⇒ 请求必然 404、页面永远空白。判定 `Regex.Split(raw, "&&|\r\n|\n|\r")`。
2. 🔴 **每项分类自己的请求配置**（`, {"method":"POST","body":"…"}`）必须跟着走，⛔ 不能 `SplitRequest` 完就丢。
3. 🔴 **`ruleExplore` → `ruleSearch` 是逐字段回退**，不是整对象回退。`ruleExplore` 只给 `bookList` 是常态，
   整对象回退会拿到空 `name` / `author`，条目全被判「书名与链接都为空」。
4. 🔴 **`ResolveUrl` 全程按字符串拼，⛔ 不走 `Uri` 合并**：分类解析阶段地址里还带 `{{page}}`，
   `Uri.TryCreate` 会失败或改写原串（`{` `}` 被转义），后面的插值就白做了。
5. 🔴 **发现页不用三段完整性判定**：`Capability == Incomplete` 的源只要有分类表照样能发现
   （`SourceAnalyzer` 同步放宽：搜索段不全但有 `exploreUrl` + 书单 ⇒ 算可用，原因标「只能发现浏览」）。
6. 🔴 **交棒顺序**：目录加载完 → 先 `Dispose` 掉目录流程的 `CancellationTokenSource` 再设 `SelectedChapter`；
   否则正文加载开头的 `Cancel()` 会把还在收尾的目录流程一起取消。
7. **进度写库**：`ProgressStore` 一本书记多行（每章一行），取 `updated_at` 最新的一行当「继续阅读」落点；
   书架一次 `LoadLatest()` 取全部（⛔ 不逐书查库）；移出书架时连带清进度。
8. **阅读页配色不写死**：`ReadingSettingsService.BackgroundOf / ForegroundOf` 给色值，code-behind 写进控件
   （库内 XAML 仍然只许 `DynamicResource`）。

## 六、追加改造（2026-11-01 第二轮，与上同批交付）

用户反馈「发现页按手机 app 的树状折叠布局、书单窄一些；搜索页要多选框控制书源；正文统一导航到阅读页；不做 WebDAV」。

| 项 | 做法 |
|---|---|
| 发现页改树 | 左栏 `Expander` 折叠树（根 = 书源、子 = 分类），右栏书单改**窄卡网格**（`WrapPanel`，卡 156×72）；点根节点 = 展开 / 折叠，点分类 = 读该分类 |
| 搜索页书源多选 | 左栏独立面板：过滤框 + `CheckBox` 列表 + 全选 / 全不选（只作用于过滤结果）+ 顶栏「📚 书源」开关；勾选只影响本次搜索，⛔ 不改库里的 `enabled` |
| 正文导航到阅读页 | 搜索页删掉目录 + 正文两栏（`SearchViewModel` 去掉 `Chapters` / `ContentText` / `LoadBookAsync` / `LoadContentAsync` / `Prev·NextChapter`），结果卡片双击 / 「📖 阅读」→ `PendingBook` → `reading-read` |
| 布局收窄 | 发现页左树 230、搜索页书源栏 220；两页书单/结果统一改窄卡网格（156px） |
| WebDAV | ⛔ 不做（从待办移除） |
| 技术点 | 🔴 树里的分类选择走 code-behind `SelectionChanged`（`Expander` + 嵌套 `ListBox`，不经 `TreeView` 的 `IsExpanded` 绑定）；🔴 换源带过来的书名要在 `AttachedToVisualTree` 再取一次（标签页复用时 VM 不重建） |
