## 背景 / 目标

「🔄 重载模块」是 NT-005 加在标题栏的第三个按钮（🧩 拼图）。用户判定：**非常用功能，不放标题栏**。

**2026-10-15 用户拍板**（两处）：
1. **选方案 A**：Shared/Core 新增 `IModuleReloadService` 契约。对比结论：性能三方无差异（点击一次的操作，µs 级）；维护性/复用性 A 优（契约显式、事件模式有 `INavigationService.Navigated` 先例、未来托盘/命令行可复用）；C（Shell 自营设置页）破 §6.5「设置页归 Module.Settings」归口且 Shell 零 `RegisterFunction` 先例；B（直接调 `ModuleLoader` 静态类）因 `IMenuService` 无任何事件 ⇒ 左树不刷新 = 静默失效，不成立。
2. **入口放功能清单页**：重载模块 = 「给功能清单增加新功能」的动作，语义最顺。

## 技术要点 / 约束（规范章节、坑点、关键文件）

- **为什么必须加服务**：设置页 VM 在 `Module.Settings` ⛔ 不能引 Shell；`BuildTree()` 是 Shell 私有 ⇒ 「Shared/Core 服务做事 + 事件通知 Shell 收尾」是唯一干净解。
- 事件模式先例：`INavigationService.Navigated`（`ShellViewModel` 构造里已订阅同款 Shared 服务事件）。
- `AllFunctionsViewModel` 是**瞬态 VM**（ favorites 订阅教训：瞬态 VM ⛔ 不被单例服务长期持有）⇒ 本项只**调用**服务，⛔ 不在 VM 里订阅 `Reloaded`（订阅方只有 Shell）。
- 重载结果反馈走**壳级底栏**（现有机制）；功能清单页当前无状态行，⛔ 不借机新增（控范围）。
- 「增加功能」操作区是页面级功能入口（规范：工具条 = 页面级功能）；该页目前无工具条，顶部操作区放**不随内容滚动**的位置（ScrollViewer 外）实施时定。
