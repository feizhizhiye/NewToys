# 待办清单（Backlog · 待办细节）

> 本目录是 **待办细节（具体要做的事）** 的载体，与 `../NewToys-项目现状与进度.md` 三、的「**待办项**」配合：
> - **台账三、 = 待办项**（紧凑：NT-id / 一句话 / 优先级 / 状态），改动小，只在「新增项」和「翻已完成」时动。
> - **本目录 = 待办细节**（每个 NT 一个文件），是执行模式的工作稿，**随 `src/` 改动而更新**，验收后清理。
> 定位：**规划模式写细节、执行模式改细节、验收后清细节**。
> 🔴 **工作流不在此定义**：`规划 / 执行双模式` + 状态机 + 验收清理的唯一定义处 = `../NewToys-AI协作提示词.md`【规划 / 执行双模式工作流】节；本文件只定义 backlog 的**格式与生命周期**。

## 状态机（单个待办项的生命周期）
`📝 草稿` → `✅ 就绪` → `🔄 执行中` → `✔ 已完成（待验收）` → （验收后）细节清理

- **📝 草稿**：已写进台账待办项，但细节尚未展开 / 未确认可执行。**不执行**。
- **✅ 就绪**：细节已展开（验收标准 / 技术要点 / 范围明确），可被批量执行。
- **🔄 执行中**：执行模式正在实现，细节随代码推进追加「执行记录」。
- **✔ 已完成**：代码落地 + 静态自检通过，等用户验收。
- **验收后**：台账待办项翻 `✔ 已完成`；细节文件按下方策略清理。

## 清理策略（验收后）
- 默认：**删除**对应的 `NT-xxx.md`（细节已完成使命，不长期占空间）。
- 或：保留**最近 3 个已完成细节**作为滚动归档，更老的已完成细节删除（避免无限累积）。
- 台账三、的待办项行**始终保留**（只翻状态），不随细节删除。

## 两条铁则（本目录专用）
1. **规划模式不碰代码**：讨论产出的待办，只在台账三、登记待办项 + 在本目录写细节，**绝不改 `src/` 代码**。可多轮累积、多个待办项并行展开。
2. **草稿闸门**：只有 `✅ 就绪` 才被执行模式批量跑；`📝 草稿` 永不执行。

## 执行模式（批量自动跑）
触发：开会话，发「**执行全部就绪待办**」（或「执行 NT-xxx」）。Agent 在循环里：
1. 读台账三、，筛出 `✅ 就绪` 且依赖已 `✔ 已完成` 的条目；
2. 按 **依赖顺序 → 优先级（P0>P1>P2）** 排序；
3. 逐条：读 `NT-xxx.md` 细节 → 按《开发需求》《开发规范》改 `src/` → 静态自检（`../../skill/scripts/check.ps1`）→ 标 `🔄 执行中` → 成功标 `✔ 已完成（待验收）` 并 git commit、回写台账、细节追加「执行记录」；
4. **遇阻塞（5 种停手情形之一）立即停并报告**，不偷偷跳过、不擅自扩大范围。

> ⚠️ 不用 automation 定时触发：它是单 prompt 提醒，无「编译→修错→再编译」迭代，跑不动真实代码。
> 「睡觉让 AI 跑」= 睡前开一个会话发「执行全部就绪待办」，agent 在循环里把就绪项跑完——这就是「你不在场」的形态。
