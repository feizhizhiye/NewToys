## 背景 / 目标
用户新需求（2026-10-13，v3.25；同日两轮追加拍板）：
① 每个模块的设置 View/VM 写进**本模块**，软件加载后**自注册进 `settings` 二级菜单**（Order 从 100 起）；
② 框架相关设置全归 `Module.Settings`，且 Settings 做成**如 Shared/Core 的框架组件**——**物理必备：跟 `NewToys.exe` 同目录**（用户已授权修改 `scripts/build.ps1`）；
③ **一个功能模块都不加载时，框架本身（首页 + 一键启动 + 设置全套）照常可用**；
④ 模块所需一切在自身 DLL，只在加载时往界面注册。

前置诊断（2026-10-13 代码核对）：跨组 `RegisterFunction` 在分组未注册时抛 `InvalidOperationException`，且被 `ModuleLoader.InitializeAll` 的逐模块 try-catch **吞掉** → Release 目录扫描（`Directory.EnumerateFiles` 顺序不保证）下菜单项**静默丢失**。改框架层已获用户明确同意（即本需求本身），交付里独立说明。

## 技术要点 / 约束（规范章节、坑点、关键文件）
- `src/Directory.Build.props`：模块 Release `OutDir` 规则（第 68 行条件组）**排除 `Module.Settings`**（`And $(MSBuildProjectName)!='Module.Settings'`）→ 它回落到根目录 `OutDir`
- `scripts/build.ps1`（**用户 2026-10-13 授权可改**）：第 62 行 `$expected` 计数排除 `Module.Settings`（`Where-Object { $_.Name -ne 'Module.Settings' }`）；可加一行「框架组件 Module.Settings → 根目录」提示。⛔ 只改计数口径，⛔ 不加任何 DLL 拷贝步骤（零拷贝铁律）
- `Shell.csproj`：`Module.Settings` 的 `ProjectReference` **移出 Debug 条件组**，与 Shared/Core 并列（无条件）；Debug 条件组只留功能模块
- `App.axaml.cs`：`GetDebugModuleTypes()` → `GetMandatoryModuleTypes()`——**必载清单 = `Module.Settings` 置顶**（无条件）；`#if DEBUG` 再追加 PcTools/WebTools/VideoTools（+未来的 MediaAssets）；Release 只传 `[Settings]`
- `ModuleLoader.LoadAll` 语义改「**必载清单 + 扫 `Modules\` 补全**」：先加载必载清单，再扫描（`IsAlreadyLoaded` 跳过同名——Shared/Core 等由此跳过）；⛔ 不再「传 null 才扫描」
  - Debug 副作用：扫 `BaseDirectory\Modules`（不存在→兜底扫程序目录）→ 功能模块 DLL 已在显式清单里加载 → 全部跳过，无行为变化
  - ⚠️ 并发写观察项：Settings 的 OutDir 改根目录后，它与 Shell 会并发写根目录的 Shared/Core（同 `Modules\` 现行「4 模块并发写」模式，Release 已关 pdb）——实构若报 MSB3026 再议
- `MenuService` **延迟补登**（纵深防御，非主保障——主保障是 Settings 物理置顶）：`RegisterFunction` 分组未注册 → 暂存不抛异常；`RegisterModule` 建组时补登（去重 + 按 Order 重排）。防的是「未来有人调了必载清单顺序 / 热加载模块先注册」等顺序意外
- `InitializeAll` 后健全性检查：解析 `IMenuService` 查 `FindGroup("settings")`，缺失写日志 + Shell 状态栏一行（提示落点执行时定，⛔ 不弹错误窗阻断）
- 框架自给现状（已核对）：首页 + 一键启动依赖 = `IMenuService` / `LaunchRunner` / `ILaunchConfigService` / `IFavoritesService`，全在 Shared/Core；新增框架功能时保持此性质
