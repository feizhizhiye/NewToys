# NT-148 · 通用筛选条 FilterBar + 右键筛选全清
- 状态：✔ 已完成（已验收 · 2026-11-05 用户确认冒烟通过）
- 优先级：P1
- 关联需求：需求 **§4.8 / §4.8.2** ｜ 规范 **`ui.md` §6.3d §10.1**
- 依赖：NT-147（表头 / 行右键职责分离）
- 创建 / 完成：2026-11-05

## 背景
用户 2026-11-05 指令：「编译通过，还有一些没实现，全部资产页，资产浏览页；右键里的筛选功能全部删除，封装一个筛选条，有需要筛选的用这个筛选条」→ 对比案例后拍板「1.2，如果是按照全部资产页的筛选条样式，直接扩展」。
现状：6 页把「🔎 筛选」塞在行右键；3 条自绘筛选条（`assets-all` 4 下拉 / `reading-sources` 3 下拉 + 按钮 / `assets-trash` 摘要提示）各写各的样式；`AssetAll` / `AssetBrowse` 两页表头口径还没补齐。

## 方案（用户拍板：按 AssetAll 样式直接扩展）
1. 新增 `NewToys.UI/Controls/FilterBar.axaml(.cs)`：沿用 `Border.filter-bar` + 一行等分 Grid + `filter-combo` + `FilterDropDownAlign`、⛔ 无滚动条。
   - `FieldsContent` 内容槽：页面自有多下拉原样放入，**绑定 / 命令 / VM 零改动**。
   - `QuickItemsSource` / `Summary` / `ClearCommand`：消费基类 `QuickFilters` / `FilterSummary` / `ClearFiltersCommand`，生成 chips（占位项跳过、点中加粗、集合变化自动刷新）。
   - 🔴 内容槽与三个属性绑定一律 code-behind 按 `Source=this` 赋值（⛔ 祖先绑定 ⇒ `ListPageSkeleton` 静默空内容事故）。
2. 6 页删右键「筛选」：`PackageView` / `AssetCategories·Collections·TagsView` / `VideoList·VideoBatchView`，改挂顶区筛选条；`PackageView`「仅看已安装」并入 `QuickFilters`。
3. 3 条自绘筛选条迁入内容槽，仅换外层壳；页面专属联动（下拉内容随类型变、重建抑制）仍留在各自 VM。
4. 2.1 补两页表头：`AssetAllView` 新增 `AssetAllView.HeaderMenu.cs`（`Opening` 按落点把「▤ 列」提到表头模式、行模式只留功能；列宽自适应 / 恢复默认）；`AssetBrowseView` 表头菜单补列宽两项。
5. Shared 基类加 `ResetColumnWidthsCommand`（清手动 / 锁定列宽，供 `ColumnGrid` 页用）。

## 实现取舍（标注）
- 用户选项 1.2 描述含「Shared 新契约」；实际只加了 **1 个 RelayCommand**，未新增模型类 —— 用内容槽承载各页下拉，避免改动 3 个 VM 的属性通知链（`OnFilterXxxChanged` / `_rebuildingOptions`），风险更低、行为完全不变。
- 框架层 = 新增 1 控件 + Shared 1 命令；⛔ 未改 Core / Shell。
