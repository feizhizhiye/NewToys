## 一、背景与目标

页面链是「**菜单字符串 Key → 视图名 → 反射解析 → 约定 VM 名**」四段全字符串 / 全约定。四段里任何一段改名漏改，**编译期不报错、运行期不抛异常**，表现只有「菜单项点了没反应」或「页面空白」。之前只有 lint 兜底（P-01 / P-02 / C-05）。

本卡目标是**把「视图名」这一段从运行期约定搬到编译期**：菜单项视图名改由泛型参数决定（`typeof(TView).Name`），View 类改名时编译器强制注册处跟随，漏改 = 编译不过。

### 方案取舍

| 方案 | 判断 |
|---|---|
| ① 源生成器（`[Page("key")]` → 生成常量 + 工厂） | 能同时根治 Key 与视图名，但要新增 `netstandard2.0` 分析器项目 + Roslyn 依赖 + 构建链改造 |
| ② **泛型 `RegisterFunction<TView>`** | ✅ **本卡采纳**：零新依赖、一处签名改动 + 机械迁移调用点，编译期即锁死「视图名 = 类名」 |
| ③ 维持字符串 + 只靠 lint | ⛔ 绕过 `accept.ps1` 直接 build 就漏（用户常这么干） |
