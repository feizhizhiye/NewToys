## 背景 / 目标
现状（`profiles\default\config` 实测）：**15 个 JSON**，其中 `hosts-profiles.json` / `scrape-tasks.json` 是 2 字节的空数组，
`ui.json` 30B、`video-tools.json` 29B、`theme.json` 64B、`window.json` 87B、`favorites.json` 123B —— 大量文件只是「默认值占位」。

两个真实缺陷：
1. **写入非原子**：全工程用 `File.WriteAllText`（`JsonOptionsStore.Save`、`ConfigStoreService`、5 个模块设置服务）。
   进程崩溃 / 断电落在写一半 → 文件截断，只能靠 `.bak` 兜底（`JsonOptionsStore.TryBackup`），等于丢一次改动。
2. **空文件噪音**：默认值也落盘，配置目录看不出「用户真正改过什么」。

本卡只做基建，**不改任何数据模型 / 不搬文件位置**，为 NT-076（单库）与 NT-077（配置分层）铺路。

## 技术要点 / 约束
- 🔴 原子写 temp 必须与目标**同目录**（跨盘 `File.Replace` 会失败）；目标不存在时 `File.Replace` 抛异常 ⇒ 先判存在再决定 `Replace` / `Move(overwrite: true)`。
- 🔴 「懒创建」的语义要写死：**默认值 = 无文件**。读方必须能接受文件缺失（现有实现大多已是「缺 = 默认」），改造前逐个确认。
- ⚠️ 行尾：工作区是 CRLF（`core.autocrlf=true`），写入保持原样，⛔ 在 helper 里统一改行尾（避免整文件 diff 噪声）。
- ⚠️ 删除文件的操作只在 `Save` 后判定，⛔ 不在启动时扫描删除 —— 避免误删用户手工加的内容。
- ⛔ 本卡不引入 `System.Text.Json` 源生成器 / 不改序列化风格（三种风格共存留给 NT-077 统一）。

**新增**：`Core/Services/AtomicJsonFile.cs`
- `Write(path, content)`：同目录 `.名字.guid.tmp` → `File.Move(overwrite)`；内容为 `""` / `{}` / `[]` / `null` ⇒ **删目标文件**（懒创建）。
- `IsEmpty(content)` 公开，供启动清理复用。
- 明确边界：**只给配置 / 小型状态用**，⛔ 不用于用户导出文件（删空文件会让用户以为导出失败）。

**改（17 处写入点，逐个替换为 `AtomicJsonFile.Write`）**

|---|---|
| Core | `JsonOptionsStore`（**一处覆盖 4 个模块设置**）/ `ThemeService` / `FavoritesService` / `ColumnLayoutService` / `AppConfigService` / `ConfigStoreService`（备份恢复段） |

**去重**：`ScriptStoreService.WriteAtomic`（原本自己实现了一份 temp+rename）改为转调 `AtomicJsonFile`，全工程只剩一个实现。

**启动清理**：`ConfigStoreService` 构造里新增 `PruneEmptyConfigFiles()` —— 递归扫 `config\**\*.json`，
内容为 `{}` / `[]` / `null` / 空串的**直接删除**（语义 = 文件不存在 ⇒ 默认值）；跳过以 `.` 开头的目录 / 文件（`.bak-*` 归档不动）。
⇒ 现有 15 个文件里 `hosts-profiles.json`、`scrape-tasks.json` 这类空壳**首次启动即消失**，不必等下次保存。

**`winget.json` 迁移（未删除，改为改名升级）**：`PackageSettingsService.Load()` 读旧文件**成功后** `File.Move` 成 `package.json`；
失败（占用 / 只读）下次再试。比「直接删」安全：万一新文件写不进去，旧设置还在。

**未做 / 有意保留**：
1. `active-profile.txt`（2 处）仍是 `File.WriteAllText` —— 它是纯文本指针、不是 JSON，`AtomicJsonFile` 语义（空即删）不适用。

   `HostsService` 写系统 `hosts` 文件 —— **保持原样**，⛔ 不属于配置写盘。
3. 未做「默认值判定」的深比较：只按「序列化结果为空集合 / 空对象」判定。

**风险提示**：`PruneEmptyConfigFiles` 是**删除操作**。依据是「读方一律把文件缺失当默认值」——
若有某个 store 用 `File.Exists` 判定「是否首次运行 / 是否要播种」，删空文件会改变其行为。
已核对 `BuiltinCollectorSeeder` / `ExampleSeeder` 用的是 `.seeded` 标记文件（不受影响）；
其余 store 均为「读不到 ⇒ 默认值」。
