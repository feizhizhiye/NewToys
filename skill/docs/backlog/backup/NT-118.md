## 背景 / 目标

把 NT-117 产出的加密包投递出去：网盘（WebDAV）为主，邮箱（SMTP）只发小包。通道按**后端适配器**实现（framework §2.1），页面按通道能力裁剪。

## 验收标准（Acceptance Criteria）

- [ ] 1. 通道契约 `IBackupTarget`：`PutAsync` / `ListAsync` / `DeleteAsync` / `MaxSize` / `DisplayName`；实现两个：`WebDavTarget`、`SmtpTarget`。
- [ ] 2. `settings-backup` 增「投递目标」节：WebDAV（URL / 用户名 / 密码 / 远端目录 / 测试连接）、SMTP（服务器 / 端口 587 / 账号 / 授权码 / 收件人 / 附件阈值）。
- [ ] 3. 任务编辑可勾选多个目标通道；每通道独立保留份数与独立失败重试（3 次，指数退避）。
- [ ] 4. `backup-archives` 增「远端」视角：`PROPFIND` 列目录 + 大小 / 时间 / 远端路径；远端包可「下载后还原」与「删除」。
- [ ] 5. 上传后校验：远端大小 + SHA256（WebDAV 用 `HEAD` + 下载前 N KB 比对不可行 ⇒ 以大小 + `GET` 校验和为准，实现取其一并在文档写清）。
- [ ] 6. 保留轮转：按任务 × 通道删超出 N 份的最旧包；首次启用需在设置里显式打开「自动删除远端旧包」才执行（默认关，防误删）。
- [ ] 7. SMTP：单包超阈值 ⇒ 该通道跳过并给出「改用网盘」提示，⛔ 不切分多封发送；只保证 587 STARTTLS（465 隐式 TLS 不支持）。
- [ ] 8. 凭据落 `config\backup\accounts.json`，密码/授权码进**同一个密码库**（受主密码保护），⛔ 明文。
- [ ] 9. 静态检查 PASS。

## 技术要点 / 约束

- 🔴 WebDAV 只用标准动词（`PUT` / `PROPFIND` / `DELETE` / `MKCOL`），⛔ 不依赖厂商私有 API；Basic Auth over HTTPS 是底线（`http://` 给红色警告）。
- 🔴 上传大文件须流式（`Stream` 直传，⛔ 不 `ReadAllBytes`）；配 `HttpClient` 超时（默认 100s）要按包大小放大。
- 🔴 邮件附件是 base64 膨胀 ~33%，阈值判定要算膨胀后大小，否则客户端拒收。
- 🔴 远端目录不存在时 `PROPFIND` 返 404 ⇒ 先 `MKCOL` 逐级建。
- ⛔ 不做断点续传 / 分片上传 / 秒传 / 分享链接（v2 评估）。
