# NT-048 · 修复分屏贴靠**初次失效**（首次拖边不贴靠，最大化一次后恢复）

- 依赖：**NT-040**（官方 CSD 路线）｜**NT-041**（样式位补丁已删）｜**NT-042**（已证与 `SetWindowRgn` 无关）

## 背景 / 现象

2026-10-15 用户实测回报：

> 分屏功能，**初次使用不行**，好像**最大化后好了**。

⛔ **关键排除**：该现象是在 NT-042 基准版本上观察到的 —— 该版本 `UseSquareRegionHack = false`，`SetWindowRgn` **全程未生效**。
⇒ 贴靠失效与「矩形窗口区域」无关，**不要往 `ApplySquareRegion` 上找**。

## 🔴 排查顺序（定点验证，⛔ 不许猜着改）

按序验证，每步先**取证**再决定是否动手：

1. **先查窗口样式位在「冷启动 → 首次贴靠前」是否已设全**
   - 关注 `WS_THICKFRAME` / `WS_CAPTION` / `WS_MAXIMIZEBOX` / `WS_SYSMENU`（贴靠资格依赖它们）。
   - 🔴 **诊断只能写文件**（`%LOCALAPPDATA%\NewToys\logs\` 或临时文件）—— ⛔ 无边框自绘窗口的 `Window.Title` **界面上看不见**，⛔ `DwmGetWindowAttribute(33)` **不支持读**（永远 -1）。
   - 对照 NT-041 留下的警告：`ShellView.axaml.cs` 注释明确写了「若日后贴靠再失效，**先怀疑是不是装饰被改回 `BorderOnly` / `None`**」。
2. **查 WndProc 钩子安装时机**：`InstallSnapFrameFix()` 在 `OnOpened` / `OnLoaded` 哪个点装？若在首次布局前装，`ExtendClientArea` 尚未跑完 → 前几帧样式位不完整。
3. **排除自绘抓取区抢事件**（NT-025 / 需求 §4.1）：四边 5px + 四角 10px 的透明热区由 `ElementRole` 标注给系统；确认拖标题栏走的是 `BeginMoveDrag`（而非落在抓取区触发 `BeginResizeDrag`）。
4. **排除全屏遗留态**：`_isFullScreen` / `WINDOWPLACEMENT` 是否残留（NT-044：全屏退出时 Avalonia 用 `SetStyle(_savedWindowInfo.Style)` **整体覆盖样式**）。

⛔ **禁止的做法**：把 NT-041 删掉的 `ApplySnapEligibleStyles` 手工补位抄回来 —— 已证它会与 Avalonia 的重算互相打架（状态变化时它把你补的位抹掉，你再补 → 无谓拉锯）。

## 验收标准（可验证清单）
- [ ] **冷启动 → 首次**把窗口拖到屏幕左 / 右边缘 → 出现 Win11 贴靠预览，松手能贴靠成功（⛔ 必须先最大化一次才生效 = 未通过）。
- [ ] 贴靠后：无露缝（NT-041 保留的 `WM_NCCALCSIZE` 零内缩仍生效）、无内容裁切、**方角保持**（NT-034）。
- [ ] 回归：最大化 → 还原 → 再拖边，仍可贴靠。
- [ ] 回归：全屏进 → `Esc` 出 → 再拖边，仍可贴靠（NT-044 已知风险项）。
- [ ] 回归：普通窗圆角 / 最大化无边框 / 全屏铺满三态无变化。
- [ ] 静态自检通过（`check.ps1` + `check-axaml-props.ps1`）。

## 技术要点 / 约束
- 🔴 圆角来自 `WS_THICKFRAME | WS_CAPTION`，与贴靠资格**绑死** ⇒ ⛔ 别动这两个样式位（动了方角与贴靠一起没）。
- 🔴 Avalonia 每次 `ShowWindow` → `ExtendClientArea()` → `UpdateWindowCornerPreference()` 会重算并回写偏好 ⇒ 补压必须放在 **WndProc 转发处理完之后**（现由 `SnapFrameWndProc` 的 `WM_WINDOWPOSCHANGED` / `WM_SIZE` / `WM_STYLECHANGED` / `WM_SHOWWINDOW` 分支负责）。
- ⛔ **一处一处改、一处一处验**（用户铁律）。本项只解决「贴靠初次失效」，不顺手改别的东西。
