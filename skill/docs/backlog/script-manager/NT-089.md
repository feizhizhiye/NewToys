## 一、背景与目标

需求 §2.3 定案：`web-scrape` / `web-rule-editor` / `web-crawl` 三页从网络工具迁入**脚本中心**，网络工具收窄为「网络配置与诊断（+NT-093 出口代理）」。

🔴 **分期修正（本次细化的核心结论）**：原分期把 089 定为「只搬三个规则服务」，但实测定不可行 ——

`CrawlPanelViewModel` / `RuleCatalogViewModel` / `RuleEditorViewModel` **同时依赖** `RuleFileService` + `RuleRunService` + `RunRecordService` + `DownloadService` + `FlowService` + `WebTransferService`（已在 `src/Module.WebTools/ViewModels/` 逐行核实）。只搬三个服务 ⇒ WebTools 侧 VM 编译不过；把 VM 留 WebTools ⇒ 要有两份服务，必然漂移（与 §2.3.7①同款理由）。

⇒ **089 = 抓取能力整体平移（服务 + 模型 + 三页 VM/View + 规则文件）**，090 只留「泛化与收尾」。

用户可见变化：

1. 左树里三页从「网络工具」移到「脚本中心」（⛔ Key 一律不改：`web-scrape` / `web-rule-editor` / `web-crawl`）。
2. 规则文件目录 `<DataDir>\web-tools\rules\*.py` → `<DataDir>\script\rules\`。
3. `web-scrape` 终态 = 脚本库的 `category=rule` 筛选态（S2）。

## 四、技术要点

- **命名空间批量改**：`NewToys.WebTools` → `NewToys.ScriptManager`（Models/Services/ViewModels/Views 全改）；XAML 顶部 `x:Class` 全名 + `xmlns` 一并改；🔴 跨程序集 xmlns 用 `using:`（规则见 `ui.md`）。
- **行尾 CRLF**（`core.autocrlf=true`）：批量改文件用 `splitlines(keepends=True)` 原样写回。
- **Avalonia UserControl/Window 必须显式写 `public Xxx(){ InitializeComponent(); }`**，新 View 落位后逐对检查（漏了 XAML 静默不加载）。
- **规则 .py 的读取/写入保持原样**：`RuleFileService.SafeName` / `ReadScriptHeader` 逻辑不动，只改目录常量。
- **DI 注册**：三服务与 VM 在 `ScriptManagerModule.RegisterServices` 注册；`WebToolsModule` 同名注册删除。
- **规则运行路径**：`RuleRunService` 依赖 `PythonRuntime`（Core，`py_worker` 由它生成）⇒ 依赖面只有 Core，搬运安全；NT-088 后统一走 Core 的 `IScriptRunner` 语义（本卡只搬位置，⛔ 不改执行语义）。
- **改动落两个模块程序集** ⇒ 与 NT-088 分开两批（088 落 Core = 整体重编；089 只重编两模块）。

## 六、风险 / 待拍板

1. **`WebTransferService` 归属**（S1 第一步 grep 判定）：若 HTTP 测试页也用 ⇒ WebTools 保留一份、ScriptManager 搬一份（**双写，须注释标注**，与 §2.3.7②同类成本）；若只有抓取三页用 ⇒ 随迁并在 WebTools 删除。**默认按「随迁」推进**。
2. **条目存储 API 是否容得下 rule 条目**（S2 前置）：脚本库条目现由 `ScriptScanner` + `QuickActionService`（落 `config\script\script.json` / `data\script\script.db`）管。S2 需把外部来源（rules 目录）合并进同一集合。
   - 推荐：**不改存储格式**，新增一条「来源 = rules 目录」的扫描入口，产出 `QuickAction`（`Category=rule`）后走现有写入路径。
   - 若现有 `ScriptScanner` 只认单一目录常量 ⇒ 在 ScriptManager 内扩展（⛔ 不上提 Core）。
3. **规则参数**（§2.3.2 说「规则 = 带参数的 Python 脚本」）：本卡只保证文件与条目搬过来，**参数化执行（base_url / 变量占位符）归 NT-092 命令链**，089 不做。
4. **`accept.ps1` 产物计数**：本卡不增不减程序集个数 ⇒ 产物核对不受影响（若 091 新模块另算）。
5. **旧目录数据**：用户已明言「无所谓老用户」（§6.2 v3.71⑤），但规则文件是用户自建资产 ⇒ S1 采用**移动 + 旧目录留空壳**，不做自动回滚脚本。
