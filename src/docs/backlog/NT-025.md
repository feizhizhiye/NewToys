## 背景 / 目标
用户新需求（2026-10-13，v3.26）：① 窗口**不能拖边框缩放**；② **不能与其它软件分屏**（要一半浏览器一半本软件审待办）。用户拍板：手动拖拽缩放能解决分屏需求即可，snap 贴靠随原生移动循环验证，⛔ 不专门做 Snap Layouts 钩子。

前置实证（2026-10-13 运行时程序集探针 + GitHub #21202）：
- Avalonia 12.1.3 **没有 `ExtendClientAreaChromeHints`**（11 时代 API 已移除）；`SystemDecorations` 已废弃（`Use WindowDecorations instead`）
- `WindowDecorations` 托管装饰在 Win32 上不可用：`BorderOnly` 丢 `WS_CAPTION`、`ElementRole` 拦截标题栏输入 → **自绘是唯一路线**
- `BeginResizeDrag(WindowEdge, e)` + `WindowEdge` 八向枚举 + `StandardCursorType` 全部方向光标**均已实证存在**；标题栏拖拽移动已在用 `BeginMoveDrag`

## 技术要点 / 约束（规范章节、坑点、关键文件）
- 🔴 **抓取区实现**：`ShellView.axaml` 根 Grid 之上叠 4 条边 `Border`（`Background="Transparent"`、宽/高 5px、四角 10px 方块，`IsHitTestVisible=True`），`PointerPressed` → `BeginResizeDrag(edge, e)`；`WindowEdge` 八向：NorthWest/North/NorthEast/West/East/SouthWest/South/SouthEast；光标 `StandardCursorType`（`SizeWestEast`/`SizeNorthSouth`/`TopLeftCorner` 等，均已实证）
- 最大化判定：`WindowState == Maximized` → 抓取区 `IsHitTestVisible=False`（⛔ 不只靠视觉隐藏——热区必须真关）
- ⛔ 抓取区别挡住页面内容：只占窗口最外缘 5/10px；内容区 `Margin` 不动；测试点：抓取区上点击不应穿透到列表行
- **bounds 记忆**：`Closed` 事件存（`config\window.json`，按配置天然隔离——每配置写自己目录）；启动时读 + `Position`/`Width`/`Height`/`WindowState` 还原；还原前用 `Screens` 夹进工作区；最小化时不覆盖位置
- ⚠️ **Avalonia 12.x 坑（规范 附录A）**：`VisualRoot as Window` **恒为 null**（视觉根是 `TopLevelHost`）→ 取窗走 `FindLogicalAncestorOfType<Window>(true)`
- ⚠️ snap 贴靠是否生效取决于 Win11「贴靠窗口」设置 + `BeginMoveDrag` 原生循环——**实机验证**，不成功先记录再议（⛔ 不擅自加 WndProc 钩子扩大范围）
- 分屏不做：Snap Layouts（最大化按钮悬停面板）、自定义 WndProc——需求明确不做

- **2026-10-13 实机验证反馈 + 修复**（用户逐项验 v3.28 后）：
  - ✅ **通过**：四边 / 四角拖拽缩放（八向光标）、最大化后抓不动、回归（标题栏拖拽 / 双击最大化 / 标签滚轮 / 窗口按钮）、**大小记忆**
  - ❌ **问题 1（已修）—— 位置没记住**：实测 `config\window.json` 存成 `X=0,Y=0`（尺寸 1157×758 是对的）。**根因**：`Closed` 时窗口句柄已销毁，`Window.Position` 退化成 `(0,0)`（`ClientSize` 是 Avalonia 侧缓存，所以尺寸没受影响）。**修法**：① 存点从 `Closed` 改到 **`OnClosing`**（句柄还活着）；② 位置改走 **`GetWindowRect`** 读真值（`Position` 只作兜底）；③ `OnOpened` **再补设一次**位置（构造期设的可能被首次 Show 覆盖）
  - ❌ **问题 2（已修，待复验）—— 系统贴靠全失效**：拖到顶边不最大化、`Win+←/→` 与拖到屏幕边缘贴靠都无反应。**根因**：Windows 的贴靠由**系统**执行，但只对带标准样式的顶层窗口生效（`WS_THICKFRAME` 等）；无边框（`WindowDecorations=None`）把这些样式去掉了 → 系统不认。**修法**：`OnLoaded` 里 `ApplySnapEligibleStyles()` 补回 `WS_THICKFRAME | WS_MINIMIZEBOX | WS_MAXIMIZEBOX | WS_SYSMENU` + `SWP_FRAMECHANGED`（客户区仍自绘，`WM_NCCALCSIZE` 归零不画系统边框）。⚠️ **回滚方式**：删掉 `OnLoaded` 里那一行调用即可
- **2026-10-13 复验第二轮：贴靠仍未通过 → 查 Avalonia 源码定论 + 改走官方装饰路线**（用户复验：位置记忆 ✅ / 无细边框副作用 ✅ / 回归 ✅ / **贴靠仍全失效** ❌；用户提示参考同为 Avalonia 的 Watt Toolkit）：
  - **根因（读 Avalonia 12 的 Win32 源码 + 官方文档定论）**：① `WindowImpl.BeginMoveDrag` 实际发的是 `WM_SYSCOMMAND / SC_MOUSEMOVE` + `WM_LBUTTONUP`，**不是** `WM_NCLBUTTONDOWN / HTCAPTION` —— 系统不把它当"拖标题栏"，**因此不触发贴靠**（这正是贴靠失效的直接原因，与样式无关）；② `WindowDecorations="None"` 时 Avalonia 的样式计算**不给** `WS_BORDER/WS_CAPTION/WS_THICKFRAME`（`WS_THICKFRAME` 条件 = `Decorations != None && IsResizable`），且 `ExtendClientArea()` 的前置条件 `GetStyle().HasFlag(WS_BORDER)` 不成立 → **DWM 扩展整段被跳过** → 系统装饰语义（贴靠 / 最大化动画 / Win+方向键）全没了。
  - **正解（Avalonia 12 官方路线，与 Watt Toolkit 同路）**：**保留系统装饰** + 把客户区扩展进装饰区 + 用 `WindowDecorationProperties.ElementRole` 做命中测试，让**系统**接管拖动 / 缩放（贴靠随之生效）：
    - `ShellView.axaml`：`WindowDecorations="None"` → **`"Full"`**（保留 `WS_CAPTION` 等 → 贴靠资格；`ExtendClientAreaToDecorationsHint=True` + `TitleBarHeightHint=40` 此时才真正生效）
    - 标题栏容器标 **`ElementRole="TitleBar"`** → 系统原生拖动（含拖到边缘贴靠 / 拖到顶边最大化 / 双击最大化）
    - 8 个抓取区改标 **`ResizeN/S/E/W/NE/NW/SE/SW`** → 系统原生缩放（光标也由系统给）
    - code-behind 的 `BeginMoveDrag` / `BeginResizeDrag` / 光标设置与 `ApplySnapEligibleStyles()` **全部保留作兜底**（角色生效时它们不会被触发）
  - ⚠️ **回滚方式**：`WindowDecorations` 改回 `None` 即可（一行）
  - 🔎 **测试信号（帮我们判断系统路径是否接管）**：若**双击标题栏最大化出现"跳两次/闪一下"**或**拖动明显更跟手**，说明 `ElementRole` 已生效 → 下一步就把我们自绘的兜底处理器删掉，代码反而更简单；若行为与之前完全一样 → 说明 12.1.3 的 Win32 角色映射没生效，改走"应用内自带贴靠命令"（自己算工作区设 Position/Size）
- **2026-10-13 复验第三轮：贴靠生效 ✅，但 Full 装饰带来两个副作用 → 空装饰主题 + 左树底部改显「配置 · 版本」**（用户实测：**贴靠全部可用** ✅；副作用：① 标题栏最右侧**多一个按钮**，点它之后回到旧状态且**标题栏按钮全部失效**；② 标题栏**最左侧把窗口标题文字画进来了**（截图里 `NewToys · default` 与 ≡/⟳ 重叠）；③ 要求：把配置名挪到**左菜单栏底部**、与版本号同显）：
  - **根因**：`WindowDecorations="Full"` + `ExtendClientAreaToDecorationsHint=True` 时，Avalonia 会**自己画一套窗框**（`WindowDrawnDecorations` 带 `Title` / `Content` / 阴影 / 边框 / 标题栏 / 缩放抓取区，默认主题里还有系统风格按钮）→ 盖在我们的标题栏上（文字重叠、多出按钮）。
  - **修法**：`App.axaml` 增一个**不做任何绘制**的 `ControlTheme x:Key="NoDrawnWindowDecorations" TargetType="chrome:WindowDrawnDecorations"`（**不设 Template = 无模板 = 不画**）；`ShellView` 设 `WindowDecorationsTheme="{StaticResource NoDrawnWindowDecorations}"`。拖动 / 缩放 / 贴靠仍由 `ElementRole` 的系统命中测试负责，界面只留自绘标题栏与抓取区。
  - **左树底部改显「配置 · 版本」（用户要求）**：`ShellViewModel.TreeVersionText` 由占位 `"1.26.10"` 改为 **`<配置名> · <版本号>`**（版本取 `UpdateService.CurrentVersion`——与「设置 → 关于」同源；配置名取 `IProfileService.ActiveProfile`）；ShellViewModel 构造注入 `IProfileService`；XAML 加 `ToolTip="当前配置 · 版本号"`。需求 §4.3 / §3.5 与规范 §2.1 同步。
  - ⚠️ **回滚方式**：`WindowDecorations` 改回 `None`（一行；那会失去系统贴靠）
- **2026-10-13 复验第四轮：空主题无效 → 改 `BorderOnly` + 手工补 `WS_CAPTION`**（用户实测：**底部「配置 · 版本」显示正常** ✅；但重叠与多余按钮**依旧**）：
  - **为什么空主题没用**：读 `Window.cs::ComputeDecorationParts()` 定论 —— `if (WindowDecorations != None) { if (platformNeeds.HasFlag(TitleBar) && **WindowDecorations == Full**) parts |= TitleBar; ... }` → **`Full` 是唯一会加 TitleBar 部件的取值**，`WindowDecorationsTheme` 只是"渲染那套部件用的主题"，部件本身照样存在；而且 `IWindowDrawnDecorationsTemplate` **没有任何 public 实现类** → 应用侧给不出真正的空模板。
  - **修法**：`WindowDecorations="Full"` → **`"BorderOnly"`** —— 此时 `ComputeDecorationParts()` 得到的部件集合为 **None**（TitleBar 只在 Full 时加；Shadow/Border/ResizeGrips 由平台标志，Win32 只上报 TitleBar）→ **Avalonia 什么都不画** ✓；同时 `BorderOnly` 仍给 `WS_BORDER`（`ExtendClientArea()` 的前置条件成立、DWM 扩展照旧、系统不画标题栏）✓。
  - **代价与补偿**：`BorderOnly` **不设 `WS_CAPTION`**（`Full` 才设）→ 贴靠资格可能丢失 → 由 code-behind 的 `ApplySnapEligibleStyles()` **手工补 `WS_CAPTION`**（+ THICKFRAME/MIN/MAXBOX/SYSMENU）；并在 **`WindowState` 变化时重补**（Avalonia 状态变化会重算样式、抹掉我们补的位）。
  - ⚠️ **本轮要重点验证**：贴靠是否仍然可用（若失效 → 说明 CAPTION 位被重算抹掉或系统另有要求，下一步改回 `Full` 并在代码里直接隐藏 Avalonia 的装饰元素）。
  - 空 `ControlTheme`（`NoDrawnWindowDecorations`）保留作兜底（BorderOnly 下部件本来就为 None）。
- **2026-10-13 复验第五轮：外观 ✅ / 贴靠 ✅ / 标题栏交互失效 → 交互控件补 `ElementRole="User"`**（用户实测：① 标题栏干净 ✅ ② 贴靠可用 ✅ ③ ❌ **五个按钮与标签页栏全部不可用**（外观正常））：
  - **根因**：`TitleBarGrid` 整块标了 `ElementRole="TitleBar"` → 该区域被系统按**标题栏**处理（`HTCAPTION`），里面的按钮 / 标签收不到点击。
  - **修法**：**TitleBar 区域里的交互控件必须另标 `ElementRole="User"`（放行点击）** —— 标在三处容器上：左按钮组 `StackPanel`（≡ ⟳）/ 标签条 `TabStrip`（标签 + ＋）/ 右窗口按钮组 `StackPanel`（— □ ✕）。中间两处 **24px 留白不标 → 保持 `TitleBar` → 那里仍是系统拖动（贴靠有效）**。
  - 🔎 若本轮标签 / 按钮仍无响应（说明角色只认"命中元素本身"而非祖先）→ 下一步把 `User` 逐个标到按钮与标签项模板上。
