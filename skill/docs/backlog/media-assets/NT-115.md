## 背景 / 目标

1. **现在只有一个"按元数据找东西"的页**：`assets-all` 是列式列表（7 列 + 筛选 + 搜索），适合"我知道文件名 / 标签 / 类型"。但用户真实场景常是"我知道它在哪个盘的那个文件夹里"—— 现在只能靠「存储源」列肉眼扫，没有目录层级。
2. **缩略图生成了却从没露过面**：`ThumbnailService`（视频抽帧 / 图片缩放 → `cache\assets\thumbs\{sha1(path)}.jpg`）已在扫描时自动跑，但**全模块零处引用**，界面上看不到一张图。图标卡视图是它的第一个消费者。
3. **目标**：新增 `assets-browse`「资产浏览」= 资源管理器形态 —— 左目录树 → 右侧「图标卡 / 详细信息」双视图 → 双击用默认程序打开。与 `assets-all` 分工：**`assets-all` 按元数据找，`assets-browse` 按磁盘位置翻**。

## 关键决策（拍板记录）

| 决策 | 结论 | 理由 |
|---|---|---|
| 新建独立页 vs 在 `assets-all` 加视图切换 | **新建 `assets-browse`** | 资源管理器灵魂是目录层级；视图切换后续可顺带补进 `assets-all`（本卡不做） |
| 目录数据来源 | **库里索引**（`storages.root_path` + `file_locations.relative_path` 聚合），⛔ 不实时枚举磁盘 | NAS / 移动盘离线时实时枚举会卡死；索引即真相 |
| 是否动框架层 | **不动**（`Shared` / `Core` / `Shell` / `NewToys.UI` 零改动） | 自绘三列 + 复用现存 `ColumnGrid` / `ListFooterBar` / `DetailCardHost`；网格用 Avalonia 内置 `ItemsRepeater` |
| 网格虚拟化 vs 分页 | **`ItemsRepeater` + `UniformGridLayout` 虚拟化为主**，分页兜底（每页 120） | 一个目录几千项时不能建几千个容器；若 `UniformGridLayout` 在 12.1.4 有坑则退回「分页 + 限额并发加载」 |
| 缩略图内存 | LRU 上限 300 张 + 按显示尺寸解码（`Bitmap.DecodeToWidth`） | 5000 张原图解码必炸；只解码可见 / 本页 |
| 与 v3.34「⛔ 卡片 / 网格视图不做」冲突 | **该条由本卡作废**（用户 2026-10-27 亲自要求） | 记录在此，避免后续把"不做网格"当铁律引用 |

## 技术要点

- **不动框架层**：全部落 `Module.MediaAssets`。用到的框架能力全是**既有只读复用** —— `NewToys.UI` 的 `ColumnGrid` / `ListFooterBar` / 详情卡宿主，不新增契约。🔴 若实施中发现必须给 `NewToys.UI` 加控件（例如通用缩略图网格），**先停下报告，不擅自改框架层**。
- **不继承 `ListPageViewModelBase`**：本页是树 + 网格，非列表页（先例 = `AssetCategoriesViewModel`）；但**多选 / 底栏 / 状态栏 / 分页**语义照抄基类口径，外部表现一致。
- 新增文件（建议划分）：
  - `Models/AssetTile.cs` — 网格项模型（`AssetRow` + `ThumbPath` + `IsLoaded` + `PlaceholderIconKey` + 尺寸）
  - `Models/AssetDirNode.cs` — 目录树节点（`StorageId` / `AppPath` / `Name` / `ChildCount` / `IsOnline` / `Children` / `IsExpanded`）
  - `Services/AssetBrowseService.cs` — 目录树聚合 + 目录内查询（可作 `AssetService` partial，二选一在实现时定）
  - `Services/AssetThumbCache.cs` — LRU + 后台解码 + 并发闸（单例）
  - `Views/AssetBrowseView.(axaml|axaml.cs)`、`ViewModels/AssetBrowseViewModel*.cs`
  - `Models/AssetColumns.cs` — 从 `AssetAllViewModel.Columns`（`AssetAllViewModel.cs:137`）抽出的列定义，两页共用（**⛔ 保留 `assets-all` 的现有行为与偏好键**）
- **目录树聚合口径**：`SELECT storage_id, relative_path FROM file_locations WHERE status <> 'deleted'` 一次取回 → 内存按 `\` 切段建树（1w 行足够快）；`relative_path` 为 NULL 的旧数据用 `path` 减 `storage.root_path` 兜底。LIKE 前缀查询沿用 `AssetService.Query.cs` 既有的 `\` 转义写法（⛔ 手拼未转义前缀）。
- **多位置资产**：一个 `asset` 可能有多个 `file_location`。目录内**按位置建行**（同一资产在 A/B 目录各出现一次是正确语义）；计数按 `distinct asset_id`；详情卡按 `asset_id` 认领，避免同资产两行互相踢掉选中。
- **缩略图**：路径 = `ThumbnailService.ThumbPathFor(filePath)`；只读缓存目录，⛔ 不在浏览时同步生成（生成走第 7 条显式命令）。`Bitmap` 后台线程构造、UI 线程赋给属性；`DecodeToWidth(96/144/200)` 按当前档位解码。
- 🔴 已知坑（沿用模块经验）：`Bitmap` 可能占着缩略图文件 ⇒ `ThumbnailService` 已有的 `.tmp.jpg` + `File.Move` 覆盖策略不动；网格项被回收后 `Bitmap` 要及时置 null，否则 LRU 就失效。
- **性能红线**：切换目录后 200ms 内必须出首屏（缩略图可后到）；⛔ 任何"为整个目录预生成缩略图"的隐式行为。
- 配置文件：视图模式 / 图标尺寸 / 上次目录 三个字段落 `config\media-assets.json`（经 `MediaAssetsSettingsIO` 现有唯一写入通道，不新开文件、不新增独立设置节）。

## 风险 / 待实施时定

1. **详情卡复用是最大不确定项**：`AssetAllViewModel.Detail.cs` 的 descriptor 构建与回调（收藏 / 评分 / 改名）深度耦合 `assets-all`。做法 = 抽模块内 `AssetDetailBuilder`（输入行 + 服务，输出 `DetailCardDescriptor`）+ 宿主接口 `IAssetDetailHost` 回写。若评估后成本过高，**降级路径**：本页详情卡先只读（展示字段 + 打开按钮），交互命令留在右键菜单 —— 降级要在卡的执行记录里写明。
2. `ItemsRepeater` + `UniformGridLayout` 在 Avalonia 12.1.4 的虚拟化/回收事件是否好用；不行则退回分页（每页 120）+ 限额并发（4）加载。
3. 目录树深度极端（如 8 层 + 宽扇出）时的左侧滚动性能 —— 树节点按需展开时再建子节点（懒建树）。
4. 同一物理文件在树里出现两次（多存储源指向同盘）属既有数据现象，本卡不治理（NT-114 的「查重合并」负责）。
