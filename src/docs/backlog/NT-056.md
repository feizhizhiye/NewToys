## 背景 / 目标
「设置 → 路径配置」（`settings-path`）与「设置 → 配置」（`settings-profile`）是**两个页面两张表**：
- 路径配置 = `app.json` 的路径项（名称 / 当前值 / 类型 / 说明 / 操作），已是标准列表页（`ListPageViewModelBase` + `ColumnGrid` + Shell 详情卡）；VM 540 行。
- 配置 = `profiles\` 下的配置档（配置名 / 数据目录）+ 右侧 160px 自绘按钮列（7 个按钮）；**未**走标准列表页；VM 251 行。

**目标**：合并成**一张表**，用**分类列**区分行类型、并按分类决定工具可用性。**根本理由不是省代码（净变化 ≈ −50 ~ +50 行），而是把它定成"设置总表"** —— 后续若要「指定某个功能默认使用哪个 json / 配置」，只加一个分类值即可，⛔ 不再新开页面。

## 用户拍板记录（2026-10-15 会话）
1. 用户提出「合并 + 加分类列 + 按钮按分类可用」，评估后确认为本方案（备选的"同页两区"未采用）。
2. 与 NT-055 **同批执行**。
3. 🔴 **已知三点代价（用户已知情）**：① 两类行的**作用域不同**（路径行改的是"当前配置的 app.json"；配置行管的是"所有配置"、切换会**重启进程**）—— 靠分类列兜住；② 合并后工具条按钮约 10 个，未选中时大面积置灰 ⇒ 信息密度下降（缓解：按分类显示不同按钮组）；③ `名称` 一列两义（键名 / 配置名）、`当前值` 一类可编辑一类只读 ⇒ 排序 / 筛选口径要重定义。
