# NT-138 · 媒体资产：扫描提速（索引与增强解耦）+ 存储源页并入资产浏览页

> 模块：media-assets ｜ 优先级：P0（用户实测「扫描太慢」）｜ 状态：✔ 已实施（2026-11-03 用户本地 build 通过）
> 依赖：NT-116（资产浏览 = 真资源管理器）· NT-137（一目录一源口径）
> 创建：2026-11-03 ｜ 更新：2026-11-03

## 一、背景 / 目标

用户 2026-11-03 反馈两点：

1. 「扫描也太慢了」——根因是**扫描里同步跑增强**：`FlushNew` 每 200 个新文件就 `GetAwaiter().GetResult()` 等一批 ffprobe / ffmpeg（4 并发），几百个视频 = 几分钟，遍历只占小头。按目录切源后又新增每目录一次索引查询、每源两次收尾 UPDATE。
2. 「存储源这个功能页好像也没必要，都有资产浏览页了」——目录级库操作在浏览页已经有（加入资产库 / 重新扫描此目录），存储源页只剩运维信息。

用户拍板：`1 全做`（五项提速）；`2.b`（存储源页从菜单移除，View/VM 留档）；`3` 不自动读元数据、缩略图按需（浏览页滚动到才生成）、元数据保留开关。

## 二、范围

| 项 | 内容 |
|---|---|
| 扫描与增强解耦 | `ScanService.FlushNew` ⛔ 不再同步跑增强；新位置交 `OnNewLocations` → 模块接到 `TaskQueue` 后台补元数据（受 `AutoExtractMetadata` 控制，默认关）；缩略图**永不**在扫描里生成 |
| 缩略图按需 | `AssetBrowseViewModel.RequestThumbGeneration` 读 `AutoGenerateThumbnails`（关 = 只显示类型图标，不读盘）；生成仍由滚动视口驱动 |
| 索引一次读 | 新增 `AssetService.ListLocationsForStorages(ids)`：子树内所有源的位置一次查完（IN 分批 500）→ 内存按源分桶，换目录不查库 |
| 源登记提速 | 新增 `AssetService.InsertStorageFast(name, root)`：调用方已用内存字典判过不存在，⛔ 不再走会全表查的 `UpsertStorage` |
| 收尾合并 | 新增 `AssetService.FinishStorageScans(ids, scannedFrom)`：missing 校准 + `last_scan_at` 合成一个事务 |
| 遍历提速 | `EnumerateFiles` → `EnumerateInfos`（`EnumerateFileSystemInfos`，Length / LastWriteTime / Attributes 随枚举缓存，少一轮 stat） |
| 存储源页撤下菜单 | `MediaAssetsModule` 删 `assets-storages` 注册；View / VM 留档不注册 |
| 功能迁移 | 资产浏览左树右键新增「✏ 重命名目录源…」（只改 `storages.name`，⛔ 不动磁盘目录名）、「🗄 目录源类型 ▸ 本地 / 移动 / NAS」（只改 `storages.type`）、「⬆ 上线 / ⬇ 下线」（只写 `storages.online`）、「🗑 移出资产库…」（只删该目录的源与位置索引）与「🔄 扫描全部已入库」；原来的「➕ 加入资产库」「🔄 重新扫描此目录」保留 |

## 三、验收标准

- [ ] 扫描一个含几百个视频的目录：进度条快速走完，不再在中途停住等 ffprobe
- [ ] 扫描结束后任务中心出现「补元数据（N 个）」任务（`AutoExtractMetadata` 打开时）；关掉则没有
- [ ] 浏览页滚动时缩略图逐张出现；设置里关掉缩略图开关 → 只显示类型图标
- [ ] 菜单里**没有**「存储源」页；「资产浏览」左树右键有「🗑 移出资产库…」与「🔄 扫描全部已入库」
- [ ] 移出资产库后：该目录的文件从库里消失，磁盘文件一个都没少；重新「➕ 加入资产库」能找回
- [ ] 左树右键「✏ 重命名目录源」改名后：「全部资产」的「存储源」列跟着变，磁盘文件夹名不变
- [ ] 左树右键「🗄 目录源类型」选「移动硬盘 / NAS / 本地磁盘」即时打勾，重开页面仍是这个类型
- [ ] 左树右键「⬇ 下线」后该目录源标离线；「🔄 扫描全部已入库」不把它的文件标丢失；「⬆ 上线」恢复
- [ ] 只有右键目录本身是存储源时，重命名 / 类型 / 上线三项才可点（子目录上的菜单项灰掉）
- [ ] 一次扫描涉及多个目录源时，`storages.last_scan_at` 对子树每个源都写了（老库自动补列）
