## 一、背景与目标

PcTools 脚本中枢四态：**收集**（脚本收集 / 命令收集）→ **展示**（本卡）→ 编排（管道页，远期）→ 工作流（新模块，远期）。
原「系统信息」页写死 C# 采集，改为**通用脚本输出呈现器**：manifest 定义列与脚本，脚本只输出"按列对齐的值数组"，页面渲染成表。切"组合脚本"= 切 manifest。

## 二、范围（本期做）

1. **`ScriptRunner`（PcTools 内新增 `Services/ScriptRunner.cs`）**：唯一"跑脚本并拿回文本"的入口。

   - 进程启动：`UseShellExecute=false` + 重定向 stdout/stderr + **`StandardOutputEncoding/StandardErrorEncoding = UTF8`**（见 §三.4）。
   - 超时 / 取消（`CancellationToken`）/ 工作目录 / 环境变量注入 / 退出码。
2. **manifest 契约** `sysinfo\sysinfo.manifest.json`（位于 `IPcToolsSettingsService.EffectiveScriptsFolder` 下的 `sysinfo\` 子目录）——见 §三.1。
3. **脚本输出契约**：按列位对齐的值数组 —— 见 §三.2 / §三.3。

5. **行模型**：`SysInfoRow { ScriptId, RowKey, Status, Values[] }` —— 见 §三.3。
6. **定时刷新（per-script）**：全局单 `DispatcherTimer`（1s tick）扫描 `interval>0` 且 `auto:true` 的脚本单独重跑；按 `RowKey` 就地改值 / 新增追加 / 消失删除；手动「🔄 重新检测」= 全跑。最小 `interval` ≥2s。
7. **改名**：`PcInfoViewModel` / `PcInfoView` 标题改「信息展示」；`pc-info` 菜单 Key 不变。
8. **自定义表头**：列集合与宽度由 manifest 决定，显隐落 `ColumnLayoutService`（页键 `pc-info`）—— 见 §三.5（D1）。
9. **容错**：单脚本失败 → 该组保留上次值并标 `status=error` + 状态栏「⚠ 脚本失败：`<file>`」；整页不炸。
10. **应用路径段**：保留**内置采集器**（`ScriptId="builtin"`，读 `_cfg/_store/_pc`）—— 见 §三.6（D3）。
11. **功能按钮**：工具条 = 🔄 重新检测 / 📂 打开脚本目录 / ✏ 编辑 manifest / ⚙ 列设置 / ⏱ 刷新间隔 / 📦 导出脚本集合 / 📂 导入脚本集合 / 📋 复制全部；行级（右键）= 重跑该脚本 / 复制行 / 编辑脚本 / 打开脚本目录。
12. **导入导出脚本集合**：导出 = 把 `sysinfo\` 目录打包为 `.zip`（含 manifest）；导入 = 解压到 `sysinfo\`，**逐条目校验**（拒绝绝对路径 / `..` / 非 `.json` `.ps1` `.py` `.bat` `.cmd` 扩展名；已存在文件先备份为 `*.bak`）。
13. **详情卡**：保留 `IDetailCardSource`，`Fields` 由当前行的 `Cells` 动态生成（列 title → 值）；`Actions` = 复制「列 = 值」/ 打开脚本目录。
14. **页面骨架**：沿用 NT-063 `ListPageSkeleton` 四段 + 空态 `TextBlock.hint-text` + `Button.ghost`（NT-060 约定）。

## 三、契约与决策（本节是本卡的验收基线）

### 三.1 manifest

```json
{
  "schemaVersion": 1,
  "columns": [
    { "key": 1, "title": "分类", "width": 140, "visible": true },
    { "key": 2, "title": "项目", "width": "2*", "visible": true },
    { "key": 3, "title": "值",   "width": "3*", "visible": true }
  ],
  "scripts": [
    { "file": "os.ps1", "group": "操作系统", "interval": 0, "auto": false, "timeout": 30 }
  ]
}
```

- `columns[].key` = **稳定整数列位（1-based）**，与数组顺序解耦：值取 `values[key-1]`。用户调整 `columns[]` 显示顺序**不影响脚本输出**。🔴 这是消解"`key` 在数组模型里没用上"的歧义口径。
- `columns[].width` = `GridLength` 字符串（`140` / `2*` / `Auto`）；**宽度唯一来源 = manifest**（见 §三.5）。
- `columns[].visible` = **默认值**；运行时显隐以 `ColumnLayoutService` 为准。
- `scripts[].interval` 秒，`0` = 仅手动；`auto` 缺省 `false`（见 §三.7）；`timeout` 缺省 30s，上限 300s。
- 缺 `schemaVersion` / 值 > 当前支持版本 / JSON 语法错 → 视为坏 manifest：空态 + 状态栏 ⚠，⛔ 不抛异常、⛔ 不猜字段。
- `scripts[].file` 支持相对 `sysinfo\` 的路径；文件不存在 → 跳过该条并计入失败集合。

### 三.2 脚本输出外壳（宽松解析，三种形态都认）

优先级从上到下，命中即停：

1. `{ "rows": [ { "key": "cpu0", "status": "ok", "values": ["CPU", "处理器", "i7-13700"] } ] }` ← **推荐形态**
2. `[ { "key": "...", "values": [...] } ]`（顶层数组 + 对象行）
3. `[ ["CPU", "处理器", "i7-13700"] ]`（裸二维数组，无 key）

解析规则（硬）：
- **行级宽松**：非数组 / 非对象的行**丢弃**；`values` 字段不足补 `""`；超出 `columns` 长度的项**忽略**。
- **单脚本失败判定**：进程退出码 ≠ 0、超时、被取消、stderr 非空**且** stdout 无法解析 → `status=error`（stderr 非空但 stdout 可解析 → `status=warn`，只记不上报）。
- 顶层 JSON 无法解析 → 该脚本整批失败（不产生任何行）。
- ⛔ 脚本里 ⛔ 不得输出日志到 stdout（引擎无"注释行"概念）；调试信息走 stderr。

### 三.3 行模型与 RowKey

`SysInfoRow { string ScriptId; string RowKey; string Status; string[] Values; }`

- `RowKey` 取值优先级：`key` 字段 → `Values[0]`（第 1 列作身份）→ 行序号（`#<index>`）。**同 `ScriptId` 下 `RowKey` 必须唯一**，重复 → 后者覆盖前者并计入 warn。
- `Status` ∈ `ok` / `warn` / `error`（保留给 §2.1-4 管道地基；**本期不着色**，按 §四「不做」处理）。
- `ScriptId` = `builtin`（内置采集器）或 `scripts[]` 的 `file`（去扩展名，如 `os`）；同一 `file` 只许出现一次，重复在加载时告警并忽略后者。

### 三.4 编码（中文环境硬要求）

- `ProcessStartInfo.StandardOutputEncoding` / `StandardErrorEncoding` = UTF-8（无 BOM）。
- 注入环境变量：`PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`。
- `pwsh` / `powershell` 启动参数固定为
  `-NoProfile -NonInteractive -ExecutionPolicy Bypass -Command "[Console]::OutputEncoding=[Text.Encoding]::UTF8; & '<脚本路径>'"`
- 解码失败（非法 UTF-8）→ 该脚本失败，状态栏提示"输出编码非 UTF-8"。
- 注入环境变量 `NEWTOYS_SYSINFO_DIR` = `sysinfo\` 绝对路径（脚本定位同目录资源用）；工作目录默认 = `sysinfo\`。

### 三.5 列机制（D1，⚠假设 — 不扩展 `Shared`）

**事实核对**：`Shared/Models/ListPageViewModelBase.cs` 的列机制是「`Columns` 元数据 + 每列一个具名 `IsXxxVisible` 属性 + XAML 静态列」，注释明确"XAML 只能绑具名属性，绑不了字典"；`PcInfoView.axaml` 表头与行单元格均写死 `Grid.Column="0..3"`。manifest 列数可变 ⇒ 静态列不可行。

**决策 D1：不碰 `Shared/ListPageViewModelBase`（框架层冻结），页内自绘动态列。**
- VM 侧：`Columns` 由 manifest 动态生成 `ListColumn(key: "c"+key, header: title, width, sortable: true)`；行内单元格暴露 `SysInfoCell { Text, IsVisible }` 集合，`IsVisible` 在构建行时用基类 `Vis("c"+key)` 求值，列显隐变化后重建。
- View 侧：表头与行内单元格都用 `ItemsControl` + 横向 `StackPanel`，每项宽度由 VM 给出的 `Width` 绑定；列数任意。
- **代价**：ColumnGrid 的**列宽拖拽 / 锁定宽度（`ResizeColumns` / `LockColumnsBySample`）本期不接**；改宽走「⚙ 列设置」写回 manifest 的 `width`。
- 显隐落 `ColumnLayoutService.LoadPage/SavePage("pc-info")`，键 = `c<n>`；落盘里没有的新列取 manifest `visible`；manifest 里已删的列在落盘里忽略（不清理，回加列时偏好复现）。
- ⚠ 若用户要求"必须保留拖拽改宽"，则该条要改成"扩展 Shared 基类"⇒ 框架层改动，需重新授权，工作量另估。

### 三.6 应用路径段（D3，⚠假设 — 保留内置采集器）

**事实核对**：现 `PcInfoViewModel.Collect()` 的「应用路径」分类读 `_cfg`（`PythonPath` 等）/ `_store`（配置目录）/ `_pc`（脚本目录）—— 这些是注入服务，脚本读不到 profiles 上下文；改成 `app-paths.ps1` 得额外定义"配置文件路径注入契约"。

**决策 D3**：保留 C# 内置采集器，作为虚拟脚本 `builtin`（`group="应用路径"`），与 manifest 脚本合并展示；⛔ 不迁 `app-paths.ps1`。其余原有分类（操作系统 / CPU / 内存 / 磁盘 / 网络 / 运行时）全部改为随包脚本，C# 采集代码删除。

### 三.7 播种与安全（D2，⚠假设）

**事实核对**：`QuickActionService.cs:25/:468` 明确「⛔ 不再读 `defaults\*.default.json` 播种，首次运行即落空清单」（NT-060 定调）；原 Core 里的 defaults 播种代码已随 NT-060 **整段删除**（现 `Core/` `Shell/` 内零播种代码），`Shell/defaults\` 目录已空但 `Shell/Shell.csproj:37` 的 `None Update="defaults\**"` 复制规则仍在。

**决策 D2**：⛔ 不回退 NT-060 对「脚本收集 / 命令收集」的空清单结论；**仅为 sysinfo 一次性播种**，且**播种器落在 `Module.PcTools`**（⛔ 不进 Core —— 框架层冻结，⛔ 不复活旧 Core 播种器）：
- 随包资源 `Shell/defaults/sysinfo/{sysinfo.manifest.json, os.ps1, cpu.ps1, mem.ps1, disk.ps1, net.ps1, runtime.ps1}`（只放数据文件、零代码改动 ⇒ 不破框架层冻结；程序根即 `defaults\sysinfo\`）。
- `SysInfoSeeder`（PcTools 内 `Services/`）：首次打开本页（或 `sysinfo.manifest.json` 不存在）时，从 `Path.Combine(AppContext.BaseDirectory, "defaults", "sysinfo")` 逐文件复制到 `EffectiveScriptsFolder\sysinfo\`；目录不存在则创建；**已存在的文件一律跳过不覆盖**；播种完成写标记 `.seeded`（内容 = 包版本），存在标记且 manifest 在 → 不再播种（用户删脚本不会被复活）。
- 播种脚本 `interval` 默认 `0`、`auto:false`（首屏靠"打开即全跑一次手动检测"出数据，不依赖定时器）。

**安全（自动执行白名单）**：无人值守（定时器触发）只跑 `auto:true` **且** `interval>0` 的脚本；`auto:true` 只能由用户在 manifest 里显式手改。用户新增脚本默认 `auto:false`。页面状态栏常驻一行提示"本页执行 `sysinfo\` 下的脚本，请确认来源可信（风险自负）"。

### 三.8 超时 / 并发 / 刷新生命周期

- 并发上限 4（`SemaphoreSlim`）；同一 `ScriptId` 正在跑时，新的定时触发**直接跳过**（不排队、不叠加）。
- 定时器仅在「本页 = 当前激活标签页 且 主窗口可见」时工作；切走 / 最小化 / 隐藏托盘 → 暂停（不发请求），回来补一次到期脚本。
- 手动「🔄 重新检测」全跑：先取消在跑的定时任务再跑，避免同 `ScriptId` 双写。

1. 删 `Collect()` 里的操作系统 / CPU / 内存 / 磁盘 / 网络 / 运行时采集代码，改由 manifest 脚本产出；「应用路径」仍由 `builtin` 产出。

7. 行右键「重跑该脚本」只刷新该脚本的行；「🔄 重新检测」全跑并取消在跑的定时任务。
8. 导出→删目录→导入：脚本与 manifest 完整回来；导入含 `../evil.ps1` 或 `x.exe` 的 zip 被拒绝并报错。
9. 坏 manifest（语法错 / `schemaVersion` 999）→ 空态引导 + 状态栏 ⚠，页面不崩。
10. AI 侧 4 项静态检查 0 ERROR / 0 WARN；用户本地 `build.ps1` / `accept.ps1` 验收通过。

## 六、技术要点 / 风险

- 输出解析必须宽松：字段不足补空、超列忽略、非数组行丢弃、`RowKey` 重复后者覆盖。
- 后台线程跑脚本 + 解析，**批量回主线程**一次提交（防卡 UI）；定时刷新只 diff 该 `ScriptId` 的行。
- 异步多脚本结果乱序 → 合并按 `ScriptId` 归舱，⛔ 不按完成顺序追加。
- **执行用户脚本 = 执行任意代码**：白名单 `auto` + 状态栏风险提示，⛔ 不静默跑未知脚本。
- 播种只加不覆盖 → 避免复活用户删掉的脚本；`.seeded` 标记缺失时才补播。
- 🔴 `Avalonia UserControl` 必须显式写 `public Xxx(){ InitializeComponent(); }`（不会自动生成，漏了整块 XAML 静默不加载）。
- 🔴 跨程序集 xmlns 用 `using:`；UI 库 XAML 只许 `DynamicResource` 引主题键；图标只用 `Path` + `Icon*` StreamGeometry。
- ⚠ 实施首个验证点：`DetailCardDescriptor.Fields` 能否在 `Selected` 变化时动态重建（若为只读集合，则详情卡退化为固定 3 字段「脚本组 / 行键 / 状态」+ 值列表以多字段平铺）。
