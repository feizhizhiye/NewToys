## 一、定位

**NewToys 是作者个人自制的工具集——「带 GUI 的脚本管理器」。** 非商业、非通用产品，「自用顺手」第一。

每个页面 ≈ 一条或几条命令行 + 一份 `config/` 配置的封装。

## 二、边界

**判据**：「如果我只写个脚本会怎么写？现在少让用户做哪一步？」—— 这就是功能边界。

- **做**：把作者日常高频的终端 / 系统能力，包成可点、可配、可备份的界面。
- **不做**：脚本里不会有的东西——社交、推荐、引导、埋点、账号、云同步、**在线插件市场 / 商店**。
- **本地模块热加载**（丢 DLL 进 `Modules\`、点刷新即时装配）**要做** —— 它不联网、不下载、不建生态，等于「加一个本地脚本」。

## 三、技术框架（硬约束）

> 本节锁「软件框架长成什么样」。具体类名 / API 签名 / 踩坑见规范。

### 3.1 分层与依赖

```
Shared（契约 / 模型，不引 Avalonia）
  ▲
Core（服务实现，不引 Avalonia）
  ▲
Shell（宿主，引 Avalonia，AssemblyName=NewToys → NewToys.exe）
  ▲
Module.*（功能模块，只引 Shared + Core）
```

- **单向依赖**，禁止反向。
- **禁止模块引用 Shell**（循环依赖）；**禁止模块之间互相引用**；跨模块协作走 `Shared` 契约。
- **Shared / Core 禁止引用 Avalonia**（系统明暗、平台能力由 Shell 探测后注入）。
- 公共基类 / 契约放 `Shared`；被 ≥2 模块用或属应用级能力才上提，判断不清默认放模块内部。
- **UI 契约**（定义在 `Shared/Services/`，页面 VM 可选实现、Shell 统一消费）：
  `IDetailPanelProvider`（详情卡）、`IHistoryProvider`（历史栈）、`IStatusProvider`（状态栏）。

### 3.2 技术栈（锁定，禁止擅升擅降）

| 组件 | 版本 |
|---|---|
| .NET | net10.0 |
| Avalonia | 12.1.3 |
| CommunityToolkit.Mvvm | 8.4.2 |
| Microsoft.Extensions.DependencyInjection | 9.0.0 |
| Microsoft.Data.Sqlite | 9.0.0 |

- **禁止引入任何第三方 UI 组件库**（Material / Suki / FluentAvalonia / Semi 等）。
- **禁止引入第三方图标字体 / 图标包**；图标以 Avalonia 内置 `Geometry` 路径数据为**最终方案**（只可手工摘取公开图标集如 Lucide / Feather 的路径数据）。
- 包版本集中在 `src/Directory.Packages.props`（中央包管理）；csproj **不写** `<PackageVersion>`。
- `LangVersion=latest`、`Nullable=enable`、`ImplicitUsings=enable`。

### 3.3 框架层冻结

- `Shared / Core / Shell` 稳定后默认不再改，**新功能只在 `Module.*` 内**。
- 确需改框架层（新增全局服务 / 契约、调全局布局）**必须先获用户明确同意**，交付里独立说明。

### 3.4 模块化与热加载

- 模块编译为独立 DLL（`Module.<模块名>.dll`），实现 `IModule { RegisterServices, Initialize }`。
- **菜单只能在 `Initialize` 注册**；`RegisterServices` 禁注册菜单。
- **启动双轨**：Debug 用 `#if DEBUG` 显式类型清单；Release 扫 `<程序目录>\Modules\`，跳过已加载同名。
- **运行期热加载**：丢 DLL 进 `Modules\` → 点刷新 → 即时装配，不重启。
  - 只读本地 `Modules\`，**不联网不下载**；`Path.GetFullPath` 校验路径落在 `Modules\` 内。
  - 每个 DLL 用独立 `AssemblyLoadContext`（`isCollectible:true`）；`NewToys.Shared/Core` 由默认 ALC 共享。
  - 逐个 `try-catch` 隔离：单 DLL 失败不影响宿主与其他模块。
  - 只做「新增」，同名不替换不卸载。

### 3.5 配置与数据

- **多配置**：`<应用根>\profiles\<配置名>\{config,data,logs}`；**当前配置**记在 `<应用根>\active-profile.txt`（必须在 `profiles\` **之外**，否则切换时把自己也换掉）。
- **所有设置落 `<配置根>\config\*.json`**（才能被数据管理页备份 / 导入）。
- **用户功能数据**同样落 `config\`、一样进备份。
- **本地数据库**落 `<配置根>\data\newtoys.db`（可随时重建的缓存，**不进备份**）；日志落 `<配置根>\logs\`。
- **应用根** = `%LocalAppData%\NewToys`，环境变量 **`NEWTOYS_HOME`** 整根切换（test vs prod）。
- **数据迁移**：首次运行新版时，若 `<应用根>\config` 存在而 `profiles\` 不存在 → 现有 `config/data/logs` **整体移动**到 `profiles\default\` 并写 `active-profile.txt = default`；失败则**保持旧结构运行**并在「设置 → 配置」提示。
- **切换配置 = 重启应用**（配置在启动时已被大量单例读取；热切换改动面大、极易残留半新半旧状态）。
- **模块只读设置**，唯一写入点在该设置的设置页；功能入口页**只读**（⛔ 不许回写 → 双真相源）。
- **改系统级配置的页面必须二次确认**（如软件源增删 → 改系统 winget）。

### 3.6 默认数据（不许硬编码）

- **内容清单不写死在 C# 里**；默认内容随程序发布在 `<程序目录>\defaults\*`，**首次运行**播种成 `config\` 或用户目录下的用户文件。
- 此后一切以用户那份为准（用户删掉的条目不会被"复活"）。

### 3.7 跨平台预留

- 主平台 **Windows 10 LTSC**；迁移方向 **Debian 13**。
- 平台相关能力（winget / `ms-settings:` / ffmpeg）**集中封装**，便于整体替换。
- 路径一律 `Path.Combine`；外部相对路径 `Path.GetFullPath` 后校验落在目标目录内。

## 四、UI 框架（硬约束）

> 本节锁「主界面长成什么样」。

### 4.0 布局总览

全窗 = **顶部标题栏 + 左侧菜单栏 + 中间主内容区 + 右侧详情卡 + 底部状态栏**：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ≡ │ ⟳   [标签页][标签页][标签页]              │ —  □  ✕   标题栏 40px    │
│     （含标签页区，窗口级）                                              │
├──────────────┬──────────────────────────────────────┬────────────────────┤
│  左侧菜单栏   │                                      │  详情卡 340px       │
│  （树状可折叠）│         主内容区                    │  选中项的具体信息   │
│              │      （当前标签页的内容）             │  以及该部分的命令   │
│  ⌂ 首页       │                                      │  （可开合）         │
│  ▢ 电脑工具 ▸ │                                      │                    │
│  ◍ 网络工具 ▸ │                                      │                    │
│  ▷ 视频工具 ▸ │                                      │                    │
│  ≡ 系统设置 ▸ │                                      │                    │
│  180px       │                 *                    │  340px / 0          │
│ （折叠→48）   │                                      │                    │
│  1.26.10     │                                      │                    │
├──────────────┴──────────────────────────────────────┴────────────────────┤
│ 状态栏 26px —— 当前功能页面的状态                                        │
└──────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 职责 |
|---|---|
| **标题栏**（顶部，窗口级） | 窗口操作 + **标签页区**（一个标签页 = 一个打开的功能页面） |
| **左侧菜单栏**（窗口级） | 树状导航：首页叶子 + 一级分组 + 二级功能叶子 |
| **主内容区**（中间） | 呈现当前标签页的内容（列表 / 播放器式预览 / 表单，按页型定） |
| **详情卡**（右侧） | 显示选中项的**具体信息**，**以及部分命令**（如将要执行的 ffmpeg 命令行） |
| **状态栏**（底部） | 显示**当前功能页面**的状态；⛔ 页面不自绘状态行 |

- 主窗口 **1280×800**，最小 **960×640**。
- 标题栏 **40px**、左菜单栏 **180px**（折叠 48px）固定；详情卡 **340px** 可开合、状态栏 **26px**。

### 4.1 标题栏（40px，窗口级）

- 元素从左到右：`≡` **折叠左菜单栏**（状态落 `config/columnlayout.json`，壳级页 Key `"shell"`）｜ `⟳` **刷新**（销毁并重建当前标签页 View+VM）｜ **标签页区** ｜ `—` `□` `✕` 窗口控制。
- **底色 = `ContentBrush`**（与窗口背景一致），底部 1px `DividerBrush` 分割线；文字 / 图标用 `PrimaryTextBrush`。
  ⚠️ 若改回深色底 → 标签项 / 窗口按钮**成套**切 `Sider*` 系。
- 图标尺寸 **18px**；区域可拖拽移动窗口、双击最大化。
- **标签页区左右各 24px 固定留白**供拖拽窗口（离 `⟳`、离 `—` 都有距离；标签再多也照留）。
- ⛔ **已删除**（功能入口另有其处）：`🏠` 主页（靠**常驻标签**返回）、`⚙` 设置（走左菜单「设置」分组）、`🌓` 主题开关（走设置页）、`◀` `▶` 前进 / 后退（`IHistoryProvider` 契约保留但**不提供 UI**）。

### 4.2 标签栏（并入标题栏中段）

- **位置**：不再是独立一行；在标题栏中段横向排列。每个标签页 = 一个打开的功能页面，一对一绑定菜单 Key。
- 组件：`ItemsControl` + 横向 `ScrollViewer`（滚动条隐藏）；标签项**只有标题 13px**（**不带图标**，样式与左菜单二级项一致）。
- **`×` 关闭按钮**：**不占位**（标签宽度只按文字算）、**叠在标题文字上层**贴右端；平时 `Opacity=0` 且不吃鼠标，**悬停该标签才出现**（允许与文字重叠 —— 换更窄标签）。
- **行为**：
  - **点左菜单二级项** → 打开 / 激活对应标签页（**同 Key 已存在则激活，不新建**）。
  - **点标签** → 切换；**中键 / `×`** → 关闭（首页除外）。
  - **在标签区滚轮** → 切换标签（上滚上一个、下滚下一个，循环）。
  - **跟随滚动**：切换后用**最小滚动**让当前标签**始终可见**（类 Chrome），不做"强推边缘"。
  - **`+`** → 打开「功能清单」页（当选择器用）。
  - **右键** → 关闭 / 关闭其他 / 关闭右侧 / 全部关闭（首页除外）。
  - **快捷键**：`Ctrl+W` 关闭当前 ｜ `Ctrl+Tab` 下一个 ｜ `Ctrl+1..9` 跳第 N 个。
- **单例语义**：同一 Key 只允许一个标签页存在（工具类应用，非文档编辑器）。

### 4.3 左侧菜单栏（180px / 折叠 48px，窗口级）

- 结构 = **首页（叶子）** + **一级分组（可展开）** + **二级功能（叶子）**。一级分组与首页**点击不打开页**，只展开 / 折叠。
- **图标**：一级分组 + 首页 = **矢量图标**（`Shell/App.axaml` 的 `Icon*` `Geometry`，模块注册时 `icon` 传几何键）；**二级功能不显示图标**（只留文字）。
- **样式区分**：一级 = 图标 + **加粗**（SemiBold）；二级 = **缩进 16px** + 常规字重 + `SecondaryTextBrush`。
- **交互**：
  - 一级**默认折叠**；点叶子 → 打开 / 激活标签页 + **确保其父级分组展开**并高亮该二级节点（父级一级同时高亮）。
  - ⛔ **不自动收起其它一级** —— 手动展开的分组保留。
  - **折叠态（48px）**：只保留一级菜单图标（自动隐藏展开箭头、标题与全部二级项）。
  - **折叠态高亮**：折叠时不展开任何一级，但当前页所属一级的**图标显示强调色**（知道"现在在哪个模块"）。
  - **折叠左菜单栏时**自动把全部一级分组收起。
  - 切到**首页**（不属于任何一级分组）→ 不动各级展开态，只清高亮。
- **「设置」组**作为一级节点，展开显示其设置子页；`RegisterModule(..., isBottom:true)` 保留（标记「设置组」语义），由左菜单渲染。
- **持久化**：`config/columnlayout.json`，壳级页 Key `"shell"`：`treeCollapsed` + `treeGroup:<groupKey>`（各一级展开态，**默认 false**、**恢复落盘**）。
- **底部版本号区**：左菜单栏**最底部**固定一行显示版本号（占位 **`1.26.10`**）。
  ⚠️ 该版本号与「设置 → 关于」的版本号（`UpdateService.CurrentVersion`）**互不相关**，是独立占位值；**折叠态隐藏**。

### 4.4 主内容区（中间）

- 单个 `ContentControl`，绑定当前激活标签页的 `Content`。
- **每个标签页持有自己的 View 实例**，切标签**不重建**；**关闭标签时才销毁**（实现 `IDisposable` 则调用）。
- 无激活标签 → 显示空态引导（居中提示），不崩。

### 4.5 详情卡（右侧 340px，可开合）

- **承载内容**：**选中项的具体信息**（参数、前后对比等）**以及该部分的命令**（如剪辑区间 + 将要执行的 ffmpeg 命令行）。
- **契约** `IDetailPanelProvider`（`Shared/Services/`，页面 VM 可选实现）：
  `HasDetailPanel`（该页是否有详情）｜`IsDetailOpen`（当前是否展开）｜`DetailContent`（详情内容）｜`DetailChanged`（通知 Shell 刷新）｜`ToggleDetail()`（页面右上角按钮调）｜`OpenDetail()`（右键首项调）。
- **Shell 职责**：标签切换时检查 `ActiveTab.ViewModel is IDetailPanelProvider` → 是则显示右列 + 订阅 `DetailChanged`（**先解绑旧 Tab 的订阅**，防泄漏）；否则隐藏该列。
- **入口**：**页面右上角**工具条末位的单个开关按钮（`❯` 收起 / `❮` 展开，常驻不隐藏）→ `ToggleDetail()`；右键首项「▤ 显示详情栏」→ `OpenDetail()`。
  ⛔ **表头不再放详情开关**（旧的"贴右缘热区 + 窄边按钮"已废除）：它占掉一整列表头宽度、鼠标不靠近还点不到，且与表头"排序 / 列显隐"两种交互混在一处。
- **宽度与记忆**：宽 **340px**；是否展开落 `config/columnlayout.json`（`FlagDetailPanel`，**按页面 Key 分别记忆**）；隐藏时该列宽度为 0，内容区铺满。
- ⏸ **页面迁移暂缓**：契约与 Shell 消费逻辑**已就位**，各页目前仍用**页内右列**（见 §4.8）；迁移方式见规范 §3.6 / §3.8。

### 4.6 底部状态栏（26px，窗口级）

- **位置**：Shell 底部，**横贯「内容区 + 详情区」**（⛔ 不跨左菜单栏）；背景 `PanelBrush` + 上边框 `DividerBrush`，文字 `SecondaryTextBrush` 12px，左内边距 16px。
- **承载**：Shell 引用 `IStatusProvider` —— VM 实现它、Shell 订阅 `StatusChanged` 并显示 `StatusText`。
- **页面不再自绘状态行**（原页面顶部那一行删除）。**列表页由 `ListPageViewModelBase` 统一实现**（一次覆盖全部列表页）；**非列表页各自实现**。
- **始终显示**（不随页面显隐），避免切换页面时布局跳动。

### 4.7 主题

- 三模式（Light / Dark / System）+ 强调色，落 `config/theme.json`，**默认深色**。
- 主题键只 `*Brush`（32 个），颜色一律 `DynamicResource`；`ApplyTheme` 纯代码构建字典注入（⛔ 禁 `MergedDictionaries.Clear()`、⛔ 禁写死 `#RRGGBB`）。
- **新增元素必须走既有样式体系**（`Classes` + 全局样式），⛔ 不在页面里复制样式。

### 4.8 列表页

- 内部 = **列表列 ｜ 详情列**；加上左菜单栏即**三列**：
  - **工具条 / 搜索框 / 筛选条一律收进「列表列」**（⛔ 不再横贯整页宽）；
  - **详情卡从页面顶部开始**（与列表列同高、整列从顶到底）。
- **硬规则**：
  1. **左键点表头 → 排序**（VM 追加 ▲▼）；**右键点表头 → 勾选列显隐**（隐藏列用**宽度 0**，不删列保一致）。
  2. 表头与行模板**完全相同的星号列定义**（逐字一致）；动态列用 `<v:ColumnGrid ColumnSpecs="{Binding VisibleColumnSpecs}">`；左右内边距一致（8px）。
  3. `ContextMenu` 挂在独立弹出树，**不保证继承宿主 DataContext** → 必须在 code-behind `OnDataContextChanged` 里**手工同步**（行菜单 + 表头菜单都要）。
  4. 列显隐元数据 `ListColumn` + 服务 `IColumnLayoutService`（落 `config/columnlayout.json`）。⛔ 列元数据里**不再追加 `Detail` 占位列**——详情开关已移到工具条（§4.5）。
  5. 空态 / 选中态**显式处理**，不留白。
  6. ⛔ 不改共享样式 `Border.detail-card` 的宽度；⛔ `Views/ColumnGrid.cs` 因模块间禁互引而**各模块各存一份**，改动必须同步。
  7. **详情卡里的滚动条**：Avalonia 12 的 `ScrollBar` 是**覆盖式**，槽落在 `ScrollViewer` 右缘**之外 8px**（偏移写死在 Fluent 模板里）。要让它收在卡内，本页 `Border.detail-card` 的 `Padding` 右侧留 **8px**、滚动内容 `Margin` 右侧再留 **8px**（⛔ 改共享样式会波及 12 个列表页）。
  8. **工具条末位 = 详情开关**：与左侧命令区同一 `WrapPanel` 的最后一项，右对齐不现实时用 `Grid ColumnDefinitions="*,Auto"` 把左侧命令包 `WrapPanel`、右侧放开关。
- **跨页投递的数据（本页一次只处理一条 / 一批）**：文件、任务等经 `VideoTaskStore` 之类的单例在页面间传递。⛔ **只在 `OnDataContextChanged` 里取是不够的** —— 标签页已存在时切回来只换可视树、`DataContext` 不变，该回调**不再触发**，表现为"送过去的文件要刷新页面才出现"。取件点必须挂在**每次进入页面都会跑**的回调上（`OnAttachedToVisualTree`）。

### 4.9 设置页

- 即时生效（⛔ 禁保存按钮）vs 显式保存（多字段表单）的判据不变；每页 ≥1 行 `StatusText`。
- 设置页作为**标签页**打开（不再是「二级菜单 → 页面」路径）。

## 五、导航模型（硬约束）

### 5.1 核心概念

- 一个**标签页** = 一个打开的功能页面 = **缓存的 View 实例** + 一份 VM + 一个历史栈。
- 打开页面的**唯一入口** = 标签页；菜单点击、`+` 等都是「打开 / 激活某个 Key 的标签页」。

### 5.2 标签页模型

`TabItemViewModel`：`Key`（菜单 key）｜`Title`｜`IconKey`｜`Content`（缓存的 View）｜`ViewModel`（供 Shell 检测契约）｜`CanClose`（首页 = false）｜`BackStack` / `ForwardStack` / `CanGoBack` / `CanGoForward`。

`ShellViewModel`：`Tabs` / `ActiveTab` + `OpenTab(key)` / `CloseTab(t)` / `GoBack()` / `GoForward()` / `Refresh()` / `ToggleTree()` / `ToggleDetail()`。

### 5.3 历史栈

- **每个标签页独立维护**，栈元素是「页面内的导航状态快照」。
- **可进**：目录切换、执行搜索、从列表进入子详情。**不进**：列表内选中不同条目（选中态）、筛选 / 排序变化（视图状态）。
- **契约** `IHistoryProvider`：`CaptureState()`（返回 null = 不记录）｜`RestoreState(state)`｜`StatePushed`（通知 Shell push）。
- 页面通过 `StatePushed` 通知 Shell push `CaptureState()`；前进 / 后退时 Shell 调 `RestoreState`；**未实现该契约的页面** → 前进 / 后退灰显。

### 5.4 启动时序

`ShellViewModel` 构造函数末尾调 `OpenTab("home")`（首页作为首个固定标签页）；其余启动时序（DI → 模块加载 → 主题 → Show）不变。

### 5.5 防闪退铁律

1. `OpenTab` 找不到 key **不得抛异常** → 忽略并记日志。
2. `ActiveTab.Content` 为 null → 内容区显示空态，不崩。
3. 关闭最后一个标签页 → **自动打开首页**（保证始终有激活标签）。
4. 关闭首页标签 → **拒绝**（`CanClose=false`）。
5. View + VM 缓存，关闭标签时销毁（`IDisposable` 若实现则调用）。

#### 6.4.1 两页详情卡（同一套规格）

> **原则：这两个页面的详情卡是同一个东西** —— 都是"把一条任务翻译成一条 ffmpeg 命令"。「视频预览」页只是**额外**能在左边看画面、拖着时间条定区间。因此两页详情卡的**分区顺序、折叠方式、命令区形态必须一致**，改一处就要同步另一处。

**统一规格**

1. **分区顺序 = ffmpeg 命令的书写顺序**：`输入 / 区间` → `编码与画质` → `输出` → `命令`。
   ⛔ **「任务类型」勾选不单独占一块放最上面** —— 它由下面两个分区自己表达（勾了哪个就执行哪段），单独列出来既重复又占地方。
2. **两个分区各自可折叠**，标题行左侧是一个**勾选框**（该段是否参与命令）+ 右侧折叠箭头；**取消勾选即自动折叠**，折叠只影响界面、**是否执行由勾选决定**。
   ⛔ **两页的勾选框都可交互**（不是只读装饰）：批量页的勾选框 = 该任务是否含这一段，**勾 / 取消即切换任务类型**（见第 5 条）。
3. **详情卡里只有"参数 + 命令"，不放任何操作按钮**（跑 / 保存 / 删除 / 打开目录 / 复制…）—— 它们属于**命令之外的动作**，一律排到列表上方的工具条里。⛔ 详情卡顶部不放按钮条。
4. **命令区**固定在最后：`SelectableTextBlock` 显示完整命令行 + 可编辑的参数框 + `↺ 重置为自动` + `📋 复制命令`；手改后参数变化**不再覆盖**手改值，执行以手改为准。
5. **两页的差异只有两处**：
   - 「视频预览」页的区间由左边的时间条驱动；「批量处理」页的区间在详情卡里填（该页没有预览画面）。
   - **勾选框的初值来源不同**：预览页由用户现勾（剪辑 / 转码可同时勾 = 一条命令干两件事）；批量页由**选中任务的类型**给出初值（`CutTask` = 只勾剪辑、`TranscodeTask` = 只勾转码、混合任务 = 两段都勾）。
     **批量页勾选框可交互**：勾上一段 / 取消一段 → 任务在「剪辑 / 转码 / 剪辑+转码」之间转换（两段都取消 = 回到「仅转码」并提示，⛔ 不允许出现"两段都不参与"的空任务）。
6. **详情卡布局一致性（本次收紧）**：宽度恒定 340（共享样式 `Border.detail-card` 锁定，⛔ 不动）；**折叠任意分区只影响该分区高、不影响整卡宽度**；所有「标签 + 输入 / 下拉」控件的**左对齐、宽度一致**（输入与 `ComboBox` 同宽、同 `HorizontalAlignment=Stretch`）；`ComboBox` 展开**不挤出 / 不遮挡**其它控件（本页 XAML 约束宽度，⛔ 依赖覆盖层自行处理）。两页 XAML 同一段结构照抄，改一处同步另一处。

> ⚠️ **用户再次强调**：预览页与批量页详情卡必须**完全一致**（同为 ffmpeg 命令可视化编辑器）。改动任一边前须比对另一页 XAML 确认无漂移，禁止两边各写一套。

**"完全一致"验收清单**（改任一边后逐条比对）

| # | 项 | 判据 |
|---|---|---|
| 1 | 分区顺序 | 剪辑 → 转码 → 输出 → 命令，两页一致 |
| 2 | 分区标题行 | 都是「勾选框 + `✂ 剪辑（截区间）` / `🔁 转码（换编码 / 格式）`」，勾选框都**可交互** |
| 3 | 字段集合 | 剪辑段：开始 / 结束 / 剪切预设 / 重编码 CRF / 自定义参数；转码段：编码预设 / 编码器 / 容器 / 宽×高 / 码率模式 / CRF·目标码率；两页逐字段对齐（标签文案允许差"也可拖左侧时间条"这类页内提示） |

| 6 | 折叠 / 勾选联动 | 取消勾选即折叠，两页同一套联动 |

#### 6.4.2 「视频预览」页（单任务编辑器）

- **定位**：只负责**边看边制定一个**任务（剪辑 / 转码 / 剪辑+转码）；真正运行在「批量处理」页。⛔ **本页一次只编一个任务**（从列表 / 批量送来的多条只取首条，其余在状态栏提示）。
- **主内容区 = 预览**：
  - **预览画面（类播放器窗口）始终显示**：载入后大画面常驻；未载入时显示空态提示（⛔ 不再整块隐藏，避免布局跳动）。
  - **预览区占主区主体、面积尽量大**：抬高低限 `MinHeight`、压缩上下留白，给画面更多空间。
  - **三条时间条（预览位置 / 开始 / 结束）始终显示**（⛔ 不再只在有 `Duration` 或勾选剪辑时才出现）：拖动即时抽帧；`开始 / 结束` 仅在勾选「剪辑」时可操作，未勾选时灰显但仍占位（布局稳定）。
  - **三条时间条纵向间距压缩**（v3.13 收过一次，v3.16.1 **再收紧**：行间 `Spacing=10`、每条 `Slider` 高度压到 26、组上方外边距 6→4），整体更紧凑，把纵向空间还给预览画面。
  - **「结束」滑块默认停最右**（v3.16.1）：整段 = 结束在片尾，探测到时长后自动把结束值填成总时长（滑块停最右、右侧显示片长）；
    ⛔ 不再和上面两条一起挤在最左（三条都停 0 时读不出"结束=片尾"这层意思，看着还像没对齐）。「↺ 区间重置」同样把结束置为整段末尾。
- **顶部「源时长」移到状态栏**：原工具条右侧「源时长 {0}」删除，源时长随其它状态信息在 **Shell 底部状态栏**显示（`IStatusProvider`）。
- **状态栏常驻「当前视频信息」**：载入后状态栏每一行都带当前文件前缀 —— `🎬 {文件名} · {分辨率} · {时长} · {完整路径}`，后面再跟动作反馈（`已复制命令` / `已发送到批量处理` …）。
  ⛔ 不允许动作反馈把"当前预览的是哪个文件"冲掉：VM 内部统一走一个 `SetStatus(msg)` 拼前缀，⛔ 不各处直接赋值 `StatusText`。未载入文件时显示"未载入视频"。
- **类播放器拖动快览按钮**：工具条新增一个**播放图标按钮**（矢量 `Geometry`，不引第三方图标包），点击切换「拖拽快览」模式 ——
  - 开启 = 拖预览位置条时**类播放器帧拖动（scrub）**：松手停在当帧，便于快速定位关键画幅；
  - 同一按钮兼「自动播放预览」开关：开 = 按时间轴自动逐帧推进（抽帧模拟播放），关 = 仅手动拖动。
  - ⚠️ 两种行为二选一由实现定（见规范 §3.9）；核心是"点一下就能像播放器一样拖着看 / 自动播"。
- **顶部工具条**（动作全归这里）：`📂 选择视频` · `▶ 拖拽快览`（类播放器图标）· `➡ 发送到批处理` · `↺ 区间重置` · `📋 复制命令` · `↺ 重置为自动` · `❮/❯ 详情`。
- **「📸 取当前帧」按钮（工具条）**：把当前拖动到的那一帧用 ffmpeg 抽成图，经任务通道送视频收藏页建卡（建卡逻辑见 §6.4.9）。
- **从「视频列表」送来的文件 → 默认进入预览**（自动探测时长 + 抽当前帧）。
- 🔴 **取件时机**：见 §4.8 硬规则 8（取件点必须在 `OnAttachedToVisualTree`，`protected override`）。

**任务入口（四处，全部打通）**

1. 「批量处理」页工具条「📂 添加文件」→ 选源文件建任务（按工具条上选的预设 / 类型）。
2. 「视频列表」页多选 → 「➡ 批量处理·转码」/「✂ 视频预览·剪辑」（走 `VideoTaskStore.EnqueueForTranscode` / `EnqueueForCut`，进对应页时取走建任务）。
3. 「视频预览」页编好一个任务 → 「➡ 发送到批处理」入队（`VideoTaskStore.AddCut` / `AddTranscode`）。
4. **「批量处理」页 → 反向送「视频预览」**（本次新增）：选中一条任务 → 「➡ 送预览」把该任务源文件送入预览页（复用 `EnqueueForCut` 同一取件通道；预览页一次只编一个，多送只取首条并提示）。

**统一队列的实现约定**

- 两类任务的**公共基类** `VideoTaskBase` 已含 `Status/Progress/Message/Name/StatusDisplay/OutputSize` → 批量列表用 `ObservableCollection<VideoTaskBase>` 合并 `CutTasks` + `TranscodeTasks`（**不改 `VideoTaskStore` 的存储结构**）。
- 运行按类型分派：`CutTask → FfmpegService.BuildCutArgs`，`TranscodeTask → FfmpegService.BuildTranscodeArgs`，统一走 `FfmpegService.RunAsync`。

#### 6.4.3 视频数据库（目录索引，SQLite）

> 与 `VideoMediaIndex`（纯扫描缓存，命中即填、不可显式导出）**不同**：视频数据库是用户主动沉淀的**目录清单**，可导出 / 可再读回。两者都落 `data\newtoys.db`（不同表），互不冲突。

- **「视频列表」页工具条新增「💾 加入视频库」按钮**：把**当前列表里所有文件**写进视频数据库（表 `video_catalog`），字段 = 文件名 / 编码格式 / 时长 / 大小 / 码率 / 文件地址 / 分辨率。
  - **只存列表已有信息**：未读取媒体信息的行，对应字段留空（NULL），⛔ 不强行跑 ffprobe；已读取的才填。
  - 去重：同文件地址已存在则更新（`INSERT OR REPLACE`）。
- **工具条「📂 导入」拆分按钮**（合并原「读取文件夹」与「读取 `.db` 数据库」入口，并新增单个视频文件导入）：点主按钮 = 默认执行「文件夹…」；下拉菜单**两项** ——
  - **① 文件夹…** → 选目录，原 `ScanAsync` 扫描逻辑不变（仅载入目录内的视频文件）；
  - **② 视频文件…** → 文件选择器**允许多选**，筛选视频扩展名（`.mp4/.mkv/.avi/.mov/.wmv/.flv/.webm/.m4v` 等）；直接把所选文件作为视频项加入列表（⛔ 不扫描整目录，按所选文件建条目；媒体信息留空，待用户在列表里按需读取）。
- **「🗄 导入视频库(.db)」独立按钮**（v3.16）：⛔ 不再塞在「📂 导入」的下拉里 —— 文件夹路径天天变、库文件路径相对固定，两者不该共用入口。
  - **点击即弹选择器**（⛔ 没有输入框、⛔ 没有"先填路径"这一步），`SuggestedStartLocation` 一律定位到「设置 → 路径配置 → 导入导出默认目录」（§6.4.5；没配就回退系统默认）。
  - 选中 `.db` → 读其中 `video_catalog` 表，把记录作为视频项载入列表（文件可能已不存在，照常显示，媒体信息用库里存的）；⛔ 不覆盖 `Folder`，导入后勾选状态清零、自动刷新。
- 三项（文件夹 / 视频文件 / 视频库）都汇入同一份列表（与现有 `_all` / `ApplyView` 一致）。
- 落盘：共享入口 `SqliteDatabase`；新增 `VideoCatalogService`（模块内私有，沿用 `VideoMediaIndex` 的同表共存模式，⛔ 不跨模块）。
- 🔴 **读取失败必须给出可诊断的原因**（v3.16 修 bug「导入后列表没反应」）：
  - `VideoCatalogService` 读外部库时**表不存在 / 缺列 / 打开失败**一律回传原因字符串，⛔ 不许 `catch` 吞掉后只返回一个空列表；
  - VM 按原因提示：`该文件里没有 video_catalog 表` / `缺少列 xxx（旧版本库）` / `no such column: …` 等原文；
  - **兼容旧库**：`PRAGMA table_info` 拿到实际列，缺的列按默认值读（⛔ 不因缺 `tags` 就整表读不出来）；本库缺 `tags` / `modified` 列时构造期用 `ALTER TABLE … ADD COLUMN` 补上。

#### 6.4.4 批量处理·任务的导出 / 导入

- **导出**：工具条「📤 导出任务」→ 把当前队列（剪辑 + 转码两类）序列化成 JSON 文件（复用 `VideoTaskStore` 的 `TaskFile` 结构）。
  - 用途：某些命令本页暂无法自动拼（如特殊滤镜链），可导出后在外部脚本批量加工，再导入回来跑。
- 🔴 **这个 JSON 是"缓存 / 备份"，不是"工作现场"**（v3.16.1）：**应用启动时 ⛔ 不自动载入它** —— 批处理列表在程序刚打开时就是**空白**的。
  - 要恢复上一次的任务，显式点「📥 导入任务」把它读回来（⛔ 不做"偷偷恢复"，用户不知道为什么一开机就有一堆旧任务）。
  - 队列里有增删改时照旧落盘（`Save`），所以它始终是一份可以随时丢掉、也可以手动读回的缓存。
- **导入**：工具条「📥 导入任务」→ 选一个导出的 JSON，把里面的任务**追加**进当前队列（⛔ 不覆盖已有）。
- 导入 / 导出都走平台文件选择器（`TopLevel.StorageProvider`）；失败在状态栏提示。

#### 6.4.5 导入 / 导出默认目录（设置 → 路径配置）

- 「设置 → 路径配置」新增一项「**导入导出默认目录**」（`PathItemKind.Folder`，落 `app.json` 的 `VideoDbFolder`，留空 = 用系统默认）。⚠️ 字段名沿用 `VideoDbFolder` 仅为向后兼容，语义上它已是**全局导入 / 导出默认目录**，不限于视频库 `.db`。
- **适用范围（用户已选 = 全局，覆盖所有导入 / 导出对话框）**：凡打开文件选择器做「导入」或「导出」，都用 `StorageProvider.TryGetFolderFromPathAsync(VideoDbFolder)` 取该目录并设为 `SuggestedStartLocation`，直接定位到它。首批覆盖：
  - 视频库 `.db` 导入 / 导出（视频列表「📂 导入 → 视频库(.db)…」及导出对话框）；
  - 批量任务 `.json` 导入 / 导出（批量处理页「导入 / 导出任务」）。
- ⚠️ 后续任何新增的导入 / 导出对话框（如收藏页导出、其他模块）**都须**复用同一默认目录 + `SuggestedStartLocation`，保持体验一致；落盘即读，无需改架构（用户在「扩充到json吧」中明确把范围从「仅 .db」扩到全局）。
- 读取：`IAppConfigService.VideoDbFolder`；设置页改动即时生效（落盘即读）。

#### 6.4.6 视频标签（tags）

- `video_catalog` 表新增 `tags` 列（文本，逗号分隔多个标签，如 `收藏,待剪`）；⛔ 不入扫描缓存 `video_media`。
- **编辑入口**：视频列表**详情卡**新增「**标签**」可编辑文本框 —— 回车 / 失焦保存 → `VideoCatalogService.UpdateTags(path, tags)`；未入视频库的项提示先点「💾 加入视频库」。
- **列表表头**：新增「**标签**」列（可隐藏 / 显示，见 §6.4.8）；多项筛选可加「标签包含」条件（按逗号拆分匹配）。
- 收藏页读同一 `tags`（见 §6.4.9）；标签随视频库走，符合"多个数据库文件"方向。

#### 6.4.7 详情卡内直接改名 + 同步磁盘

- 视频列表详情卡新增「**文件名**」可编辑字段：改完提交 → `VideoFileService.RenameAsync`（复用现有**防穿越 / 同名检查**）→ 更新 `VideoItem.Name / FullPath`。
- 同步视频库：若该项已在 `video_catalog`，按旧路径 `UPDATE` 新路径（标签等不变）。
- ⛔ **不触发整目录重扫**（避免丢失勾选 / 媒体信息）；只更新单条。预览页 / 批量页涉及源文件改名时同样走此服务（保持单点）。

#### 6.4.8 列表表头扩充（更多可隐藏列）

- **视频列表**：在现有 名称 / 类型 / 大小 / 时长 / 分辨率 / 编码 / 码率 / 修改时间 基础上**扩充**常用列（表头右键均可隐藏 / 显示）：建议新增 —— **标签**（§6.4.6）、**帧率(fps)**、`容器格式`、音频编码、路径、创建时间、是否已收藏。
- **批量处理列表**：扩充任务相关列（源文件 / 类型 / 状态 / 进度 / 输出大小 / 命令摘要 / 创建时间 等），同样可隐藏 / 显示。
- 复用现有 `ListPageViewModelBase` 列显隐机制（`IsXxxVisible` + `columnlayout.json`），⛔ 不复刻一套；新增列键 = 属性名中间段（如 `Fps` → `IsFpsVisible`）。

#### 6.4.9 视频收藏页（新页面）

- **菜单 key** `video-fav`（新）；模块内新 `VideoFavoritesView` / `VideoFavoritesViewModel`；注册进视频工具分组。
- **数据**：sqlite 管理（`VideoFavoritesService`，模块内私有，表 `video_favorites(path, thumb, added_at)`，与 `video_catalog` 同库 `data\newtoys.db`）。⛔ 本期不做独立 DB 文件（"多个数据库文件"是后续方向，仅记）。
- **主显示区**：`ItemsControl` + `WrapPanel` 的**卡片网格**（非列表页），每张卡 = **缩略图 + 文件名 + 标签**：
  - **缩略图**：磁盘文件 `data\thumbs\{sha1(path)}.jpg`，`video_favorites` 记相对路径；取图在**视频预览页「📸 取当前帧」**（§6.4.2）把当前拖动到的帧用 ffmpeg 抽成图 → 经 `VideoTaskStore` 导航参数送收藏页建卡。

- **来源**：仅从**视频列表**页「➡ 收藏」送过来（勾选 / 选中 → 加入 `video_favorites`）；⛔ **不支持直接导入文件**（必须是视频数据库里的文件）。
- **详情卡**：与**视频列表详情卡同一套**（路径 / 大小 / 修改时间 / 分辨率 / 编码 / 码率 / 时长 / 标签 / 文件名编辑 / 💾 入视频库），复用同一 XAML 片段。

- **☑ 图标右键**弹出独立菜单（⛔ 与表头其它位置的「列显隐」菜单分开，两者互不干扰）：
  - **☑ 全选**（勾选当前列表里**显示出来的**全部行）
  - **☐ 取消选择**（清空勾选）
  - **🔄 反选**
- **工具条上那三个按钮删除**（视频列表页），勾选项只在表头 ☑ 右键菜单里；批量处理页同样新增行首勾选列 + 表头 ☑ 菜单，两列表页行为一致。

#### 6.4.11 清除列表（≈ 浏览器的无缓存刷新）

- **视频列表**「🧹 清除列表」：清空当前列表（内存里的 `_all` / `Videos`）+ 勾选 / 选中 / 筛选条件，回到"尚未扫描"空态。
  ⛔ **不动磁盘、不动视频库、不重扫目录**（清完想重来就点「📂 导入」/「🔍 扫描」）。
- **批量处理**「🧹 清除缓存」（v3.16.1 更名 + 改语义，⛔ 不再叫"清除队列"）：**只清页面上的这条缓存** ——
  - 清掉内存里的整个队列（剪辑 + 转码两类），回到空列表；
  - ⛔ **不动磁盘上的 `config\video-tasks.json`**（不删文件、也不把"空队列"写回去）—— 也就是说"不再加载当前这个 json"，
    想再要回来就点「📥 导入任务」。下次启动本来也不会自动载入（见 §6.4.4）。
  - 与旁边「🧹 清理已结束」的区别：那个只清跑完 / 失败 / 已取消的，**这个是把整页清空**。
- 两个按钮都要**二次确认**（清错了没有撤销），确认文案写明清的是什么、不清什么（例如"不会删除任何视频文件"）。
- 清完在状态栏说明结果（"已清除 N 条"）。

## 七、设计原则（六条）

1. **模块化** — 按模块拆分，可独立开发 / 启停。
2. **插件化** — 模块编译为独立 DLL，运行时装配，加模块不改宿主。
3. **轻量务实** — 工具类应用，重效率稳定，UI 不炫技。
4. **自控** — 不引入任何第三方 UI 库 / 图标包，全局控件自己写。
5. **命令行封装** — 功能以「包既有命令行 / 系统能力」为主，不超命令行上限；配置一律落文件、可备份。
6. **可热加载** — DLL 放入 `<程序目录>\Modules\`，运行中点「刷新」即时装配，不必重启；加载源仅限本地文件夹。
