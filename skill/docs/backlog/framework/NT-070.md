# NT-070 · 启动提速：模块初始化两段式（`InitializeDeferred`）
- 状态：🔄 **已实施**（2026-10-18，⏳ 待用户本地 build + 看 startup 日志核对收益）
- 优先级：P1
- 关联需求：需求规格 §3.4（模块加载）/ §3.3（生命周期）
- 依赖：`Shared/Models/IModule`、`Core/Services/ModuleLoader`、`Shell/App.axaml.cs`（**框架层 ⇒ 用户已授权**，2026-10-18）
- 创建：2026-10-18

## 背景 / 目标
启动时窗口要等所有功能模块跑完 `Initialize` 才出现，而 4 个模块的 `Initialize` 里有大量 IO：
`ScriptManager`（打开 SQLite + 清超龄观测 + 两遍种子播种）、`VideoTools`（打开库 + DROP 3 张表）、
`MediaAssets`（读 `config\media-assets.json` + 扫描器接线 + 回收站到期清理入队）。

**不可动的约束**：`ModuleLoader.LoadAll`（`RegisterServices`）必须早于 `BuildServiceProvider()`，
所以**模块程序集加载无法延后**；菜单注册也必须早于首帧，否则左树「先空后跳」。

⇒ 能延后的只有 `Initialize` 里的 IO。方案 = 把 `Initialize` 拆成两段。

## 验收标准
1. `IModule` 有 `InitializeDeferred(IServiceProvider)`，**默认空实现**（不覆盖的模块零改动）。
2. 4 个模块的 `Initialize` 里只剩「菜单注册 + 钩子接线」；DB / 配置读取 / 播种 / 扫描接线 / 入队全部在 `InitializeDeferred`。
3. `Shell` 在 `win.Show()` 之后 `Dispatcher.UIThread.Post(..., DispatcherPriority.Background)` 驱动 `InitializeAllDeferred`。
4. **左树不跳变**：首帧前菜单已完整（含模块设置项）。
5. 热加载（`ModuleLoader.HotReload`）也紧接着跑 `InitializeDeferred`，否则热加载模块永远空数据。
6. `logs\startup-*.log` 出现两行打点：`启动打点（累计毫秒）：…` / `模块延迟初始化 Nms（首帧之后）`。
7. 编译通过 + `accept.ps1` PASS。

## 技术要点 / 约束
- 🔴 **必须留在 UI 线程**，⛔ 不用 `Task.Run`：`Sqlite` / 配置 store 非线程安全，换线程会和「用户已点开页面」的读取撞车。代价 = 启动瞬间 UI 卡几十毫秒。
- 🔴 `DispatcherPriority.Background` 低于 `Render` ⇒ 排在首帧之后；也低于输入 ⇒ 用户抢点菜单会插队（页面必须能按空数据渲染）。
- ⚠️ `MediaAssets.InitializeDeferred` 里的 `scan.ApplySettings` 若没跑，扫描会用默认忽略规则 —— 首帧后才可交互，实际不会漏。
- ⚠️ `startHidden`（启动最小化到托盘）分支下也照样 Post，窗口没 Show 不影响延迟层执行。
- 未做：`SetupTrayIcon`（`startHidden` 判定依赖它）/ `StartupService.SetEnabled`（注册表）仍在首帧前 —— 各约 10~30ms，收益不抵改造风险。

## 执行记录
- 2026-10-18：实施完成，AI 侧未跑构建（按铁律）。⏳ 待用户 `pwsh -File .\scripts\build.ps1` + 查看 `logs\startup-*.log`。

### 首轮实测（用户 2026-10-18 17:51，Debug）
```
启动打点：模块扫描与DI注册 2173 → 容器构建 2182 → 模块菜单初始化 2199 → 主窗口构造 2614 → 窗口显示 2959
模块延迟初始化 58ms（首帧之后）
```
🔴 **结论与假设相反**：模块 IO 只有 58ms，真正的大头是 **2173ms 的「扫描与 DI 注册」**。
根因 = `ScanModulesDirectory` 扫的是**程序目录全部 `*.dll`**：Debug 程序目录有 **49 个 DLL**
（Avalonia / AngleSharp / SQLite / 工具包…），每个未加载的都 `Assembly.LoadFrom` + `GetTypes()`，
而其中根本没有 `IModule`。`HotReload` 早有 `Module.*` 前缀过滤，`LoadAll` 漏了。

### 第一轮修复（2026-10-18）
1. `ScanModulesDirectory` 枚举改为 `Module.*.dll`（与 `HotReload` 对称）—— 预计吃掉 2000ms。
2. 打点拆细：`DI注册` / `模块扫描` 两个点，下轮可直接看出剩余占比。
3. 剩余已知成本（未动）：主窗口构造 415ms（XAML 解析 + `BuildTree`）、窗口显示 345ms（含 `SetupTrayIcon` / 启动项注册表 / 首帧布局）。

### 第二轮实测（2026-10-18 17:55，连续两次，热启动）
```
DI注册 1 → 模块扫描 9/11 → 容器构建 18/22 → 模块菜单初始化 36/44 → 主窗口构造 442/472 → 窗口显示 787/826
模块延迟初始化 64ms（首帧之后）
```
✅ **修复生效**：`模块扫描` 2173ms → **9~11ms**；总启动 **2959ms → 787~826ms（-73%）**。

🔴 **排查中踩的坑（务必记住）**：同一份二进制「冷启动 2173ms / 热启动 93ms」——
所以**单次日志不能作为结论**。新编译产物的第一次启动必然慢（冷读 + 杀毒实时扫描 + JIT）。
判断优化是否生效，要么跑两次取第二次，要么看分项打点（`模块扫描` 这个点热冷差异小）。
17:54 那条 2044ms 就是新产物首次运行的假信号，差点被误判成「过滤没生效」。

### 剩余成本（Avalonia 首帧固有，未动）
- 主窗口构造 442~472ms（`ShellView` XAML 解析 + `ShellViewModel.BuildTree`）
- 窗口显示 787~826 区间内约 345ms（`CreateAppIcon` + `SetupTrayIcon` + 启动项注册表对账 + `Show()` 首帧布局渲染）
- 继续压最多再省 100~150ms，代价是动托盘 / 首帧顺序，风险 > 收益 ⇒ **建议到此为止**。

## 结论
启动从 2.96s 降到 0.8s。日常改代码后的**第一次**启动仍会慢（冷启动固有，与代码无关）。
