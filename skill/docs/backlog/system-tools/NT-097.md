## 一、背景与目标

用户 2026-10-23 指令（原话要点）：

1. 「命令库页面还用以前的那种布局，就类似当前脚本库，**功能和布局都类似**」—— NT-091 平移时命令库被精简重写（固定四列、页内工具条、无列显隐、无详情卡渲染），要**对标脚本库**重做。
2. 「**删除快捷命令页面**」—— `system-quick` 整页删除（View / VM / Catalog / DI / 菜单注册）。
3. 「把**收藏夹放到模块下第一个页面**」—— 菜单 Order：收藏夹 1 / 命令库 2 / 软件包 3（Key ⛔ 不改）。
4. 「在命令库里**预设 windows 下的常用命令和快捷设置**，winget 相关命令也放进去」—— 随包预设，首次运行播种一次。
5. 「可以把命令库里的命令**添加进收藏夹**页面」—— 沿用既有 `IsFavorite` 机制（工具条 ★ 收藏 → 收藏夹按钮墙）。

## 三、技术要点 / 约束

- **模板**：VM 抄 `BookmarkViewModel`（`ListPageViewModelBase` + 详情三契约的最小范式）；View 抄 `ScriptLibraryView.axaml`；播种器抄 `ExampleSeeder` 的 `.seeded` 标记口径。
- **详情卡**：保留现有字段（名称 / 功能 / 简介 / 命令 / 需要管理员 / 隐藏窗口），「分类」由只读文本改为 `FieldKind.Select` 下拉（auto / cmd / pwsh，写回 `SystemCommand.Shell`）。
- **列定义**：`Title`(240, 标识列) / `Category`(120) / `Shell`(~110) / `Description`(*) / `Favorite`(90) / `Action`(~96)；⛔ 不加 `Detail` 占位列；每列给 `sample`（锁列宽判定）。
- **列偏好落盘**：页键 `script-commands` 不变 ⇒ 老用户 `columnlayout.json` 偏好继续生效。
- **模块边界**：⛔ 不引 Shell / 不引其它模块；执行仍走 Core `ScriptRunner`；⛔ 不开 DB。
- **Avalonia 硬规**：`UserControl` 必须显式 `InitializeComponent()`；跨程序集 `xmlns` 用 `using:`；颜色只 `DynamicResource` 主题键。
- **导出 / 导入**：沿用既有固定路径（`commands-export.json` 落数据文件同目录，按 Id 合并）——本轮⛔ 不改对话框化（脚本库那套 DialogHooks 导出留待后续）。

## 六、偏差与风险

1. **「分类」列语义替换**：脚本库的「分类」= 脚本后缀 / Shell 宿主派生值；命令库的「分类」= Shell 宿主（自动 / cmd / pwsh）——同列不同义，属预设口径。
2. **快捷命令页的「打开设置页 ↗」能力**：原页面对 `ms-settings:` 用 `Process.Start`；并入命令库后统一走 `start ms-settings:…`（Shell=cmd，`ScriptRunner` 静默执行）—— 行为等价，少一个特例分支。
3. **winget 预设命令的真实性**：只收 Winget 1.29 实测存在的子命令（`source list/reset`、`list/upgrade/upgrade --all/export/import/pin list`），⛔ 不收带占位符（`<包Id>`）或未经确认的旗标的命令。
