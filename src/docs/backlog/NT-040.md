## 背景 / 目标

当前标题栏在 v3.28 / v3.29 / NT-034 三轮里叠了 **4 层 Win32 P/Invoke 补丁**（补样式位、接管 `WndProc` 改 `WM_NCCALCSIZE`、`SetWindowRgn`、DWM 圆角偏好），越改越脆。Avalonia 12 已把 `TitleBar` / `CaptionButtons` / `ChromeOverlayLayer` 统一成 **`WindowDrawnDecorations`（CSD）**，并修好了客户区扩展在 Windows 的全部场景（PR #20067）。

**目标**：把窗框对接从「Win32 补丁」换回「框架正门」——用 `WindowDecorations` + `ElementRole` + **`WindowDecorationsTheme`** 承载，让拖动 / 双击最大化 / 贴靠 / 缩放光标全部由系统提供。

## 验收标准（可验证清单）
- [ ] `WindowDecorations` 改为 `Full`，并提供**自定义 `WindowDecorationsTheme`**（`ControlTheme` `TargetType="chrome:WindowDrawnDecorations"`）。
- [ ] 自定义主题**只保留需要的 PART**：至少 `PART_TitleBar`（透明 `Border`，仅作拖动区）；⛔ **不画**标题文字与 caption 按钮（避免与自绘标题栏重叠 —— v3.28 实测过这个坑）。
- [ ] 标题栏五个按钮（≡ / ⟳ / 🧊 / — / □ / ✕）与标签栏**点击正常**（`ElementRole="User"`）。
- [ ] 拖标题栏移动窗口、**双击最大化**、拖到屏幕边缘贴靠半屏 / 四分屏、`Win+方向键` —— 全部由系统行为提供，且**不依赖** `ApplySnapEligibleStyles`（见 NT-041）。
- [ ] 八向缩放可用（`ElementRole=ResizeN…SW`）。
- [ ] 启动无 NRE（模板 PART 缺失会在 `OnApplyTemplate` 抛）。
- [ ] 静态自检通过。

## 技术要点 / 约束
- 🔴 **PART 完整性**：`WindowDrawnDecorations.OnApplyTemplate` 按名绑定按钮事件，缺 PART 会**抛 NRE 或按钮无响应**（AtomUI 实战指南 §15）。**稳妥做法 = 7 个按钮 PART（`PART_CloseButton` / `MinimizeButton` / `MaximizeButton` / `FullScreenButton` / `PART_PopoverCloseButton` / `PART_PopoverFullScreenButton` + `PART_TitleBar`）全部给出，不需要的设 `IsVisible="False"`**；只给 `PART_TitleBar` 的风险需实测确认。
- ⚠️ **Win32 硬契约**：Win32 上 `RequestedDrawnDecorations` **只有 `TitleBar`** → `:has-border` / `:has-shadow` **恒 `false`**，边框 / 阴影 / resize 抓手由 DWM 提供。任何依赖这三个伪类的样式在 Windows 都不会触发 → **阴影 / 边框要写无条件选择器**（配合 NT-039 的自绘外框）。
- ⚠️ **该指南针对 AtomUI 6.0 分支的 12.x，未在 12.1.3 上验证过** → 首次落地必须一次完整回归（普通窗 / 最大化 / 分屏 / 全屏）。
- `WindowDecorationProperties.ElementRole` 只在 `ExtendClientAreaToDecorationsHint="True"` 时生效（官方明确）。
- 伪类备查：`:normal :maximized :minimized :fullscreen :has-shadow :has-border :has-titlebar :has-minimize :has-maximize :has-fullscreen`。
- 跨平台门控信号见需求 §3.7；⛔ 不用 OS 嗅探。

  编译报 `AVLN2000: Unable to resolve type WindowDrawnDecorationsTemplate from namespace using:Avalonia.Controls.Chrome`
  + `Internal compiler error … (ResolveContentPropertyTransformer) Index out of range`。
  **根因（已核实版本事实）**：12.1.3 的 `Avalonia.Controls.Chrome` **公共类型只有 6 个**，`WindowDrawnDecorationsTemplate` 是 **internal**，
  且 `WindowDrawnDecorations.Template` 属性是**接口** `IWindowDrawnDecorationsTemplate` → XAML 既写不出模板元素、也实例化不了接口。
  ⇒ **12.1.3 上不存在「自定义装饰模板」这条路**；AtomUI 那份指南对应它的 6.0 分支，不适用本版本。
- ✅ **修正后的实现**：`Full` + **只顶掉默认主题、不给 `Template`** 的 ControlTheme（无模板 → 框架不应用 → 不画任何装饰视觉）。
  副作用：既然没有模板，「缺 PART 抛 NRE」那条风险也就不存在了（它的前提是有模板才会 `OnApplyTemplate` 按名找 PART）。
  `DefaultTitleBarHeight=40` / `DefaultFrameThickness=0` / `DefaultShadowThickness=0` 三个 setter 保留。
- ⛔ **未删 `ApplySnapEligibleStyles()`**：按任务卡分工，删除归 NT-041（需先本地验证贴靠不回归）。`Full` 下样式位本就齐了，该函数走 `if (want == style) return` 直接返回 → 保留无害，作保险。
