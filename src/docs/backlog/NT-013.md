## 背景 / 目标
ffmpeg 命令卡的剪辑 / 转码 `Expander` 内层多套一层 inset，导致内部输入框左缘比下方「输出目录 / 文件名 / 命令」行缩进更多、不齐；转码默认参数与输出命名、默认宽高需固化，减少手动填。

## 验收标准（可验证清单）
- [x] 剪辑 / 转码输入对齐：下方「输出 / 命令」块补 16px 左内边距，与 `Expander` 内容左缘统一
- [x] 转码默认：H.265 / CPU / mp4 / CRF23
- [x] 输出文件名默认加 `_H265`（`TranscodePreset.OutputSuffix`）
- [x] 宽高附近加「默认宽高」输入（仅手动输入）：原始宽高 **> 默认** 按默认；**≤ 默认** 按原始视频大小

## 技术要点 / 约束
- 输入对齐：两页详情卡 XAML，把下方输出区（输出目录 / 文件名 / 命令）包一层与 `Expander` 内容**同 inset** 的容器（Margin 对齐），最小改动；执行期核对确切 Margin 值（v3.12 密度基线：容器内边距 12）。
- 转码默认：`TranscodeTask` 构造 / 初始化默认 `Codec=H265`、`Encoder=CPU`、`Container=mp4`、`Crf=23`、`OutputSuffix="_H265"`。
- 默认宽高：详情卡增 `DefaultWidth` / `DefaultHeight` 输入；`FfmpegService.BuildTranscodeArgs` 仅当原始宽高 **> 默认** 时拼 `-vf scale=W:H`（或 `scale` 不超过默认；与 NT-012 旋转同一条 `-vf` 合并）；**≤ 默认** 不拼 scale（按原始）。
