## 一、背景 / 目标

用户原话：「按 legado 的方式增加书源管理工具，增加替换规则，阅读时自动预下载 5 章，增加全部下载一键整合功能」。
四项都是 legado 的招牌能力，桌面端此前缺口：

1. **书源管理工具**：书源坏了只能删了重导 —— 缺「看原始规则 / 改一条规则 / 试一下断在哪」。
2. **替换规则**：清广告这类共性需求只能一条条改书源里的 `replaceRule`，且跟着源走、换源就丢。
3. **预下载**：翻章每次都要等网络。
4. **整本下载**：想把一本书攒成一份 TXT 离线看 / 存档，没有入口。

## 二、范围

| 项 | 内容 |
|---|---|
| 书源编辑 | 书源页工具条「✎ 编辑」：浮层里编辑原始 JSON（有 `RawJson` 就用原始文本，保住本程序不认识的字段），保存前解析校验，缺 `bookSourceUrl` 拒绝写库 |
| 书源试跑 | 工具条「▶ 试跑」：输关键词依次跑「搜索 → 详情 → 目录 → 正文」，每段报耗时 + 摘要 / 失败规则（`SourceDebugService`） |
| 全局替换规则 | `ReplaceRuleService`（两段 `正则##替换`，行首 `#` 注释）+ 设置页「替换规则」节；`ContentAsync` 在书源内联规则之后执行 |
| 预下载 | `PrefetchService`：打开 / 翻章后串行抓后面 N 章写正文缓存（默认 5，0 = 关，设置页可改） |
| 整本下载 | `BookDownloadService` + 阅读页「⬇ 下载」：先选保存位置 → 逐章抓（命中缓存跳过）→ 合成单份 TXT（书名 / 作者 / 每章标题，`-----` 分隔） |

## 三、验收标准

- [ ] 书源页「✎ 编辑」能打开原始 JSON；改坏 JSON → 保存被拒且提示原因；改对 → 保存后列表刷新且规则立即生效
- [ ] 编辑时改了 `bookSourceUrl` → 提示「等于新增一条」，原条目仍在
- [ ] 「▶ 试跑」输一个书名，四段依次出结果；某段失败时停在那段并给出规则名 / 原因
- [ ] 设置页「替换规则」填 `广告\d+##` 后，新抓的正文里广告行消失；填错正则只跳过该条，正文照常
- [ ] 「🧹 清空正文缓存」能把缓存清掉，重读章节重新抓
- [ ] 阅读时后台自动抓后 5 章（设置改 0 则不抓）；翻到已预取的章节不出现「正在抓正文」
- [ ] 「⬇ 下载」跑完全书 → 得到一个 TXT，含书名 / 作者 / 每章标题与正文；中途取消仍保存已抓部分
- [ ] `pwsh skill/scripts/accept.ps1` 一次通过

## 四、技术要点 / 约束

1. 🔴 **只改 `Module.Reading`**：⛔ 未动 Shared / Core / Shell / NewToys.UI。
2. 🔴 **两套替换语法不许混用**：书源内联 `replaceRule` 是 legado 三段 `规则##正则##替换`（`RuleSyntax.SplitReplace`）；
   全局规则是本机两段 `正则##替换`（`ReplaceRuleService`）。书源那段保持原实现，避免改变存量书源行为。
3. 🔴 **正文缓存的读写解耦**：`ContentAsync` **总是**先查缓存（预下载写进去的也算命中），
   「缓存正文」开关只管**写**；预下载自己 `Put`，否则默认关缓存时预下载等于白抓。
4. 🔴 **预下载换章重起一轮**：`_prefetchCts` 每次 `Cancel` 旧的再起新的，⛔ 不在旧队列上叠加；
   章节集合必须在 UI 线程 `ToList()` 取快照后交给后台。
5. 🔴 **整本下载先选路径再开跑**：下载可能几分钟，别让用户等完才发现没处存；取消只停后续章节，已抓内容照常合并落盘。
6. 书源编辑保存时沿用原启用状态（JSON 常不写 `enabled`），⛔ 不能因为改规则把源悄悄停用。
