## 背景 / 目标

用户需求（2026-10-28）：「扫描一个指定文件夹里的数据，压缩后发送到邮箱或者上传到网盘里，需要一个密码生成器，这样压缩的时候就可以加密，上传后也是加密的，这些备份的文件要支持还原」。

拍板结论（2026-10-28）：

| 决策点 | 结论 |
|---|---|
| 归档加密后端 | **外置 7z.exe**（AES-256 + `-mhe=on` 头部加密）；⚠️ 用户机器需装 7-Zip，设置页探测 + 缺失时状态栏 `⚠` |
| 投递通道 | **WebDAV + SMTP 邮件**（通道能力清单化，后续加别家只加实现） |
| 密码 | **生成器 + 主密码密码库**（PBKDF2 → AES-GCM，主密码不落盘） |
| v1 范围 | **手动触发 + 全量归档 + 保留轮转**；定时 / 增量 / 断点续传列 v2 |

本卡只做「本地闭环」：能建任务 → 生成密码 → 归档加密 → 本地包清单 → 还原回去。投递（WebDAV / 邮件）与远端轮转在 **NT-118**。

## 技术要点 / 约束

- 🔴 **`-mhe=on` 必开**：只加密码不加密头部，包内文件名与目录结构仍可读，「加密」不成立。
- 🔴 **密码只能走命令行 `-p`**（7z 不支持 stdin / 密码文件）⇒ 同机其他用户可看到进程命令行；缓解 = 包级独立密码 + 密码库加密 + 日志绝不回显命令原文。
- 🔴 **还原必须防路径穿越**：7z 解包不保证拒绝 `..`；先解到 `data\backup\staging\restore-<ts>` 再校验搬运（同时避免解到一半污染目标目录）。
- 🔴 **7z 退出码**：0 成功 / 1 警告（可接受）/ 2 致命 / 7 命令行错 / 8 内存不足 / 255 用户中断 —— 2 与 7 要区分提示（后者多半是参数或路径带引号问题）。
- 🔴 **源目录递归遇锁文件**：v1 不做 VSS，遇到独占文件按 7z 警告（退出码 1）继续并汇总「跳过 N 个文件」，⛔ 不因此判整个任务失败。
- 🔴 密码库与 `plans.json` 分开落文件：改了任务配置不影响密码库，损坏时可独立处理。
- ⛔ 不复用 `Core/BackupService.cs`（那是配置节备份），命名避开 `BackupService`（本模块用 `ArchiveService` / `VaultService` / `BackupPlanStore`）。
- ⛔ 不引第三方压缩库 / 不写 DPAPI（保持跨平台中立，见 framework §2.1）。
