## 背景 / 目标
竖屏视频转横屏、录屏带一圈黑边、只想保留画面中间一块——现在只能手写 `-vf crop=...`。
本卡把裁剪做成**四个数 + 一个按钮**：填宽高与起点，或点「🖼 探测黑边」让 ffmpeg 自己算。

## 验收标准
- [x] `TranscodeTask` 新增 `CropWidth / CropHeight / CropX / CropY`，随任务 JSON 持久化；`IsCropping` 要求宽高同时 > 0
- [x] 两页详情卡出现「裁剪（宽 × 高）」「裁剪起点（X × Y）」两个成对输入
- [x] 「🖼 探测黑边」：跑 2 秒 `cropdetect=24:2:0`，把最后一条 `crop=W:H:X:Y` 填进四个框（预览页从预览位置取，批量页从区间起点取）
- [x] 命令滤镜顺序 = 旋转 → **裁剪** → 缩放 → 字幕（先裁再缩，用户填的像素坐标才对得上）
- [x] `-c copy` 预设遇到裁剪自动升级 `libx264`（滤镜没有 copy 的落脚处）
- [x] 预检：只填一个边 → 红字；奇数边 → 提示会自动取偶；探测失败 → 状态栏照实说，不改已有值

## 技术要点
- `FfmpegService.CropFilter` 宽高向下取偶（yuv420p 2×2 采样，奇数边编码器直接拒）
- `FfmpegService.DetectCropAsync` 独立 `Process`（要的是 stderr 日志，不走 `RunAsync` 的进度解析）
- 批量页探测结果只进**编辑缓冲**，点「💾 保存修改」才写回任务（与其它字段一致）

## 范围 / 不做
- 不做可视化取景框（拖框选区域）——数值 + 探测已覆盖「去黑边」这个主场景
