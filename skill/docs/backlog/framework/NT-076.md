## 背景 / 目标
用户拍板（2026-10-19）：**放弃多库切换**，一个配置档 = 一个总库；「同一批文件多套标签」由库内 `tags` / `collections` 表达，
彻底隔离则新建 profile（= 新库）。

现状与目标差距：
| 项 | 现状 | 目标 |
|---|---|---|
| 数据库 | `data\newtoys.db`（资产/视频）+ `data\script\script.db`（脚本观测，106KB） | **只剩 `data\newtoys.db`** |
| 内容型 JSON | `config\script\script.json`（28KB）、`web-tools\bookmarks.json`、`ping-targets.json`、`scrape-tasks.json`、`hosts-profiles.json`、`video-tasks.json` | 进表；JSON 只做导入导出 |
| 建表位置 | 分散在 `AssetDatabase.cs:75-203` / `VideoMediaIndex.cs:42` / `ScriptDatabase.cs:52-64` 的**构造函数** | 统一入口按模块契约跑 |
| 版本 | 无 | `PRAGMA user_version` + 每模块 `SchemaVersion` |

🔴 为什么必须统一建表入口：总库由 4 个模块共建 14+ 张表，用户若只打开资产页，脚本表压根不存在；
一旦将来出现「按需打开某模块」，表缺失会直接崩。这跟「一个配置一个库」是否切换库无关，是总库本身的要求。

## 技术要点 / 约束
- 🔴 **不可逆操作必须先快照**：迁移前 `VACUUM INTO '<DataDir>\backups\pre-migrate-<时间戳>.db'`（⛔ `File.Copy`，WAL 下会拿到坏快照）。
- 🔴 迁移只在「目标表为空 且 源存在」时执行，重复启动不重复搬；判定失败按「已迁移」处理（宁可漏搬也不重复插）。
- ⚠️ 现有 `VideoMediaIndex` 与 `assets` 表存在**双份文件索引**，本卡只立纪律、不做合并（合并是后续独立工作项）。
- ⚠️ `script.json` 的结构里含嵌套（采集器/视图/集合），直接拆表成本高；允许先「整份 JSON 存一列 + 索引列单独拆」（`kind` / `rootPath` / `name`），保证查询面够用。
- ⚠️ 单实例：已有 profile mutex；本卡不引入库锁（已否决多库切换）。
- ⛔ 不做多库、不做库指针、不做热切换。
- 建议同时补最小单测（`tests/Core.Tests`）：迁移幂等 + 版本降级拒绝 + `VACUUM INTO` 快照可打开。只测这三类，⛔ 不铺 UI 测试。
