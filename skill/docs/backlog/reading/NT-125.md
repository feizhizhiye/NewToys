## 技术要点 / 约束

### 求值器设计（🔴 决定成败）

```csharp
// 🔴 返回联合体，⛔ 不能是 List<string>
enum RuleValueKind { Texts, Nodes, Json }
readonly record struct RuleValue(RuleValueKind Kind, IReadOnlyList<string> Texts, IReadOnlyList<IElement> Nodes, JsonElement? Json);

// context = 文档根 or 某个节点（bookList 命中的单个条目）
RuleValue Evaluate(string rule, RuleContext ctx);
```

- **分段顺序**：`{{}}` → `||` → `&&` → `##`（`##` 后两段是「正则 / 替换串」，⛔ 不是规则）
- 🔴 **`@js:` / `<js>` 片段不参与拆分**（那里的 `||` 是 JS 逻辑或），本卡直接标记「需 JS」返回空
- 🔴 **条目字段的作用域**：`ruleSearch.bookList` 求值得到**节点集**后，`name` / `author` 等字段要在**每个节点内**分别求值（`ctx.Root = 该节点`），⛔ 不能都对整页求值再按索引拼 —— 那是现有 `Module.ScriptManager` 抓取引擎错位的根因
- 选择步骤逐层收窄：`class.result@tag.li&&tag.a@text` 的第 1 步在根内找 `.result`，第 2 步在每个 `.result` 内找 `li`，`&&` 之后以 li 节点集为新根继续

### 管线状态机

```
Search(url,key) → [ResultItem] → Detail(bookUrl) → BookDetail
                              → Toc(bookUrl|tocUrl) → [Chapter]  (含 nextTocUrl 翻页)
                              → Content(chapterUrl) → string     (含 nextContentUrl 拼接)
```

- 每步都记录 `(step, ruleName, rule, error)`，界面按这个显示。
- HTTP 走 `HttpClient`（`AllowAutoRedirect`），编码嗅探沿用查看器那套（BOM → 严格 UTF-8 → GB18030）。

### 数据

- 库：**一个模块一个库** ⇒ `store\reading\reading.db`（`ReadingSchemaContributor : ILibrarySchemaContributor` 幂等建表，`DatabaseKey = "reading"`；照 `Module.MediaAssets` 的 `AssetsDb` 模式，⛔ 不并进别模块的库）
- 表：`book_sources`（url 主键 / name / group / type / enabled / rules_json / last_used_at）、`shelf`、`reading_progress`（批3 用，本卡先建表不接 UI）
- 设置：`config\reading.json`（并发 / 超时 / UA / 缓存开关），唯一写入点 = 本模块设置页（本卡可先只读默认值）
