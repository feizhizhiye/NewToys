## 背景 / 目标
用户新需求（2026-10-13，v3.26）：软件已支持多配置，但要**同时启动多个配置**（多实例）。核心 = 数据隔离 + 启动机制。
已核对的代码事实：① 现无单例互斥（同配置多开=共享 config/db 互相踩）；② `ProfileService.SwitchTo` 现语义 = 写 `active-profile.txt` + `RestartApp()` 无参重启——多实例下 A 窗切换会偷改 B 窗下次无参启动的默认；③ SQLite `busy_timeout=3000` 已设（`SqliteDatabase.cs`）。

## 验收标准（可验证清单）
- [ ] `NewToys.exe --profile work` 起实例跑 work 配置；无参起实例读 `active-profile.txt`；参数非法 / 配置不存在 → 回退默认 + 状态栏一行提示（⛔ 不崩）
- [ ] 同时开 2+ 个不同配置的实例：数据完全隔离（各自 config/db/缩略图/日志），互不感知
- [ ] **每配置单例**：同配置起第二例 → 提示「该配置已在运行」后退出；⛔ 不静默、⛔ 不抢焦点；不同配置不受影响
- [ ] 某实例内「切换配置」→ 本窗重启到目标配置；**`active-profile.txt` 内容不变**（grep/read 验证）；另一实例的下次无参启动默认不变
- [ ] 「设为默认配置」→ 写 `active-profile.txt`；之后无参启动 = 该配置
- [ ] 「设置 → 配置」页每配置行有「🚀 新开」，点起新实例（带 `--profile`）

- [ ] 回归：单实例全部现有行为不变（切换/重启/新增/重命名/删除）

## 技术要点 / 约束（规范章节、坑点、关键文件）
- **参数解析**：`App.OnFrameworkInitializationCompleted` 最早处（建 `ServiceCollection` 前）从 `Environment.GetCommandLineArgs()` 取 `--profile <名>`；`ConfigStoreService` 加 profileOverride 构造参数 / 属性，`ActiveProfileName` 解析顺序 = **参数 > `active-profile.txt` > `default`**（现行 `ReadActiveProfileName` 只读文件 → 加一层优先級）
- **每配置单例**：`new Mutex(false, "Local\\NewToys_Profile_" + name.ToLowerInvariant())` + `WaitOne(0)`；占不住 → 提示 + `Environment.Exit(0)`。⛔ 别用 `Global\`；配置名大小写不敏感 → mutex 名统一小写；⛔ mutex 对象必须全局持有（⛔ 别 using 掉——`using` 会释放）
- **切换新语义**：`IProfileService.SwitchTo(name)` **不再写指针**；`RestartApp` 改 `RestartApp(string profile)` → `Process.Start(new ProcessStartInfo(exe, $"--profile {profile}") { UseShellExecute = true, WorkingDirectory = AppContext.BaseDirectory })`；新增 `SetAsDefault(name)` 才 `SetActiveProfile`
- **视图层**：`ProfileViewModel`（settings-profile 页）切换按钮文案 / 二次确认保留；新增「⭐ 设为默认」与「🚀 新开」两个按钮；标题在 `ShellView` 启动时按 `IProfileService.ActiveProfile` 设 `Title`
- 首启迁移竞态：⛔ 不加迁移锁（需求已定：容忍 + 自愈）；`ProfileMigrationError` 既有提示路径复用
- ⚠️ `ConfigStoreService` 构造时机：在 DI 注册前还是作为单例注入——执行时定（参数优先走「注入前已知」，别让覆盖值被容器生命周期绕坏）
