# 任务卡（Task Card · 工作项细节）

> 🔴 **术语**：本目录的每一份 `NT-xxx.md` = **任务卡（Task Card）**；《项目状态与路线图》三、里那一行 = **工作项（Work Item）**。术语唯一定义见 `../NewToys-AI协作手册.md`【术语对照】。
> 两级的分工：
> - **台账三、 = Backlog 工作项**（紧凑：NT-id / 一句话 / 优先级 / 状态），改动小，只在「立项」和「翻已完成」时动。
> - **本目录 = 任务卡**（每个工作项一个文件），是实施期的工作稿，**随 `src/` 改动而更新**；验收后**默认保留**，被后续工作项整体取代 / 明确作废的卡删除。
> 定位：**规划期写任务卡、实施期改任务卡、验收后归档保留**。
> 🔴 **流程不在此定义**：`研发流程（规划期 / 实施期）` + 状态机 + 归档策略的唯一定义处 = `../NewToys-AI协作手册.md`【研发流程】节；本文件只定义任务卡的**格式与生命周期**。

## 状态机（单个工作项的生命周期）
`📝 草稿 Draft` → `✅ 就绪 Ready` → `🔄 执行中 In Progress` → `✔ 已完成 Done（待验收）` → （验收后）`Accepted`

- **📝 草稿（Draft）**：已立项进台账，但任务卡细节尚未展开 / 未确认可执行。**不执行**。
- **✅ 就绪（Ready）**：**通过就绪闸门（DoR · Definition of Ready）** —— 验收标准 / 技术要点 / 范围明确，可被批量执行。
- **🔄 执行中（In Progress）**：实施期正在实现，任务卡随代码推进追加「执行记录」。
- **✔ 已完成（Done）**：代码落地 + 静态检查（Lint）通过，等用户验收。
- **验收后（Accepted）**：台账工作项翻 `✔ 已完成`；任务卡**保留**（见下方归档策略）。

## 归档策略（验收后）—— **默认保留**，作废卡删除（2026-10-17 修订）
- `NT-xxx.md` **默认保留**：任务卡是**按需读取**的——只有真去读它才花 token，留着不额外占用；且能当历史归档查「当时怎么定的 / 踩过哪些坑」。
- 🔴 **删除例外**：内容被后续工作项**整体取代 / 明确作废**的卡**直接删除**（历史价值 = 0），台账三、对应行标 `🗑 已作废（卡已删）`。
- 台账三、的工作项行**始终保留**（只翻状态）。
- ⛔ 已废止：2026-10-14「全量保留」定调、更早的「验收后删除 / 只留最近 3 个」。

## 两条铁则（本目录专用）
1. **规划期不碰代码**：讨论产出的工作项，只在台账三、登记 + 在本目录写任务卡，**绝不改 `src/` 代码**。可多轮累积、多个工作项并行展开。
2. **就绪闸门（DoR）**：只有 `✅ 就绪` 才被实施期批量跑；`📝 草稿` 永不执行。

## 实施期（批量自动跑）
触发：开会话，发「**执行全部就绪待办**」（或「执行 NT-xxx」）。Agent 在循环里：
1. 读台账三、，筛出 `✅ 就绪` 且依赖已 `✔ 已完成` 的条目；
2. 按 **依赖顺序 → 优先级（P0>P1>P2）** 排序；
3. 逐条：读 `NT-xxx.md` 任务卡 → 按《需求规格》《工程规范》改 `src/` → 静态检查（`../../scripts/accept.ps1`，一键验收）→ 标 `🔄 执行中` → 成功标 `✔ 已完成（待验收）` 并 git commit、回写台账、任务卡追加「执行记录」；
4. **遇阻塞（5 种阻塞上报情形之一）立即停并报告**，不偷偷跳过、不擅自扩大范围。

> ⚠️ 不用 automation 定时触发：它是单 prompt 提醒，无「编译→修错→再编译」迭代，跑不动真实代码。
> 「睡觉让 AI 跑」= 睡前开一个会话发「执行全部就绪待办」，agent 在循环里把就绪项跑完——这就是「你不在场」的形态。

- 关联需求：需求规格 §x.y
- 依赖：NT-yyy（无则删此行）
- 创建：YYYY-MM-DD ｜ 更新：YYYY-MM-DD

## 背景 / 目标
## 验收标准（Acceptance Criteria，可验证清单）
- [ ]
## 技术要点 / 约束（规范章节、坑点、关键文件）
## 范围 / 预估文件清单
