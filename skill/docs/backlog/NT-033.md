## 背景 / 目标
`AssetMergeService.MergeAssets` 注释写明"**一律新建**"，资产级**不做去重**；位置级去重（`storage+relative_path` / `hash+size`）只覆盖 `file_locations`。结果：
- **重合并同一库第二次**：资产全部新建，位置因已存在而全部 skipped → 主库多出一批**零位置的孤儿资产**；类注释第 47 行"幂等…基本全跳过"**名不副实**。
- **合并两个共享文件的不同库**：共享文件在主库已有资产，源库资产仍新建、其位置因 hash+size 命中被 skip → 同样产生孤儿资产、列表计数虚高。

## 验收标准
- [ ] 重合并同一 `.db` 第二次：不产生零位置孤儿资产（重复资产在事务内被清除）。
- [ ] 合并与现有库共享文件的两个库：共享文件不新增孤儿资产。
- [ ] 首次合并一个**独立**库：行为与修复前一致（所有资产都有位置，零清除）。
- [ ] 合并结果文案与 `MergeResult` 准确反映"新增资产 / 新增位置 / 跳过重复位置 / 清除孤儿资产"。

## 技术要点 / 约束
- 🔴 `MergeLocations` 返回本次**实际落到主库位置的资产 id 集合**（`located`）。
- 在链接表 / 关联合并**之后**、`tx.Commit()` **之前**，清除"本次新建却零位置"的资产：删 `assets` + 其 `asset_tags` / `asset_categories` / `collection_assets` / `relations`（双向）。仅删 `assetMap.Values` 中不在 `located` 的 id（⛔ 不动合并前已存在的主库资产）。
- `newAssets`（最终上报）= `located.Count`；`MergeResult` 新增 `SkippedAssets` 字段承载清除计数；修正类注释"幂等"表述。
- ⛔ 不动框架层；仅改 `Module.MediaAssets/Services/AssetMergeService.cs`。
