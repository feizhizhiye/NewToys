# 任务卡（Task Card · 工作项细节）

> 🔴 **术语**：本目录的每一份 `NT-xxx.md` = **任务卡（Task Card）**；《项目状态与路线图》三、里那一行 = **工作项（Work Item）**。术语唯一定义见 `../NewToys-AI协作手册.md`【术语对照】。
> 两级分工：
> - **台账三、 = Backlog 工作项**（紧凑：NT-id / 一句话 / 优先级 / 状态），只在「立项」和「翻已完成」时动。
> - **本目录 = 任务卡**（一个工作项一个文件），是实施期的工作稿，**随 `src/` 改动而更新**。
> 🔴 **流程不在此定义**：`研发流程` + 状态机 + 归档策略的唯一定义处 = `../NewToys-AI协作手册.md`【研发流程】；本文件只定义**目录组织、格式与生命周期**。

## 一、目录组织（2026-10-18 起）

```
backlog/
  framework/        跨模块 / 改 Shared·Core·Shell·UI 的卡
  script-manager/   脚本管理器
  media-assets/     媒体资产
  video-tools/      视频工具
  web-tools/        网络工具
  reading/          阅读（Module.Reading，NT-125 起）
  (无 settings-app/ —— 应用级设置 + 首页的卡已于 2026-10-18 整目录删除，新卡一律放 framework/)
  (无 viewer/ —— 查看器 NT-124 改 UI 库 + Shell，卡放 framework/)
```

- **一个模块一个目录**；新增模块 ⇒ 新增同名目录（与 `docs/modules/<模块>.md` 同名）。
- 🔴 **涉及 2 个以上模块、或要改 Shared / Core / Shell / UI 的卡，一律放 `framework/`**（并在 `framework.md` §11 登记一行）。
- 台账「详情」列写 `backlog/<目录>/NT-xxx.md`。

## 二、滑动窗口（每目录 ≤5 张已验收卡）

- **每个目录最多保留 5 张「已验收」卡**；新增卡使已验收数超 5 ⇒ 删除**最旧**的那张。
- `📝 草稿 / ✅ 就绪 / 🔄 执行中 / ✔ 已完成（待验收）` 的卡**不参与淘汰计数**（防止正在实施的长卡被挤掉）。
- 🔴 **验收即蒸馏（前置条件）**：卡验收后先把「结论 / 偏差 / 坑点 / 关键文件」写进 `docs/modules/<模块>.md`（跨模块写 `docs/framework.md` / `docs/ui.md`），该卡**才可**被淘汰。
- 被后续工作项**整体取代 / 明确作废**的卡 → 直接删除，台账行标 `🗑 已作废（卡已删）`。
- 台账行**始终保留**（只翻状态）。
- ⛔ 已废止：2026-10-14「全量保留」、2026-10-17「默认保留 + 仅删作废卡」（被本条取代）。

## 三、状态机（单个工作项的生命周期）

`📝 草稿 Draft` → `✅ 就绪 Ready` → `🔄 执行中 In Progress` → `✔ 已完成 Done（待验收）` → （验收后）`Accepted`

- **📝 草稿**：已立项进台账，但细节未展开 / 未确认可执行。**不执行**。
- **✅ 就绪**：通过就绪闸门（DoR）—— 验收标准 / 技术要点 / 范围明确，可被批量执行。
- **🔄 执行中**：实施期正在实现，卡随代码推进追加「执行记录」。
- **✔ 已完成**：代码落地 + 静态检查通过，等用户验收。
- **Accepted**：台账翻 `✔ 已完成（已验收）`；卡进入滑动窗口。

## 四、两条铁则（本目录专用）

1. **规划期不碰代码**：讨论产出的工作项只在台账登记 + 本目录写卡，**绝不改 `src/`**。可多轮累积、多个工作项并行展开。
2. **就绪闸门（DoR）**：只有 `✅ 就绪` 才被实施期批量跑；`📝 草稿` 永不执行。

## 四之二、粒度与攒批（2026-10-19 起）

- **一张卡 = 一个用户可感知的功能单元**，卡内可含多个子步骤；⛔ 不为单点样式 / 文案 / 布局微调 / 返工新开卡（并入当前卡或当轮直接修）。
- **一批卡一次 build**：同程序集 / 同改动面的卡分组实施，全组做完**由用户跑一次** `scripts/build.ps1`；AI 侧只跑 `accept.ps1`（纯静态检查，不构建）。改动落入 Shared/Core/Shell/UI 时合并为一次验收。
- ⛔ 中途不要求用户为局部改动重建。


## 五、实施期（批量自动跑）

触发：开会话发「**执行全部就绪待办**」（或「执行 NT-xxx」）。Agent 在循环里：
1. 读台账三、，筛出 `✅ 就绪` 且依赖已 `✔ 已完成` 的条目；
2. 按 **依赖顺序 → 优先级（P0>P1>P2）** 排序；
3. 逐条：读卡 → 按《需求规格》/`framework.md`/`ui.md`/`modules/<模块>.md` 改 `src/` → **同组卡全部做完后** `pwsh skill/scripts/accept.ps1`（静态检查，⛔ 不构建）→ 标 `🔄 执行中` → 成功标 `✔ 已完成（待验收）` + git commit + 回写台账 + 卡内追加「执行记录」；构建由用户在组末统一跑一次 `scripts/build.ps1`；
4. **遇阻塞（5 种阻塞上报情形之一）立即停并报告**，不偷跳、不擅自扩大范围。

> ⚠️ 不用 automation 定时触发（单 prompt 无「编译→修错→再编译」迭代）。
> 「睡觉让 AI 跑」= 睡前开会话发「执行全部就绪待办」。

- 关联模块：script-manager | media-assets | video-tools | web-tools | framework（应用级设置 / 首页 / 功能清单已归 framework）

- 依赖：NT-yyy（无则删此行）
- 创建：YYYY-MM-DD ｜ 更新：YYYY-MM-DD

## 验收标准（Acceptance Criteria，可验证清单）
- [ ]
