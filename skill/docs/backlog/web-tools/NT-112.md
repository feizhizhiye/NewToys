## 背景 / 需求（用户 2026-10-26 原话）

> hosts管理页也应支持shift，Ctrl等多选，并能实现校验是否有效，应把shift，Ctrl多选写进文档，这样的体验就类似windows资源管理器了。

现状（NT-111 之后）：两栏都是 `SelectionMode="Single"`，只能一次选一行；「🔍 检测」只能对右栏整份方案跑一遍 —— 想只验几条、或想验左栏草稿里的几条都做不到。

## 设计决策

**D1 · 多选交由 View 自算（照 `BookmarkView` 的既有做法）**
- `SelectionMode="Multiple"` 只管「能选多个」，Avalonia 不会自动给 Shift 连选 ⇒ 修饰键点击在**隧道**阶段接管：`Ctrl` 切换该行 / `Shift` 从 `_anchor` 连选 / `Ctrl+A` 全选本侧条目行；无修饰键放行默认逻辑并重设基准。
- 通用口径写进 `ui.md` **§6.10**（此后其它列表页照抄，⛔ 各自发明）。

**D2 · 多选快照与详情卡分离**
- `SelectedItem` 继续只服务详情卡（单一侧别）；多选快照 `_selectedSystemRows` / `_selectedProfileRows` 由 View 的 `SelectionChanged` 回填。
- 两栏**互斥**（一侧多选即清另一侧）。
- `RefreshRows` 重建行后按**行号**回填高亮（`SelectionRestoreRequested` 事件 → View 重设 `SelectedItems`），否则启用 / 禁用一刷新就掉选。
- 计数写列表内计数文本「已选 N」（⛔ 状态栏，§10.4）。

**D3 · 「检测选中」= 只验选中的条目，结论上列表**
- 无多选 ⇒ 退回「🔍 检测」（整份方案），保持旧入口有效。
- **选中即测**：`HostsCheckService` 只测 `Enabled` 条目，但用户显式选中就是要验 ⇒ 造 `Enabled=true` 的临时 `HostsEntry` 去测。
- 结论落点：右栏行 + 方案真条目（`Status / LatencyMs / ResolvedIp / Port`）；左栏是草稿投影、文本里不存结论 ⇒ 走页面缓存 `_leftProbeCache`（「行号 + IP + 主机名」对上才复用）。
- 列表「状态」列改为 `StatusColumnText`：有结论显示结论，没测过才显示「禁用」；列宽 64 → 132。

**D4 · 批量启停（多选的第二个落点）**
- `✅ 启用选中` / `⏸ 禁用选中`：左栏改草稿（`ParseLines` → 改 `Enabled` → `RenderLines`）、右栏改方案内存；各自仍需原落盘点（`✅ 写入系统 hosts` / `💾 保存方案`）。
- 备份快照只读 ⇒ 左栏拒绝并给提示。

## 验收标准

1. 两栏都能 `Ctrl` 逐条加减、`Shift` 连选、`Ctrl+A` 全选；选中行一起高亮，计数显示「· 已选 N」；两侧互斥。
2. 多选后右键 `🧪 检测选中` ⇒ 只测选中条目，结论出现在「状态」列（✅ 可达 / ⚠ 解析不一致 / ❌ 不可达 / ⏱ 超时）；左栏草稿行也能测。
3. 未多选时点 `🧪 检测选中` ⇒ 等价旧的整份方案检测。
4. 多选后 `✅ 启用选中` / `⏸ 禁用选中` ⇒ 左栏改草稿（底栏按钮出现「（有改动）」）、右栏改方案内存；刷新后选中不丢。
5. 右键落在**未选中**行 ⇒ 改为单选它；落在**已选中**行 ⇒ 保持整批（批量命令吃整批）。
6. 文档双写：`ui.md` §6.10（通用口径）+ `modules/web-tools.md` §2.5 操作表 + §5 坑点 46~48 + 说明书 §四 / §五。
