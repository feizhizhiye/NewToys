- **追加**：2026-10-27 编译通过后用户追加「也增加 Ctrl/Shift 多选模式」⇒ 第一轮的「☑ 多选」开关被**整体替换**为列表原生多选

## 背景（为什么做）

1. **清理重复缺手段**：列表一行 = 一条资产。同一物理文件被多条资产收录时，删除只有两条路 —— `DeleteToRecycle`（把文件搬进系统回收站）与 `DeleteFromDisk`（真删文件）。两者都会动磁盘，**不能用来自整理索引**。缺的是「只删库存记录」。
2. **查重入口藏太深**：`AssetService.MergeDuplicatePaths()` 早已存在，入口只在「存储源」页的 `🧹 合并重复`，在「全部资产」看到重复行的用户找不到。
3. **媒体信息有服务没入口**：`MetadataService`（ffprobe / 图片文件头）已注册、扫描时会自动跑，但没有手动补读入口。
4. **选择机制是两套状态**：`SelectionMode="Single"` + 每行常显勾选框 ⇒ 勾选行与"当前选中"互不相干，用户不知道点哪里；而资源管理器式多选（Ctrl / Shift）根本没有。

## 验收标准

1. 工具条新增 4 项：`⤫ 从库移除` / `📊 读媒体信息` / `🔍 查重合并`；批量项的启用条件 = 有选中行。
2. **多选与资源管理器一致**：单击 = 只选该行；`Ctrl` = 增选 / 取消；`Shift` = 从基准行连选；`Ctrl+Shift` = 追加连选；`Ctrl+A` = 全选当前页。**无勾选列、无「多选开关」**，高亮即选中即批量对象。
3. 底栏「已选 N」= 选中条数；列表右键尾部有「☑ 全选当前页 / ☐ 取消选择 / ⇄ 反选当前页」。
4. `⤫ 从库移除`：二次确认 → `DeleteAsset`（连带位置 / 挂接 / 关联）→ 刷新；**磁盘文件零操作**；文案说明"文件仍在已登记源目录 ⇒ 下次扫描会重新入库"。
5. `🔍 查重合并`：先 `CountDuplicatePaths()` 报组数 → 确认 → `MergeDuplicatePaths()` → 刷新并报「合并 N 组 / 删除 N 条 / 重挂 N 个位置」；组数为 0 时引导到「从库移除」。
6. `📊 读媒体信息`：只跑**还没读过**的（时长 / 分辨率 / 编码全空）⇒ 幂等；走 `TaskQueue`（可取消）；逐条报进度；单条失败不影响其余；结束刷新列表。
7. 详情卡 IconBar 新增 `⚡ 读媒体信息`（`IconZap`）：读当前选中项，成功后 `RefreshView()` 按 Id 认领选中项（详情卡不跳走）。
8. 静态检查通过（`accept.ps1 -SkipBuild`：0 阻断）。

## 技术要点

- **不动框架层**：全部落在 `Module.MediaAssets`，服务层复用 `AssetService` / `MetadataService`。
- 新文件 `ViewModels/AssetAllViewModel.Maintain.cs`（partial）：三个维护命令 + `CanReadMediaInfo` 判据。
- **选中真相在 VM**（`AssetAllViewModel.Selection.cs` 的 `SelectedRows` / `SelectedCount` / `HasSelectedRows`）：View 只把鼠标行为翻译成 `SelectedItems` 变化后回填；VM 侧改选中（全选 / 反选 / 重建认领）走 `SelectionSyncRequested` 事件反向回填，`_syncingSelection` 抑制回抛。
- 🔴 **Avalonia 12.1.4 的 `SelectionMode` 只有 `Single / Multiple / Toggle / AlwaysSelected`，没有 Ctrl/Shift 扩展语义**；且 `Multiple` 的单击默认是「追加」⇒ 无修饰键也必须自己接管（替换语义），否则单击看详情会越选越多。做法与 `Module.WebTools` 的 Hosts 页（NT-112）一致：`PointerPressedEvent` 在**隧道**阶段接管 + `Ctrl+A` 走 `KeyDownEvent`。
- `ReconcileSelection()` 在每次列表重建后按 Id 认领选中项（`Items` 里都是新实例），并把「高亮 == 详情 == 批量对象」三者对齐（详情有内容就必须有一行被选中）。
- 勾选列已删 ⇒ 表头 / 行模板的 `Grid.Column` 全部 -1；`Columns` 里 `Pick` 列移除。

## 执行记录

- 2026-10-27 第一轮：三个命令 + 「☑ 多选」开关（勾选列随开关显示）。用户本地 build 通过。
- 2026-10-27 第二轮（用户追加 Ctrl/Shift）：撤勾选列与开关，改列表原生多选 + 隧道修饰键接管；`SelectedRows` 成为唯一选中真相；`accept.ps1 -SkipBuild` → PASS 6 / WARN 1 / FAIL 0（WARN = 存量 tech-guard 1 条）。
- 2026-10-27 第三轮（用户反馈「Ctrl+A 列表开始滚动、界面卡死」）：根因 = `SelectingItemsControl.AutoScrollToSelectedItem` 默认开 —— 批量回填 `SelectedItems` 时每 `Add` 一项都 `ScrollIntoView`（虚拟化下还要建容器 + 布局），全选 N 行 = N 次滚动。修法 = `AssetAllView.BulkUpdateSelection`：批量改动期间临时关自动滚动 + `_syncingSelection` 抑制回抛，`finally` 恢复原值（键盘方向键仍自动滚动）；`SelectRange` / `Toggle` / `ReplaceWith` / `OnSelectionSyncRequested` 四处统一走它。
- 2026-10-27 第四轮（用户反馈「查重合并第二次点弹窗跟第一次一样」）：根因 = **计数与合并口径不一致** —— `CountDuplicatePaths()` 统计所有「同路径多资产」组，而 `LoadDuplicateGroups` 里有一句 `if (组内含 trashed) continue` 把含回收站资产的组全跳过 ⇒ 用户先前把多余行「移入回收站」后，这些组永远计数得到、永远合并不掉。修法：删掉该过滤（组内 active 优先排序已保证保留在用那条，回收站记录只贡献挂接后被删）；`MergeDuplicatePaths` 的 `catch` 不再静默吞异常，改记 `LastDedupError` 并由 VM 显示；合并后复核 `CountDuplicatePaths()`，有残留就在状态栏明说剩余组数。
