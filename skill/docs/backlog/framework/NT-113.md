## 背景 / 目标

用户提问（2026-10-26）：「媒体资产模块的数据也放进对应的配置文件夹内…用 `newtoys.db` 会搞混淆的吧」→ 拍板走**最彻底方案**。

现状问题：
| 问题 | 说明 |
|---|---|
| 名字没信息量 | 4 个模块共用 `data\newtoys.db`，看不出是哪个模块的 |
| 语义自相矛盾 | `data\` 的定位是「可重建、不进备份」，但媒体资产的标签 / 分类 / 集合 / 关联**重建不了** |
| 备份/分享没有粒度 | 想只备份资产标签、或把资产库发给别人，只能连视频索引、书签一起打包 |
| 为此额外做的绕路 | `UserDataExport`（手工数据另存 json 兜底）本质是给共库打的补丁 |

⚠️ **与 NT-076 的关系**：NT-076（2026-10-19 用户拍板）否决的是「多库切换 / 库指针 / UI 里选库」；
本卡做的是**按模块固定拆物理文件**，模块与库一一绑定、没有选库 UI。二者不冲突。

## 技术要点 / 约束

- 🔴 **迁移必须在库被创建之前跑**，但模块服务可能在迁移前就把空库建出来 ⇒ 拆库**逐表判断「目标表为空才搬」**（`INSERT INTO … SELECT`），`CREATE` 语句改写成 `IF NOT EXISTS` 幂等形式。
- 🔴 **拆库以新库为主连接、`ATTACH` 旧库来读**：这样 DDL 与索引天然建在新库；反过来做会把索引建回旧库。
- 🔴 **老库只改名不删**：`store\legacy\newtoys-v1.db`（+ `-wal` / `-shm`）。改名前 `SqliteConnection.ClearAllPools()`。
- 🔴 **抓取目录元数据跨库搬家**：抓取能力原属网络工具 ⇒ `scrape-tasks` 文档在 `web_docs` 里；现归脚本模块 ⇒ 迁移器把它复制进 `script.db` 的 `script_docs`（`INSERT OR IGNORE` 幂等），`RuleCatalogService` 随之改用 `script` 前缀。
- 🔴 **脚本实体目录保持 `store\scripts`**（不并进 `store\script\`）：用户可能已在设置里保存了指向该目录的绝对路径，改名会让老配置失效。
- ⛔ 不做自动回退（太贵）：装回旧版本需手工把 `store\legacy\newtoys-v1.db` 覆盖回旧位置。
- ⛔ 不引入库指针 / 选库 UI / 跨库查询。
