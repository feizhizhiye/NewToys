## 一、产品定位

**NewToys = Windows 桌面「命令行能力封装器 + 文件资产管理器」**，自带 GUI、模块化、本地运行、单机自用。

| 维度 | 内容 |
|---|---|
| 一句话 | 把散落在命令行 / 系统设置 / winget / ffmpeg / 脚本里的能力，收进一个窗口里点一下就能用 |
| 用户画像 | 有电脑知识的个人用户；不需要假数据、不需要引导 |
| 交付形态 | 单窗口桌面应用 + `Modules\` 目录下的独立模块包 + 随包 `defaults\` 默认资源 |
| 主平台 | Windows 10 LTSC（当前）；预留迁移 Debian 13（平台后端见 `framework.md` 技术债 B5） |

### 1.1 边界（做什么 / 不做什么）

**做**：查看 + 命令生成 + 批量执行 + 文件索引与整理 + 脚本/命令/采集器的收集与展示 + 本地配置档管理。

**不做**（⛔ 已定调，重写时也别做）：

| 不做 | 原因 / 去向 |
|---|---|
| 社交 / 推荐 / 埋点 / 云同步 / 账号 | 单机自用工具 |
| 内容分发与自动更新下载 | 只保留"更新检查"开关位 |
| 在线播放 / 转码服务化 | 播放 = 调用外部播放器；转码 = 调 ffmpeg |
| AI 自动打标 / 分类 | 不做 |
| 移动端 / 多端 | 不做 |
| 第三方 UI 库 / 图标字体 | 全局控件自绘 |

### 1.2 六条设计原则（产品取舍的裁决依据）

1. **模块化** —— 按功能域拆分，可独立开发 / 启停。
2. **插件化** —— 模块是独立编译产物，运行时装配；加模块不改宿主。
3. **轻量务实** —— 工具类应用，重效率与稳定，UI 不炫技。
4. **自控** —— 不引第三方 UI 库 / 图标包，控件自己写。
5. **命令行封装** —— 功能以「包既有命令行 / 系统能力」为主，不超命令行上限；**配置一律落文件、可备份**。
6. **可热加载** —— 模块文件放进 `Modules\`，运行中点一下即装配，不必重启；加载源**仅限本地文件夹**。

> 验收底线（每加一个功能都要能答上四问）：① 对应哪条命令行 / 哪个系统能力？② 配置落在哪个 `config/*.json`？③ 失败时用户在哪一行看到原因？④ 拷进 `Modules\` 后运行中点刷新能否用上？失败会不会拖垮宿主？

## 二、界面总览

### 2.1 布局骨架

全窗 = **标题栏（含标签页） + 左侧菜单栏 + 中间主内容区 + 右侧详情卡 + 底部状态栏**。

```
┌────────────────────────────────────────────────────────────────────────┐
│ ≡ │ ⟳   [标签页][标签页][标签页]            ＋ │ ⛶  —  □  ✕  标题栏 40px │
├──────────────┬──────────────────────────────────┬─────────────────────┤
│  左侧菜单栏   │                                  │  详情卡 340px        │
│  （树状折叠）  │        主内容区                  │  选中项的信息 +      │
│ 150px/48px   │    （当前标签页的内容）            │  该对象的命令       │
│              │                                  │  （可开合 → 0）      │
│  ⌂ 首页      │                                  │                     │
│  ▸ 脚本管理器 │                                  │                     │
│  ▸ 网络工具   │                                  │                     │
│  ▸ 视频工具   │                                  │                     │
│  ▸ 媒体资产   │                                  │                     │
│  1.26.10     │                                  │                     │
├──────────────┴──────────────────────────────────┴─────────────────────┤
│ 状态栏 26px —— 当前页面的状态（横贯内容区 + 详情区，⛔ 不跨左菜单栏）    │
└────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 职责 |
|---|---|
| 标题栏（窗口级） | 窗口控制 + 折叠左栏 + 重建当前页 + **标签页区** |
| 左菜单栏（窗口级） | 树状导航：首页叶子 + 一级分组 + 二级功能叶子；底部显示版本号 + 当前配置名 |
| 主内容区 | 当前标签页内容（列表页 / 预览页 / 表单页 / 设置页，按页型定） |
| 详情卡（右侧） | 选中项的**具体信息** + 针对该对象的**命令**（如将要执行的 ffmpeg 命令行） |
| 状态栏（窗口级） | 当前页面的状态一行（或几行）；**页面不自绘状态行** |

- 主窗口 **1280×800**，最小 **960×640**，可自由缩放；窗口大小 / 位置按配置记忆。
- 窗口标题 = `NewToys · <配置名>`（多实例在任务栏区分）。

### 2.2 密度与视觉基线（复刻"成熟感"的关键）

| 区域 | 尺寸 |
|---|---|
| 标题栏高 | 40px |
| 标签项内边距 | 水平 8 / 垂直 3；标题字号 13 |
| 左菜单栏宽 | 150px（折叠 48px）；树行高 30；缩进每级 16 |
| 内容区外边距 | 12 |
| 工具条内边距 | `12,6` |
| 筛选条内边距 | `12,4` |
| 卡片 | 圆角 8、内边距 12 |
| 按钮圆角 / 内边距 | 6 / `primary` 12,6、`ghost` 10,5 |
| 表头行高 | 32 |
| 表格行高 | 28（单元格左右内边距 8） |
| 详情卡宽 | 340（恒定） |

- **字号只有 3 档**：页面标题 15(SemiBold) / 正文·表单标签·树节点·标签页 13 / 表头·次要信息·状态 12。⛔ 不引入第 4 档。
- **圆角**：卡片 8 / 按钮 6 / 输入框 4；标题栏域一律 0。

## 三、通用交互机制（所有页面共用）

> 这一章是"重写时最先要建好的地基"—— 页面可以后做，这七件机制先立起来，后面 20 多页才不会各写各的。

### 3.1 导航模型

| 概念 | 规则 |
|---|---|
| 标签页 | 一个标签页 = 一个打开的功能页面 = 缓存的视图实例 + 一份视图模型 + 一个历史栈 |
| 打开方式 | 左树点叶子 → 若已打开则切过去、否则新开标签；首页也是标签栏里的一个标签（不可关闭），入口 = 左树「首页」或标签栏 `＋` |
| 标题栏 `⟳` | **销毁并重建**当前标签页（清掉页面内存状态）；⛔ 与页内「🔄 重读…」不是一回事 |
| 历史栈 | 契约已定义、当前**未实装导航**（前进 / 后退灰显） |
| 快捷键 | `F11` 全屏切换、`Esc` 退出全屏（全屏 = 铺满并覆盖任务栏，与最大化不同） |
| 托盘图标 | 左键 = 切显示/隐藏；右键五项 = 显示隐藏 / 打开首页 / 打开设置 / 用另一个配置打开 / 退出 |

### 3.2 列表页标准形态（三列 + 三段）

列表页内部 = **列表列 ｜ 详情列**；加左菜单栏即三列。工具条 / 搜索框 / 筛选条**一律收进列表列**（⛔ 不横贯整页宽）；详情卡从顶部开始、与列表列同高。

**主显示区 = 工具条 → 筛选条 → 列表 三行**，高度必须可预期：

1. **工具条默认最多两行**，按钮按优先级排序（XAML/声明顺序 = 优先级顺序），末尾固定一个 `⋯`：
   - 两行内放得下就全显示；放不下才把**尾部**几项收进 `⋯`；
   - 点 `⋯` = 全部显示 / 再点收起；全部放得下时 `⋯` 自己消失；
   - 🔴 底线：**窗口拉到最窄 960 + 详情卡展开，也不许破到第三行**；宁可少显示一个按钮。
2. **工具条前三项固定**（仅"数据来自外部"的页）：① 数据入口动作（📁 扫描 / 📂 导入…）→ ② 路径 / 来源输入框 → ③ 搜索框。**两个输入框必须相邻**；宽度统一 88；一律用占位水印提示（⛔ 框前不放文字标签）。
   - 纯管理页（标签 / 回收站 / 任务中心 / 分类 / 集合 / 存储源）⛔ 不许凭空凑三项，只保留搜索框 + 本页主动作。
3. **筛选条恒一行**：窗口变窄时筛选项自己变窄，⛔ 不换行 / ⛔ 不滚动 / ⛔ 不折叠进二级（前提是筛选项数量固定）。
4. **工具条只放页面级功能**（作用于整个列表 / 页面）；**针对某一条的动作一律放行右键菜单**。
5. 工具条按钮样式一律描边款；实心强调色**只留给详情卡动作与对话框主按钮**。红色款 ⛔ 只给会丢数据的动作。尺寸只存在一处（字号 12 / 内边距 10,5 / 最小高 28 / 圆角 6）。
6. 「需先勾选」的按钮：禁用时**提示词也必须弹得出来**（写明"先在列表里勾选行"）。⛔ 工具条里不放「已勾选 N 个」这类指示文字。

### 3.3 列表本体的交互

| 交互 | 行为 |
|---|---|
| 左键点表头 | 按该列排序（标题追加 ▲▼） |
| 右键点表头 | 「勾选列显隐」菜单（隐藏列 = 宽度 0，⛔ 不删列，保索引一致）+ 筛选分类项 |
| 拖动表头两列交界 | 手动改列宽（左宽多少、右窄多少，总宽守恒，每列 ≥24）；**只存本次会话**，⛔ 不落盘 |
| 列宽三态 | 星号比例（默认）→ 手动像素 → 隐藏(0)。⛔ **没有"自动调整列宽"**（会把长内容列撑爆） |
| 列宽锁定判定 | 每列填一条**示例值**（不显示，只参与计算）：示例文本宽 ≤ 表头文字宽 → 该列锁成表头宽（≥34），不可拖；否则照常星号 |
| 行首勾选框 | 有；表头 `☑` 图标**右键**弹出「全选 / 取消选择 / 反选」（⛔ 与表头其它位置的列显隐菜单分开） |
| 行右键菜单 | 打开 / 打开所在文件夹 / 复制 / 删除 / 发送到… 等单条动作 |
| 底栏 | 左计数 ｜ 分页链 ｜ 「每页 N 条」（含"全部"）。分页链靠右紧挨"每页"；窄空间优先牺牲左计数 |
| 空态 | 列表区居中显示「一行说明 + 一个入口按钮」，入口**复用该页既有命令**；⛔ 不显示半透明示例行、⛔ 不造假数据 |
| 详情卡空态 | 未选中时显示一句说明 |

- **右键菜单挂在独立弹出树上，不继承页面数据上下文** → 必须在code-behind/等效机制里**手工同步**数据源（行菜单 + 表头菜单都要）。
- **跨页投递**（如"多选 → 送到批量处理"）：经模块内单例 store 传递；取件点必须挂在**每次进入页面都触发**的生命周期回调上（⛔ 只用"数据上下文变化"回调 → 标签页已存在时切回来不触发，表现为"送过去要刷新才出现"）。

### 3.4 工具条 / 详情卡 / 状态栏 —— 「页面给数据，宿主给实现」

三件机制套路相同：**页面提供描述符（纯数据，不依赖 UI 框架），宿主统一渲染**。目的是 20 多个页面不各写一份 XAML。

| 机制 | 页面提供 | 宿主负责 |
|---|---|---|
| 工具条 | 条目列表（8 类：按钮 / 拆分按钮 / 勾选框 / 输入框 / 下拉 / 次要文字 / 分隔线 / 按钮组）+ 变更通知 | 渲染 + 自动折叠算法 + 末尾 `⋯` |
| 详情卡 | 卡片描述（标题 / 分区 / 字段 / 动作）+ 当前选中对象 | 渲染 + 空态 + 开合 |
| 状态栏 | 文本 + 变更通知 | 一条状态栏，始终显示（避免切页时布局跳动） |

- 页面未实现契约 ⇒ 宿主⛔ 不留空行（工具条行高 0）。🔴 **同一页不得宿主与页面各渲染一份**。
- 工具条项类型**只做加法**：优先用现有项 + 修饰位；只为某一页的特殊布局**不加**新类型（该页保持页内自绘）。

### 3.5 详情卡（右 340px）

- 内容 = 分区表单（字段 / 下拉 / 可编辑文本）+ 底部**命令区**（完整命令行，可选中复制 + 可手改参数 + 重置为自动）。
- 卡片内**零操作按钮**—— 跑 / 保存 / 删除 / 打开目录 之类一律排到列表上方的工具条（例外：媒体资产详情卡允许「保存」「应用到文件」）。
- 分区可折叠；**可勾选的分区 = 该段是否参与命令**，取消勾选即自动折叠。
- 宽度恒定 340，折叠分区只影响高度。
- 滚动条是覆盖式 → 卡内右侧留 8px + 内容右侧再留 8px，滚动条才收在卡内。

### 3.6 设置页

- 形态 = **树状滚动 + 节点抬头磁吸**（⛔ 无独立标题栏），一页到底。
- **即时生效**（⛔ 禁保存按钮）；多字段表单才用显式保存。
- 每页至少一行状态文字。
- 设置页作为**标签页**打开。

### 3.7 命名与按钮文案铁律（复刻体验的隐形部分）

1. **页内「重载数据」按钮命名** = `🔄 <动词><来源>`，⛔ 不只写"刷新"：
   - **重扫** = 枚举磁盘目录 →「🔄 重扫目录」
   - **重读** = 读数据库 / 配置文件 →「🔄 重读资产库」「🔄 重读书签」
   - **重查** = 联网查询 →「🔄 重新查询」
   - 🔴 同一页有两个时必须**名称不同**（重扫盘 vs 重读库）。
2. 按钮文字取**最短可比达义**：⛔ 不重述本页上下文；省略的名词写进悬停提示。
3. 同类动作用**动词区分**（`并入…` vs `另存为…`），⛔ 不并列两个同名词。

## 四、功能清单

> 全部页面清单与菜单 Key 见 §七 附录。Key 一经发布 ⛔ 不改（它落进用户的列布局 / 收藏 / 偏好文件）。

### 4.1 首页

- **按钮墙**布局：常用 / 收藏功能，一排按钮只显名称，**点一下即跑**；配色统一用强调色（⛔ 不多色）。
- 收藏卡**尾部恒排一张「显示更多」**：就地展开内嵌的**功能清单**（全集），再点收起。
- **一键操作固定在页面最底部**、位置不变（⛔ 不随收藏增删而动，保护肌肉记忆）。
- 状态栏显示「已加载 N 个模块 / M 个功能」。
- 首页是一个**常驻标签**（在标签栏最前、不可关闭）；`＋` 点一下也是回到首页。

### 4.2 脚本管理器（模块键 `script`）

**定位**：把「脚本 / 命令 / 采集器 / 软件包」四类可运行的东西收进一个四层模型 —— **采集器**（一条脚本或命令，产出结构化行）→ **集合**（若干采集器的组合 = 一屏数据）→ **视图**（列集合 / 筛选 / 排序 / 布局 / 刷新策略）→ **页面**。

| 页面 | 用途 | 要点 |
|---|---|---|
| **收藏夹** | 常用脚本与命令，点一下即运行 | 按钮墙 |
| **脚本库** | 脚本目录下 `.py/.ps1/.bat/.cmd` 的清单 + 运行 + 增删改查 + 收藏 | 条目入库存 `config/script/script.json`；右键可外部编辑器打开；「运行」= 像双击脚本文件（走系统文件关联） |
| **命令库** | 系统自带设置 / 工具入口的命令行清单 + 运行 | 有输出的用 pwsh 开可见终端（先回显命令再显示输出）；GUI 启动类静默跑不弹窗；逐条可设宿主(Auto/Cmd/Pwsh)与隐藏窗口；需管理员走 UAC |
| **软件包** | winget 图形界面：搜索 / 安装 / 升级 / 卸载 / 锁定 | 工具条源下拉 + 搜索 / 已安装 / 可升级 / 已锁定 / 重新加载 / 刷新索引 + 安装 / 升级 / 全部升级 / 卸载，结果都显示在下方的同一个列表（⛔ 不让用户敲命令）；被锁定的包带 🔒 标记；可导出已装清单为 json |
| **集合** | 按需组合采集器的容器（主从两栏） | 左 280 集合列表（搜索 + kind/标签筛选 + 置顶/最近/全部分段）｜右 成员表（**勾选即增删，即时生效无保存按钮**）+ 详情卡。工具条：新建 / 复制 / 删除 / 归档 / 扫描目录 / 发送到信息面板 / 导出 |
| **信息面板** | 按集合分节展示采集器输出 | 见 4.2.1 |
| **脚本管理器设置** | 脚本目录（留空 = 用随包默认目录） | 落 `config/script-manager.json`（⚠️ 分区名 ≠ 模块键 `script`），外部程序路径则属应用级（设置 → 运行环境） |

**四层概念的关键约束**

- 集合带 `kind`（`script` / `command` / `info` / `package`），决定它在哪个页出现；⛔ 不为每个集合新增菜单项。
- 内置集合 `脚本库` / `命令库`（可改名、不可删）。
- **可采集 `collectable`**：脚本 = 扩展名合法且文件存在；命令 = 不在副作用黑名单（`start`/`explorer`/`control`/`ms-settings:`/`shutdown`/`pause`）且标记为可捕获。自动判定 + 用户可覆盖。
- 扫描由**用户手动触发**（⛔ 不自动登记）：扫描脚本目录 → 候选面板三态（已入库灰 / 新文件默认勾选 / 不可采集灰显不可勾）→ 加入库 + 可同时选「加入某集合」。
- **首次运行会给一份示例**（脚本目录 `examples\` 下 3 个脚本 + 1 个采集器模板，命令库 8 条 Windows 设置 / 管理工具入口），改或删都随你 —— 删了不会再回来（示例只在第一次启动播种）。
- 删除条目 ⛔ 不删文件；文件不存在 ⇒ 标 `missing`（列表标红 / 灰）。
- 数据两分：**手工数据**（集合 / 条目 / 标签 / 视图 / 工作区）→ `config\script\script.json`（可手改、**进备份**）；**观测快照与运行日志** → `data\script\script.db`（可重建、**不进备份**）。

#### 4.2.1 信息面板（分节展示）

- 顶部工具条：**集合 ▾**（下拉，排序 = 置顶 → 最近使用 → 名称，文案「名称 · 成员数」）+ 视图 ▾ + 全部刷新 + 节设置 + 打开脚本目录。
- ⛔ **不做横向排列的按钮条 / 标签条**：一次显示一个集合，切换即整屏换；记住上次集合，重启恢复。
- 主体 = **一个滚动容器内按采集器分节**：
  - 节头 = 采集器标题 + 状态点（正常/警告/错误**着色**）+ 上次采集时间 + 行数 + 折叠 + 局部刷新 + 节设置；**节头吸顶**（手写浮层实现）。
  - 节体 = 该采集器**自己的列**（由输出属性并集决定），节与节列宽独立；**预览 20 行 + 展开全部**。
  - 节数上限 40。
- **分节模式关闭分页**，底栏改摘要（本次耗时 · 节数 · 总行数）。
- 空态两种：没有集合 / 集合里没采集器。

**与外部脚本的契约**（重写时可原样保留，这是本模块最有价值的资产）

- 采集脚本只输出**结构化数据**，完全不感知显示：
  - JSON 口径（推荐）：`{"rows":[{"key":"行标识","status":"ok","attrs":{"列名":"值",…}}]}`
  - 另支持每行一条 / CSV。列名 = 属性名。
- **随包脚本必须 UTF-8 带 BOM**（否则 Windows PowerShell 5.1 按 ANSI 读，中文会乱码）。
- 脚本用标准输出吐结果，⛔ 不打日志到 stdout。
- 列 schema 在采集器**首次成功采集**时按输出属性顺序生成，**新属性追加到末尾**（⛔ 不动已有列序 / 宽度 / 标题），原子写回 `script.json`；列显隐 / 宽度在「节设置」里改。
- **执行频率三层**：采集器级间隔 / 集合级刷新模式（手动 / 进入页面时 / 定时）/ 视图级可覆盖。硬约束：仅只读项允许定时；最小 2 秒、上限 3600 秒；前一次未完成跳过本次；离开页面停表；只刷新**未折叠**的节。
- **保留策略**（逐条目）：只留最新 / 保留最近 N 次 / 保留 N 天。
- 命令也能当采集器（无脚本文件）：只读 + 不在黑名单 + 强制超时（默认 15s、上限 120s、超时杀进程树）。
- 边界：⛔ 后台刷新 / 托盘常驻采集；⛔ 列宽拖拽。

### 4.4 视频工具（模块键 `video`）

**定位**：比资源管理器显示更多信息的**视频查看器** + **ffmpeg 命令的制定与批量执行**。🔴 只做"查看 + 命令生成 + 批量执行"，**不做资产库 / 标签 / 收藏**（那些归媒体资产）。**无默认视频目录**（每次手选）。

| 页面 | 用途 | 要点 |
|---|---|---|
| **视频列表** | 简易本地视频查看器，用途 = 给批量任务快速挑文件 | ffprobe 媒体信息（本地缓存，只为扫描提速）；导入 = 拆分按钮（文件夹… / 视频文件… 多选）；表头 ☑ 右键做全选/反选/取消；详情卡内**改名（同步磁盘）**、删除到回收站；多选 → 送批量处理·转码 / 送视频预览·剪辑；🔄 重扫目录；🧹 清除列表 |
| **视频预览** | 单任务编辑器（边看边定一个剪辑 / 转码） | 预览画面常显 + 三条时间条（预览位置 / 开始 / 结束）常显；拖动即时抽帧；"结束"默认在片尾；旋转预览（0/90/180/270/翻转）；工具条动作全部在顶部；一次只编一个任务 |
| **批量处理** | 剪辑 + 转码混排的统一任务队列 | 行首勾选列；逐条改参数 / 编辑命令；批量运行 / 逐条跑 / 停止；任务的导出 / 导入（JSON，**启动时不自动载入**，队列在刚打开时是空白的）；🧹 清除缓存（只清页面，⛔ 不动磁盘文件）；「➡ 送预览」反向送回预览页；⛔ 本页无"重载"按钮 |
| **视频工具设置** | 最大并发数 | 落 `config/video-tools.json` |

**两页详情卡 = 同一个东西**（把一条任务翻译成一条 ffmpeg 命令），规格必须完全一致：

1. 分区顺序 = 命令书写顺序：**输入 / 区间 → 编码与画质 → 输出 → 命令**。
2. 前两个分区各带一个**可交互勾选框**（该段是否参与命令）+ 折叠箭头；取消勾选即自动折叠。
3. 命令区固定在最后：完整命令行（可选中复制）+ 可编辑参数框 + 重置为自动；**手改后以手改为准**。
4. 卡片内**零操作按钮**。
5. 两页差异只有两处：预览页的区间由左侧时间条驱动（批量页在卡里填）；批量页勾选框初值来自任务类型（勾/取消 = 切换任务类型，两段都取消则回到"仅转码"并提示，⛔ 不允许空任务）。

**任务入口四处全部打通**：批量页添加文件 → 建任务；视频列表多选 → 送批量/送预览；预览页编好 → 发送到批处理；批量页 → 反向送预览。

**其他已定细节**：转码默认 = H.265 / CPU / mp4 / CRF23 / 文件名加 `_H265`；列表按全路径（大小写不敏感）去重；删除一律送系统回收站 + 二次确认；⛔ 无"自动调整列宽"。

### 4.5 媒体资产（模块键 `assets`）

**定位**：把本地视频 / 音乐 / 文档 / 书籍 / 图片等文件索引进本地数据库，并在库里完成标签、分类、集合、关联、重命名 / 移动 / 复制 / 删除管理的**通用文件资产库**。

| 页面 | 用途 | 要点 |
|---|---|---|
| **全部资产** | 唯一的资产浏览入口 | 混合视图；列 = 文件名 / 类型 / 标签 / 分类 / 集合 / 大小 / 修改时间 / 存储源。**类型切换由筛选栏的类型控件承担**（🔴 原 5 个类型页已撤销合并进本页） |
| **标签管理** | 名称 / 命名空间 / 颜色 / 使用数；支持合并与清理未使用 | |
| **分类管理** | 左树 + 右成员列表（本模块唯一的非列表内容页） | |
| **集合管理** | 手动 + 智能集合；成员可拖拽排序 | |
| **存储源** | local / removable / nas；在线状态 | 移除**只移索引**，⛔ 不删磁盘文件 |
| **任务中心** | 扫描 / 重命名 / 移动 / 复制 / 删除 / 元数据 / 缩略图任务：取消 / 重试 / 日志 | |
| **回收站** | 已软删除资产 | 恢复 / 永久删除（二次确认）/ 清空 |
| **媒体资产设置** | 扫描 / 缩略图 / 命名模板 / 回收站 / 物理操作 / 元数据 / 导入导出 | 落 `config/media-assets.json` |

**核心流程**

- **扫描**（异步任务，直接入库）：忽略规则 → 遍历（默认含子目录，可关）→ 依次按 `存储源+相对路径` / `大小+修改时间` / `快速哈希+大小` 三级匹配（前两级**零 IO**）→ 建 / 更新记录（批量事务）→ 提取元数据 + 生成缩略图 → 本次未出现的旧位置标 `missing`（⛔ 不删资产）。
  - 🔴 新文件 **⛔ 不立即算完整内容哈希**（会把每个文件整读一遍）；完整哈希留给独立的「补全哈希」任务。
- **预览扫描**（用户操作主路径，**一个字节都不写库**）：选文件夹或几个文件 → 只遍历建内存行 → 列表进入**草稿态** → 用户二选一：`💾 加入库`（按目录分组登记存储源，一个事务批量落库，⛔ 只建索引绝不动磁盘）/ `🧹 清除列表`。草稿态之外这两个按钮一律置灰。
- **批量登记 + 扫描全部**：`➕ 登记文件夹` 把目录加进待扫列表（登记时不扫描）；`🔄 扫描全部` 一次扫完所有在线存储源并直接入库。
- **多库融合**：`🗄 并入` 选一个外部库文件**合并进主库**（只读挂载源库，⛔ 不改源文件；一个事务，重复并入基本全跳过）；`💾 另存为` 把当前库另存为新文件（一致快照）。
- **逻辑操作**（只改库 + 写操作日志，可撤销）：显示名 / 标签 / 分类 / 集合 / 关联 / 软删除 / 恢复 / 评分描述。
- **物理操作**（⛔ 先写日志(pending) 再动磁盘，成功改 success、失败改 failed 并留 before_json）：重命名 / 移动 / 复制 / 删除；默认送系统回收站 + 二次确认；防穿越 + 冲突检查；⛔ 失败不自动回滚磁盘。
- **外部变更**：文件不见 → 标 missing；新路径 + 哈希匹配 = 视为移动；移动硬盘离线时**不动**其下记录，重新上线再扫描校准。

**数据模型**（13 张表，与视频工具共库、表级隔离）：`storages` / `assets` / `file_locations`（一资产多位置）/ `tags`+`asset_tags` / `categories`+`asset_categories` / `collections`+`collection_assets` / `relations` / `operation_logs` / `scan_jobs`+`scan_errors`。类型专属列暂塞 `assets.metadata_json`。缩略图 = `data\thumbs\{sha1(路径)}.jpg`。

> ⚠️ **已知取舍（重写时可修正）**：标签 / 分类 / 集合 / 关联是**用户手动数据**，与"数据库 = 可重建缓存、不进备份"冲突 —— 重建库会丢。当前缓解 = 设置页提供「导出用户数据为 JSON」（4 类表）。

**怎么找某一节（v3.67）**

| 想做的事 | 怎么做 |
|---|---|
| 从首页一键操作进对应的设置 | 点一键区右上角 `⚙` ⇒ **直接打开「一键按钮」节**并滚到位（不是打开整页让你自己找） |
| 一屏看全所有节点 | 点顶部吸顶抬头右上角「**全部收起**」⇒ 只剩一排节点标题；点任意标题 ⇒ 展开并自动滚到它；也可直接往下滚 —— 滚到哪节自动展开哪节（v3.68） |
| 只看当前在哪一节 | **当前节点整行高亮**（底色 + 强调色文字），跟随滚动实时变化；顶部吸顶抬头显示的就是它 |
| 回到全部展开 | 同一按钮此时显示「**全部展开**」 |
| 收起单独一节 | 点该节标题（再点一次展开） |

- 折叠是**用户表态**：手动收起过的节，之后滚动经过不会自己弹开；再点一次标题才展开。往下滚时，标题进入页面上半部就会自动展开（一次只开一个），这是"一路滚一路看"的默认手感；「全部收起」属于临时总览，滚过去照样会展开。

- **配置档**（本软件最重要的概念之一）：每个配置**隔离整个数据根**（config + data + logs），可同时开多个实例各跑一个配置；切换 = 二次确认后**本窗重启**到目标配置；「设为默认」才影响以后无参启动；删除前二次确认且⛔ 不许删当前正在用的；**新建配置 = 只建目录** ⇒ 天然"全清、各项留空即系统默认"。
- **功能清单**（独立于设置页的页面）：首页收藏卡尾部「显示更多」**就地展开**它；独立页保留给标题栏 `＋` 与关于节按钮当选择器用。

## 五、操作逻辑（典型使用方法）

| # | 场景 | 操作路径 |
|---|---|---|
| 1 | **切到另一套数据** | 设置 → 运行环境 → 配置档 → 切换（二次确认 → 本窗重启）。想常驻：设为默认。想同时开两套：该行「🚀 新开」 |

| 5 | **导入浏览器书签** | 网络工具 → 书签管理 → 导入书签 HTML → 右键可测连通性 / 批量打开 |
| 6 | **测一批主机并逐个换 DNS** | 网络工具 → 网络 Ping → 导入目标（文件 / 批量）→ 逐 URL 或整体切 DNS → 看状态 / 往返 |
| 7 | **把本地资料建成资产库** | 媒体资产 → 全部资产 → 📁 扫描（预览扫描，不写库）→ 勾选 → 💾 加入库。想长期维护：➕ 登记文件夹 → 🔄 扫描全部。整理：打标签 / 划分类 / 加集合 / 改显示名（都只改库，可撤销）。要挪文件：物理操作（先写日志再动磁盘，默认送回收站）。误删：回收站恢复 |
| 8 | **换机器 / 备份** | 设置 → 数据管理 → 备份（只打包 `config\`，含各模块手工数据；⛔ 不含 `data\` 缓存与数据库 → 那些可重建）→ 新机器导入 config |

**通用习惯（用户养成的肌肉记忆，重写时别破坏）**

- 想"重来一遍"找工具条上的 `🔄 <动词><来源>`；想"彻底重置页面"才用标题栏 `⟳`。
- 动一条 → 右键菜单；动整页 → 工具条。
- 表头左键排序、右键管列与筛选；表头 `☑` 右键管勾选。
- 会丢数据的动作（删除 / 清除 / 永久删除 / 切换配置）都要**二次确认**，确认文案写明清什么、不清什么。

## 六、数据在哪 / 备份什么

```
<应用根> = %LocalAppData%\NewToys          （环境变量 NEWTOYS_HOME 可整根切换）
├─ active-profile.txt   当前配置名
├─ app.json             机器级：外部程序路径 + 加密 DNS + 更新地址（⛔ 不随配置切换）
├─ profiles\<配置名>\
│  ├─ config\           ← 进备份（主题 / 窗口 / 列布局 / 一键按钮 / 各模块设置 / 用户功能数据）
│  ├─ data\             ← 不进备份（数据库 / 缩略图 / 缓存，可重建）
│  └─ logs\
└─ 程序目录
   ├─ Modules\          模块包（热加载源，仅限本地）
   └─ defaults\         随包默认资源（只给默认路径 / 文件名，⛔ 不给内容清单）
```

- **备份只打包 `config\`**（设置 → 数据 → 备份）；`data\` 是缓存与数据库，重建即可。
- 例外：媒体资产的**标签 / 分类 / 集合 / 关联**暂存库内（技术债 B14），设置页另有「导出用户数据为 JSON」。
- **一个配置 = 一套独立数据根**（config + data + logs）：切配置 = 换一整套数据，互不干扰。
- 🔴 用户可见的模块设置文件 = `script-manager.json` / `web-tools.json` / `video-tools.json` / `media-assets.json`（⚠️ `script` 模块的分区名 ≠ 模块键）。
- 文件层细节（表结构 / 写入点 / 分区名）见 `framework.md` §7，⛔ 不在用户手册展开。

> 原 §七「外部依赖与可移植性」/ §八「重写指引」已迁出用户手册 —— 平台后端能力矩阵见 `framework.md` §2 技术债 B5 + 《需求规格》§3.7，重写契约见 `framework.md` §2 §3 §6。本文件只保留「怎么用」。

### 7.3 术语表

| 术语 | 含义 |
|---|---|
| 配置档 | 一整套隔离的数据根（config + data + logs），可多开 |
| 模块 | 独立编译 + 运行时装配的功能域（脚本管理器 / 网络工具 / 视频工具 / 媒体资产） |
| 热加载 | 把模块文件放进 `Modules\` 后运行中点一下即装配（只新增，移除需重启） |
| 工具条 | 页面顶部三行中的第一行，**只放页面级功能** |
| 筛选条 | 三行中的第二行，恒一行 |
| 详情卡 | 右侧 340px，显示选中项信息与针对该对象的命令 |
| 列表页基类 | 提供排序 / 筛选 / 列显隐 / 列宽 / 勾选 / 分页 / 空态的页面基类 |
| 采集器 | 一条能产出结构化行的脚本或命令 |
| 集合 | 若干采集器的组合 = 一屏数据（脚本管理器与媒体资产同义） |
| 视图 | 列集合 / 筛选 / 排序 / 布局 / 刷新策略的组合 |
| 存储源 | 媒体资产里的一个被索引的根目录（本地 / 移动盘 / NAS） |
| 物理操作 | 会动磁盘的动作（重命名 / 移动 / 复制 / 删除），先写日志再执行 |
| 逻辑操作 | 只改库的动作（改名 / 标签 / 分类 / 集合 / 软删除），写日志可撤销 |
