## 一、背景 / 目标

用户 2026-11-03 拍板：**多选 + 规则对话框**做批量改名（不接受「逐个弹输入框」）。
现状：`✏ 重命名…` 一次只改一个（`FileOperationService.Rename`，冲突策略 `AppendNumber`，只走 `FileOperationService` 落盘 + 更新索引）。

## 二、范围

| 项 | 内容 |
|---|---|
| 入口 | 「全部资产」工具条 / 行右键 + 「资产浏览」文件右键各加一条 `✏ 批量重命名…`（≥2 个选中时启用；单选用原单条 `✏ 重命名…`） |
| 对话框 | 规则式，可组合：① 查找替换（支持正则开关，默认关）② 前缀 / 后缀 ③ 起始编号（位数、步长、连接符）④ 大小写（不变 / 全小写 / 全大写 / 首字母大写）⑤ **只改选中的扩展名** 开关（默认保留原扩展名） |
| 预览 | 对话框下半 = 两列预览表（原名 → 新名），冲突行标红并给出处理方式（跳过 / 自动加序号），确认按钮在「无红行」时才可点 |
| 落盘 | 逐个 `FileOperationService.Rename`：成功即更新 `file_locations.path` + 所在资产 `name`；某个失败不影响其它，末尾汇总「成功 N / 跳过 M / 失败 K」 |
| 撤销 | ⛔ 本期不做（改名不可批量回滚；对话框里给了预览，误改自行用同样的规则反向操作） |

实现落点（全在 `Module.MediaAssets`，🔴 未动框架层）：

- `Models/RenameRules.cs` —— 规则集 + 纯文本变换（`Apply(fileName, index)` → 新名 / 错误），顺序固定：查找替换 → 大小写 → 前缀 / 编号 / 后缀组装。
- `ViewModels/BatchRenameViewModel.cs` —— 弹层 VM：规则字段 → 预览行（含目录内查重 + 自动加序号避让）→ 确认后入任务队列逐个 `Rename`，写一条 `rename_batch` 摘要日志。
- `Views/BatchRenameOverlay.axaml(.cs)` —— 遮罩 + 居中卡片（与确认卡片同观感），两页共用、`DataContext = BatchRename`。
- `ViewModels/AssetAllViewModel.BatchRename.cs` / `AssetBrowseViewModel.BatchRename.cs` —— 两页各自的候选收集 + 入口命令 + 刷新回调。

## 三、验收标准

- [x] 选中 5 个文件 → 「✏ 批量重命名…」弹出对话框，预览 5 行原名 / 新名
- [x] 规则「前缀 + 起始编号」= `旅途_01`、`旅途_02`… 位数与步长生效（落点选「替换原名」）
- [x] 改出的新名与目录里已有文件重名 → 该行标红，「确认」不可点；勾「自动加序号」后变可点
- [x] 不在对话库里 / 未入库的项不参与（提示「已跳过 N 个未入库项」）
- [x] 「资产浏览」里批量改名后，卡片名与磁盘文件名同时变；「全部资产」列表同步
- [x] 磁盘上原有文件一个不少（失败项保持原名并在状态栏列出）

## 四、拍板结论（2026-11-03）

1. **扩展名默认不参与替换 = 是**（「保留扩展名」默认勾选；取消勾选后查找替换 / 大小写连扩展名一起改）。
2. **冲突默认策略 = 自动加序号**（与单条改名一致；另给「跳过冲突项」，选了就变红行并禁用「应用」）。
3. **写操作日志 = 是**：每条 `Rename` 自带一条 `operation_logs`，批量结束再加一条 `rename_batch` 摘要（`renamed` / `failed` / `unchanged`）。
