## 背景 / 目标

回归官方 CSD（NT-040）时，Fluent 默认装饰主题带的全屏按钮被一并顶掉了。用户看了一轮后认为**这个按钮有必要保留**（点一下铺满屏、隐藏任务栏）。

**目标**：在自绘标题栏的窗口按钮组里补一个全屏按钮（`⛶`），并配齐退出手段，图标 / 尺寸 / 配色与现有 `— □ ✕` 完全统一。

**真实场景**：媒体资产模块的图片 / 视频预览、密集列表页 —— 铺满屏 + 隐藏任务栏确实有用。

## 功能清单（已核实 12.1.3 的 API 现状）

| # | 能力 | 12.1.3 现状 | 做法 |
|---|---|---|---|
| 1 | `WindowState.FullScreen` | ✅ 存在 | 直接切 |
| 2 | `ElementRole="FullScreenButton"` | ✅ 存在 | 标在按钮上 → **切换行为由框架执行**，我们只画图标 |
| 3 | 图标切换（全屏 / 退出全屏） | — | 自绘，扩展现有 `UpdateMaxIcon()` |
| 4 | `ToggleFullScreen` / `ExitFullScreen` 方法 | 🔴 **不存在** | 自己写开关 |
| 5 | `F11` / `Esc` 内建按键处理 | 🔴 **不存在** | 自己加 `KeyDown` |
| 6 | 顶部下拉浮层（`FullscreenPopover`） | 🔴 **不可用**（只在装饰模板里，本版本无模板类型） | ⛔ 放弃，**用快捷键兜底** |
| 7 | `CanFullScreen` 能力开关 | 🔴 **不存在** | ⛔ 不做动态显隐，按钮常驻 |

## 技术要点 / 约束
- 🔴 图标**只能用 Rectangle / Border / TextBlock** —— 已有实证：`Path`（尤其带 `Stretch=Uniform`）在 `BareButtonTheme` 的 `ContentPresenter` 里**渲染不出来**（不报错、图标直接消失）。⛔ 别用 Path。
- 按钮套 `Theme="{StaticResource BareButtonTheme}"`，与 `— □ ✕` 一致；前景色走 `Button.win-btn` 的继承，⛔ 不写本地值。
- 状态判定统一走 `OnPropertyChanged(WindowStateProperty)`（已有钩子），把 `FullScreen` 与 `Maximized` 一起判断。
- `UpdateMaxIcon()` / `UpdateResizeGrips()` / `UpdateWindowFrame()` 三处都要覆盖 `FullScreen`。
- 键盘处理挂在 Window 的 `KeyDown`（隧道阶段优先，避免被页面内的输入框吃掉 —— 参照标签栏滚轮用隧道注册的先例）。
- 🔴 框架层 Shell 改动 —— 已获用户 2026-10-14 授权（「走官方路线」）。
