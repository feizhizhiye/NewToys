## 背景 / 目标
**现状**：20 个页面各写一份 `Border.toolbar` XAML（合计 ≈600~700 行）；自动折叠逻辑只在「全部资产」页有一份（`AssetAllView.axaml.cs` ≈110 行，含两条防抖：项宽首次布局后缓存一次 + 容量幂等短路）；16 个页面各手写 12 行 `detail-toggle` 块。
**目标**：**实现只存在一份** —— Shell 承载工具条（含折叠 + 浮动详情开关），页面 VM 只输出数据。净减 ≈300~400 行；后续改一次全局生效。

## 用户拍板记录（2026-10-15 会话）
1. 方案选 **X1（Shell 承载）**；⛔ 不选"每模块一份副本"（加代码）、⛔ 不选"`Shared` 引 Avalonia"（破铁律、增架构复杂度）。
2. 详情开关：**不占独立列**、浮在容器上层、位置 = 容器右上角；**容量计算里避让**（⛔ 不遮按钮）；宽度进一步压缩（20 → 可到 18），样式与容器内按钮同源。
3. 迁移范围本批 = **14 个 View 文件**；媒体资产那 6 个"不符合规范"页本批**不动**（逐页 opt-in，不冲突）。
4. 与 NT-056 **同批执行**。

## 技术要点 / 约束（规范章节、坑点、关键文件）
- 🔴 **框架层改动**（`Shared` 新契约 + `Shell` 新控件与布局）⇒ **本批交付首审项**，需用户审核。
- 🔴 铁律：`Shared/Core` ⛔ 不引 Avalonia ⇒ 描述符必须是纯 POCO（先例：`DetailAction.Command` 用 BCL `ICommand`）。
- 🔴 折叠算法搬迁时，两条防抖**缺一即抖**（切标签页 / 拉窗口会出现工具条跳动）。
- ⛔ 不给 `ToolbarHost` 设 `DataContext`（与 `DetailCardHost` 同口径：绑 `Source` = 页面 VM）。
- **逃生舱**：描述符 4 类表达不了的控件（如 VideoList 工具条里的复杂项）→ 本页**暂不迁移**，保留页内自绘；⛔ 不为统一而强行改造页面。
- ⚠️ Shell 现有绑定源（`StatusBarText` / `DetailCard` / `DetailCardSource`）均在 `ShellViewModel`，新工具条走**同一处**探测与订阅，先解绑旧页再订阅新页（防泄漏）。
