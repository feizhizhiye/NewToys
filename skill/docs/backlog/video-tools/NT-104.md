## 背景 / 目标
「压到 50 MB 以内」是上传限制下的真实需求，但现在的「目标码率」要用户自己算
（`MB × 8192 ÷ 秒数 − 音频码率`）。本卡把这个除法交给程序，用户只填 MB。

## 验收标准
- [x] `TranscodeTask` 新增 `TargetSizeMb`（0 = 不用），随任务 JSON 持久化
- [x] 两页详情卡出现「目标体积（MB）」，填了显示提示行：「按 50 MB ÷ 时长 ≈ 视频 xxx kbps」（已扣音频与容器开销）
- [x] 优先级：目标体积 > 目标码率 > CRF（命令里出现 `-b:v Nk -maxrate 1.5Nk -bufsize 2Nk`）
- [x] `-c copy` 预设遇到目标体积自动升级 `libx264`
- [x] 预检：填了体积但读不到源时长 → 红字说明算不出来
- [x] 换源文件时目标体积清零（依赖具体文件时长）

## 技术要点
- `FfmpegService.AutoBitrateKbps`：`MB × 8192 ÷ 秒 − 音频 kbps − 8`，最低 50 kbps
- 单遍 ABR（不做两遍）：两遍要在界面上显示两条命令，「看到的 ≠ 跑的」违反 NT-098 定的原则
