## 一、定位

**带 GUI 的脚本管理器**，作者个人自用工具集。非商业、非通用产品，「自用顺手」第一。每个页面 ≈ 一条或几条命令行 + 一份 `config/` 配置的封装。

- **干净启动**：软件 = 空壳 + 按需加载。启动后只有必要配置（主题 / 列宽 / 模块注册）与首页、设置页有内容，**其余列表一律初始为空**，内容由用户导入 / 收集。
- **用户画像**：有电脑知识的人 ⇒ ⛔ 保姆式引导、⛔ 内置示例内容；配置**可读 / 可手改 / 可备份**是加分项。

## 二、边界

判据：**「如果我只写个脚本会怎么写？现在少让用户做哪一步？」**

| 做 | 不做 |
|---|---|
| 把日常高频终端 / 系统能力包成可点、可配、可备份的界面 | 社交、推荐、引导、埋点、账号、云同步、在线插件市场 |
| **本地**模块热加载（丢 DLL → 点刷新 → 即时装配） | 联网下载模块 / 建生态 |

### 2.1 远期规划（**勿立项、勿重复评估** —— 省 token）

1. 上架应用商店（近期无计划）
2. 跨平台 Debian 13（主平台仍是 Windows 10 LTSC）
3. 脚本管理器整体备份 + 多平台预留（包管理器 / shell / 系统设置入口集中封装）
4. 脚本中枢「编排」态 + 工作流引擎（独立新模块，**当前不立项、不评估**）

### 2.2 编排能力上限（2026-10-19 定调）

- 分级：L1 单命令 → L2 集合 / 分类 / 收藏 → **L3 命令链**（有序 + 变量传递 + 失败策略）→ L4 条件分支 → L5 图编排 → L6 触发调度。
- 🔴 **封顶 L3**；L4 只在真撞上时做且优先写脚本；**⛔ L5 / L6 永不做**。
- 命名口径：叫「**命令链 / 抓取管道 / 多步抓取**」，⛔ 不叫「工作流 / 节点 / 执行实例」。
- L3 唯一落点 = **复用「集合」加执行语义**（已有 `order` 字段），⛔ 不新造工作流模型。
- 触发门槛（未满足前 ⛔ 不设计、⛔ 不预留）：① 同样几条命令第 3 次手动点；② 某命令输出被手工复制给另一条；③ 集合出现 `01_` `02_` 顺序命名。
- 现在唯一要守的伏笔：命令必须有 `capture` + 明确输出格式（`line / csv / regex / json`）。

## 三、技术框架（硬约束）

### 3.1 分层（单向，禁反向）

```
Shared（契约 / 模型，不引 Avalonia）
  ▲ Core（服务实现，不引 Avalonia）
  ▲ Shell（宿主 → NewToys.exe）
  ▲ Module.*（只引 Shared + Core）
```

- ⛔ 模块引 Shell、⛔ 模块互引；跨模块协作走 `Shared` 契约。
- 公共基类 / 契约放 `Shared`；被 ≥2 模块用或属应用级能力才上提，判断不清默认留模块内。

### 3.2 技术栈（锁定，禁擅升擅降）

.NET 10 · Avalonia 12.1.4 · CommunityToolkit.Mvvm 8.4.2 · Microsoft.Extensions.DependencyInjection 9.0.0 · Microsoft.Data.Sqlite 9.0.0。
⛔ 第三方 UI 组件库 / 图标字体 / 图标包；图标 = Avalonia `Geometry` 路径数据（可手摘 Lucide / Feather 路径）。
版本只在 `src/Directory.Packages.props`；csproj ⛔ 写 `<PackageVersion>`。

### 3.3 框架层冻结

`Shared / Core / Shell` 默认不再改，**新功能只在 `Module.*`**；确需改框架层**必须先获用户明确同意**，交付里独立说明。

### 3.4 模块化 / 热加载

- 模块 = 独立 DLL，实现 `IModule { RegisterServices, Initialize }`；**菜单只能在 `Initialize` 注册**。
- 启动双轨：Debug 走 `#if DEBUG` 显式清单；Release 扫 `<程序目录>\Modules\`。
- 热加载：丢 DLL → 点刷新 → 独立 `AssemblyLoadContext(isCollectible)` 装配；逐个 try-catch 隔离；**只做新增，同名不替换不卸载**；源仅本地目录（`Path.GetFullPath` 校验）。
- **模块自包含**：View / VM / 服务 / 设置页全在自己 DLL 里；⛔ 搬进 Shell 或其他模块代持。
- **模块设置页挂本模块分组**（`settings-<模块键>`，长名标题 ⛔ 简化）；**应用级设置归 Shell**（原 `Module.Settings` 已撤销）。判据：描述**软件自身运行环境 / 应用行为** ⇒ 应用级；描述**某功能扩展怎么工作** ⇒ 模块级。
- **框架自给**：一个功能模块都不加载时，首页 / 一键启动 / 收藏 / 主题 / 多配置 / 设置全套必须可用。

### 3.5 配置与数据

- 多配置：`<应用根>\profiles\<配置>\{config,data,logs}`；当前配置在 `<应用根>\active-profile.txt`（必须在 `profiles\` 之外）。
- **三层 + 一个总库**：L0 机器级 `<应用根>\env.json`（外部程序路径 / DNS / 更新地址，⛔ 不随配置切换）· L2 框架偏好 `config\shell.json` · L3 模块设置 `config\modules\<模块>.json` · 应用行为 `<应用根>\app.json`。
- **内容型数据**（书签 / ping 目标 / 抓取任务 / hosts 方案 / 视频任务队列 / 脚本集合与条目 / 资产索引）→ `<配置根>\data\newtoys.db`（**一个配置档一个库**，表名 `<模块前缀>_*`，DDL 唯一入口 `LibrarySchemaService`）。**配置类**才进 `config\*.json`（能被备份）。
- 切换配置 = 重启（显式传 `--profile`，⛔ 不写 `active-profile.txt`）；每配置单例。
- 模块设置**只读**，唯一写入点 = 该模块设置页；功能页 ⛔ 直接写文件。路径无效 ⇒ 状态栏红字 + ⛔ 不写盘。
- 改系统级配置的页面必须二次确认。

### 3.6 默认数据

⛔ 内容清单不写死 C#；默认内容放 `<程序目录>\defaults\*`。
v3.60 收窄：**不提供默认内容清单**，只提供默认路径；内容全由用户导入。
`ExampleSeeder` 一次性示例（标记 `.seeded`，删了不复活）合法。

### 3.7 跨平台预留

主平台 Windows 10 LTSC，迁移方向 Debian 13。平台能力（winget / `ms-settings:` / ffmpeg）集中封装；路径一律 `Path.Combine`。
🔴 跨平台判定用**运行时信号**，⛔ OS 嗅探；窗口装饰唯一判据 = `WindowDecorationMargin.Top > 0`。

## 五、设计原则（六条）

1. 模块化 2. 插件化（独立 DLL，运行期装配）3. 轻量务实（不炫技）4. 自控（⛔ 第三方 UI 库）5. 命令行封装（不超命令行上限，配置落文件可备份）6. 可热加载（源仅本地）

## 六、验收底线（答不上就不做）

1. 对应哪条命令行 / 哪个系统能力？
2. 配置落在哪个 `config/*.json`（或哪张库表）？
3. 失败时用户在哪行看到原因？
4. 涉及模块：拷进 `Modules\` 后点刷新能否用上？失败会不会拖垮宿主？
