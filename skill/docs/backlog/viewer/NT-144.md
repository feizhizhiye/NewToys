# NT-144 · 查看器渲染器全下沉 + 阅读／查看器职责重划

> 模块：viewer（渲染器全迁入 `Module.Viewer/Controls/`）｜ 优先级：P1（用户主动提，期望值提升）｜ 状态：🚧 批 1 / 批 2 已实施（2026-11-04，批 1 用户本地 build 通过；批 2 待 build）；批 3 待实施
> 依赖：NT-134（查看器 V2）/ NT-142 / NT-143（音乐播放器三批，均已验收）
> 创建：2026-11-04（用户拍板：`1 做 / 2 落盘 / 3 跟到查看器`）

## 一、需求（用户 2026-11-04 原话）

1. **把 `UI` 里的 viewer 全部迁移到模块里**（渲染器不再放 `NewToys.UI`）。
2. **阅读模块里不实现阅读的功能**：通过「导入索引」的方式在查看器里读正文；阅读模块本身只保留书架 / 目录 / 抓取，**最多留一个简易预览**。
3. **听书 TTS 跟到查看器**（边看边听才成立，不自立一套后台朗读）。
4. 依据：用户「我对本项目的期望提升了，希望可以更好适应我个人使用习惯」。

## 二、摸底结论

- **外部代码零依赖**：`Module.MediaAssets` 只在注释里提过 `ViewerHost`，实际通信用 `IModuleBus` 主题 ⇒ 「渲染器必须上 UI 库」的原始理由**已不成立**（`viewer.md` §5 旧结论已标作废）。
- **唯一卡点 = `TextViewer`**：`Module.Reading/Views/ReaderView.axaml` 直接 `<ui:TextViewer>` 做正文预览。它留在 UI 库直到批 3 把阅读正文交出去。
- **`ReaderShell` 目前只吃「单份文本 + 正则切章」**（`Load(text, chapters, position, out error)`），不认识「多章外置文件」。
- **阅读侧已有正文缓存表** `content_cache`（按 `chapter_url` 存清洗后正文）与全书下载器 `BookDownloadService`（逐章抓取 → 拼整本）⇒ 落盘索引可直接复用这条链，不必新写抓取。
- **TTS 现状**：`Module.Reading/Services/TtsService.cs` + `SpeechSettings`（语速 / 音量 / 系统音色），与播放器 `IAudioTone`（均衡预设）**完全无关**，无共用 UI。

### 批 2 · 正文落盘 + 索引交接（✔ 已实施 2026-11-04，待用户本地 build）

> 实施记录：落盘根 = `store/reading/books/<bookId>/`（卡原写 `data/`，存储 V2 已把 data 分裂为 store/cache，索引书属持久数据归 `store/`）；进度续读复用 `ViewerSettingsService.SetReaderPosition`（按 index.json 路径记），未另写 progress.json。`ReaderShell` 加 `LoadIndex` 索引书模式（章按需读文件、全书搜索逐章读）；`BookIndexWriter` 导 `index.json` + 已缓存章；打开 / 翻章 / 整本下载后自动补导；`ReaderView` 移除 `TextViewer`（预览 500 字 + 「📖 在查看器中打开」），排版 / 样式卡 UI 随正文一并让位给查看器（设置页样式方案保留）。

**数据形态**（`profiles/<配置>/data/reading/books/<bookId>/`）：

```
index.json          { bookId, title, author, sourceUrl, chapters: [{ index, title, url, file }] }
chapters/0001.txt   清洗后的正文（UTF-8，一段一行）
```

- `index.json` 由阅读模块在「打开这本书 / 下载全书」时生成（复用 `ContentCacheStore`，抓过的章直接落盘不重复请求）。
- 查看器只读这两个东西 ⇒ 天然支持离线、重启续读、跨页复用。

**交接通道**：`IModuleBus` 新增跨模块主题（🔴 框架层，`ModuleTopics` 加一个常量）

```csharp
public const string ReaderOpenBook = "viewer.reader.openbook";   // 载荷 = 索引文件绝对路径
```

Viewer 侧订阅后：`ReaderShell` 新增 `LoadIndex(indexPath)`，把 `chapters/*.txt` 按章装载。

**ReaderShell 改造**（`Controls/ReaderShell.axaml.cs`）：
- 新增「索引书」模式：章内容按需从 `chapters/<n>.txt` 读（⛔ 全量进内存，几千章会吃掉几百 MB）。
- 目录 / 书签 / 全书搜索 / 排版 四件复用现有实现（它们只认「章文本列表」，接上即可）。
- 阅读进度写回 `index.json` 同目录的 `progress.json`（或复用 `ProgressStore`，二选一实施时定）。

**阅读模块收尾**：`ReaderView` 移除 `<ui:TextViewer>`，改成「书架 + 目录 + 打开（跳到查看器）」，可选留 500 字预览。

## 四、验收标准

| 批 | 判据 |
|---|---|
| 1 | 编译通过；文本 / 图片 / 音频三类打开行为与迁移前一致 |
| 2 | 阅读页「打开」→ 查看器出现目录 + 正文；翻章不联网；重启后能续读；离线可用 |
| 3 | 边看边听可用（朗读高亮跟读），阅读模块无正文控件 |

## 五、风险

- `ReaderShell` 现为单文本 + 正则切章，加「索引书」模式要动它的装载入口 ⇒ 需回归单 txt 阅读与压缩包内 txt（批 2 一次 build 验两条路径）。
- 落盘正文量：几千章 × 单章 5~10 KB ≈ 20~60 MB，可接受；⛔ 不做压缩（读时解压拖慢翻章）。
