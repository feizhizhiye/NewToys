## 背景 / 目标

NT-034 用 `SetWindowRgn`（矩形窗口区域）强制方角，**代价是 DWM 窗口阴影一起消失** —— 这直接加剧了「窗口叠在同色窗口上分不清边界」的问题。本项复核：官方路线落地后，是否还需要这道硬手段。

**三个层次，按序收敛**：
1. **阴影优先**：方角是观感、阴影是可用性。若二者只能取一 → **取阴影**。
2. **官方优先**：`Win32Properties.SetWindowCornerPreference(DoNotRound)` 是 Avalonia 认可的下发通道，比单方面 P/Invoke 更不容易被重算抹掉。
3. **硬手段兜底**：`SetWindowRgn` 只在上面都不行时才保留，并登记技术债。

## 技术要点 / 约束
- ⚠️ Win11 **最大化窗口本就无圆角** → ⛔ 别把「最大化没圆角」当成验证通过的证据，**必须看普通窗 + 分屏**。
- ⚠️ 两条已证伪的诊断别再用：① `Window.Title`（无边框自绘窗口不显示）；② `DwmGetWindowAttribute(33)`（**不支持读**，永远 -1）。
- MS 官方：窗口有 region 时系统不对其应用圆角 → 这是硬手段生效的原理，也是阴影消失的原因（同一机制）。
- 备选（未采用，记录备查）：`DwmSetWindowAttribute(DWMWA_BORDER_COLOR=34, COLORREF)`（Win11 22000+）可改边框色，MS 文档要求「应用自己按激活状态改色」；但它依赖 DWM 仍在画边框，客户区扩展 + region 后不保证 → ⛔ 不作主方案。
