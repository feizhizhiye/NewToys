# NT-038 · 三配置档（debug / default / release）：运行时永久驻留
- 状态：✔ 已完成（已验收 · 2026-10-14）
- 优先级：P1
- 关联：`ProfileService` / `ConfigStoreService`（NT-024）；需求 §3.5（配置与数据）/ §2.1（远期规划）

## 目标
内置三档 `debug` / `default` / `release`，**永久驻留开发机**，随时切换、**不丢数据**（debug 有测试需求，不能 debug 一次就丢配置）。

## 决策（2026-10-14 用户确认）
- **Q2 · debug 播种 = 采用建议**：三档永久存在；**debug 首启播种 = 复制当前 `default` 内容**为初始态（测试资源用户稍后提供，接入后再调整播种源）。
- **Q3 · 商店版 = 转远期，暂不实现**：近期无上架计划 → 商店版配置（条件播种 / 打包排除 dev 文件 / 仅 `default`）归入需求 **§2.1 远期规划**，本轮不做、⛔ 不建 todo。

## 本轮实现范围（仅运行时）
- 三档在**开发构建（Debug）首启自动播种**：`default`（既有；缺失则按现状播种）；`debug`（= 复制 `default` 内容）；`release`（= 干净初始态，同全新 default）。
- **持久化**：`profiles\<名>\{config,data,logs}` 永久存在，⛔ 无任何自动清理。
- 动作：**「重置为初始态」**（按播种源填回）替代「删除」。
- ⛔ 不做：商店打包 / dev 文件排除 / 条件构建（→ 远期 §2.1）。

## 验收标准
- [ ] 开发构建首启后，`profiles\` 下存在 `debug` / `default` / `release` 三档，且 `debug` 内容 = 当前 `default`。
- [ ] 三档可切换（既有「设置 → 配置」/ `--profile` 机制）；切走再切回，档内数据仍在（重启不丢）。
- [ ] 提供「重置为初始态」，重置后档内容回到播种初始态（debug = default 复制态）。
- [ ] ⛔ 三档不被任何自动清理删除。

## 技术要点 / 约束
- ⚠️ **涉框架层 `Core`**（`ConfigStoreService` / `ProfileService` 加"播种 / 重置"）—— 按铁律 3.3，执行前需用户明确同意；本设计已获用户认可。
- **播种只增不覆盖**：已存在的档不动（用户数据优先），仅缺失时创建。
- ⛔ 不动模块层；⛔ 不联网。
