## 四、技术要点 / 约束

1. 🔴 **只改 `Module.Reading`**，⛔ 不碰 Shared / Core / Shell / NewToys.UI（TTS 因需音频播放契约，本批不做）。
2. 🔴 **正文缓存落点**：`ReadingDatabase` 建 `content_cache` 表（`chapter_url` PK + `content` + `updated_at`）；`ContentAsync` 在 `ReplaceRule` 应用前、`StripMarkup` 之后缓存**最终正文**（⛔ 缓存原始 HTML，否则换排版不受影响但会多存一坨）；key 用 `chapter_url`（同一本书不同章地址唯一）。缓存读写都要过 `_settings.CacheEnabled`。
3. 🔴 **换源要复用 `SearchManyAsync`**（并发门已内建），⛔ 另写一套并发。比对结果模型放 `Models/CrawlModels.cs` 或新 `SourceCandidate`；排序键 = 三段成功数降序 → 响应耗时升序（命中即可用，⛔ 不必全三段都跑，先搜到书名即可入榜）。
4. 🔴 **换源浮层**：复用「书籍卡 / 目录」的覆盖层观感（遮罩 + 居中卡片），⛔ 再新造一套弹层组件。选源后 `OpenAsync` 原地重开（带当前章节定位）。
5. 🔴 **发现页 `@js:` 分类**：`ParseExploreCategories` 现在是 `static`，执行 JS 需要 `RuleEvaluator` 实例 ⇒ 改为实例方法或注入。JS 返回的「分类::地址」串按现有 `&&`/换行切分逻辑复用；`@js:` 段求值失败则跳过该项并记 `RuleContext.Errors`（⛔ 不阻断其它分类）。
6. 🔴 **`t2s` 映射表**：常用繁体→简体对照放一个 `static readonly` 字典（或 `switch` 生成的表），⛔ 不引第三方繁简库（保持零新依赖）；逐字符替换，未命中保留原字符。`s2t` 维持原样返回（待办只点了 `t2s`）。
