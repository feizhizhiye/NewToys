## 背景 / 目标
主平台 Windows 10 LTSC，迁移方向 Debian 13（需求 §3.7）。**本期不做跨平台**，但架构必须能换平台而不重写页面。
本卡记录实施顺序，**不阻断任何当前工作**；唯一日常生效的是「§2.1 六条硬约束」——每张卡自检。

## 已定调的架构结论（2026-10-19 讨论）
1. **只有 winget 需要复杂解析**：其他包管理器可让命令自己吐机读数据（`dpkg-query -W -f=…` / `flatpak list --columns=…` / `snap list`）⇒ 保留 winget 的 C# 启发式解析器，补**一份通用 TSV/JSON 解析**即可。
2. ⛔ **不设「脚本解析层」**：脚本解析换不来可移植性，反而引入编码 / locale / 协议漂移。
3. ⛔ **写操作不脚本化**：取消（进程树）、提权（UAC vs sudo）、交互确认、失败原因、并发串行会全部退化；只允许**命令模板外置**（占位符 + C# 替换）。
4. 三层分工：页面/VM 一份 · 后端适配器每后端一份（薄）· 平台底座每 OS 一份。

## 实施顺序（真要迁移时按此走，⛔ 不跳步）
1. **发布链冒烟**：`Directory.Build.props:17` 的 `win-x64` 改条件化 RID → Linux 能 build & 启动主界面。
2. **守卫收口**：`shell32`（回收站）/ `user32`（MessageBoxW、贴靠）/ `gdi32`+`dwmapi`（CSD）/ `Registry`（开机启动）/ 托盘 —— 全部收到平台适配处并带内联 `OperatingSystem.IsWindows()` 守卫。
3. **平台底座**：抽 `IProcessRunner`（启动 / 读取流 / **取消进程树** / 编码统一 / 提权方式）到 `Core`。
4. **解析分层**：把 `PackageOutputParser` 的通用部分（表格 → 字典）与 winget 固有启发式分开；新增通用 TSV/JSON → 行模型。
5. **后端适配器**：先 apt（或 snap / flatpak 之一）验证「页面零改动、只加适配器」是否成立。
6. **页面形态拍板**：同页切换（`ScriptCollectionKind.Package` + 库下拉）vs 另开独立页 —— 见需求 §6.2.3 待评估点，届时再定。

## 验收标准（Acceptance Criteria）
- [ ] Linux 下能构建并启动主界面，Windows-only 能力按平台降级且不崩。
- [ ] 新增后端 = 新增适配器 + 命令模板，**页面 / VM 零改动**；无新增解析器。
- [ ] 写操作仍为 C# 执行，支持取消（进程树）与失败原因。
- [ ] `pwsh skill/scripts/accept.ps1` PASS。

## 技术要点 / 约束
- 🔴 平台判定一律运行时信号（`OperatingSystem.Is*()`），⛔ `#if` / OS 嗅探（需求 §3.7）。
- 🔴 外部命令输出编码必须显式（`LC_ALL=C` / `chcp 65001`），⛔ 依赖系统 locale。
- ⛔ 把 Windows-only API 写进 `Shared`（Shared 零平台依赖）。
- ⛔ 本期不为「将来跨平台」提前写空实现 / 预留接口类（YAGNI）；只要求**现有实现不堵路**。
