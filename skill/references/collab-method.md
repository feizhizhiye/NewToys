# 通用协作方法论（跨项目母本）

> 本文件与具体项目无关。复制到任何新项目时，只需改同目录的 `<project>-spec.md`，本文件原样保留。
> v1.0 · 2026-10-12

---

## 一、铁律（通用，跨项目适用）

1. **变更顺序**：新需求 → 先写需求/规格文档 → 再改代码 → 最后更新台账。⛔ 先改代码后补文档。
2. **框架层冻结**：架构/框架层改动先问用户；新功能只在模块/业务层。
3. **版本记录走 git commit**（`&lt;type&gt;: &lt;简述&gt;`），⛔ 不写 md 日志；指导性文档仅过时/冲突才改；**代码 &gt; 文档**。
4. **评估/讨论类内容不进文档**，只在会话里谈。
5. **停手仅 5 种**：改框架层 / 删用户已确认实现 / 需求自相矛盾 / 文档与代码冲突且影响本次 / 缺关键标识符。其余按最合理假设推进并在交付里标注假设。
6. **不代跑构建/编译**：构建由用户本地执行；AI 只做静态自检，⛔ 不谎称「已编译通过」。

---

## 二、两阶段工作流

- **A. 准备期（讨论 → 需求 → 待办）**：澄清歧义；确认后写需求文档；生成可验收的待办清单（P0/P1…）。⛔ 准备期只动文档，不动代码。
- **B. 执行期（待办 → 代码 → 提交）**：按待办 + 规范改代码；做完同步台账「已完成」并 git commit。

---

## 三、变更声明（动手前先给）

① 文件清单（增/改/删逐条一句话）② 验收标准 ③ 已知风险 / 待用户拍板点。小改动可口头带过。

---

## 四、静态自检（交付前必跑）

- `.axaml` ↔ `.axaml.cs` 同步；using / 类型 / 命名空间对得上；主题键在白名单；引用的资源键都存在。
- 改列表页：表头与行同套列定义；隐藏列用宽度 0；`Grid.Column` 索引逐字核对。
- 改跨页投递：取件点在视图挂载回调（非数据上下文变更回调）。
- 改标签/树/导航：单例判定、关首页被拒、关最后自动回首页。
- 项目特定检查见 `<project>-spec.md`；部分项可用 `scripts/check.ps1` 自动化。

---

## 五、交付要求

- 变更清单（增/改/删逐条）+ 前置基线 + 用户本地验证命令。
- 直接写工作区，用 read/ls 确认落盘；⛔ 不打 zip、不列下载链接、不做 sources md 快照。
- 功能级交付 git commit（`&lt;type&gt;: &lt;简述&gt;`）；纯修报错不回写台账。
- 摸底用 grep/read 定向检索，⛔ 不整读、⛔ 不读 `artifacts/ bin/ obj/`。

---

## 六、分级读档原则

- 只加载用得上的：先读入口（`AGENTS.md` 类）+ 台账基线，再按任务读规格相关章节。
- 冲突以源码为准并回写文档；框架约束是硬规则，不可擅改。
- 同一条规则只在权威文档定义一次，其余引用不复制（避免双源漂移）。
