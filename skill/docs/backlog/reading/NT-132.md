## 一、背景 / 目标

用户原话：「书架批量更新做」（本轮同时定调：正文图片 / 图片阅读不做、reading 只做 txt 类；登录不做）。
现状：书架只能「继续阅读 / 分组 / 移出」，**没法知道哪本书更新了新章节** —— 想追更只能一本本点进去看目录。

## 二、范围

| 项 | 内容 |
|---|---|
| 批量更新 | 工具条「🆕 批量更新」：作用域 = 当前筛选结果，逐本回源站抓**详情 + 目录**（⛔ 不抓正文），并发 = 设置里的并发数 |
| 比章数 | 用目录章数跟上次基线比 ⇒ `new_count`；首次检查只建基线（`0`） |
| 单本更新 | 右键「🆕 更新这本」 |
| 更新列 | 列表新增「更新」列：`有 N 章更新 / 已是最新 / 未检查 / ⚠ 更新失败`，悬停看最新章节 / 章数 / 检查时间 / 失败原因 |
| 筛选 | 页内筛选条：分组 + 更新状态（有更新 / 已是最新 / 未检查 / 更新失败）+「只看有更新」 |
| 详情卡 | 加「更新 / 最新章节 / 检查结果」三项 |
| 数据 | `shelf` 增 `last_chapter` / `chapter_count` / `new_count` / `checked_at` / `update_note`（schema v4 → v5，`EnsureColumn` 补列） |

## 三、验收标准

- [ ] 书架点「🆕 批量更新」：状态栏实时报「正在检查… N / M 本」，跑完后「更新」列出现结果
- [ ] 第一次跑 = 全部「已是最新」（只建基线）；隔天再跑，有新增章节的书显示「有 N 章更新」
- [ ] 「只看有更新」只留有新章节的书；跑完再跑一次，没变化的书数字归零
- [ ] 某本书源被删 / 站点 404 ⇒ 该书标「⚠ 更新失败」并给出原因，**整批继续跑**
- [ ] 失败后再次成功：章数基线与「有 N 章更新」重新算对（失败那次不清基线）
- [ ] 「🔄 刷新书架」仍只重读本地库，不发网络请求
- [ ] 关闭书架标签页时正在跑的批量更新被取消
- [ ] `pwsh skill/scripts/accept.ps1` 一次通过

## 四、技术要点 / 约束

1. 🔴 **只改 `Module.Reading`**：⛔ 未动 Shared / Core / Shell / NewToys.UI。
2. `ShelfUpdateService`：`Task.Run` + 本地 `SemaphoreSlim(settings.Concurrency)`；`onDone` 逐本回调（UI 侧用 `Progress` 回到 UI 线程）。
3. 只抓详情 + 目录：一本 2 个请求；正文留给阅读页 / 预下载按需抓。
4. `ShelfStore.SetUpdate` 分两条 SQL：成功写全量，失败只写 `checked_at` + `update_note`（保基线）。
5. `shelf` 老库补列走 `EnsureColumn`，`Version` 4 → 5。
