## 1. 职责与边界

- **定位**：本地媒体资产的索引 + 整理（标签 / 分类 / 集合）+ 物理操作（移动 / 复制 / 软删 / 永久删）+ 任务队列。
- 🔴 **`FileOperationService` = 唯一动磁盘处**；其它服务只改索引。
- 物理删除唯一入口 = 列表右键「⛔ 从磁盘删除」（二次确认 + 任务队列 + 删索引）；详情卡 IconBar 的 🗑 只做**软删除**（移入回收站）。

## 2.5 操作逻辑（交互契约）

> **列表本体**：表格型列表页 = `<v:TableViewHost>`（原生表格）。点表头排序、拖列边界调列宽（会话内有效）；**表头右键只管列宽与列显隐，行右键管功能与筛选**。磁贴页（`assets-browse`）仍用 ListBox + 自绘 `ColumnGrid`（表头右键本就独立）。详见 `../ui.md` §6.3c。

> 跨模块共用语义见 `../ui.md` §10。本模块**所有磁盘写入只经 `FileOperationService`**，其它操作只改索引。

### 全部资产 `assets-all`（唯一资产浏览页）

工具条顺序：`📁 扫描`(SplitButton: 文件夹 / 文件) + 路径框(回车=预览) → `➕ 登记` → `🔄 扫描全部` → `🔎 校验文件` → `🏷 加标签` → `📚 加集合` → `▶ 播放`(SplitButton: 播放选中 / 导出播放列表) → `🗑 移入回收站` → `⤫ 从库移除` → `📊 读媒体信息` → `✏ 批量重命名…` → `🔍 查重合并` → `💾 加入库` → `🧹 清除列表` → `🔄 重读` → `🗄 并入…` → `💿 另存为…` → `📤 导出` → `📥 导入`。

> 批量类按钮（加标签 / 加集合 / 移入回收站 / 从库移除 / 读媒体信息）的启用条件是**有选中行**（`HasSelectedRows`）；选中口径 = 列表原生多选（见下表「多选」行）。状态栏右端「已选 N」显示选中条数。

| 操作 | 触发 | 结果 / 状态变化 | 约束 |
|---|---|---|---|
| 扫描预览 | `📁 扫描` 主钮 / 菜单「📄 文件…」/ 路径框回车 | 结果进列表（**草稿态**） | **⛔ 只进内存、不入库**；入库要再点 `💾 加入库` |

| 清除列表 | `🧹 清除列表` | 只清显示（含勾选 / 筛选） | 库里的数据仍在，点 `🔄 重读` 找回；⛔ 不删文件 |

| 从库移除 | `⤫ 从库移除` | 删 `assets` + 它的 `file_locations` 记录 | 对勾选行；**⛔ 不碰磁盘**（清理重复行的正解）；文件仍在已登记源目录里 ⇒ 下次扫描会重新入库 |
| 查重合并 | `🔍 查重合并` | 先报组数 → 确认 → 每组保留一条资产，其余标签 / 分类 / 集合 / 关联 / 位置并过去后删除 | 只认**完全相同的物理路径**（忽略大小写 / 分隔符）；⛔ 不动磁盘；不同路径的真副本要手工「从库移除」 |

### 资产浏览 `assets-browse`（资源管理器形态 · NT-115 → NT-116 改造）

**分工**：`assets-all` 按**元数据**找（搜索 / 标签 / 筛选），`assets-browse` 按**磁盘位置**翻（我知道它大概在哪个盘哪个文件夹）。
🔴 **数据来源 = 磁盘实时枚举为主 + 索引叠加**：左树 = 盘符 / 共享根 + 逐层子目录（**展开才枚举该层**，⛔ 不递归整盘）；右侧 = 当前目录的真实内容（子目录 + 全部文件）。索引命中 = 「已入库」（有缩略图、可做库操作），未命中 = **标灰但功能不减**（可打开 / 定位，库操作点了给提醒）。

**布局**：左「目录树」（宽 240，工具条 `◧ 目录树` 可整体收起）｜ 右「面包屑 + 双视图 + 底栏」；右侧详情卡由 Shell 统一承载（本页实现 `IDetailPanelProvider` / `IDetailCardSource`，工具条末位详情开关照旧）。

**详细视图列**：与「全部资产」共用同一份 `AssetColumns.All`（名称 / 类型 / 标签 / 分类 / 集合 / 大小 / 修改时间 / 存储源 / 时长 / 分辨率 / 编码 / 码率）；视频四列（时长 / 分辨率 / 编码 / 码率）在本页**默认隐藏**（默认图标卡视图），表头右键可逐个打开，显隐 / 列宽偏好按页键 `assets-browse` 独立落盘。

工具条顺序：`▦ 图标卡 / ☰ 详细信息`（按钮组）→ 排序（名称 / 大小 / 修改时间 / 类型，再点同一项 = 反向）→ 类型下拉 → 搜索框 → `➕ 加入资产库` → `🔄 重读` → `↥ 上一级` → `◧ 目录树`。

## 5. 坑点（🔴 实测过）

1. 🔴 **扫描「大小 + 修改时间」当识别键会碰撞**（误判为复制 / 改名）⇒ 必须叠加路径，见 NT-032。
2. 🔴 **多库融合重复 / 重叠并入会产生孤儿资产**（NT-033 已修）⇒ 合并后按主键去重 + 关系重挂。
3. 集合成员排序在**详情卡**用 **⬆⬇ 按钮**（⛔ 不是拖拽）；**智能集合规则未实装**（NT-018 偏差，仍开放）。
3.1 🔴 **分类列表的层级顺序 = DFS 序号，不是按名称**：`BuildRows` 先按 `parent_id` 建树、递归填 `Depth` / `FullPath` / `_treeOrder`，默认排序键用 `_treeOrder`。脏数据（父不存在 / 自环）必须**兜底成根**再入列 —— 否则那些分类整条从列表里消失。
3.2 🔴 **改父级的候选必须剔除自己与整棵子树**：`Move` 服务层会拦，但候选里留着就会让用户点了没反应；`SubtreeIds` 已带自环保护。
3.3 🔴 **`MusicTagService` 写标签是同步文件 IO**：文件被播放器 / 杀软占用时 `TagLib.File.Save()` 会抛 ⇒ 必须 `try/catch` 转成状态栏文案，⛔ 让异常冒到 UI。
3.4 **MusicBrainz 必须带可识别 UA 且限速 ~1 req/s**：一次联网只发一个 GET + 最多两次封面 GET；⛔ 批量循环查询（会被 503）。
4. 回收站曾缺「删除时间」列（NT-029 已修）：`AssetRow.UpdatedAt` + `AssetService.QueryRows` 末尾追加 `a.updated_at`（列索引 14，⛔ 不动 0~13）；移动 / 复制的 UI 入口 NT-030 曾补（现已删，见第 5 条），当时的两条约束仍有效：目标只能是已登记存储源根（`IsInside` 防穿越）+ 详情卡 ComboBox 用 `SelectedValueBinding`（⛔ WPF 专有 `SelectedValuePath` 在 Avalonia 会 AVLN2000）。
5. 收藏 / 评分 **即时落盘**（⛔ 不走「保存」）；「移动到 / 复制到（目标存储源）」整块已删（低频重操作不进卡）。
6. 资产详情卡 chips 的 `OptionsPath` 必须是常驻集合实例，否则 ComboBox 回写会抹掉页面值（见 `../ui.md` §7.2）。
7. `AssetTasksView` **不是标准列表页**（三块堆叠 + `ScrollViewer`）⇒ ⛔ 不套 `ListPageSkeleton`。
8. 空态引导只覆盖资产列表类页（`assets-all` 等）；`assets-categories` / `assets-collections` 数据源是左树 + 成员列表，**无空态也无 `HasItems`**（NT-060 遗留，未补）。
9. 🔴 **右键「📂 打开 / 📁 打开所在文件夹」⛔ 不许在 UI 线程直接 `File.Exists` + `Process.Start`**：两者都要碰目标文件所在卷，机械硬盘休眠唤醒要数秒、网络盘还要等超时 ⇒ 整窗卡死，用户会以为「比资源管理器慢」。资源管理器双击快是因为它不做前置存在性检查、且关联处理器已在 shell 进程内热加载。现在统一走 `AssetAllViewModel.FileOps.cs::RunOffUiThread`（线程池 + `Dispatcher.UIThread.Post` 回投文案）。
10. 🔴 **`TagsExpr` / `CategoriesExpr` / `CollectionsExpr` 内层必须 `SELECT n.name AS name`**：外层 `group_concat` 只能引用内层**输出列名**（`name`），写成 `group_concat(n.name, …)` 会让 SQLite 抛 `no such column: n.name`。这三个表达式只出现在 **WHERE（搜索）/ ORDER BY（按那三列排序）/ 表头筛选**，不在 `QueryPage` 的 SELECT 里 ⇒ 列表本身照常显示，但**任何关键字搜索恒返回 0 行、按标签/分类/集合排序恒空**，且异常被 `catch` 吞成空页（2026-10-27 修；`LastQueryError` 现在会上状态栏 `⚠`）。
11. 🔴 **存储源 = 目录；一个文件只属于它上一级文件夹的源**（2026-11-03 口径**反转**，取代旧版「归覆盖它的祖先源 / 拒绝父子源」）：
    - 扫描时按目录**就地登记**源（`ScanService.EnsureStorageForDir`）；父子源共存是正常数据，⛔ 不再拒绝登记。
    - 历史挂在祖先源下的位置，扫到同一路径时**改归**自己的目录源（`LoadSubtreeLocations` 认领），⛔ 不重复建资产。
    - 仍会重复的只剩映射盘 `Z:\` 与 `\\nas\` 双写法（路径不同）⇒ 手动移除其中一个源，或 `🧹 合并重复`。
12. 🔴 **对话框 `await` 之后必须回到 UI 线程**：`await DialogHooks.ConfirmAsync(...).ConfigureAwait(false)` 会让后续代码跑在线程池上，紧接着的 `Reload()` → `Items.Clear()` / `Selected` setter → Shell `ToolbarHost` 改可视属性，直接抛 `InvalidOperationException: The calling thread cannot access this object…`（未捕获 ⇒ **整个窗口崩掉**，日志 `logs\crash-*.log`）。
    - 规则：模块内所有 `DialogHooks.*Async` 一律 `ConfigureAwait(true)`（本项目 `RuleCatalogViewModel` / `VideoFileService` 同口径）；`Reload()` 自身还有一道 `Dispatcher.UIThread.CheckAccess()` 兜底。
    - 别在 `DialogHooks` 的调用点上写 `ConfigureAwait(false)` 图"性能"——它换来的是跨线程崩溃。
13. 🔴 **批量改 `ListBox.SelectedItems` 必须先关 `AutoScrollToSelectedItem`**：`SelectingItemsControl` 默认每 `Add` 一项就把该项滚进视野（虚拟化下还要实例化容器 + 触发布局）⇒ 全选 / 大范围 `Shift` 连选上百行 = 上百次滚动，表现为「列表自己往下滚 + 界面卡死」。`AssetAllView.BulkUpdateSelection` 统一处理（临时关滚动 + `_syncingSelection` 抑制回抛 + `finally` 恢复，保证键盘方向键仍自动滚动）。
14. 🔴 **资产浏览页的「一行」= 一个磁盘条目**（文件或子文件夹）：同一资产在 A / B 两个目录各出现一次是正确语义 ⇒ 缩略图键 / 选中认领 / 去重一律按**绝对路径**，⛔ 用 `LocationId` 或 `Row.Id`（未入库项的合成行 `Id=0`，用 Id 会让它们全部互相匹配）。库操作的对象 = `SelectedRows`（**只装已入库项**），未入库项只走「打开 / 定位 / 加入资产库」。
15. 🔴 **缩略图缓存淘汰时⛔ 不许 `Dispose`**：被淘汰的 `Bitmap` 可能正被界面的 `Image` 持有，释放后下一帧渲染会崩在 Skia 里。`AssetThumbCache` 只丢引用、交给 GC；LRU 上限 300 远大于一页（≤500，默认 120），正常使用不会淘汰正在显示的图。
16. 🔴 **目录树计数按「已入库子孙文件数」累加，不是 `Children.Count`**：`AssetBrowseService.CountByAncestor` 对每条已入库位置行的目录一路加到根（父目录 = 自己 + 全部子孙），未入库目录显示 0（不显示徽标）。
17. 🔴 **树 = 磁盘真实目录 + 懒加载，⛔ 别再按索引建树**：顶级 = 所有可访问盘符 + 不在任何盘符下的存储源根（UNC）；**节点首次展开才枚举它这一层**（`AssetBrowseService.LoadChildDirectories`，⛔ 不递归），权限 / 掉线 ⇒ `IsAccessible=false` 显示「（无法访问）」。`↕ 展开` 只展开**已枚举过的层级**（递归全盘展开等于进页面就把所有盘扫一遍）。节点是否「已入库」= 路径落在某个 `storages.root_path` 之内（`AssetBrowseService.IsUnder`）。
18. 🔴 **切目录卡顿的三处真凶**：① 左树是 `ListBox#TreeList`（自带虚拟化；⛔ 换回 `ItemsControl` + `StackPanel` 就是给每个节点建 Button）且 `RebuildTree()` 一次性换 `TreeNodes` 引用；`SelectNode` 只在展开状态**真的**变了才重建，选高亮只动「旧 + 新」两个节点；② 目录内容枚举（`DirectoryInfo.EnumerateFileSystemInfos`）一律在**后台线程**，回 UI 按 `_viewVersion` 校验后填卡；③ 排序 / 筛选在 UI 线程也要 O(n) 文化比较 ⇒ 大目录先丢后台。
19. 🔴 **缩略图只解「可视区」，⛔ 别在填卡时全量解；且只解已入库项**：未入库项 ⛔ 不读盘（`AssetTile.WantsThumb` 里已经排除）。口径 = `FillChunk` 只解首屏 `InitialThumbQuota`（36）张；其余靠 **`ScrollViewer` 的 `Offset` / `Extent` / `Viewport` 属性通知**驱动 `ReportViewport(offset, viewport, extent)`，VM 按「平均每项占高」估算索引范围、上下各预取一屏，`_thumbRequested`（按**绝对路径**）去重。🔴 **⛔ 用 `LayoutUpdated` 当滚动驱动**：滚动只改 ScrollViewer 偏移，不保证每帧都触发本页布局回调 ⇒ 滚到底部时可视区一次都没上报过，缩略图停在首屏那 36 张（本轮 bug 根因）。缺缓存的图由**生成泵**随滚动持续追加生成（不是进目录一次性整页批处理）。换视图 / 换尺寸时 View 要解绑旧 ScrollViewer 的监听并把 `_lastReportedOffset` / `_lastReportedExtent` 重置成 `NaN`。
20. 🔴 **嵌套文件夹（2026-11-03 口径反转，取代旧版「归覆盖源 / 跳过子孙源」）**：① 目录加入库 ⇒ 每个文件归它**上一级文件夹**的源，该目录没有源就登记一个（`AssetService.FindExactStorage` / `CommitRows`），⛔ 不再归祖先源；② 父源扫描会为子树里每个文件夹各自登记源，子源因「父源已拆好」而跳过，⛔ 不是被排除；③ 单文件入库登记的是**它所在的目录**，⛔ 不登记盘符根（否则一扫就是整个盘）。
21. 🔴 **TableView 内置列宽拖拽不能直接用**（Avalonia 12.1 `TableViewColumnHeader.OnResizerDragDelta`）：① 下限取 `resizer.Bounds.Width`（12px）⇒ 表头文字能被拖没；② 每帧算 `ActualWidth + delta`，而把手随列宽移动 ⇒ 正反馈，轻推一下列宽就跳一大截。本页改成**自绘拖拽**（`AssetAllView.axaml.cs::TryBeginColumnResize`）：命中口径是**列边界**（先命中把手 `PART_Resizer` 的 Thumb，兜底 ±10px 几何；主题把把手 IsEnabled 绑到列的 CanUserEffectivelyResize，固定列需用本地值放开），按下即 `e.Handled = true` 拦掉 Thumb；XAML 里所有列都可拖（⛔ 别再写 `CanUserResize="False"`），边界两侧一增一减、总宽守恒，最右列无右邻时只改自己，位移一律用**指针绝对 X − 起始 X**；首次移动时把其余可见星号列按当前宽**固化像素**，之后只改「被拖列 + 右侧最近的一个可拖列」一增一减 ⇒ 总宽守恒、其它列（含中间固定列）纹丝不动；下限 = 表头文字测宽 + 18。换别的页用 TableView 同样要自绘，⛔ 别指望控件自带。
22. 🔴 **「最近扫描」⛔ 不能按 `scan_jobs` 查**：一次「扫描全部」只建**一条** job（`storage_id` 为 NULL），按 job 查会把没单独扫过的源全显示成「从未扫描」（用户实测报障）。现在扫到哪个源就写 `storages.last_scan_at`（`AssetService.SetStorageLastScan`），列优先读它、老库回退 job。扫描是按目录切源的，所以收尾时对**子树内每个源**都要写一次（`ScanService.SubtreeStorages`）。
23. 🔴 **扫描里 ⛔ 不许读元数据 / 生成缩略图**（用户实测「扫描太慢」的根因）：`FlushNew` 曾经每 200 个新文件就 `GetAwaiter().GetResult()` 等一批 ffprobe / ffmpeg 跑完 —— 几百个视频 = 几分钟，遍历只占小头。现在扫描只写索引，新位置交给 `ScanService.OnNewLocations` → 模块接到 `TaskQueue` **后台**补元数据（开关 `AutoExtractMetadata`）；缩略图只在**浏览页滚动到可视区**时按需生成（开关 `AutoGenerateThumbnails`）。配套三处提速：① 子树内所有源的位置一次 `ListLocationsForStorages` 查完分桶，换目录不查库；② 新目录的源走 `InsertStorageFast`（⛔ 不用会全表查的 `UpsertStorage`）；③ 收尾的 missing 校准 + 最近扫描合成一个事务（`FinishStorageScans`）。
24. NT-114 · 选中真相 = `SelectedRows`（列表原生 Ctrl/Shift 多选，⛔ 勾选列 / 「多选」开关）；`⤫ 从库移除` 只删索引（磁盘零操作）、`🔍 查重合并` 只认完全相同的物理路径、`📊 读媒体信息` 走 `MetadataService` 手动补读；关键文件 `AssetAllViewModel.Selection.cs` / `AssetService`。

25. 🔴 **详情卡编辑态（`EditFileName` / `EditFileExtension` / 评分 / 标签 chips…）与 `Selected` 是两套数据**：只读字段直接绑 `DetailRow.*`（= `Selected`），编辑字段只在 `OnSelectedChanged → LoadDetail` 里填。构造函数原先在 `Reload()` 之后调 `LoadDetail(null)` ⇒ 首行已被认领但编辑态被清空，表现为**初次打开页面文件名框空、后缀也不显示，点一行才恢复**（去掉「含扩展名」水印后才显眼）。修法 = ctor 末尾改 `LoadDetail(Selected)`；任何「初始化时清空编辑态」都要先看 `Selected` 是否已被认领。数据流见 §3.3。
