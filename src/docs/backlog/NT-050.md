## 背景 / 目标

设置分组里混着**模块专属**设置页。本次按媒体资产（NT-021）既定模式归位：

| 设置页 | 归属判定 | 处置 |
|---|---|---|
| 软件源 `settings-package` | PcTools 软件包功能的源设置（数据落 `config\package.json`，Core 服务不变） | **迁入 Module.PcTools**（View/VM + DI + 菜单自注册） |
| 加密 DNS `settings-dns` | 写 `app.json`、`EncryptedDnsService` 在 Core ⇒ **应用级** | ⛔ 不迁，留 Module.Settings |
| 一键按钮 `settings-launch` | 首页（Shell 一级菜单）功能 | ⛔ 不迁 |
| 功能清单 `settings-all` | 菜单注册表总览 | ⛔ 不迁 |
| 媒体资产 `settings-media-assets` | 已归模块（NT-021） | 仅**改名**「媒体资产设置」——现名与一级菜单「媒体资产」同名，左树两处出现易混淆 |

## 技术要点 / 约束（规范章节、坑点、关键文件）

- View/VM 由 Shell 按 `RegisterFunction` 的视图名 + DI 解析 ⇒ 换项目后**只要 DI 注册即可解析**，无其它耦合点。
- `PackageSourceViewModel` 依赖均在 Shared（`IPackageManagerService` / `IPackageSettingsService` …，实施时按构造函数据实核对）⇒ PcTools 注入无门槛。
- ⚠️ 搬移后检查 `PackageSourceView.axaml` 是否引用 `Module.Settings` 内的资源/样式（应只有 App.axaml 全局键）；若有一起处理。
- ⛔ 不改 `settings-package` 的 Key / Order / 图标 / 描述——收藏与跳转按 Key 寻址，Order 变会打乱左树。
- 媒体资产改名是**一处字符串**，⛔ 不顺手改别的。
