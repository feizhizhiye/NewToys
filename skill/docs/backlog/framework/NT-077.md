## 背景 / 目标
三层语义：
| 层 | 落点 | 生命周期 |
|---|---|---|
| L0 机器环境 | `%LOCALAPPDATA%\NewToys\env.json` | 跟随机器，不随配置档 |
| L2 框架偏好 | `profiles\<p>\config\shell.json` | 跟随配置档 |
| L3 模块设置 | `profiles\<p>\config\modules\<模块>.json` | 跟随配置档 |

现状问题：
1. `app.json`（应用根）把**机器级**（`FfmpegPath` / `PlayerPath` / `PythonPath` / `PwshPath` / `UpdateUrl` / DNS）与 Profile 参数混在一起。
2. 🔴 `app.json.VideoDbFolder` 写死了**某个 profile 的绝对路径**（实测 = `...\profiles\default\data`）—— 切配置后视频工具指向别人的目录，属现存缺陷。
3. 5 个框架级小文件（`ui` / `theme` / `window` / `favorites` / `columnlayout`，合计 <2.2KB）各占一个文件、各有写入者。

## 验收标准（Acceptance Criteria）
- [ ] 1. `%LOCALAPPDATA%\NewToys\env.json` 承载机器级项（解释器三路径 / `UpdateUrl` / DNS 偏好），从 `app.json` 拆出；
      覆盖链：命令行 `--python/--pwsh/--ffmpeg` > 环境变量 `NEWTOYS_PYTHON` 等 > `env.json` > 内置探测。
- [ ] 2. `profiles\<p>\config\shell.json` 合并 `ui.json` + `theme.json` + `window.json` + `favorites.json` + `columnlayout.json`；
      一次性迁移（旧文件改名 `.legacy`，⛔ 不删），迁移幂等。
- [ ] 3. 4 个模块设置文件迁入 `profiles\<p>\config\modules\<模块>.json`（`script-manager` / `media-assets` / `video-tools` / `web-tools`）。
- [ ] 4. 删除 `app.json.VideoDbFolder` 字段（含 `GeneralViewModel` / `PathViewModel` 的展示项），视频目录一律由 `ConfigStoreService.DataDir` 推导。
- [ ] 5. 迁移后 `config\` 只剩：`shell.json` + `modules\*.json`（≤5 个文件）；`app.json` 只剩端口 / 启动 / 浏览器批量打开等**应用行为**，或整体并入 `env.json`（实施时定，见 §技术要点）。
- [ ] 6. 三层各自的「唯一写入点」明确：`env.json` 只由 `AppConfigService` 写；`shell.json` 只由 Shell 的 5 个服务写；模块文件只由该模块设置服务写。
- [ ] 7. 旧 `app.json` 读不到时不崩（首次启动自动生成），坏文件走 `.bak` 归档。
- [ ] 8. `pwsh skill/scripts/accept.ps1` PASS。

## 技术要点 / 约束
- 🔴 `app.json` 里 `Launch`（含 `Browser1/Browser2/Programs` 的 URL 列表）是**应用行为**而非机器环境：体积大、会随使用变化。
  实施时二选一并在卡内记录结论：(a) 留 `%LOCALAPPDATA%\NewToys\app.json`（机器级、跨配置共享，现状）；
  (b) 下沉到 `shell.json`（跟随配置档，但体积会让 shell.json 变大）。
  **倾向 (a)** —— 保持现状、零迁移，只把 `VideoDbFolder` 删掉。
- ⚠️ 跨程序集常量：`env.json` 只有 Core 写，模块只读 `IAppConfigService`，⛔ 模块感知文件名。
- ⚠️ `WindowBoundsService` 是 Shell 单例、`ThemeService` 在 Core —— 合并进 `shell.json` 后写入点变多，必须**同一把锁**（`JsonOptionsStore` 已有 `_gate`，可复用其写入序列）。
- ⛔ 不做「配置档继承 / 模板」；新建 profile 仍是空配置。

### 2026-10-19 · 第二批（`env.json` + `config\modules\` + 清退 `VideoDbFolder`）

**新增**：`Core/Services/EnvConfigService.cs`
- `<应用根>\env.json`（默认 `%LOCALAPPDATA%\NewToys\env.json`）**唯一读写入口**；键 = `ffmpeg` / `player` / `python` / `pwsh` / `pwsh51` / `updateUrl` / `dnsEnabled` / `dnsProviderId` / `dnsCustomUrl`（短小写，手改友好）。
- 覆盖链（读）：命令行 `--ffmpeg/--player/--python/--pwsh/--pwsh51/--update-url` ＞ 环境变量 `NEWTOYS_FFMPEG` / `NEWTOYS_PYTHON` 等 ＞ `env.json` ＞ 内置默认（`ffmpeg` 走 PATH）。**写只写文件**，覆盖值⛔ 不落盘。
- `OverrideNote` = 「当前被命令行 / 环境变量覆盖了哪几项」（设置页标注用）。

**改**
| 文件 | 改动 |
|---|---|
| `Core/Services/AppConfigService.cs` | 九项机器级字段降级为**迁移遗留**（`[JsonIgnore(WhenWritingDefault)]`）；新增 `MigrateMachineFieldsOnce()`：只填空 → 清空 app.json 旧键 → 立即 Save；九个属性改代理 `EnvConfigService`（`IAppConfigService` 表面不变 ⇒ 模块零改动） |

**结果**：`config\` 只剩 `shell.json` + `modules\*.json`（5 个）+ 用户数据导出件；`app.json` 只剩 `MaxConcurrency` + `Launch`。

**偏差 / 注意**
1. `package.json` 也搬进 `modules\`（它是 script-manager 模块的设置数据，不是框架偏好）。
2. `media-assets-user-data.json`（用户数据导出件）**没搬** —— 它是个导出产物，不是设置。
3. 迁移是**纯移动**（不复制）：只有目标已有同名文件时才用 `.legacy` 留档，避免同一份设置出现两份真相。
4. 搬文件失败（占用 / 只读）时读方会兜底读旧位置 ⇒ 不会「设置全丢」。
5. ⚠️ `env.json` 的「内置探测」只做到了默认值（`ffmpeg` / PATH），没做按安装位逐个探测 —— 那是 `InterpreterResolver` 的活，本卡不重复实现。
