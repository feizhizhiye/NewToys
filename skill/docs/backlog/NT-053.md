## 背景 / 目标

用户要求：各页面容器「至少适配一种」——最窄界面或默认大小。基线（已核实）：

- 窗口 `MinWidth=960` / `MinHeight=640`（`ShellView.axaml` 第 24-25 行），默认 1280×800。
- 设置页**无详情卡**（Module.Settings 无 `IDetailPanelProvider` 实现）⇒ 左树展开时**内容宽最窄 = 960-240 = 720**。
- 现有实测（2026-10-15 立项评估）：11 个设置页**均有根 `ScrollViewer`（ProfileView 例外，见下）**；`MaxWidth=760/860/1000` 是**上限不是固定宽** ⇒ 不违规；固定宽控件（`Width=300/260/280`、`Height=110/100/120` 多行框）单体均 < 720 ⇒ 不违规。
- **疑似点**：① `ProfileView` 根为 `Grid RowDefinitions="Auto,*"`、**无根 ScrollViewer**（内层 ListBox 若自带滚动则只需记录结论，否则补壳）② `DataView` `*,120,180` 固定列（720 宽下列表余量 420，判定 OK ⇒ 不改，记录结论）。

## 技术要点 / 约束（规范章节、坑点、关键文件）

- ⛔ 不给 `TextBlock` 用 `MinHeight` 撑行高（已知坑，行高基线在 `ListBoxItem`）。
- 本项是**审计 + 定点修**，⛔ 不趁机重排任何页面布局；改不动的一律记录结论。
- 业务模块页面（PcTools / VideoTools / WebTools / MediaAssets 的功能页）**不在本项范围**——用户诉求指向设置页；如后续要全量适配另立工作项。
