# NewToys 开发需求（宪法）

> 配套：`开发规范.md`（怎么做）｜`项目现状与进度.md`（做到哪了）｜`AI协作提示词.md`（会话启动）

---

## 一、定位

**NewToys 是作者个人自制的工具集——「带 GUI 的脚本管理器」。** 非商业、非通用产品，「自用顺手」第一。

每个页面 ≈ 一条或几条命令行 + 一份 `config/` 配置的封装。

## 二、边界

**判据**：「如果我只写个脚本会怎么写？现在少让用户做哪一步？」——这就是功能边界。

- **做**：把作者日常高频的终端/系统能力，包成可点、可配、可备份的界面。
- **不做**：脚本里不会有的东西——社交、推荐、引导、埋点、账号、云同步、**在线插件市场/商店**。
- **本地模块热加载**（丢 DLL 进 `modules/`、点按钮装载）**要做**——它不联网、不下载、不建生态，等于「加一个本地脚本」，不是"插件市场"。

## 三、功能域（一级，稳定）

首页（常用/收藏，无二级菜单）｜ PC 工具箱 ｜ Web 工具箱 ｜ 视频工具箱 ｜ 系统设置（固定最底）

- 具体页面清单、完成度由规范+台账维护，宪法不锁定。
- 宿主级能力（导航、主题、**模块装配与热加载**、数据管理）由 Shell 提供，不计入页面清单。

## 四、设计原则（六条）

1. **模块化** — 按模块拆分，可独立开发/启停。
2. **插件化** — 模块编译为独立 DLL，运行时装配，加模块不改宿主。
3. **轻量务实** — 工具类应用，重效率稳定，UI 不炫技。
4. **自控** — 不引入任何第三方 UI 库，全局控件自己写。
5. **命令行封装** — 功能以「包既有命令行/系统能力」为主，不超命令行上限；配置一律落文件、可备份。
6. **可热加载** — DLL 放入程序目录 `modules/`（= `<程序目录>\Modules\`，单一目录），运行中点「刷新/加载」即时装配新模块，不必重启；加载源仅限本地文件夹。

## 五、取舍

| 推论 | 落地 |
|---|---|
| 命令行上限 = 页面上限 | 软件包=winget GUI；视频库=ffmpeg/FS GUI；一键启动=Process.Start GUI |
| 配置即数据，可备份迁移 | 全部设置落根 `config/*.json`，数据管理页备份/恢复 |
| 参数暴露但有默认值 | 高级项不藏，默认值取"多数情况对的" |
| 失败要看得见原因 | 每页至少一行 StatusText，命令报错翻译成人话 |
| 不做平台/生态 | 模块=本地 DLL；热加载不联网；失败只影响该模块，宿主不崩 |

## 六、平台与工具链

- 主平台：**Windows 10 LTSC**（当前交付）；预留跨平台能力，迁移方向 **Debian 13**。
- 本地依赖：**pwsh 7 / python3 / ffmpeg**。
- .NET/Avalonia/MVVM 等具体版本锁在规范，宪法不锁。

## 七、新功能验收底线

答不上这四问就不做：
1. 对应哪条命令行/哪个系统能力？
2. 配置落在哪个 `config/*.json`？
3. 失败时用户在哪行看到原因？
4. （涉及模块）拷进 `modules/` 后运行中点刷新能否用上？失败会不会拖垮宿主？

## 八、文档体系

| 文档 | 回答 | 更新时机 |
|---|---|---|
| 本文件 | 做什么/为什么/边界 | 极少；定位/边界变化时 |
| 开发规范 | 怎么做（硬约束+折衷项） | 架构/约定/技术栈变化时 |
| 项目现状与进度 | 做到哪了/还差什么 | **每完成一个功能/一次交付更新一次** |
| AI协作提示词 | 本次会话怎么开工 | 协作流程变化时 |

- **单一权威**：同一条规则只在权威文档定义一次，其余引用不复制。
- **代码 > 文档**：冲突以 `src/` 源码为准并回写文档。
